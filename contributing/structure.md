# 目录结构与归档规则

## 仓库分工

```text
newswitch.github.io/
├── docs/                    # 技术正文：文件夹就是网站分类
├── blog/                    # 按日期发布的个人博客
├── src/
│   ├── data/domains.mjs      # 一级技术域、名称、排序和入口
│   ├── components/          # 可复用展示组件
│   ├── css/                 # 全站样式
│   ├── pages/               # 首页、lab 风格参考等独立页面
│   └── theme/               # Docusaurus 主题定制
├── static/img/              # 图片、技术图和分类图标
├── examples/                # 文章配套可执行源码
├── scripts/
│   ├── checks/              # 格式、链接、源码、运行和浏览器验证
│   ├── generators/          # 导航元数据和技术图生成
│   └── migrations/          # 有明确适用版本的一次性历史迁移
├── contributing/            # 不发布的维护说明、验证历史、迁移清单
├── sidebars.js              # 一级入口 + 基于物理目录的自动侧边栏
└── docusaurus.config.js     # 路由、主题、搜索与构建设置
```

`build/`、`.docusaurus/`、缓存和示例构建产物属于本地生成物，不作为文章源码提交。不要为了整理目录删除用户的本地产物或运行环境。

## 技术域

```text
docs/
├── intro.mdx
├── learning/             # 跨模块地图与阅读顺序
├── linux/                # 系统原理与原生命令
├── hardware/             # CPU、DIMM、主板、硬盘、NIC、供电与固件
├── gpu/                  # NVIDIA、昇腾、整机、CUDA/CANN、互联和设备管理
├── networking/           # 协议、路由交换、数据中心、RDMA、代理与网络排障
├── storage/              # I/O、本地存储、NFS、Ceph、对象存储、AI 存储
├── cloud-native/         # 容器、Kubernetes、服务发现与服务网格
├── ai-systems/           # 运行环境、训练、推理、模型制品与 MLOps
├── data-systems/         # 数据库、缓存、消息、搜索、分析与大数据
├── development/          # 语言、框架及开发组件
├── sre/                  # 可观测性、性能、可靠性和事故复盘
├── automation/           # 自动化工具、交付与 DevOps
├── projects/             # 跨技术域的完整项目
└── personal-projects/    # 独立作品
```

一级目录只表达技术主题。二级及以下直接来自文件夹，不通过手写侧边栏拼出另一套归档位置。

Java 组件的独立文件夹保留，方便后续扩展。仅有一篇正文的分类直接链接该文，不再增加空的分类卡片页；展开时仍保留正文子项，防止 Docusaurus 把整个文件夹折叠为一个文章链接。以后增加第二篇时，应明确选择总览文章或生成索引。

Java 配套源码按主题命名为 `language-lab`、`standard-library-lab`、`concurrency-lab`、`build-testing-lab` 和 `jvm-diagnostics-lab`，不再按写作批次命名。

## 归档与命名

1. 每篇文章只有一个主归属；跨模块通过相对 Markdown 链接串联，不复制正文。
2. 通用硬件归 `hardware/`；GPU/NPU 架构与执行栈归 `gpu/`；PyTorch 和推理框架归 `ai-systems/`。
3. Kubernetes 网络、NetworkPolicy 归 `networking/kubernetes/`，PV/PVC/CSI 归 `storage/kubernetes/`，通用控制面及扩展归 `cloud-native/kubernetes/`。
4. MySQL、PostgreSQL、MongoDB 归 `data-systems/databases/`，通用备份/PITR/容灾归 `database-reliability/`；缓存、消息、搜索、向量库各有独立父目录。
5. 命令参考放在各技术域的 `commands/`，按操作对象分类。命令分组与学习路线可以不同：路线是阅读顺序，文件夹是内容归属。
6. 有学习顺序的文件使用 `00-`、`01-` 等前缀，`sidebar_label` 使用对应序号。不要只为凑统一篇数或层数拆分文章。
7. 文件夹使用稳定、可识别的英文技术名称；中文展示名称写入 `_category_.json`。系列入口使用 `00-xxx学习路线.md` 或学习地图。
8. 每个分类默认 `collapsed: true`。当前技术目录最深四级；新增更深层级前先判断能否去掉重复概念，不机械增加 `platform`、`articles`、`content` 层。
9. 技术文档统一位于 `/docs/...`。Docusaurus 按前缀解析规则生成 ID，通常会去掉排序数字，日期和类似版本号的名称有例外（如 `02-8021X`）；不要手工猜测路由。逻辑父子关系必须与本地一致。

## 导航维护

`src/data/domains.mjs` 只维护一级技术域，不保存文章列表。首页、文档导读、侧边栏共用它。修改一级标题、顺序或入口后执行：

```bash
npm run sync:navigation
npm run check
```

二级及以下由 `sidebars.js` 的 autogenerated 生成。分类可使用已有文章作为入口，也可配置 generated-index。多篇分类的入口文章不再重复列入子项；单篇分类保留“文件夹 → 正文”层级，文件夹本身也能一键进入文章。

改目录时同时改相对链接、分类入口、示例路径、验证脚本和硬编码 URL。格式和链接检查通过之后，执行生产构建以及 `npm run check:site`，逐层比较生成侧边栏与实际文件夹。不要只检查首页能打开就认定迁移完成。
