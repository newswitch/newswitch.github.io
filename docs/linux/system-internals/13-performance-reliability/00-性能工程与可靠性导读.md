# 性能工程与可靠性导读

性能不是“把利用率调高”，可靠性也不是“服务还活着”。系统要在给定工作负载和故障条件下，持续满足吞吐、延迟、正确性和恢复目标。

## 1. 先定义问题

```text
工作负载：请求大小、并发、读写比、连接模型、数据局部性
约束：CPU/NUMA、内存/cgroup、存储、网络、功耗与成本
指标：吞吐、延迟分布、错误率、资源效率
可靠性：故障域、超时、重试、降级、RTO、RPO
```

没有固定工作负载和基线，优化前后数字不可比较。平均延迟也不能代表 P99；设备利用率不高也不能证明没有串行等待、配额节流或单队列热点。

## 3. 闭环

```text
明确用户目标与工作负载
→ 记录稳定基线
→ 找到等待时间和饱和资源
→ 提出单一、可证伪假设
→ 一次只改变一个主要变量
→ 回归正确性、长尾、资源与成本
→ 保存环境、数据和结论适用边界
```
