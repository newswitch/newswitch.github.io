# 内存性能：带宽、延迟、局部性、缺页与回收

“内存还有很多”只回答容量。应用可能因内存带宽饱和、远端 NUMA、Cache miss、TLB miss、缺页或直接回收而慢。

## 1. 路径

```text
寄存器
→ L1/L2/L3 Cache
→ 本地内存控制器与 DRAM
→ Socket 互连 → 远端 DRAM
→ 缺页分配/文件读取/Swap
```

每下降一层，延迟与共享竞争通常增加。工作集大小和访问模式决定 Cache/预取是否有效。

## 2. 带宽与延迟

顺序流式访问容易用满带宽并被硬件预取；随机 pointer chasing 更受单次延迟限制。平均 CPU 使用率相同，两者性能特征完全不同。

硬件内存带宽事件依平台，需使用厂商 PMU/工具并与 NUMA 拓扑对应，不能用 `free` 推导。

## 3. Page Fault

- minor fault：页无需从块设备读入，例如匿名页首次分配/COW/已在 page cache。
- major fault：需要 IO 获取页面，通常延迟更高。

```bash
pidstat -r -p <PID> 1
perf stat -e page-faults,minor-faults,major-faults -p <PID> -- sleep 10
```

minor fault 多也可能造成 mmap 大模型/大堆启动延迟和页表开销。

## 4. 回收与 Compaction

内存低水位触发后台/直接回收；分配者进入 direct reclaim 会直接增加请求延迟。高阶页/THP 分配还可能触发 compaction。检查 vmstat、PSI、cgroup `memory.events`，区分全局与 memcg 压力。

## 5. Allocator 与 RSS

应用 free 后，内存可能留在 allocator arena/tcache，RSS 不立即下降；但页面可复用，不等于泄漏。要用 heap profile、smaps/PSS 和增长趋势区分 live objects、碎片与缓存。

## 6. 练习与答案

**问题：Swap 使用量不为 0 是否表示系统正在抖动？**

答案：不表示。冷页可长期留在 Swap；要看持续 swap-in/out、major fault、PSI 和业务延迟。

**问题：开启 THP 一定提高性能吗？**

答案：不一定。它可减少 TLB miss，但也可能增加 compaction、内存放大和延迟，需按 workload 验证。
