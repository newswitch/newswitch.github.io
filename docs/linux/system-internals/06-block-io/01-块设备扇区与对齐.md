# 块设备、扇区与对齐：Linux 如何描述磁盘、LUN 和 NVMe Namespace

块设备向上提供按逻辑块寻址的随机访问接口。它可能是物理盘、NVMe Namespace、SAN LUN、RAID、LVM LV、dm-crypt 或 loop 设备；设备节点名称并不能说明底层只有一层。

## 1. 设备节点与内核对象

`/dev/sda`、`/dev/nvme0n1` 是设备节点，通过主设备号和次设备号关联内核块设备对象：

```bash
ls -l /dev/sda /dev/nvme0n1 2>/dev/null
lsblk -o NAME,MAJ:MIN,TYPE,SIZE,FSTYPE,MOUNTPOINTS
```

udev 根据设备属性创建稳定符号链接，如 `/dev/disk/by-id/`、`by-uuid/`。生产配置应优先使用与目标语义匹配的稳定标识，而不是依赖枚举顺序。

## 2. 逻辑扇区与物理扇区

- Logical sector：操作系统向设备寻址和提交 IO 的基本逻辑单位。
- Physical sector：设备介质内部最小物理更新单元之一。
- 文件系统块：文件系统分配和组织数据的单位，可能大于逻辑扇区。
- Page/Folio：内存管理与 Page Cache 的单位，又是另一层。

```bash
lsblk -o NAME,LOG-SEC,PHY-SEC,MIN-IO,OPT-IO,ALIGNMENT
blockdev --getss /dev/DEVICE
blockdev --getpbsz /dev/DEVICE
```

设备、虚拟层和阵列可能报告不同粒度，信息也可能被虚拟化层隐藏。

## 3. 对齐为什么重要

一个上层写入若跨越底层物理更新边界，设备可能执行读—改—写，增加写放大。分区起点、RAID stripe、文件系统布局和应用块大小都可能影响对齐。

```text
应用 4KiB 写
→ 文件系统块
→ LVM/加密/RAID stripe
→ 设备逻辑/物理单元
```

不能只检查分区起点就宣布“全栈对齐”；还要结合中间虚拟层和工作负载。

## 4. 分区不是必须层

文件系统可以建立在分区、整盘、LVM LV、MD RAID 或其他块设备上。GPT/MBR 描述磁盘分区布局，文件系统再管理其获得的块范围。分区表损坏和文件系统损坏是不同层的问题。

## 5. discard/TRIM

删除文件时，文件系统释放逻辑块，但 SSD 不自动知道哪些闪存页不再有用。Discard/TRIM 可把释放范围通知下层；可周期批量执行，也可在线 discard。

持续 discard 的延迟行为与设备、阵列、加密和云盘支持有关。看到挂载选项不代表整条路径一定透传，应逐层验证。

```bash
lsblk -D
findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS
```

## 6. 容量为什么分层不一致

- 设备标称十进制 TB 与系统二进制 TiB 单位不同。
- RAID、纠删码、快照和 thin provisioning 改变可用容量。
- 文件系统保留块、元数据和日志消耗空间。
- 云盘/LUN 的逻辑容量可能大于实际后端已分配空间。

## 7. 练习与答案

**问题：`/dev/sdb` 是一块物理磁盘吗？**

答案：不一定。它可以是虚拟机磁盘、SAN LUN、USB、RAID 逻辑盘或其他 SCSI 风格块设备，需沿 sysfs、udev、控制器和平台信息确认。

**问题：文件系统块大小 4KiB，是否证明底层所有写都 4KiB 且完全对齐？**

答案：不能。请求可能合并、拆分，且还经过 RAID、LVM、加密、设备物理单元和控制器缓存。
