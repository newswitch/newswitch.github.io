# 中断、异常与陷阱：CPU 为什么会离开当前指令流

CPU 正常顺序执行指令，但设备事件、当前指令错误、缺页或程序主动请求内核服务都会改变控制流。它们都可能“进入内核”，触发原因和恢复方式却不同。

## 1. 先按是否同步分类

| 类型 | 与当前指令是否同步 | 示例 | 返回后通常做什么 |
|---|---|---|---|
| 硬件中断 | 异步 | 网卡完成收包、NVMe 完成 IO、定时器 | 继续被打断的执行流或触发调度 |
| 异常 | 同步 | 缺页、除零、非法指令、保护错误 | 修复后重试、向进程发信号或终止 |
| 系统调用/陷阱 | 同步且由程序主动触发 | `syscall`、`svc` | 执行内核服务后返回下一条用户指令 |
| 软件中断类机制 | 由内核安排 | NET_RX_SOFTIRQ、定时器后半部 | 在受限内核上下文处理延后工作 |

不同架构术语不完全一致。分析时不要纠结某个名字是否都叫“陷阱”，应关注触发源、同步性、当前上下文、能否睡眠以及返回语义。

## 2. 硬中断为什么要尽快结束

设备通过中断控制器通知 CPU。CPU 保存必要状态并运行中断处理程序。硬中断上下文不能执行可能睡眠的操作，否则没有普通进程上下文可供安全阻塞。常见策略是：

```text
硬中断上半部
  → 确认设备和中断原因
  → 禁止或节流后续通知
  → 安排后半部工作
  → 尽快返回

软中断/NAPI/工作队列
  → 批量处理数据
  → 必要时唤醒等待进程
```

网卡高吞吐场景不会简单地“每个包触发一次完整中断”。NAPI 会在中断通知后切换到轮询批处理，降低中断风暴，但可能让 CPU 时间集中在 `NET_RX` softirq。

## 3. 缺页异常不一定是错误

CPU 访问虚拟地址时，如果页表不存在有效映射或权限不符，会触发 Page Fault。内核根据 VMA 判断：

- 合法但尚未建立映射：分配匿名页、建立文件页映射或执行 Copy-on-Write。
- 页面已换出：从 Swap 读回。
- 地址不属于合法 VMA或权限不允许：通常向进程发送 `SIGSEGV`。

因此“发生 Page Fault”很正常。Minor Fault 不需要从块设备读入目标页；Major Fault 通常需要等待存储，延迟可能显著更高。

## 4. 异常如何变成信号

硬件报告异常后，内核先判断能否在内核内部修复。如果错误来自用户态且无法修复，内核把它转化为信号，例如：

| 事件 | 常见信号 |
|---|---|
| 非法地址或权限访问 | `SIGSEGV` |
| 非法指令 | `SIGILL` |
| 算术错误 | `SIGFPE` |
| 调试断点 | `SIGTRAP` |
| 总线/对齐或硬件地址错误 | `SIGBUS` |

同一个信号可以有多个原因，需要结合 `siginfo_t`、Core Dump、日志和指令地址判断。

## 5. 中断会在哪个 CPU 上处理

硬件中断有 IRQ Affinity，可以投递到一个或多个 CPU。网卡多队列还会通过 RSS 把不同流映射到不同接收队列。软中断通常在触发它的 CPU 或对应 `ksoftirqd/N` 上处理。

```bash
cat /proc/interrupts
cat /proc/softirqs
grep -E 'NET_RX|NET_TX|BLOCK|TIMER' /proc/softirqs
```

示例：

```text
           CPU0       CPU1       CPU2       CPU3
NET_RX:   12480      99210      98111      13002
BLOCK:     8012       7998       8130       8066
```

这表示累计事件在 CPU1、CPU2 上更多，不等于当前每秒速率。需要间隔采样求差，并结合 IRQ、队列和业务流量判断是否失衡。

## 6. 常见误判

- `%si` 高不代表网卡坏了；它表示 CPU 花在软中断的时间多，原因可能是流量、包率、队列或亲和性。
- 某个 IRQ 计数只在一个 CPU 增长不一定异常，可能是配置的 affinity。
- Page Fault 多不等于内存不足；需要区分 minor/major、首次访问、COW 和回收。
- 中断处理快不代表业务延迟一定低，后续软中断、调度和应用队列都可能拥塞。

## 7. 练习与答案

**问题：网卡收到数据时，为什么应用线程不一定立即得到 CPU？**

答案：数据要经过 DMA、IRQ/NAPI、软中断、协议栈和 Socket 接收队列。内核唤醒应用后，线程还要进入运行队列等待调度。

**问题：缺页异常发生在用户指令上，为什么由内核处理？**

答案：MMU 检测页表或权限问题后同步陷入内核，内核拥有地址空间和物理页管理权限，负责建立映射、读回页面或向进程报告非法访问。
