# 容器边界误区与现场排查：共享内核意味着什么

容器隔离能显著缩小进程视图和权限，但边界强度取决于配置与宿主内核。特权容器、宿主 Namespace、危险挂载和设备访问会有意打开边界。

## 1. 高风险配置

- `privileged`：通常赋予广泛 capability、设备和宽松 LSM 标签。
- `hostPID/hostNetwork/hostIPC`：共享宿主对象视图。
- 挂载宿主 `/`、`/proc`、`/sys`、运行时 Socket 或 kubelet 凭据。
- `CAP_SYS_ADMIN`、`CAP_SYS_MODULE`、`CAP_BPF`、`CAP_SYS_PTRACE` 等高影响 capability。
- 可写设备节点、Docker/containerd Socket。
- 禁用 seccomp、SELinux/AppArmor 或允许不受约束 profile。

风险来自组合，不应只检查 `privileged` 一个字段。

## 2. 边界验证

```bash
grep -E 'Cap(Inh|Prm|Eff|Bnd|Amb)|NoNewPrivs|Seccomp' /proc/<PID>/status
readlink /proc/<PID>/ns/*
cat /proc/<PID>/mountinfo
cat /proc/<PID>/cgroup
cat /proc/<PID>/attr/current 2>/dev/null
```

需要从宿主 PID 检查，容器内工具可能缺失且视图受限。把结果与工作负载清单和 runtime inspect 交叉验证。

## 3. “只读 rootfs”边界

只读 rootfs 只限制该挂载树的写入；tmpfs、volume、`/proc/sys`、设备、Unix Socket 和外部服务仍可能提供写路径。应用也需要明确可写目录和容量限制。

## 4. Runtime Socket 为什么危险

能控制高权限容器运行时 API，通常就能请求创建挂宿主目录、使用宿主 Namespace 的新容器，效果接近宿主 root。把 Socket 只读挂载也不让其协议调用变成只读。

## 5. 安全排障不要先关闭策略

按层确认：DAC → capability → LSM → seccomp → mount/device/cgroup。将拒绝日志与精确操作关联，修改最小策略并回归。全局设置 permissive/unconfined 会隐藏真正缺失的权限模型。

## 6. 最小化原则

```text
非 root / User Namespace
→ drop ALL 后按需增加 capability
→ RuntimeDefault seccomp
→ SELinux/AppArmor 强制策略
→ 只读 rootfs + 明确可写 volume
→ 禁止宿主 Namespace/Runtime Socket/不必要设备
→ 及时修补宿主内核与运行时
```

## 7. 练习与答案

**问题：容器使用非 root 用户，是否一定无法影响宿主？**

答案：不一定。危险 Socket/设备/挂载、过量 capability、内核漏洞和凭据仍可能扩大影响；非 root 是重要一层但不是完整防线。

**问题：seccomp 拒绝 syscall 与 SELinux 拒绝文件访问如何区分？**

答案：检查进程 seccomp 状态、返回信号/errno 和 audit 记录；SELinux 通常产生 AVC，二者处于不同检查层。
