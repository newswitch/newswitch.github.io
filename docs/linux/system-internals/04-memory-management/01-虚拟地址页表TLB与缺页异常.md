# 虚拟地址、页表、TLB 与缺页异常：CPU 怎样找到真正的内存

进程读写的是虚拟地址。CPU 的 MMU 根据当前地址空间的页表把它翻译成物理地址，并在 TLB 中缓存近期翻译。内核负责创建页表、处理缺页并保证不同进程隔离。

## 1. 为什么要有虚拟地址

虚拟内存提供：

- 每个进程独立、连续的地址视图。
- 页级读、写、执行权限。
- 按需分配，保留地址不必立即占物理页。
- 同一物理页映射到多个地址，实现共享库和共享内存。
- 文件映射、COW、Swap 和 NUMA 迁移的统一基础。

虚拟地址空间大小由 CPU 架构和内核配置决定，不等于机器安装的 RAM。

## 2. VMA 与页表分工

`vm_area_struct` 描述一段连续虚拟地址的高层语义：范围、权限、匿名或文件来源等。页表描述具体虚拟页到物理页的映射和硬件权限。

```text
mm_struct
├── VMA A：代码，r-x，文件映射
├── VMA B：数据，rw-，文件/匿名
├── VMA C：堆，rw-，匿名
├── VMA D：共享库
└── VMA E：栈，rw-，匿名

虚拟地址
→ CPU 查询 TLB，未命中则按架构遍历页表
→ 映射和权限有效：物理页帧 + 页内偏移
→ 缺页/权限异常：内核查 VMA，决定补页、COW 或拒绝访问
```

VMA 存在不代表每个页面都已经驻留，也不代表页表项已经建立。

## 3. 多级页表为什么存在

如果为巨大虚拟地址空间建立一张完全展开的线性表，会浪费大量内存。多级页表只为实际使用的地址范围分配中间层。具体层数、页大小和条目格式依架构及配置变化。

以常见 4 KiB 基础页为例，虚拟地址可概念性拆成多个页表索引和 12 位页内偏移。不要把 4 KiB 当成所有架构唯一页大小。

### 3.1 四级 x86-64 页表的逐位手算

限定为四级页表、48-bit Canonical 地址、4 KiB 页、每项 8 字节；不含五级模式、Huge Page 和嵌套虚拟化。每张 4 KiB 页表有 512 项，因此每级索引占 9 bit：

```text
bits 47..39：PGD/PML4 索引
bits 38..30：PUD/PDPT 索引
bits 29..21：PMD/PD 索引
bits 20..12：PTE/PT 索引
bits 11..0 ：页内偏移
```

取合法用户地址 `0x0000000123456789`，四个索引依次是 0、4、282、86，页内偏移为 `0x789`。若页表根物理基址是 `0x100000`，先读 `0x100000+0×8` 的项，提取下一张表的页帧；在下一表基址加 `4×8` 读取，再用 `282×8`、`86×8`。中间项的权限与末级权限共同限制访问，不能只检查最终 PTE。

若最终映射 PFN 为 `0xABCDE`，物理页基址为 `0xABCDE000`，目标物理地址为 `0xABCDE789`。页表项的标志位要先剥离，不能把整个 PTE 数值直接当物理地址。Linux 的五级软件抽象在四级配置折叠 P4D，硬件遍历层数因此不能只按结构名字数。[内核 Page Tables](https://docs.kernel.org/mm/page_tables.html)解释了分层、折叠和大页的关系。

### 3.2 稀疏页表的容量账

一张末级表覆盖 `512×4 KiB=2 MiB`。映射连续且对齐的 1 GiB 基础页，末级表需 512 张，即 2 MiB；还要加上对应上级表。若使用一个对齐的 1 GiB 大页叶子映射，则可以在更高层终止遍历，但须满足架构、连续物理内存和权限粒度条件。

反例是每个独立 2 MiB 区间只放一个 4 KiB 页：每个区间仍可能需要独立末级页表。数据页只占 4 KiB，页表也占 4 KiB。虚拟映射稀疏不等于没有页表成本。

## 4. TLB 为什么关键

每次内存访问都走多级页表会增加多次内存读取。TLB 缓存虚拟页到物理页的近期翻译：

- TLB hit：快速得到翻译。
- TLB miss：硬件或软件遍历页表后填充 TLB。
- 页表无有效映射/权限不符：触发 Page Fault。

任务切换、修改页表、迁移页面时需要维护 TLB 一致性。多核上的 TLB shootdown 会通过跨 CPU 通知使旧翻译失效，大规模映射变化可能形成性能成本。

### 4.1 改页表之后为什么还不能立即复用旧物理页

CPU0 撤销一个映射并改写 PTE 时，CPU1 可能仍缓存旧 TLB 翻译；若旧物理页立刻分给另一个对象，CPU1 可能通过旧地址破坏新对象。正确生命周期是“更新映射 → 使相关 CPU 的旧翻译失效并完成必要同步 → 才能按规则复用”。具体通过页表锁、TLB Flush、延迟释放等内核机制实现，不能用一个普通内存屏障代替 TLB 失效。

TLB Miss、Page Walk Cache Miss、数据 Cache Miss 是不同层的问题；四级遍历不代表每次都从 DRAM 读四次，页表数据和上级翻译可能命中缓存。TLB Hit 也不绕过缓存中的权限，权限变更仍须正确失效。地址空间标识可减少切换时的全量失效，不会使映射更新的同步要求消失。

## 5. Page Fault 的处理

```mermaid
flowchart TD
    A["CPU 访问虚拟地址"] --> B{"TLB/页表允许?"}
    B -- 是 --> C["访问物理内存"]
    B -- 否 --> D["陷入内核 Page Fault"]
    D --> E{"VMA 存在且权限允许?"}
    E -- 否 --> F["SIGSEGV/SIGBUS 等"]
    E -- 是 --> G{"页面来源"}
    G --> H["分配零页/匿名页"]
    G --> I["COW 复制"]
    G --> J["Page Cache/文件读取"]
    G --> K["Swap-in"]
    H --> L["更新页表并重试指令"]
    I --> L
    J --> L
    K --> L
```

Minor Fault 一般不需要等待目标页面从块设备读入，例如零页、已有 Page Cache 或 COW 映射；Major Fault 通常需要存储 IO。两者都可能有明显 CPU 成本，Minor 不等于免费。

## 6. 权限与 NX

页表项和 VMA 共同表达读写执行权限。典型代码段可读可执行但不可写，数据段可读写但不可执行。W^X、安全模块和硬件 NX 能降低把数据页直接作为代码执行的风险，但 JIT 等场景需要受控地改变映射权限。

## 7. 如何观察

```bash
cat /proc/<PID>/maps
grep -E '^(Rss|Pss|Anonymous|AnonHugePages|Private|Shared)_' /proc/<PID>/smaps_rollup
pidstat -r -p <PID> 1
perf stat -e page-faults,minor-faults,major-faults -p <PID> -- sleep 10
```

示例 `maps`：

```text
55d8c1c00000-55d8c1c21000 r--p 00000000 08:02 1234 /usr/bin/example
55d8c1c21000-55d8c1d00000 r-xp 00021000 08:02 1234 /usr/bin/example
7f1a84000000-7f1a84200000 rw-p 00000000 00:00 0
```

地址范围是虚拟地址；权限最后的 `p/s` 表示 private/shared 映射语义，不是当前页面是否实际被多个进程共享。

## 8. 常见误解

- Page Fault 不等于程序错误。
- TLB miss 不等于 Page Fault；页表可能有效。
- VIRT 大不等于物理内存占用大。
- Major Fault 多不一定是 Swap，也可能是文件页从存储读入。
- 页表本身也占用物理内存，大量稀疏映射并非完全无成本。

## 9. 练习与答案

**问题：进程第一次写刚分配的匿名内存，为什么可能产生 Minor Fault？**

答案：地址范围已合法，但物理页可能尚未分配。首次写触发缺页，内核分配清零页并建立页表，不需要从磁盘读取，因此通常计为 Minor Fault。

**问题：TLB miss 后一定进入内核吗？**

答案：不一定。很多架构由硬件完成页表遍历并填充 TLB；只有映射缺失、权限错误或特定架构需要软件处理时才进入相应异常路径。
