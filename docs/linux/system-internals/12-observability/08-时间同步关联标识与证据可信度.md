# 时间同步、关联标识与证据可信度：跨主机事件为什么会排错顺序

排障时间线若跨多个主机，而时钟偏差大于事件间隔，“A 先于 B”就可能是错的。高质量证据不仅要有数值，还要说明时间基准、对象身份和采集缺口。

## 1. 两类时间

- realtime：适合跨主机的人类时间关联，但会受校时、时区显示影响。
- monotonic：适合本机持续时间，不因墙上时间调整倒退，却不能直接与另一主机比较。

日志同时保留 realtime、boot ID 和 monotonic offset，能更稳健地处理单机重启和时间跳变。

## 2. NTP 与 PTP

NTP 通过网络估计 offset/delay 并逐步校频或必要时 step；PTP 借助硬件时间戳可提供更高精度。两者都需监控同步源、stratum/状态、offset、频率和 holdover，不是“进程在运行就同步正常”。

```bash
timedatectl timesync-status 2>/dev/null
chronyc tracking 2>/dev/null
chronyc sources -v 2>/dev/null
pmc -u -b 0 'GET TIME_STATUS_NP' 2>/dev/null
```

## 3. 对象身份会复用

PID、FD、端口和 inode 数字都可能复用。记录 PID 时还应保存 process starttime、boot ID、container ID/cgroup；记录连接时保存完整 5-tuple 和时间窗。

## 4. 观测缺口

证据可信度要包含：

- 指标 scrape 间隔与失败次数。
- 日志 drop/rate limit/rotation。
- trace buffer overrun 和采样率。
- profiler multiplex/丢样本。
- 时钟同步状态和时区。

“没有观察到”只有在已知采集完整性时才有排除价值。

## 5. 时间线模板

```text
UTC/realtime + monotonic offset
host + boot_id
process/container identity
event source and collection method
raw evidence reference
known clock error / sampling gap
inference versus directly observed fact
```

## 6. 练习与答案

**问题：两台主机日志只差 2 ms，能否断言先后？**

答案：只有两台时钟最大误差显著小于 2 ms 且日志路径延迟已知时才可能；否则顺序不确定。

**问题：PID 相同能否把重启前后日志归为同一进程？**

答案：不能。需结合启动时间、boot ID、可执行文件、容器实例等。
