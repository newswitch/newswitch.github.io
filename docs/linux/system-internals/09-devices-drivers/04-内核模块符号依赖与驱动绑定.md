# 内核模块、符号、依赖与驱动绑定：ko 文件如何成为运行中的驱动

`.ko` 是可重定位内核对象，不是普通用户态动态库。加载时，内核校验格式/版本/签名，解析依赖和符号，执行 init；驱动注册后才可能与设备匹配。

## 1. 从文件到驱动

```text
modprobe 读取 modules.dep/alias/softdep/config
→ 按依赖调用 finit_module
→ 内核校验 ELF、vermagic、签名和许可
→ 重定位并解析 EXPORT_SYMBOL
→ module_init 注册 bus driver/filesystem 等对象
→ 设备模型按 alias/ID 匹配并调用 probe
```

模块加载成功不等于 probe 成功；probe 成功也不等于设备请求路径健康。

## 2. `modprobe` 与 `insmod`

- `insmod file.ko`：直接请求加载指定文件，不解析常规模块依赖和配置。
- `modprobe name`：按模块名处理 alias、依赖、blacklist、参数和 install/remove 规则。

```bash
modinfo <module>
modprobe --show-depends <module>
lsmod
cat /sys/module/<module>/refcnt 2>/dev/null
```

生产排查优先 `modprobe -n -v` 预览，不要为了试验随意卸载存储、网络或 GPU 驱动。

## 3. 版本与符号

运行内核 ABI、`CONFIG_MODVERSIONS`、编译器特征和发行版补丁会影响兼容性。`invalid module format` 要结合 `dmesg` 与 `modinfo vermagic` 判断，而不是只改文件名。

`Unknown symbol` 可能是依赖模块未加载、符号未导出、命名空间/import 缺失或 CRC 不匹配。

## 4. 自动加载

设备 uevent 携带 `MODALIAS`，用户态根据 `modules.alias` 找模块并加载。加载后 driver 的 ID table 再由内核匹配具体 device。

```bash
cat /sys/bus/pci/devices/<BDF>/modalias
modprobe -R "$(cat /sys/bus/pci/devices/<BDF>/modalias)"
```

## 5. 卸载安全

正确 exit 要注销外部入口、停止新请求、同步 IRQ/timer/work、等待引用并释放资源。强制卸载会绕过部分保护，可能造成崩溃或数据损坏；生产内核通常不应开启。

## 6. 练习与答案

**问题：`lsmod` 看见模块，为什么 `lspci -k` 仍显示设备没有 driver in use？**

答案：模块只完成加载；ID 不匹配、probe defer/fail、设备被其他驱动绑定或手工 override 都可能导致未绑定。

**问题：复制另一台同发行版的 `.ko` 就一定能用吗？**

答案：不一定。必须匹配精确内核 ABI、配置、符号版本、架构和签名策略。
