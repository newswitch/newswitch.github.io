# 设备模型与驱动导读

驱动不是一段“直接控制硬件”的孤立代码。设备先由固件或总线枚举，Linux 设备模型建立对象与层级，bus 按 ID 匹配 driver，驱动取得 MMIO、IRQ、DMA 等资源后注册进块、网络、字符等子系统，应用最终通过稳定接口使用设备。

## 1. 从硬件到应用

```text
固件 ACPI / Device Tree 或可枚举总线
→ device/bus/class/driver 对象
→ modalias 与驱动匹配
→ probe：映射 BAR、设置 DMA、申请 IRQ、初始化设备
→ 注册到 netdev / block / tty / DRM / hwmon 等子系统
→ /dev、sysfs、netlink、ioctl、mmap 等用户接口
→ remove/shutdown/suspend：停止新请求并回收资源
```

`/sys/devices` 更接近物理/逻辑设备拓扑，`/sys/bus` 按总线观察，`/sys/class` 按功能观察；它们常是同一内核对象的不同视图。

## 3. 观察入口

```bash
lspci -nnk
lsusb -t
find /sys/bus -maxdepth 2 -type d | head
udevadm info --query=all --name=/dev/<device>
cat /proc/iomem
cat /proc/interrupts
```

不要只看设备节点是否存在。应把“设备是否枚举、驱动是否绑定、资源是否成功申请、子系统是否注册、请求是否完成”分成五层。
