# 字符、块与网络设备接口：驱动为什么不能只实现 read 和 write

Linux 为不同类型设备提供不同子系统契约。字符设备常面向字节流或控制接口；块设备支持随机块 IO、队列和文件系统；网卡面向包、队列和网络协议栈。

## 1. 三类接口

| 类型 | 核心接口 | 用户入口 | 关键语义 |
|---|---|---|---|
| 字符 | `cdev`、`file_operations` | `/dev/*`、read/write/ioctl/mmap | 由驱动定义流与控制语义 |
| 块 | `gendisk`、`request_queue`、blk-mq | 块节点、文件系统 | 扇区、request、flush/FUA、队列 |
| 网络 | `net_device`、NAPI、ethtool ops | socket、netlink | packet、TX/RX queue、offload |

## 2. 字符设备

`open` 得到 `struct file`，驱动可把每次打开的私有上下文放在 `private_data`。`ioctl` 适合结构化控制，但要处理 ABI 大小、32/64 位兼容和不可信用户指针。

`mmap` 设备内存时必须限制范围和缓存属性；把任意物理地址暴露给用户会破坏隔离。

## 3. 块设备

文件系统/页缓存把 IO 形成 bio，块层合并并映射为 request，blk-mq 把请求提交到硬件队列。驱动还必须正确实现 flush、discard、write zeroes、错误和超时语义，否则“写成功”可能在掉电后丢失。

## 4. 网络设备

发送路径从 qdisc/协议栈调用驱动 `ndo_start_xmit`，驱动映射 skb 数据并放入 TX Ring；完成后回收。接收通常由 IRQ 安排 NAPI poll，构造/提交 skb。队列停止与唤醒必须和 Ring 可用空间一致。

## 5. 设备节点与 major/minor

字符和块节点包含类型、major、minor，用于定位内核设备号；它不是驱动文件路径。udev 依据属性设置名称、权限和稳定链接。

```bash
stat /dev/<node>
cat /proc/devices
ls -l /sys/dev/{char,block}/ 2>/dev/null | head
```

## 6. 练习与答案

**问题：网络设备为什么通常没有 `/dev/eth0`？**

答案：它通过 socket、netlink 和网络子系统使用，不采用字符设备文件读写包的主接口。

**问题：块驱动返回完成是否等于数据已到非易失介质？**

答案：不一定，取决于写缓存和 flush/FUA 语义。数据库和文件系统的持久性依赖整条栈正确兑现这些保证。
