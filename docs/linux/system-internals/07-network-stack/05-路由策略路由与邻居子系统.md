# 路由、策略路由与邻居子系统：一个目的地址如何找到出口和下一跳

发送 IP 包前，内核需要决定：这是本机地址还是转发流量、查哪张路由表、从哪个接口发、下一跳是谁、使用哪个源地址。二层网络还需要把下一跳 IP 解析为链路层地址。

## 1. 策略规则与 FIB

```text
目的/源/mark/接口等条件
→ Routing Policy Database 规则
→ 选择路由表
→ FIB 最长前缀匹配
→ route type、下一跳、出口接口、metric
→ 源地址选择
```

主路由表不是唯一表。多网卡、VRF、容器、策略路由和隧道环境必须先看 `ip rule`。

```bash
ip rule show
ip route show table all
ip route get <dst> from <src> mark <mark>
```

`ip route get` 更接近一次具体查询结果，仍需使用正确 Network Namespace、mark、源地址和输入/输出条件。

## 2. Local、Unicast 与其他路由类型

目的命中 local table 时交给本机协议栈；unicast 通常向下一跳转发。blackhole、unreachable、prohibit 等类型会以不同方式丢弃或返回错误。容器 Service、策略规则和本地地址会让“目的 IP 看似远端却在本机终止”。

## 3. 邻居子系统

IPv4 常用 ARP，IPv6 使用 Neighbor Discovery。邻居缓存把下一跳网络层地址映射到链路层地址，并维护可达性状态：

```text
INCOMPLETE → REACHABLE → STALE → DELAY → PROBE
                         ↘ FAILED
```

状态机会根据确认、使用和探测变化，不是静态 ARP 表。

```bash
ip neigh show nud all
ip -s neigh show dev <interface>
```

## 4. 同网段与跨网段

- 直连目标：二层目的通常是目标主机 MAC。
- 经网关：二层目的通常是下一跳网关 MAC，IP 目的仍是最终目标（除非 NAT）。

每经过一个三层路由节点，二层头重建、TTL/Hop Limit 变化；普通路由器不会因此重建 TCP 连接。

## 5. 反向路径过滤

`rp_filter` 可根据返回路径检查源地址，严格模式在非对称路由、多宿主和策略路由环境可能丢弃合法包。关闭它不是默认解决方案，应先设计对称性、策略路由和安全边界。

## 6. 路由缓存与变更

现代 Linux FIB 和目的缓存实现随版本演化。已有连接可能持有已解析路径信息，路由/邻居变化后的生效时机不应只靠“flush cache”经验命令推测；应通过实际连接、trace 和抓包验证。

## 7. 练习与答案

**问题：访问跨网段服务器时，ARP 查询的是服务器 MAC 还是网关 MAC？**

答案：通常查询路由选择出的下一跳网关 MAC；IP 目的地址仍是服务器。

**问题：默认路由存在是否保证所有目的都走默认路由？**

答案：不保证。更具体前缀、local table、策略规则、mark 和特殊路由类型都可能优先决定结果。
