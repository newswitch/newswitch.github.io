# 文件描述符与打开文件生命周期：open、dup、fork、exec、close

文件描述符是当前进程文件表中的整数。真正保存偏移、状态标志和操作方法的是内核打开文件描述。分清这两层，才能解释偏移共享、CLOEXEC 泄漏和删除文件仍占空间。

## 1. 三层引用

```text
进程 files_struct
  fd 3 ─┐
  fd 7 ─┴→ struct file（open file description）
             → dentry/inode
```

`dup(3)` 可创建 fd 7，让两者引用同一个 `struct file`，因此共享当前文件偏移和 file status flags。fd flags（例如 close-on-exec）属于描述符条目，可彼此不同。

## 2. 两次 open 与一次 dup

```text
open(path) → fd3 → file A → inode X
open(path) → fd4 → file B → inode X
dup(fd3)   → fd5 → file A → inode X
```

fd3/fd5 共享偏移，fd4 有独立偏移。所有实例都指向同一 inode 和文件内容。

## 3. fork 和 exec

fork 后父子文件描述符表通常分别存在，但条目引用相同打开实例，所以共享偏移。exec 成功后：

- 标记 `FD_CLOEXEC` 的 fd 关闭。
- 其他 fd 保留，除非程序显式处理。

并发程序应在创建 fd 时原子设置 `O_CLOEXEC`，而不是先 open 再 fcntl；否则另一个线程可能在间隙 fork+exec，泄漏敏感 fd。

## 4. close 成功代表什么

`close(fd)` 让当前描述符不再引用对象。当最后引用消失时，内核释放打开实例；但：

- 其他 dup/fork 得到的 fd 仍可持有它。
- mmap 可以让页面映射在 fd 关闭后继续存在。
- 异步 writeback 错误可能在此前或同步操作中报告。
- close 不等于业务数据已持久化。

不要在 close 返回不确定结果后盲目重试同一 fd 数字，因为它可能已被其他线程复用指向新对象。

## 5. fd 上限

```bash
ulimit -n
cat /proc/<PID>/limits | grep 'open files'
sysctl fs.file-max
ls /proc/<PID>/fd | wc -l
```

限制包括进程软/硬 RLIMIT、systemd Unit `LimitNOFILE`、容器配置以及系统级文件对象容量。`EMFILE` 是进程描述符上限，`ENFILE` 更偏系统范围打开文件对象耗尽。

## 6. Socket、pipe 和设备也是 fd

统一 fd 接口允许 `poll/epoll` 同时等待 Socket、pipe、eventfd、timerfd 等对象，但它们的 seek、read/write、关闭和错误语义不同。不能因为都叫 fd 就假设都是磁盘文件。

```bash
ls -l /proc/<PID>/fd
cat /proc/<PID>/fdinfo/<FD>
lsof -p <PID>
```

## 7. 竞态和线程安全

fd 表在多线程进程中共享。一个线程关闭 fd，另一个线程同时使用相同数字，可能出现复用竞态。安全设计应明确所有权，使用对象生命周期协议，必要时 `dup` 独立持有引用。

## 8. 练习与答案

**问题：父子进程 fork 后分别读取同一个继承 fd，文件偏移是否独立？**

答案：通常共享，因为两个 fd 条目引用同一个打开文件描述。若各自重新 open，才通常得到独立偏移。

**问题：为什么 CLOEXEC 要在 open 时原子设置？**

答案：多线程程序若分两步设置，另一个线程可能在间隙 fork+exec，把尚未标记的 fd 泄漏给新程序。
