# 原子操作、内存屏障与可见性：写入完成为什么不等于别人已经看见

多核并发中，“CPU0 先写数据再写 ready”只是源码顺序。编译器和 CPU 都可能在允许范围内重排，缓存一致性也不等同于所有访问按源码顺序被观察。

## 1. 四个概念不要混用

| 概念 | 含义 |
|---|---|
| 原子性 | 某个操作不会被观察为中间撕裂状态 |
| 可见性 | 另一个执行者何时能观察到写入 |
| 顺序性 | 两次访问被其他执行者观察的先后 |
| 互斥 | 同时只有一个执行者进入临界区 |

`atomic_inc()` 保护的是该增量操作，不会让与它相关的普通字段自动形成一致事务。

## 2. 发布—获取模式

```c
/* producer */
WRITE_ONCE(obj->value, 42);
smp_store_release(&obj->ready, 1);

/* consumer */
if (smp_load_acquire(&obj->ready))
        use(READ_ONCE(obj->value));
```

release 保证其前的访问不会越过发布点，acquire 保证其后的访问不会跑到获取点之前；二者通过同一同步变量配对。真实内核代码应优先使用已有锁、RCU、completion 等高级原语，而不是随意手写无锁算法。

## 3. `READ_ONCE` / `WRITE_ONCE`

它们约束编译器只进行一次该对象访问并避免部分优化，但不是完整 CPU 内存屏障，也不让复合操作变为原子。以下仍可能丢更新：

```c
WRITE_ONCE(counter, READ_ONCE(counter) + 1);
```

两个 CPU 可读到同一个旧值后分别写回。

## 4. 屏障类别

- `smp_mb()`：SMP 全屏障，约束前后读写。
- `smp_rmb()` / `smp_wmb()`：针对读或写顺序。
- acquire/release：围绕同步点提供方向性顺序，通常比全屏障更精确。
- DMA/MMIO 屏障：处理 CPU 与设备之间的可见性，不能简单用普通 SMP 屏障替代。

在单核或强内存序架构上“测试没出错”，不证明算法在 ARM、RISC-V 或不同编译优化下正确。

## 5. 锁已经携带顺序语义

正确配对的锁获取/释放提供临界区所需的内存顺序。给锁保护代码额外堆屏障通常说明模型没有理清，也可能掩盖真正的数据竞争。

## 6. 设备所有权转换

描述符交给 NIC 前，驱动必须确保 buffer 和 descriptor 内容对设备可见；收到 completion 后，也要按 DMA API 规则同步 CPU/设备视图。缓存一致 DMA、非一致架构和流式 DMA 的规则不同，应使用 DMA API，不能靠 `volatile`。

## 7. 练习与答案

**问题：`volatile` 能否替代锁或内存屏障？**

答案：不能。它主要约束编译器对该访问的优化，不提供跨 CPU 互斥，也不完整表达内存顺序。内核对并发和 MMIO 提供专门原语。

**问题：缓存一致协议存在，为什么还要屏障？**

答案：一致协议保证同一缓存行最终一致，不保证不同内存访问按源码顺序被其他 CPU 观察。
