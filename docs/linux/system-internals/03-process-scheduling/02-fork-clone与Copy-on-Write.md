# fork、clone 与 Copy-on-Write：新任务如何继承资源

`fork()` 看起来复制一个进程，但现代 Linux 不会立即复制全部物理内存。内核创建新的任务和资源视图，通过 Copy-on-Write 暂时共享物理页，在某一方写入时再复制。

## 1. 三类接口

| 接口 | 典型语义 |
|---|---|
| `fork()` | 创建独立子进程，继承父进程状态 |
| `vfork()` | 子任务在 exec/exit 前与父任务存在更强共享和约束，误用危险 |
| `clone()` / `clone3()` | 通过标志精确选择共享资源，也是线程和 Namespace 创建基础 |

glibc 的线程创建会使用 clone 系列接口，并配置共享地址空间、文件表、信号处理等标志。容器运行时同样利用 clone/unshare/setns 组合隔离环境。

## 2. 创建路径的核心工作

概念路径：

```text
用户调用 fork/clone
→ 分配 task_struct 和内核栈
→ 建立 PID/线程组/父子关系
→ 按 clone 标志复制或共享 mm/files/fs/sighand/ns
→ 复制页表项并建立 COW 保护
→ 把新任务加入可运行队列
→ 父子任务从调用点分别返回
```

父进程得到子 PID，子进程得到 0。谁先运行由调度器决定，不能依赖固定顺序。

## 3. COW 共享的是什么

fork 后，父子拥有不同的虚拟地址空间对象和页表视图，但许多页表项暂时指向相同物理页，并去掉可写权限：

```text
父虚拟页 ─┐
           ├→ 同一物理页（只读/COW）
子虚拟页 ─┘

任一方写入
→ 写保护缺页
→ 分配新物理页
→ 复制旧内容
→ 修改写入方页表
→ 重新执行写指令
```

如果物理页实际只有当前映射持有，内核可能不必复制，而是恢复可写映射。具体优化随页类型和版本变化。

## 4. fork 仍然可能很贵

COW 避免立即复制所有数据页，但仍有成本：

- 创建任务和内核对象。
- 复制多级页表结构和 VMA 元数据。
- 修改页表权限并进行 TLB 维护。
- 大地址空间下遍历页表。
- 子进程大量写入时发生 COW 页面复制。

Redis 等大内存进程执行 fork 做持久化时，即使子进程主要读取，页表复制、父进程写入导致的 COW 和内存峰值仍可能产生延迟。

## 5. 文件描述符如何继承

fork 后父子通常各有文件描述符表视图，但对应条目引用相同的打开文件描述 `struct file`，因此共享文件偏移和状态标志。两者同时读取普通文件时，偏移行为不能按两个完全独立 `open` 理解。

`FD_CLOEXEC` 是描述符级标志，用于后续成功 exec 时自动关闭；fork 本身不会因为该标志关闭描述符。

## 6. 多线程进程 fork 的风险

多线程进程调用 fork 后，子进程只复制调用 fork 的线程，其他线程不在子进程中继续运行；但它们可能在 fork 时持有用户态锁。子进程若在 exec 前调用非异步信号安全函数，可能永远等待一个不存在的线程释放锁。

常见安全模型是：fork 后子进程尽快调用 `execve()`，中间只执行受允许的最小操作；语言运行时和库通常为此提供专门封装。

## 7. 观察 COW

```bash
grep -E '^(Rss|Pss|Private|Shared)_' /proc/<PID>/smaps_rollup
grep -E '^(Threads|VmRSS|RssAnon):' /proc/<PID>/status
perf stat -e page-faults,minor-faults,major-faults -- <command>
```

RSS 在共享页场景不能直接跨进程相加；PSS 按共享比例分摊，更适合估算总物理占用，但采集成本和口径也要说明。

## 8. 练习与答案

**问题：一个 100GB RSS 进程 fork 后，系统是否立即多占 100GB 内存？**

答案：通常不会立即复制全部物理页，但要创建子任务、VMA 和页表；父子后续写入会触发 COW，实际峰值取决于写入工作集、共享页和内核行为。

**问题：线程和进程在 Linux 中的本质分界是什么？**

答案：都由任务结构调度，主要差别是创建时选择共享哪些资源。共享地址空间、文件表和信号处理等资源的一组任务形成通常意义上的线程组。
