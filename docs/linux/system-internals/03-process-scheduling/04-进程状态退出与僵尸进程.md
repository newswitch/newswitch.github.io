# 进程状态、退出与僵尸进程：R、S、D、T、Z 分别意味着什么

`ps` 的状态字母是内核内部状态的用户态映射。它描述采样瞬间任务在做什么，不直接告诉你根因。特别是 `R` 同时包含正在 CPU 上执行和已在运行队列等待的任务。

## 1. 常见状态

| `ps` 状态 | 概念含义 | 是否消耗 CPU |
|---|---|---|
| `R` | Running/Runnable | 正在运行或等待 CPU |
| `S` | 可中断睡眠 | 等待事件，可被信号唤醒 |
| `D` | 不可中断睡眠 | 等待关键内核事件，通常不在执行 |
| `T` / `t` | 作业控制停止或被调试跟踪 | 不运行 |
| `Z` | Zombie，已退出等待父进程回收 | 不运行 |
| `I` | 空闲内核线程等状态映射 | 视具体内核和工具 |

附加字符如 `s`、`l`、`+` 表示 Session leader、多线程、前台进程组等属性，不是新的主状态。

## 2. 睡眠和唤醒

任务等待 Socket、锁、定时器或 IO 时，把自己挂到相应等待队列，设置状态并调用调度器。事件完成方修改条件并唤醒任务，任务重新进入某个 CPU 的运行队列。

防止“检查条件后、真正睡眠前事件已发生”的丢失唤醒，需要等待队列、锁和条件检查遵循严格顺序。应用层条件变量也有类似原则。

## 3. D 状态为什么难处理

不可中断睡眠用于某些不能随意中途撤销的等待。任务在真正返回可调度路径前，`SIGKILL` 也只能保持待处理，无法让它立即消失。

常见原因包括块设备、NFS、驱动、文件系统、内存回收或内核锁等待。排查应结合：

```bash
ps -eLo pid,tid,stat,wchan:32,comm | awk '$3 ~ /D/'
cat /proc/<PID>/stack
cat /proc/<PID>/wchan
dmesg -T | tail -200
cat /proc/pressure/io
```

读取 `/proc/PID/stack` 通常需要权限。`wchan` 只是睡眠位置线索，必须结合调用栈、设备指标和日志。

## 4. 退出与僵尸

任务调用 `exit` 或被终止后：

1. 关闭/释放大部分资源。
2. 保存退出码和少量统计。
3. 通知父进程。
4. 进入 Zombie 状态。
5. 父进程通过 `wait*()` 取得状态后，内核回收剩余任务记录。

Zombie 不占用原进程的全部内存和 CPU，但会占 PID 和任务表项。大量持续僵尸说明父进程没有正确回收子进程，修复对象通常是父进程；不能“kill 已经死掉的僵尸”。

## 5. 孤儿进程

父进程先退出时，子进程会被重新托管给合适的 subreaper，最终可能由 PID 1 或设置了 child subreaper 的进程负责回收。容器 Runtime 和进程监督器常利用这一机制。

## 6. Load Average 与状态

Linux load average 主要把可运行任务和某些不可中断等待任务纳入计算。因此：

- 大量 `R` + CPU 忙：可能是 CPU 饱和。
- 大量 `D` + CPU 空闲：可能是 IO/驱动/内核等待。
- load 高不能单独证明 CPU 不够。

## 7. 练习与答案

**问题：D 状态任务能否用 `kill -9` 立即杀掉？**

答案：通常不能。信号会保持待处理，任务必须从不可中断等待返回并到达可处理信号的位置。应修复它等待的设备、网络、驱动或内核条件。

**问题：僵尸进程为什么 CPU 为 0？**

答案：它已经结束执行，只保留退出状态供父进程读取，不再参与普通调度。
