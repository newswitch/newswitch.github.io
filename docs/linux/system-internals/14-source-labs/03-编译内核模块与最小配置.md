# 编译内核、模块与最小配置：从 .config 到可启动产物

内核构建应在独立输出目录完成，并保留源码 commit、`.config`、编译器和构建日志。第一次实验不要覆盖当前机器唯一可启动内核。

## 1. 安全构建流程

```bash
make O="$PWD/out" defconfig
make O="$PWD/out" menuconfig
make O="$PWD/out" -j"$(nproc)"
make O="$PWD/out" modules
```

目标架构、交叉编译前缀和镜像路径依平台而异。构建成功不代表能启动：rootfs 驱动、控制器、文件系统、initramfs 和 console 必须 built-in 或在早期可加载。

## 2. 复用发行版配置

```bash
cp /boot/config-"$(uname -r)" out/.config
make O="$PWD/out" olddefconfig
```

`olddefconfig` 为新选项取默认值，仍需检查差异。发行版配置可能依赖其补丁、证书路径和构建脚本，直接上游编译会因不存在的 key/文件失败。

## 3. 产物

- `vmlinux`：未压缩 ELF，含符号/调试时用于 GDB、perf、crash。
- 架构 boot image：如 x86 `bzImage`、arm64 `Image`。
- `.ko`：模块，安装后需 depmod。
- `System.map`、generated headers、BTF 等。

不要 strip/丢弃唯一的 debug vmlinux；运行镜像可精简，分析符号需单独安全保存。

## 4. 调试配置

`CONFIG_DEBUG_INFO`、BTF、KASAN、KCSAN、LOCKDEP 等能增强分析，但显著增加体积和开销。按实验目标开启，性能基准不要与调试内核混为一组。

## 5. 最小配置陷阱

`localmodconfig` 只参考当前已加载模块，可能漏掉尚未使用的启动盘、备用 NIC、恢复键盘和故障时才需要的驱动。最小化应在 QEMU 快照中验证完整启动/恢复路径。

## 6. 可复现性

记录 `ARCH`、compiler、binutils、commit、config hash、环境变量和构建时间戳设置。字节级可复现还受用户名、路径、时间和签名影响。

## 7. 练习与答案

**问题：根文件系统驱动编成模块，initramfs 没包含它，会怎样？**

答案：内核无法挂载真正 rootfs，通常在启动早期报找不到 root device/无法 mount root。

**问题：debug 内核跑得慢能否说明代码修改有性能回归？**

答案：不能直接说明。调试选项自身改变时序和开销，必须用同配置对照。
