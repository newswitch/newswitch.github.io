# 内核实验报告与证据复现模板：让结论可以被别人验证

一个可信实验要让读者知道测了什么、没测什么、如何复现、观测是否改变结果，以及结论在哪些版本和负载下成立。

## 1. 实验摘要

```text
问题：要解释的可观察现象
假设：机制、预测结果和可否定条件
结论：支持/否定/证据不足
适用范围：内核、硬件、配置、工作负载
风险：实验是否会 panic、损坏数据或影响网络
```

## 2. 环境清单

```bash
uname -a
cat /etc/os-release
cat /proc/cmdline
lscpu
free -h
lsblk -o NAME,TYPE,SIZE,FSTYPE,MOUNTPOINTS
```

同时记录：源码 commit、发行版补丁、`.config` hash、compiler、固件、虚拟化、容器/cgroup 限制、设备 topology、应用和依赖版本。命令输出注意脱敏。

## 3. 输入与控制变量

| 项 | 内容 |
|---|---|
| 数据集 | 大小、分布、冷热状态、校验值 |
| 工作负载 | 速率/并发/请求比例/持续时间 |
| 固定变量 | CPU/NUMA、频率、后台任务、网络路径 |
| 改变变量 | 本轮唯一主要变量 |
| 重复 | 预热、轮数、间隔、随机种子 |
| 停止条件 | 错误率、温度、空间、影响时长 |

## 4. 原始证据

保存原始日志、trace、profile 和指标，而不是只贴截图。每份文件写明采集命令、开始/结束时间、scope、采样/过滤、丢失计数和 checksum。

## 5. 结果写法

```text
直接观察：原始数据可支持的事实
推断：由事实和机制得到的解释
反例：哪些现象若出现会否定解释
扰动：观测工具与环境变化可能造成的影响
边界：尚未覆盖的内核/硬件/负载
```

不要把相关性写成因果，也不要隐藏不符合预期的轮次。

## 6. 回滚与清理

- 恢复 sysctl、cgroup、IRQ affinity、mount 和服务配置。
- 停止 trace/BPF，检查是否仍有 pinned object。
- 删除实验 Namespace/cgroup/镜像层和临时数据。
- 验证服务、监控、时间同步与容量回到基线。
- 保留可审计变更记录。

## 7. 练习与答案

**问题：别人复制命令却无法复现，最先补哪些信息？**

答案：精确内核/配置/硬件、workload 和数据状态、容器/cgroup 限制、采集 scope 以及源码/工具版本。

**问题：一次实验符合预测，是否已证明机制？**

答案：只是支持证据。还需重复、对照、反例和不同条件验证，并声明未覆盖边界。

至此，Linux 系统原理路线从内核入口、进程、内存、IO、网络，延伸到并发、驱动、隔离、安全、观测、性能和源码实验，形成完整闭环。
