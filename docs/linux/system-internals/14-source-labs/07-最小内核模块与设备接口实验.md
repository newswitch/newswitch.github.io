# 最小内核模块与设备接口实验：理解 init、exit、引用与并发清理

本实验目标不是编写生产驱动，而是观察模块从 ELF 文件到内核对象的生命周期。只在可回滚 VM 中进行，不加载来源不明模块。

## 1. 实验边界

- 模块只记录加载/卸载并暴露只读参数或 debug counter。
- 不读写任意物理地址，不拦截 syscall，不修改安全策略。
- 保留 VM 串口和快照；使用匹配运行内核的 headers/build tree。

## 2. 最小 Kbuild

```makefile
obj-m += lab_module.o

all:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	$(MAKE) -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean
```

模块源码应包含 `module_init`、`module_exit`、许可和说明；所有注册成功后的资源必须在错误路径和 exit 逆序释放。

## 3. 观察流程

```bash
modinfo ./lab_module.ko
sudo insmod ./lab_module.ko
lsmod | grep lab_module
find /sys/module/lab_module -maxdepth 2 -type f -print
journalctl -k -n 30
sudo rmmod lab_module
```

具体执行需在隔离 VM 并确认 sudo 权限。若 Secure Boot/签名强制开启，未签名模块会被拒绝，这是安全策略而非编译失败。

## 4. 引用与卸载

模块被外部对象引用时，正常 `rmmod` 应失败。exit 要先撤销用户入口，停止 timer/work，等待正在执行 callback，再释放对象；这与真实驱动 remove 的生命周期相同。

## 5. 增量实验

按顺序增加并每步回归：

1. 只加载/卸载日志。
2. 只读 module parameter。
3. 在 sysfs/debugfs 暴露只读计数。
4. workqueue 定期增加计数，并在 exit 同步取消。

每一步都验证重复加载/卸载、失败注入和并发读取，避免一次加入字符设备、timer、IRQ 等太多变量。

## 6. 练习与答案

**问题：模块没有进程，为什么卸载仍可能等待？**

答案：IRQ、timer、workqueue、RCU callback、打开 FD 和其他内核对象都可能引用模块代码或数据。

**问题：`printk` 很多是否适合性能调试？**

答案：不适合。console/logging 会严重改变时序并可能限速；应使用受控 tracepoint、动态调试或计数器。
