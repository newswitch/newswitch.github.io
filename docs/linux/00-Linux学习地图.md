# Linux 学习地图：从命令使用到系统原理

Linux 学习不能只停留在“记住一条命令”，也不能一开始就陷入某个内核函数。完整能力由三层组成：能操作系统、能解释机制、能用证据定位问题。

```mermaid
flowchart LR
    A["命令与接口<br/>会观察和操作"] --> B["系统原理<br/>理解对象与路径"]
    B --> C["性能与故障<br/>用证据定位层次"]
    C --> D["源码与实验<br/>验证而不是猜测"]
```

## 1. 两套互补内容

| 入口 | 回答的问题 | 使用方式 |
|---|---|---|
| [Linux 系统原理](./system-internals/00-Linux系统原理学习路线.md) | 进程、内存、文件和网络在内核里怎样工作，故障为何发生 | 按顺序学习 |
| [Linux 命令参考库](./00-Linux命令参考库学习路线.md) | 命令有哪些参数，输出怎样解释，操作风险是什么 | 学习与按需查询 |

命令文章不会替代原理文章。例如 `free` 可以显示内存统计，但只有理解匿名页、文件页、回收和 cgroup，才能解释“宿主机还有可用内存，Pod 为什么 OOM”。反过来，只读原理而不会采集证据，也无法完成生产排查。

## 2. 系统原理主线

```text
硬件与固件
  → Bootloader
  → Linux 内核初始化
  → PID 1 与用户空间
  → 进程和线程
  → 调度与内存管理
  → VFS、块 IO 与网络栈
  → 驱动和硬件
  → Namespace、cgroup 与安全边界
  → 可观测性、性能与故障恢复
```

第一阶段先建立内核架构、启动、进程调度和内存管理四条基础主线；后续文件系统、网络、容器和可观测性都依赖这些概念。

## 3. 学习方法

每个主题都按同一套问题学习：

1. 这个机制解决什么问题。
2. 有哪些核心内核对象，生命周期由谁管理。
3. 一次请求按什么顺序经过这些对象。
4. 用户空间可以从哪些接口观察它。
5. 指标异常分别对应哪一层。
6. 哪些结论能由证据支持，哪些只是猜测。
7. 如何用小实验复现并验证。

完成一章后，应能不用背稿画出主要路径，并能把命令输出映射回路径中的具体对象。

## 4. 版本约定

系统原理文章以 **Linux 6.6** 作为固定源码阅读基线，同时说明 4.18、5.4、5.10、5.14、6.1 等生产常见内核可能存在的差异。企业发行版经常回移特性和修复，判断能力不能只看 `uname -r`，还要结合发行版变更记录、内核配置和实际接口。

## 5. 模块边界

Linux 原理模块讲内核机制：Socket、Page Cache、Block Layer、Namespace、DMA 等。网络、存储、Kubernetes 和 GPU 模块继续讲各自的协议、产品和部署实践，通过链接相互衔接，避免复制相同内容。
