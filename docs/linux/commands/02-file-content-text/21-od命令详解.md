# `od` 命令详解：字节、偏移、端序与数据类型观察

`od` 把原始字节用无歧义的字符、八/十/十六进制整数或浮点格式显示，并标注输入偏移。它适合检查 BOM、CRLF、NUL、协议头、Magic、损坏边界和端序；显示方式只是解释视图，不会改变源文件。

## 1. 命令档案

| 项目 | 内容 |
|---|---|
| 实现 | GNU coreutils |
| 文档基线 | GNU coreutils 9.11 |
| 安全级别 | `[R]`；可能把 Secret/二进制控制内容转换为可见输出 |
| 主要对象 | 字节、地址偏移、分组宽度、整数/浮点解释与端序 |

```bash
type -a od
env od --version
env od --help
```

## 2. 完整语法：现代、兼容与传统三种形式

```text
od [OPTION]... [FILE]...
od [-abcdfilosx]... [FILE] [[+]OFFSET[.][b]]
od [OPTION]... --traditional [FILE] [[+]OFFSET[.][b] [[+]LABEL[.][b]]]
```

现代脚本只使用第一种以及 `-j/-N/-A/-t`。旧位置 Offset 会让数字文件名产生歧义：`od foo 10` 中 `10` 可能被视为 Offset，而非第二个文件。使用 `--` 和显式现代参数。

## 3. 全部通用参数

| 短参数 | 长参数 | 作用 |
|---|---|---|
| `-A RADIX` | `--address-radix=RADIX` | 偏移进制：`d/o/x/n`，默认八进制 |
| `-j BYTES` | `--skip-bytes=BYTES` | 跳过开头字节 |
| `-N BYTES` | `--read-bytes=BYTES` | 最多读取指定字节 |
| `-S[BYTES]` | `--strings[=BYTES]` | 仅显示至少 N 个可打印字节且 NUL 结尾的字符串；默认 3 |
| `-t TYPE` | `--format=TYPE` | 选择一种或多种数据解释格式，可重复累积 |
| 无 | `--endian=little|big` | 按 Type Size 重排字节以指定端序解释 |
| `-v` | `--output-duplicates` | 不用 `*` 省略连续相同输出行 |
| `-w[N]` | `--width[=N]` | 每输出行读取 N 字节；默认 16，省略 N 时 32 |
| 无 | `--traditional` | 启用传统 Offset/Label 语法 |
| 无 | `--help`、`--version` | 帮助与版本 |

`-j/-N/-S` 支持 `b=512`、`KB=1000`、`K/KiB=1024`、M/G/T/P/E/Z/Y/R/Q 等 SIZE 后缀。

## 4. TYPE 语言

```text
a  named character（忽略高位）
c  可打印单字节字符、C 转义或三位八进制
d  有符号十进制
f  浮点数
o  八进制
u  无符号十进制
x  十六进制
```

`a/c` 之外可指定字节数，例如 `x1`、`u4`、`d8`、`f4`。整数还可用 C 类型 Size Code：`C/S/I/L`；浮点可用 `B/H/F/D/L` 表示 bfloat16、half、float、double、long double（具体支持受构建/平台限制）。结尾加 `z` 会在该格式行右侧附可打印单字节字符视图。

```bash
od -A x -t x1z -v -- file.bin
od -A d -t u2 -t x2 --endian=little -- header.bin
```

多个 Type 会对同一批输入连续输出多个解释行，不是多读输入。

## 5. 短格式选项

| 短参数 | 等价 TYPE |
|---|---|
| `-a` | `-t a` |
| `-b` | `-t o1` |
| `-c` | `-t c` |
| `-d` | `-t u2` |
| `-f` | `-t fF` |
| `-i` | `-t dI` |
| `-l` | `-t dL` |
| `-o` | `-t o2` |
| `-s` | `-t d2` |
| `-x` | `-t x2` |

这些格式依本机 C Type Size/端序时可能不可移植。协议排障优先明确字节宽度，例如 `-t x1`，不要把 `-x` 误认为十六进制字节。

## 6. 常用可靠视图

```bash
# 十六进制字节 + 右侧可打印字符，不省略重复行
od -A x -t x1z -v -- packet.bin

# C 风格字符，发现 CR/LF/NUL/TAB
od -A x -t c -- text.txt

# 只看偏移 0x100 开始的 64 字节
od -A x -j 0x100 -N 64 -t x1z -- image.bin

# 不显示地址，适合比对纯字节
od -A n -t x1 -v -- sample.bin
```

默认格式是按本机 C `short int` 分组的八进制，不适合新人直读；显式 `-A x -t x1z` 更可重复。

## 7. 地址不是数据

每行首字段是输入 Offset，最后还有最终 Offset。`-A n` 可隐藏。若拼接多个 FILE，Offset 通常按输入流累计，不为每个文件重新从零开始；需要单文件局部偏移时分别运行。

`-j` 从拼接后的输入流跳过，`-N` 限制整个剩余流。输入为 Pipe 时，跳过意味着读掉数据，不能 Seek 回去。

## 8. 重复行省略

默认连续两行以上完全相同，od 只显示第一行并用 `*` 表示中间重复。这是输出压缩，不是文件里只有一行：

```bash
od -A x -t x1 zeroes.bin
od -A x -t x1 -v zeroes.bin
```

取证、精确行数或脚本解析必须加 `-v`。

## 9. 端序与类型宽度

```bash
printf '\x01\x02\x03\x04' > word.bin
od -A n -t x4 --endian=little word.bin
od -A n -t x4 --endian=big word.bin
```

端序只在多字节 Type 上有意义；`x1` 是逐字节，不受端序影响。`--endian` 按指定 Type Size 重排，多个不同 Size Type 时要谨慎解释。文件协议以规范为准，不能看到某个“合理数字”就断言端序正确。

## 10. `--strings` 边界

```bash
od --strings=8 -- executable.bin
```

它查找至少 N 个连续可打印单字节、随后有 NUL 的字符串，不是通用 Unicode Strings，不理解 UTF-16/UTF-8 语义。配合 `-N` 时，截断的字符串会被视作 NUL 终止。输出可能泄露 Token、路径、用户名和编译信息。

## 11. 终端与证据安全

`-c/-t x1z` 会把不可打印字节转义，比 `cat` 二进制安全，但可打印区域仍可能含敏感文本和 Unicode 欺骗。大文件不要全部 Dump 到交互终端；用 `-j/-N` 限制范围，输出文件设置 `umask 077` 并记录源 Hash、偏移、长度和命令。

## 12. 退出状态与排查

成功为 0，参数、读写或不支持格式为非 0。

| 现象 | 检查方向 |
|---|---|
| 十六进制值和预期反转 | 使用多字节 Type 且端序不同；改 `x1` 或指定 Endian |
| 中间只有 `*` | 默认省略重复输出，加 `-v` |
| 偏移显示 `000010` | 默认八进制地址；用 `-A x/d` |
| `-w` 报错 | 宽度须兼容所有 Type Size 的最小公倍数 |
| 数字文件被当 Offset | 使用现代 `--` 和显式 `-j`，避免传统语法 |
| strings 漏掉中文 | 只识别符合条件的单字节可打印 NUL 字符串 |

## 13. 动手实验

1. 创建含 LF、CRLF、TAB、NUL、BOM 的文件，用 `-t c/x1z` 比较。
2. 对全零文件比较默认与 `-v`。
3. 用四字节输入比较大/小端 `x4` 和不受端序影响的 `x1`。
4. 用 `-j/-N` 精确截取协议 Header。
5. 混合 `u2/x2/c`，观察同一输入的多种解释。
6. 用二进制中的 ASCII/UTF-8/UTF-16 比较 `--strings` 能力边界。

## 14. 掌握标准

- 能列出 `od` 全部通用、格式与短参数。
- 能区分地址进制、数据进制、Type Size 和端序。
- 能解释 `*`、最终 Offset、`z` 字符侧栏和多 Type 输出。
- 能用 `-j/-N` 保存可重复的局部证据。
- 能说明 `od` 是字节解释器，不是文件格式解析器或 Secret 脱敏器。
