# `wc` 命令详解：字节、字符、词、行与最长显示宽度

`wc` 统计 byte、character、word、newline 和最大行显示宽度。最容易出错的地方是把“行数”当业务记录数、把“字符数”当屏幕字形数，或依赖默认对齐文本作为稳定机器接口。

## 1. 命令档案

| 项目 | 内容 |
|---|---|
| 实现 | GNU coreutils |
| 文档基线 | GNU coreutils 9.11 |
| 安全级别 | `[R]`；需要完整读取输入，可能产生明显 IO |
| 主要对象 | 字节、字符、词、LF 数和显示列宽 |

```bash
type -a wc
env wc --version
env wc --help
```

## 2. 完整语法与默认列

```text
wc [OPTION]... [FILE]...
wc [OPTION]... --files0-from=FILE
```

无选择参数时输出：

```text
lines words bytes filename
```

无文件或 `FILE=-` 时读取标准输入。标准输入没有可显示文件名；多个文件默认增加 `total` 行。

## 3. GNU coreutils 9.11 全部参数

| 短参数 | 长参数 | 作用 |
|---|---|---|
| `-c` | `--bytes` | 输出字节数 |
| `-m` | `--chars` | 按当前 locale 输出字符数；编码错误不计入字符数 |
| `-l` | `--lines` | 输出 LF 字节数量 |
| `-L` | `--max-line-length` | 输出最大行显示宽度；多文件 total 取最大值而非求和 |
| `-w` | `--words` | 输出词数 |
| 无 | `--files0-from=FILE` | 从 NUL 分隔清单读取文件名；不能再给命令行文件 |
| 无 | `--total=WHEN` | 控制 total；`auto/always/only/never` |
| 无 | `--help` | 显示帮助并退出 |
| 无 | `--version` | 显示版本并退出 |

选择选项会累积，例如 `wc -cm` 同时输出字符数和字节数。列顺序固定为 lines、words、chars、bytes、max-line-length，而不是选项书写顺序；机器解析应显式选择字段并了解该固定顺序。

## 4. 五种统计口径

### 4.1 `-c` 字节

```bash
wc -c -- file
```

普通文件字节数常可由 `stat` 快速获得，但 `wc` 的语义是读取输入；对标准输入、特殊文件和变化中文件结果不同。

### 4.2 `-m` 字符

字符解码受 `LC_CTYPE` 和输入合法性影响：

```bash
LC_ALL=C wc -m -- utf8.txt
LC_ALL=en_US.UTF-8 wc -m -- utf8.txt
```

Unicode 组合字符可能多个字符显示成一个字形；emoji 序列也可能由多个 code point 组成。因此 `-m` 不等于用户感知字符数。

### 4.3 `-l` 行

它统计换行符 LF，不是抽象记录：

```bash
printf 'one\ntwo' | wc -l
# 1
```

最后一条无 LF 的文本仍有人类所见内容，但 `wc -l` 不计为完整行。CRLF 中仍只有一个 LF，因此通常计一行，但 CR 会影响其他处理。

### 4.4 `-w` 词

GNU `wc` 按当前 locale 的空白规则切分非零长度字符串。标点通常属于相邻词，CJK 无空格文本可能整行只算一个词。不要用它统计自然语言词汇、代码 token 或模型 tokenizer token。

### 4.5 `-L` 最长行

报告显示宽度，不是字节数或字符数：TAB 会推进到 tab stop，宽字符可能占两列，非打印字符宽度为 0。多文件 total 是各文件最大值。

```bash
wc -L -- table.txt
```

显示宽度仍受 locale 和实现影响，不等于浏览器/编辑器最终渲染宽度。

## 5. `--total` 四种模式

| WHEN | 行为 |
|---|---|
| `auto` | 默认；多个文件才输出 total |
| `always` | 即使一个文件也输出 total |
| `only` | 只输出总数，无各文件、无前导填充、无 `total` 文本 |
| `never` | 从不输出 total |

```bash
wc -l --total=only -- *.log
wc -l --total=never -- a.log b.log
```

`only` 更适合机器读取单一汇总值。若某个输入失败，仍必须检查退出码，不能只相信输出数字。

## 6. `--files0-from`

```bash
find . -type f -name '*.log' -print0 |
wc -l --total=only --files0-from=-
```

规则：

- 文件名以 NUL 分隔，可安全包含空格和换行。
- 不能同时在命令行给文件操作数。
- `FILE=-` 时，标准输入用于读取文件名清单，因此不能同时把标准输入本身作为待统计内容。
- 相比 `find ... -print0 | xargs -0 wc`，它不会因 xargs 分批产生多个局部 total。

如果清单为空，结果取决于所选 total 模式，不应把“无文件”误认为“一个空文件”。

## 7. 并发变化与统计一致性

文件在读取过程中可能 append、truncate、rename 或被替换：

- 结果是读取期间观察到的数据，不是事务快照。
- 多文件 total 也不是同一时刻的集群快照。
- 网络文件系统可能出现缓存、短读或 I/O 错误。
- 稀疏文件的 `wc -c` 是逻辑字节流长度，不是已分配空间。

需要一致统计时，先创建不可变快照、版本目录或存储快照，再对固定对象运行。

## 8. 机器解析

以下脆弱：

```bash
set -- $(wc file)
```

文件名可含空白/换行，默认列会变化。更稳妥：

```bash
bytes=$(wc -c < file) || exit 1
lines=$(wc -l < file) || exit 1
```

重定向后输出不含文件名，但数字可能有前导空格；Shell 算术可接受，文本协议可先 `read`：

```bash
read -r lines < <(wc -l < file) || exit 1
```

## 9. 性能

- `wc -c` 对可 seek 普通文件可能优化，但不要依赖不读取内容的实现细节。
- `-m/-w/-l/-L` 需要检查内容。
- 多项统计通常一次 `wc -lwm` 比三次单独扫描更省 IO。
- 压缩文件统计的是压缩字节；需要解压内容必须显式解压，会消耗 CPU 和临时资源。
- 海量小文件常受 open/stat 和元数据延迟限制。

## 10. 生产场景

### 10.1 判断文本是否缺少末尾换行

不能只用 `wc -l`。结合最后一个字节：

```bash
test ! -s file || tail -c 1 -- file | od -An -tx1
```

### 10.2 统计任意名称日志总行数

```bash
find /logs -type f -name '*.log' -print0 |
wc -l --total=only --files0-from=-
```

### 10.3 容量估算

```bash
wc -c -- model.bin
stat -c 'logical=%s blocks=%b' -- model.bin
du --block-size=1 -- model.bin
```

三者分别观察字节流逻辑长度、inode 分配块、目录统计口径；稀疏/Reflink/压缩场景会不同。

## 11. 退出状态与排查

`0` 表示所有输入和输出成功，非 `0` 表示至少一个失败。

| 现象 | 检查方向 |
|---|---|
| 中文 chars 与预期不同 | locale、非法编码、组合字符 |
| lines 少 1 | 最后一行没有 LF |
| words 很少 | CJK/无空白文本，wc 不是分词器 |
| `-L` 与字符数不同 | TAB、宽字符、组合/非打印字符 |
| 出现多个 total | xargs 分批；改用 `--files0-from` |
| total 数字仍变化 | 文件并发写入，没有快照 |

## 12. 动手实验

1. 用 ASCII、中文、组合字符和 emoji 比较 `-c/-m/-L`。
2. 比较有/无最后 LF 的 `-l`。
3. 对空格、TAB、标点和 CJK 文本观察 `-w`。
4. 测试 total 四种模式和一个/多个/零文件清单。
5. 创建带换行文件名，通过 `--files0-from=-` 统计。
6. 创建稀疏文件，比较 wc/stat/du。
7. 统计同时 append 的文件，理解非快照结果。

## 13. 掌握标准

- 能列出 `wc` 全部参数和 total 全部模式。
- 能区分 bytes、characters、words、LF 和显示宽度。
- 能解释 locale、编码、组合字符和末尾换行影响。
- 能安全统计任意文件名集合且只产生一个总计。
- 能说明 wc 结果为什么不是并发一致快照。
