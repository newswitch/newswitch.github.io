# 文件内容与文本处理命令导读

Linux 命令看到的通常不是“表格”或“日志对象”，而是一串字节。命令如何把字节解释成字符、行、字段或记录，决定了统计、截取、拼接和故障排查是否正确。

```mermaid
flowchart LR
    A["文件/标准输入"] --> B["字节流"]
    B --> C["编码解释"]
    C --> D["换行或 NUL 切分记录"]
    D --> E["字段与位置选择"]
    E --> F["标准输出"]
    F --> G["管道中的下一个进程"]
```

## 1. 先建立六个基础概念

### 1.1 字节不等于字符

ASCII 字符通常占 1 字节，UTF-8 中文通常占 3 字节，组合字符还可能由多个 Unicode code point 共同显示成一个字形。`head -c`、`cut -b` 可以截断多字节字符；`wc -m` 和 `wc -c` 回答的问题不同。

### 1.2 文本文件没有统一强制格式

常见差异包括 UTF-8/UTF-16/GBK、LF/CRLF、是否含 BOM、最后一行是否以换行结束。`cat` 能复制字节，但不能自动替你修复这些差异。

### 1.3 行是分隔约定

多数文本工具把 LF 当记录结束符。文件名本身允许包含 LF，因此处理文件名列表时不能使用换行协议；GNU 工具常用 `-z` 把 NUL 作为记录分隔符。

### 1.4 标准输入只能消费一次

管道下游读走数据后，上游不能“倒带”。`tac` 对管道等不可 seek 输入需要缓冲到临时文件；多个 `-` 操作数也会顺序消费同一个标准输入。

### 1.5 文本显示不等于安全解析

控制字符可能改变终端显示，日志字段可能包含分隔符，CSV 还支持引号、转义和字段内换行。简单 `cut -d,` 不是通用 CSV 解析器。

### 1.6 管道退出码容易被忽略

默认 Shell 管道状态通常来自最后一条命令。Bash 自动化应按场景启用 `set -o pipefail`，并检查 `${PIPESTATUS[@]}`，但也要理解 `head` 提前退出可能让上游收到正常的 `SIGPIPE`。

## 2. 命令关系

| 命令 | 主要对象 | 关键能力 | 安全级别 |
|---|---|---|---|
| `cat` | 完整字节流 | 拼接、显示不可见字符、压缩空行 | `[R]` |
| `tac` | 记录序列 | 按行、字符串或正则逆序 | `[R]`，可能大量临时 IO |
| `nl` | 逻辑页面和行 | 分区编号、格式、步长与正则选择 | `[R]` |
| `head` | 流的前部 | 按行/字节截取，或排除尾部 | `[R]` |
| `tail` | 流的尾部/增长文件 | 截取、持续跟踪、轮转重开 | `[R]`，长期占用 fd/IO |
| `wc` | 字节、字符、词、行 | 统计与最长显示行 | `[R]` |
| `cut` | 字节/字符/字段位置 | 范围、补集、输入输出分隔符 | `[R]` |
| `paste` | 多个记录流 | 按列或串行拼接记录 | `[R]` |
| `sort` | 记录与排序键 | locale、数值/版本、稳定性、外部归并 | `[R]/[W]` |
| `uniq` | 相邻记录组 | 去重、计数、重复/唯一筛选和分组 | `[R]/[W]` |
| `comm` | 两个有序序列 | 差集、交集、对称差和计数 | `[R]` |
| `join` | 两个有序键值序列 | inner/outer/anti merge join | `[R]` |
| `tr` | 字符数组 | 翻译、删除、压缩和补集 | `[R]` |
| `expand` | TAB 与显示列 | 按制表位展开为空格 | `[R]` |
| `unexpand` | blank 与显示列 | 按制表位压缩成 TAB | `[R]` |
| `fold` | 行与宽度 | 按显示列、字符或字节折行 | `[R]` |
| `fmt` | 自然语言段落 | 合并短行、目标宽度、缩进与注释前缀 | `[R]` |
| `pr` | 页面和栏 | 页眉页脚、多栏、并排打印与行号 | `[R]`，可能截断 |
| `split` | 固定大小/记录/分区 | 连续或轮询切分、命名与 Filter | `[W/D]` |
| `csplit` | 上下文边界 | 行号、正则、偏移、重复和跳过区段 | `[W]` |
| `od` | 原始字节 | 偏移、字符、整数、浮点和端序视图 | `[R]` |
| `base64` | 二进制与可打印 ASCII | RFC 4648 编码和解码 | `[R/W]`，不是加密 |

## 3. 推荐学习顺序

1. `cat`：认识标准输入、标准输出、连接顺序和不可见字符。
2. `tac`：理解记录分隔符、逆序与不可 seek 输入缓冲。
3. `nl`：理解逻辑页面、正文/页眉/页脚和编号状态。
4. `head`：区分按行、按字节和“除末尾 N 项外”的流式截取。
5. `tail`：理解从尾部读取、descriptor/name 跟踪和日志轮转。
6. `wc`：区分 byte、character、word、line 与显示宽度。
7. `cut`：理解范围、字段分隔和字符边界。
8. `paste`：把多个记录流横向或串行合并。
9. `sort`：建立 locale、键、稳定性与外部归并模型。
10. `uniq`：理解只有相邻记录才能组成重复组。
11. `comm`：在相同预排序契约下比较两个集合。
12. `join`：按有序键连接两个文件并控制输出 schema。
13. `tr`：掌握单字节字符翻译、删除、压缩及 UTF-8 边界。
14. `expand`：理解 TAB 到制表位，而非固定数量空格。
15. `unexpand`：理解行首/全行 blank 压缩及格式语义。
16. `fold`：区分显示列、字符和字节，并保护原记录边界。
17. `fmt`：理解完整段落重排、目标宽度和缩进启发式。
18. `pr`：理解分页、多栏、并排合并以及长行截断风险。
19. `split`：按固定行/字节/记录或分片数量生成可验证分片。
20. `csplit`：按行号和正则上下文定义有状态边界。
21. `od`：把不可见字节转换为带偏移和类型的诊断证据。
22. `base64`：在二进制和可打印文本间可逆转换，并区分编码与安全。

## 4. 安全实验数据

```bash
lab_dir=$(mktemp -d) || exit 1
cd -- "$lab_dir" || exit 1
printf 'alpha\n\nbeta\n' > lines.txt
printf 'a\tb\n1\t2\n' > fields.tsv
printf 'red\0green value\0blue\nvalue\0' > records.nul
printf '中文 UTF-8\n' > utf8.txt
```

观察原始字节：

```bash
od -An -tx1 -c -- lines.txt utf8.txt records.nul
```

实验完毕后返回原目录，确认路径再清理；不要在业务目录直接使用递归删除。

## 5. 管道设计检查表

- 输入是普通文本、二进制内容，还是文件名列表？
- 记录分隔符是 LF、CRLF、NUL，还是自定义协议？
- 位置按字节、字符、显示列还是字段计算？
- locale 和编码是否固定且已知？
- 输入是否可 seek，是否可能无限增长？
- 输出中是否可能含分隔符或终端控制字符？
- 下游提前退出时，上游 SIGPIPE 是否属于预期？
- 是否检查每个关键阶段的退出状态？

## 6. 本章验收

- 能解释字节、字符、显示宽度、行和记录的区别。
- 能说明为什么文件名列表要使用 NUL 协议。
- 能判断命令是否需要完整读取输入、缓冲或持续跟踪。
- 能识别 CRLF、编码、控制字符和缺少末尾换行造成的误判。
- 能为一条生产管道写出输入契约、输出契约和退出状态策略。
- 能让 `sort`、`uniq`、`comm`、`join` 使用一致的排序和等价规则。
- 能判断 TAB、空白、Unicode 宽度和折行是否会破坏数据格式。
- 能根据“段落排版、页面显示、固定切分、上下文切分”选择 `fmt/pr/split/csplit`。
- 能用 `od` 验证原始字节、偏移和端序，而不是凭终端渲染猜测。
- 能安全使用 Base64 严格解码，并说明编码不提供机密性和完整性。
