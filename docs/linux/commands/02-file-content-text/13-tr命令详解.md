# tr 命令详解：字符翻译、删除、压缩与补集

`tr` 从标准输入读取、向标准输出写入，对字符数组执行一对一翻译、删除或连续重复压缩。它不接受文件操作数，也不是正则替换器。GNU `tr` 对安全单字节 locale 支持最完整，对 UTF-8 多字节字符可能按字节处理，不能直接当 Unicode 文本转换器。

## 1. 命令档案

| 项目 | 内容 |
|---|---|
| 实现 | GNU coreutils |
| 文档基线 | GNU coreutils 9.11 |
| 安全级别 | `[R]`；重定向覆盖由 Shell 负责，可能 `[D]` |
| 输入/输出 | 只使用标准输入和标准输出 |

```bash
type -a tr
env tr --version
env tr --help
```

## 2. 完整语法与全部参数

```text
tr [OPTION]... STRING1 [STRING2]
```

| 短参数 | 长参数 | 作用 |
|---|---|---|
| `-c`、`-C` | `--complement` | 把 ARRAY1 替换成 STRING1 字符集合的补集 |
| `-d` | `--delete` | 删除 ARRAY1 中字符，不执行普通翻译 |
| `-s` | `--squeeze-repeats` | 将最后指定数组中字符的连续重复压缩成一个 |
| `-t` | `--truncate-set1` | 翻译时把 ARRAY1 截短到 ARRAY2 长度 |
| 无 | `--help` | 显示帮助并退出 |
| 无 | `--version` | 显示版本并退出 |

选项必须位于操作数前。`STRING1/2` 展开为字符数组，不是正则表达式。

## 3. 四种运行组合

| 命令形态 | 行为 |
|---|---|
| `tr S1 S2` | 把 ARRAY1 对应字符翻译为 ARRAY2 |
| `tr -s S1` | 只压缩 ARRAY1 中连续重复字符 |
| `tr -d S1` | 删除 ARRAY1 中字符 |
| `tr -ds S1 S2` | 先删除 ARRAY1，再压缩 ARRAY2 中连续重复字符 |
| `tr -s S1 S2` | 先翻译 ARRAY1→ARRAY2，再压缩 ARRAY2 中重复字符 |

```bash
printf 'aaabbbccc\n' | tr -s 'ab'
printf 'a1 b2 c3\n' | tr -d '[:digit:]'
printf 'a,,,b;;;c\n' | tr -ds ';' ','
```

## 4. STRING 字符数组语法

### 4.1 字面字符和转义

| 写法 | 字符 |
|---|---|
| `\a` | bell |
| `\b` | backspace |
| `\f` | form feed |
| `\n` | newline |
| `\r` | carriage return |
| `\t` | TAB |
| `\v` | vertical TAB |
| `\\` | backslash |
| `\OOO` | 1～3 位八进制值 |

必须引用，避免 Shell 解释反斜杠、glob 和空白：

```bash
tr '\t' ' '
tr '\r' '\n'
```

### 4.2 范围

```text
CHAR1-CHAR2
```

例如 `a-z`。范围语义受 locale 影响且不同实现可能不同；只处理 ASCII 协议时固定：

```bash
LC_ALL=C tr 'A-Z' 'a-z'
```

### 4.3 重复

```text
[CHAR*]
[CHAR*REPEAT]
```

主要用于 STRING2，把字符重复到需要长度或明确次数：

```bash
printf 'abc123\n' | tr '[:alnum:]' '[x*]'
```

Shell 同样需要引用方括号，防止 pathname expansion。

### 4.4 POSIX 字符类全集

| 类 | 典型含义 |
|---|---|
| `[:alnum:]` | 字母和数字 |
| `[:alpha:]` | 字母 |
| `[:blank:]` | 水平 blank，常见空格/TAB |
| `[:cntrl:]` | 控制字符 |
| `[:digit:]` | 数字 |
| `[:graph:]` | 可见非空白字符 |
| `[:lower:]` | 小写字母 |
| `[:print:]` | 可打印字符，含空格 |
| `[:punct:]` | 标点 |
| `[:space:]` | 空白，如空格、TAB、LF 等 |
| `[:upper:]` | 大写字母 |
| `[:xdigit:]` | 十六进制数字 |

写法必须是双层括号：

```bash
tr -d '[:cntrl:]'
tr '[:lower:]' '[:upper:]'
```

字符类内容由 locale 决定。STRING2 中类的使用受限制；最常见可靠组合是 lower↔upper 成对转换。

### 4.5 等价类

```text
[=CHAR=]
```

表示当前 locale 中与 CHAR 排序等价的字符集合。支持程度和跨平台结果有限，不适合作为稳定数据清洗规则。

## 5. 翻译数组长度

```bash
printf 'abcabc\n' | tr 'abc' 'XY'
```

GNU 默认会把 ARRAY2 最后字符扩展以覆盖较长 ARRAY1，因此 `a→X`、`b→Y`、`c→Y`。加 `-t` 则截短 ARRAY1，`c` 保持原样：

```bash
printf 'abcabc\n' | tr -t 'abc' 'XY'
```

不同历史实现对短 ARRAY2 的扩展细节存在差异。生产规则最好让数组长度明确相等，或显式使用 `-t`/重复语法表达意图。

## 6. 删除与压缩

### 6.1 删除 CR

```bash
tr -d '\r' < windows.txt > unix.txt
```

这会删除所有 CR，不只 CRLF 中的 CR。如果业务正文允许独立 CR，应该使用理解换行协议的转换工具。

### 6.2 连续空白压缩

```bash
LC_ALL=C tr -s '[:blank:]' ' ' < input
```

翻译后压缩空格/TAB为一个空格。它会改变引号内、缩进、固定宽度字段等所有空白，不能用于保留语法的配置、YAML 或代码。

### 6.3 删除后再压缩

```bash
tr -ds '[:punct:]' '[:space:]' < text
```

先删标点，再压缩空白。结果仍是简单字符级清洗，不是自然语言 tokenizer。

## 7. 补集 `-c/-C`

```bash
LC_ALL=C tr -cd '[:print:]\n\t'
```

表示删除不在允许集合中的字符。风险：

- 在 UTF-8 中按字节补集可能破坏所有非 ASCII 字符。
- locale 定义改变补集范围。
- 删除不可见字节可能破坏二进制、签名或协议。
- “只保留允许字符”不等于安全转义或输入验证。

安全策略应在解码和规范化后，用应用语言按 Unicode/code point 或业务 schema 校验。

## 8. UTF-8 的核心限制

GNU 手册明确说明，`tr` 完整可靠支持的是单字节 locale。UTF-8 中：

```bash
printf 'ö\n' | tr 'ö' 'Ł'
```

操作数会展开为多字节序列，tr 可能逐对应字节翻译，产生并非预期字符的结果。需要 Unicode 字符转换时使用：

- `iconv`：字符编码转换，不负责通用大小写。
- Perl/Python 等 Unicode 字符串库。
- ICU 工具或应用语言 locale/normalization API。

只对 ASCII 协议字节转换时显式 `LC_ALL=C`，并确认输入确实是 ASCII/字节协议。

## 9. 标准输入、文件覆盖和二进制

`tr` 没有文件参数：

```bash
tr 'a-z' 'A-Z' < input > output
```

以下会由 Shell 先截断 input：

```bash
# 错误：不要执行
tr 'a-z' 'A-Z' < file > file
```

使用临时文件、校验、同文件系统 rename。对于 NUL 等二进制字节，可用八进制表示，但多字节/locale 和平台差异仍需测试。

## 10. `tr` 与其他工具

| 需求 | 工具 |
|---|---|
| 单字节一对一翻译、删除、压缩 | `tr` |
| 固定/正则字符串替换 | `sed`、Perl |
| 字段条件与重排 | `awk` |
| 编码转换 | `iconv` |
| Unicode normalization/case folding | Unicode 感知语言库/ICU |
| 结构化格式修改 | 对应 JSON/YAML/CSV 解析器 |

## 11. 退出状态与排查

`0` 成功，非 `0` 表示语法、数组构造、读取或写入失败。

| 现象 | 检查方向 |
|---|---|
| 中文乱码 | tr 按 UTF-8 字节处理，多字节限制 |
| 范围比预期多/少 | locale 和 `a-z` 排序范围 |
| `[:class:]` 原样 | 缺少外层 `[]` 或 Shell 引用错误 |
| 输出字符全变最后一个 | ARRAY2 比 ARRAY1 短，默认扩展 |
| 格式被破坏 | 对所有空白/标点无上下文处理 |
| 文件变空 | 输入和重定向输出是同一文件 |

## 12. 动手实验

1. 验证翻译、只压缩、只删除、删除后压缩四种模式。
2. 测试全部转义、范围、重复、字符类。
3. 比较短 ARRAY2 默认行为和 `-t`。
4. 在 C 与 UTF-8 locale 比较范围、class 和补集。
5. 用 ASCII、中文、组合字符验证多字节限制。
6. 制作 CRLF 与独立 CR，验证全局删除风险。
7. 在临时目录演示安全输出替换。
