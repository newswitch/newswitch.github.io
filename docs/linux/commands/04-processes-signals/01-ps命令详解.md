# ps 命令详解：进程选择、线程、状态与自定义字段

`ps` 从 procfs 读取某一时刻的进程快照。它兼容 Unix、BSD 和 GNU 三套参数风格；混用可能改变默认选择和输出，生产脚本应显式选择对象、字段和排序。

## 1. 命令档案与默认行为

| 项目 | 内容 |
|---|---|
| 实现 | procps-ng |
| 输入 | 当前 PID namespace 中可见的 `/proc` |
| 权限 | `[R]`；hidepid、权限与 LSM 可隐藏字段 |

```text
ps [option ...]
```

无参数默认只选与调用者相同 EUID、同一终端的进程，显示 PID、TTY、累计 CPU 时间和命令名；输出默认不承诺排序。

```bash
ps --version
ps --help all
ps L                 # 列出格式关键字
```

## 2. 三套参数语法

- Unix：带单横线，可组合，如 `ps -ef`。
- BSD：不带横线，如 `ps axu`；会改变默认选择并增加 STAT/args。
- GNU：双横线，如 `ps --sort=-rss`。

避免 `ps -aux`：它在标准语义中可能是“选择用户 x”，只是没有用户 x 时 procps-ng 常猜成 `ps aux`。

## 3. 进程选择参数全集

| 参数组 | 参数 |
|---|---|
| 全部/基本集合 | `a`、`-A/-e`、`-a`、`-d`、`g`、`r`、`T`、`x` |
| 反选 | `-N`、`--deselect` |
| PID/快速 PID | `PID`、`p/-p/--pid LIST`、`q/-q/--quick-pid LIST` |
| 父、进程组、会话 | `--ppid LIST`、`-PGID`、`-g LIST`、`--group LIST`、`-s/--sid LIST`、`+SID` |
| 命令名 | `-C LIST`，匹配 `comm` 而非完整 command line |
| 真实用户/组 | `-U/--User LIST`、`-G/--Group LIST` |
| 有效用户/组 | `U/-u/--user LIST`、`--group LIST`；注意 `-g` 的兼容歧义 |
| 终端 | `t/-t/--tty LIST`，`-` 可表示无 TTY |

多个正向选择条件通常是并集，不一定是 AND。需要复合过滤时，先用一个稳定主键集合再通过 `-o` 字段过滤，或用 `pgrep` 的 AND 选择语义。

## 4. 输出格式与修饰参数全集

| 类型 | 参数 |
|---|---|
| 预设格式 | `-f/-F`、`j/-j`、`l/-l`、`u`、`v`、`s`、`X`、`-y`、`-P` |
| 自定义格式 | `o/-o/--format FORMAT`、`O/-O FORMAT`；`O` 有格式/排序歧义 |
| 安全上下文 | `-M`、`Z`、`--context` |
| 树形 | `f`、`-H`、`--forest` |
| 命令/环境 | `c` 显示真实命令名，`e` 把环境附到命令后（可能泄密） |
| 排序 | `k SPEC`、`--sort=SPEC`、兼容 `O ORDER` |
| 宽高 | `w/-w`、`--width/--cols/--columns N`、`--rows/--lines N` |
| 标题 | `h`、`--headers`、`--no-headers/--no-heading` |
| 数字/累计 | `n`、`S/--cumulative` |
| 日期/分隔 | `-D/--date-format FORMAT`、`--delimiter CHAR` |
| 信号名 | `--signames` |

环境变量可能含密码、token 和连接串；不要在共享终端/日志使用 `ps e`。`--delimiter` 只有单字符，`args` 本身可含空白和换行，ps 文本不是任意 argv 的无歧义序列化。

## 5. 线程与其他参数

| 作用 | 参数 |
|---|---|
| 线程显示 | `H`、`-L`、`m/-m`、`-T` |
| 帮助 | `--help simple|list|output|threads|misc|all` |
| 格式词清单 | `L` |
| 调试信息 | `--info` |
| 版本 | `V/-V/--version` |

```bash
ps -eLo pid,tid,nlwp,psr,cls,rtprio,pri,ni,stat,wchan:24,comm
```

Linux 每个线程都有 TID；同一进程线程共享 TGID。CPU 飙高时应定位 TID，再与应用线程 dump/perf 对齐。

## 6. 推荐字段模板

```bash
ps -eo user:16,pid,ppid,pgid,sid,tty,stat,lstart,etime,etimes,%cpu,%mem,rss,vsz,nlwp,psr,wchan:24,comm,args \
  --sort=-%cpu
```

- `comm` 是任务名，历史内核/工具链常有 15 字符限制；`args/cmd` 是可变且可伪造的 argv 显示。
- `etimes` 是经过秒数；`lstart` 是墙钟启动时间。PID 与启动时间组合比 PID 单独更可靠。
- `rss/vsz` 不是完整物理/虚拟内存归因；共享页、页表、内核栈和 cgroup 需要其他证据。
- `%CPU` 常是生命周期平均，不是最近一秒利用率。

## 7. 状态、信号和僵尸

```bash
ps -eo pid,ppid,stat,wchan,pending,blocked,ignored,caught,comm
ps --signames -p PID -o pid,pending,blocked,ignored,caught,comm
```

主状态：`R/S/D/T/t/Z/I/X`。附加字符如 `<` 高优先级、`N` nice、`L` 锁页、`s` session leader、`l` 多线程、`+` 前台 process group。

Zombie 已执行完，只剩退出信息等待父进程 `wait()`；应修复/重启父进程，不能通过向 zombie 发 KILL 清除。`D` 状态任务可能在内核不可中断等待中暂不响应信号。

## 8. namespace、可见性与快照竞态

容器内 PID 可能与宿主机不同，`ps` 只显示当前 PID namespace 和挂载的 procfs 允许看到的对象。`hidepid`、`subset=pid`、Yama/LSM 会进一步限制。

扫描期间进程可退出/PID 可复用，因此 `ps` 输出不是事务快照。破坏性动作不要依赖 `ps | grep | awk | kill`；使用服务管理器、cgroup 或支持 pidfd 的工具。

## 9. 退出状态、实验与掌握标准

成功输出返回 `0`，语法、格式或读取错误返回非 `0`；“选择为空”在不同选项/版本下不应作为唯一存在性协议，使用 `pgrep` 的明确退出码。

实验：比较三种语法默认集合；定制无标题稳定字段；观察线程、process group/session、zombie、`D`/`T`；在容器内外比较 PID；证明 argv 和进程名可被修改。

掌握标准：能按 `ps --help all` 重新归类全部参数；能解释核心字段与状态；能指出一次快照、PID 复用、namespace 和敏感环境的边界。
