# `bg` 命令详解：让停止的 Shell 作业在后台继续

`bg` 是 Bash builtin，向指定停止作业发送继续语义并让它保持后台状态。它不会创建新进程、不会重定向 I/O、不会脱离终端，也不会保证 Shell 退出后继续运行。

## 1. 语法与参数

```text
bg [jobspec ...]
```

`bg` 没有命令专属选项；多个 jobspec 可一次处理，省略时使用当前作业 `%+`。`--` 是否作为通用选项终止符取决于 Bash builtin 解析，使用纯 jobspec 最清楚。

```bash
type bg
help bg
```

## 2. 从前台停止到后台继续

交互终端中 Ctrl-Z 通常向前台 process group 发送 `SIGTSTP`：

```bash
long_command
# Ctrl-Z
jobs -l
bg %1
jobs -r
```

`bg` 的继续效果近似 `SIGCONT`，但还更新 Shell 作业状态。直接 `kill -CONT -PGID` 不会替代 Shell 对 jobspec 和通知的管理。

## 3. 后台不等于无终端

后台程序仍继承原 stdin/stdout/stderr 和控制终端：

- 读控制终端可能收到 `SIGTTIN` 并再次停止；
- `stty tostop` 开启后写终端可能收到 `SIGTTOU`；
- 输出仍会与提示符混杂；
- Shell/终端关闭时仍可能收到 SIGHUP 或遭会话清理。

长任务应在启动前设计日志、输入、服务管理和恢复，而不是运行后临时 `bg`。

## 4. 作业控制条件与退出状态

没有 job control（常见于非交互 Shell）、jobspec 不存在/已完成、作业无法继续时返回非零；全部成功返回 `0`。后台继续只说明收到/处理了继续请求，不证明业务健康。

## 5. 实验与掌握标准

用 `sleep` 和一个读取 stdin 的脚本测试 Ctrl-Z、`bg`、`SIGTTIN`；观察 PGID/TGPID；关闭 job control 后验证失败；对比 `fg`、`disown`、`nohup`。

掌握标准：能说明 `bg` 无参数表且只操作当前 Shell 作业表；能解释后台继续、I/O、TTY 和 SIGHUP 是四个不同问题。
