# mv 命令详解：原子重命名、跨文件系统移动与覆盖策略

`mv` 在同一文件系统内通常调用 rename，只改变目录项；跨文件系统时则退化为“按 `cp -a` 复制，成功后删除源”。这两条路径在性能、原子性、空间峰值和失败恢复上完全不同。

## 1. 命令档案

| 项目 | 内容 |
|---|---|
| 命令 | `mv` |
| 实现 | GNU coreutils |
| 文档基线 | GNU coreutils 9.11 |
| 软件包 | `coreutils` |
| 安全级别 | `[W]` 重命名或移动；覆盖和源删除具有 `[D]` 风险 |
| 主要对象 | 目录项、inode、跨文件系统数据副本、目标覆盖 |

```bash
type -a mv
mv --version
mv --help
```

## 2. 三种语法

```text
mv [OPTION]... [-T] SOURCE DEST
mv [OPTION]... SOURCE... DIRECTORY
mv [OPTION]... -t DIRECTORY SOURCE...
```

- 一对一：把 SOURCE 重命名/移动到 DEST。
- 多源：最后操作数为目标目录。
- `-t`：显式目标目录。
- `-T`：不把最后操作数当目录，适合目录整体替换或交换。

## 3. 同文件系统与跨文件系统

### 3.1 同文件系统

通常只更新目录元数据：

- 速度与文件内容大小基本无关。
- 文件 inode 和打开 FD 仍指向同一对象。
- 单个 rename 在支持条件下具有原子可见性。
- 不能由此推导“数据已经持久化到介质”，持久化还涉及 fsync 和文件系统语义。

### 3.2 跨文件系统

内核 rename 返回跨设备错误后，GNU `mv` 通常：

1. 近似使用 `cp -a` 复制到目标。
2. 复制成功后删除源。
3. 复制失败时清理部分目标。

这会带来：

- 消耗真实读写带宽。
- 需要源与目标同时存在的空间峰值。
- 移动过程中目标可能不完整可见。
- ACL、xattr、Capability、SELinux 等受目标文件系统能力影响。
- 批量移动可部分成功，不具备整体事务。

确认是否同一文件系统：

```bash
stat -c '%d %m %n' source destination-parent
findmnt -T source
findmnt -T destination-parent
```

## 4. GNU coreutils 9.11 全部参数

| 短参数 | 长参数 | 是否带值 | 作用 |
|---|---|---:|---|
| `-b` | `--backup[=METHOD]` | 可选 | 覆盖目标前创建备份 |
| 无 | `--debug` | 否 | 输出移动/复制决策，并隐含 verbose |
| `-f` | `--force` | 否 | 覆盖时不询问 |
| `-i` | `--interactive` | 否 | 覆盖每个目标前询问，否定时失败 |
| `-n` | `--no-clobber` | 否 | 不覆盖已有目标并以失败体现；已不推荐 |
| 无 | `--no-copy` | 否 | 跨文件系统无法 rename 时失败，不退化为复制删除 |
| 无 | `--exchange` | 否 | 交换两个已存在对象；要求同文件系统支持原子交换 |
| `-u` | `--update[=WHICH]` | 可选 | 按 `all/none/none-fail/older` 决定替换 |
| `-v` | `--verbose` | 否 | 输出每个移动关系 |
| 无 | `--strip-trailing-slashes` | 否 | 移除源参数末尾 `/` |
| `-S SUFFIX` | `--suffix=SUFFIX` | 是 | 指定备份后缀 |
| `-t DIR` | `--target-directory=DIR` | 是 | 显式指定目标目录 |
| `-T` | `--no-target-directory` | 否 | 把 DEST 当普通目标，不解释为目录 |
| `-Z` | `--context` | 否 | 按系统默认类型调整目标 SELinux 上下文 |
| 无 | `--help` | 否 | 显示帮助并退出 |
| 无 | `--version` | 否 | 显示版本并退出 |

这就是 GNU coreutils 9.11 `mv` 的完整选项集合。

## 5. 覆盖选项与顺序

`-f`、`-i`、`-n` 多次出现时，最后一个生效：

```bash
mv -i -f source dest    # force
mv -f -i source dest    # interactive
```

`-n` 与备份互斥，并且因不同平台退出状态不同已不推荐。新脚本优先使用 `--update`：

| WHICH | 行为 |
|---|---|
| `all` | 覆盖所有已有目标；未提供 update 时的默认 |
| `none` | 跳过已有目标，不失败 |
| `none-fail` | 跳过已有目标，诊断并失败 |
| `older` | 仅目标 mtime 比源旧时替换；`-u` 默认 |

```bash
mv --update=none source dest
mv --update=none-fail source dest
mv --update=older source dest
```

`-n` 存在时 `-u` 被忽略。mtime 相同不等于内容相同，不能用 update 代替校验。

## 6. `--no-copy`：只允许 rename

```bash
mv --no-copy source dest
```

当跨文件系统无法 rename 时立即失败，不进行复制删除。适用场景：

- 必须保持原子 rename 语义。
- 不允许产生双份容量峰值。
- 不允许长时间数据传输。
- 调用方要显式处理跨文件系统。

它是生产发布、队列目录和状态机切换中的重要保护参数。

## 7. `--exchange`：原子交换两个对象

```bash
mv -T --exchange current next
```

要求：

- source 和 destination 都存在。
- 位于同一文件系统。
- 文件系统和内核支持原子 exchange。
- 交换所有数据和元数据，类型可以不同。

目录交换应配合 `-T` 消除“把目标当目录”的歧义。若未来实现可能支持复制式交换，而业务只允许原子操作，可再加 `--no-copy`。

交换是 `[D]` 变更。必须记录双方 inode、类型、内容校验和和回滚命令，并确认打开文件/工作目录的应用如何感知变化。

## 8. `-T`、`-t` 与目录替换

### 8.1 `-t DIR`

```bash
mv -t /archive -- file1 file2
```

显式目标目录，适合批量和自动化。

### 8.2 `-T`

```bash
mv -T new-tree active-tree
```

把 `active-tree` 当目标本身，而不是在其中创建 `new-tree`。GNU `mv` 只会用源目录替换空目标目录，不会合并两个非空冲突目录。

发布目录替换前要确认同一文件系统、目标类型和应用打开 FD 语义。

## 9. 备份策略

```bash
mv -b --suffix=.before-move source dest
```

METHOD：

| METHOD | 行为 |
|---|---|
| `none/off` | 不备份 |
| `numbered/t` | 编号备份 |
| `existing/nil` | 已有编号则编号，否则简单备份 |
| `simple/never` | 简单后缀备份 |

`VERSION_CONTROL`、`SIMPLE_BACKUP_SUFFIX` 会影响默认值。备份与新目标在同一故障域，不能替代正式备份。

## 10. 源末尾斜杠与符号链接

源名称末尾 `/` 表示调用者期望目录。在不同系统中，源若是指向目录的符号链接，底层 rename 行为可能不同或失败。

```bash
mv --strip-trailing-slashes -- source-link/ dest
```

此参数移除每个源参数末尾斜杠，使语义更明确。仍应先用：

```bash
ls -ld -- source-link
readlink -- source-link
```

确认对象类型。

## 11. SELinux 与扩展属性

同文件系统 rename 通常保留 inode 和属性。跨文件系统复制时，GNU `mv` 尝试复制 xattr，其中可能包括 ACL、Capability 和 SELinux context；失败会按类型产生诊断。

`-Z/--context` 按目标位置的系统默认类型调整安全上下文，类似 `restorecon`。移动后验证：

```bash
stat source-or-dest
getfacl dest
getfattr -d dest
ls -Z dest
```

## 12. 打开文件和运行中服务

同文件系统 rename 不会让已打开 FD 自动切换到另一个 inode：

- 进程打开旧文件后，路径被新文件替换，进程仍可继续读旧 inode。
- 新打开操作看到新路径对象。
- 日志轮转正是利用 rename 与 reopen 的差异。

发布配置或模型时，需要知道应用是每次按路径打开、持续持有 FD，还是 mmap 后长期使用。

## 13. 故障与部分成功

多源或跨文件系统移动不是事务。例如移动三个目录时，第一个可能已成功复制并删除源，第二个失败，第三个未开始。

常见问题：

| 现象 | 检查方向 |
|---|---|
| 移动突然很慢 | 是否跨文件系统、网络存储、文件数量 |
| 空间翻倍 | 复制删除阶段源和目标共存 |
| 权限/ACL 变化 | 目标 FS 能力、xattr、SELinux、特权 |
| `Directory not empty` | 目标非空目录，mv 不做目录合并 |
| `Invalid cross-device link` | 使用了 `--no-copy` 或底层限制 |
| 源部分消失 | 批量操作部分成功 |
| 服务仍读旧内容 | 进程仍持有旧 inode/FD |

## 14. 退出状态

| 状态 | 含义 |
|---:|---|
| `0` | 全部目标按所选策略处理成功或允许跳过 |
| 非 `0` | 至少一个目标失败，或 `none-fail`/`-n` 导致失败 |

非零后同时盘点源和目标；不要未经对账直接重跑，否则可能覆盖已成功部分。

## 15. 安全发布 Runbook

1. 用 `stat -c %d` 确认临时对象与最终目录同文件系统。
2. 校验新文件内容、权限、owner、ACL、xattr 和安全上下文。
3. 记录当前目标 inode、链接和回滚路径。
4. 使用明确的 `-T` 和 `--no-copy` 保证一对一 rename 边界。
5. 执行后让应用 reopen/reload，并验证业务。
6. 保留旧版本到观察窗口结束，再按生命周期清理。

## 16. 动手实验

1. 在同一目录移动大文件，观察 inode、耗时和空间。
2. 在两个实验文件系统间移动，观察复制删除过程。
3. 使用 `--no-copy` 拒绝跨文件系统移动。
4. 比较 `--update=none`、`none-fail`、`older` 的退出状态。
5. 在实验目录交换两个文件和两个目录，验证 `-T --exchange`。
6. 打开一个文件描述符后替换路径，比较旧 FD 和新路径内容。

## 17. 掌握标准

- 能列出 GNU `mv` 的全部选项。
- 能在执行前判断 rename 还是复制删除。
- 能解释 `-f/-i/-n` 与 update 的覆盖关系。
- 能说明 `--no-copy` 与 `--exchange` 的原子性价值。
- 能预测 `-t/-T` 的目录布局。
- 能处理批量移动部分成功并完成源目标对账。
