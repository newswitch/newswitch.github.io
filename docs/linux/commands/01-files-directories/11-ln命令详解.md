# `ln` 命令详解：硬链接、符号链接与目标目录语义

`ln` 默认创建硬链接，使用 `-s` 才创建符号链接。二者看起来都能“从另一个路径访问对象”，但数据结构、跨文件系统能力、失效方式和移动语义完全不同。

## 1. 命令档案

| 项目 | 内容 |
|---|---|
| 命令 | `ln` |
| 实现 | GNU coreutils |
| 文档基线 | GNU coreutils 9.11 |
| 软件包 | `coreutils` |
| 安全级别 | `[W]` 创建目录项；`-f/-i/-b` 可能替换目标，属于 `[D]` 风险 |
| 主要对象 | inode、目录项、硬链接计数、符号链接内容 |

```bash
type -a ln
ln --version
ln --help
```

## 2. 四种语法

```text
ln [OPTION]... [-T] TARGET LINK_NAME
ln [OPTION]... TARGET
ln [OPTION]... TARGET... DIRECTORY
ln [OPTION]... -t DIRECTORY TARGET...
```

- 两个名称：从 `LINK_NAME` 创建到 `TARGET` 的链接。
- 一个目标：在当前目录使用目标基名创建链接。
- 多个目标加目录：在该目录为每个目标创建链接。
- `-t`：显式指定目标目录，适合自动化和 `find -exec`。

## 3. 硬链接与符号链接

| 特性 | 硬链接 | 符号链接 |
|---|---|---|
| 创建参数 | 默认 | `-s` |
| 保存内容 | 指向同一 inode 的目录项 | 保存一段目标路径字符串 |
| 跨文件系统 | 不可以 | 可以 |
| 目标可不存在 | 不可以 | 可以，形成悬空链接 |
| 原名称删除后 | 其他硬链接仍访问数据 | 可能悬空 |
| 目录链接 | 通常禁止 | 可以 |
| inode | 与原文件相同 | 链接有自己的 inode |

```bash
printf 'data\n' > original
ln original hardlink
ln -s original symlink
stat -c '%i %h %F %n' original hardlink symlink
readlink symlink
```

## 4. GNU coreutils 9.11 全部参数

| 短参数 | 长参数 | 是否带值 | 作用 |
|---|---|---:|---|
| `-b` | `--backup[=METHOD]` | 可选 | 替换目标前创建备份 |
| `-d` / `-F` | `--directory` | 否 | 允许有权限用户尝试建立目录硬链接；通常仍被系统拒绝 |
| `-f` | `--force` | 否 | 删除已有目标后建立链接 |
| `-i` | `--interactive` | 否 | 替换已有目标前询问；否定时失败 |
| `-L` | `--logical` | 否 | 创建硬链接时，源是符号链接则链接其目标 |
| `-n` | `--no-dereference` | 否 | 最后操作数是指向目录的链接时，把它当普通目标，而非目录 |
| `-P` | `--physical` | 否 | 创建硬链接时，源是符号链接则链接符号链接本身 |
| `-r` | `--relative` | 否 | 配合 `-s`，自动生成相对于链接位置的目标路径 |
| `-s` | `--symbolic` | 否 | 创建符号链接而非硬链接 |
| `-S SUFFIX` | `--suffix=SUFFIX` | 是 | 指定 `-b` 备份后缀 |
| `-t DIR` | `--target-directory=DIR` | 是 | 在指定目录中创建链接 |
| `-T` | `--no-target-directory` | 否 | 把最后操作数当作链接名称，不把它解释为目录 |
| `-v` | `--verbose` | 否 | 成功后输出链接关系 |
| 无 | `--help` | 否 | 显示帮助并退出 |
| 无 | `--version` | 否 | 显示版本并退出 |

这就是 GNU `ln` 的完整选项集合。

## 5. 硬链接源的 `-L` 与 `-P`

源是符号链接时：

```bash
ln -L symlink hard-to-target
ln -P symlink hard-to-symlink
```

- `-L`：硬链接到符号链接指向的目标 inode。
- `-P`：尝试硬链接符号链接本身。
- 两者都给出时最后一个生效。
- 使用 `-s` 时两者被忽略，因为此时创建的是新符号链接。

GNU 系统通常默认 `-P`；部分 BSD 语义可能默认跟随，因此便携脚本应显式选择。

## 6. 相对符号链接

手工创建：

```bash
ln -s ../releases/v2/app current-app
```

链接中的相对路径是相对于“链接所在目录”解析，不是相对于执行 `ln` 时的当前目录。

GNU 自动计算：

```bash
ln -srv /srv/releases/v2/app /srv/current/
```

`-r` 只允许和 `-s` 一起使用，并基于规范化后的目标和链接目录计算相对路径。若需要保留路径中的符号链接组件或处理不存在目标，使用 `realpath --relative-to` 前应明确规范化策略。

相对链接适合可整体移动的目录树；绝对链接适合固定主机路径，但容器、chroot、网络共享或不同挂载位置中可能失效。

## 7. 目标目录歧义：`-n`、`-T` 和 `-t`

如果 `LINK_NAME` 已经是指向目录的符号链接，默认可能把它当成目标目录，并在目录里面创建新链接。

### 7.1 `-n` / `--no-dereference`

把最后一个“指向目录的符号链接”视为普通文件名，以便配合 `-f/-b` 替换链接本身。它比 `-T` 弱，二者同时出现时 `-T` 决定语义。

### 7.2 `-T` / `--no-target-directory`

```bash
ln -sfnT releases/v2 current
```

明确把 `current` 当作链接名称，即使它指向目录。发布切换常见该写法，但替换现有链接仍是 `[D]` 变更，应先验证新目标和回滚链接。

### 7.3 `-t DIR`

```bash
ln -s -t /srv/app/links target1 target2
```

显式声明所有链接都创建在 DIR 中，避免依靠“最后参数是不是目录”的猜测。

## 8. 覆盖、交互与备份

默认不替换现有目标。

```bash
ln -f source link
ln -i source link
ln -b --suffix=.bak source link
```

- `-f`：删除已有目标。
- `-i`：询问是否删除，否定时该目标失败。
- `-b`：先把已有目标改名备份。

备份 METHOD：

| METHOD | 含义 |
|---|---|
| `none` / `off` | 不备份 |
| `numbered` / `t` | 编号备份 `.~1~` 等 |
| `existing` / `nil` | 已有编号备份则编号，否则简单备份 |
| `simple` / `never` | 简单后缀备份，默认 `~` |

还受 `VERSION_CONTROL` 和 `SIMPLE_BACKUP_SUFFIX` 环境变量影响。自动化应显式参数和清理策略。

## 9. 硬链接限制

### 9.1 不能跨文件系统

```bash
ln source /other-filesystem/hardlink
```

通常得到 `Invalid cross-device link`。使用 `stat -c %d` 或 `findmnt` 比较文件系统。

### 9.2 目录硬链接通常禁止

目录硬链接可能制造环并破坏树结构。即使提供 `-d/-F`，现代系统通常仍拒绝；不要尝试绕过文件系统保护。

### 9.3 权限与 protected_hardlinks

Linux 内核可通过 `fs.protected_hardlinks` 限制非 owner 建立硬链接，防止权限攻击：

```bash
sysctl fs.protected_hardlinks
```

不要为了创建链接直接关闭保护。先确认 owner、权限和业务设计。

## 10. 链接计数与数据生命周期

```bash
stat -c 'inode=%i links=%h name=%n' original hardlink
```

删除一个硬链接：

```bash
rm -- original
cat hardlink
```

数据仍存在。只有最后一个硬链接删除且没有进程持有打开 FD 后，存储块才可回收。

符号链接不增加目标 inode 的硬链接计数。目标删除后：

```bash
test -L symlink && echo 'link exists'
test -e symlink || echo 'target missing'
```

## 11. 生产发布链接

典型结构：

```text
/srv/app/releases/v1
/srv/app/releases/v2
/srv/app/current -> releases/v2
```

切换前：

```bash
test -d /srv/app/releases/v2 || exit 1
readlink /srv/app/current
```

更严格的原子发布通常先创建新的临时链接，再在同一目录使用原子 rename 替换；直接 `ln -sfn` 的细节和跨文件系统边界需要结合系统调用验证。保留旧目标路径可快速回滚。

## 12. 常见错误与排查

| 错误 | 原因方向 |
|---|---|
| `File exists` | 目标已存在且未选择替换策略 |
| `Invalid cross-device link` | 硬链接跨文件系统 |
| `Operation not permitted` | 目录硬链接、protected_hardlinks、权限/安全策略 |
| 链接创建后打不开 | 相对路径基准错误、目标不存在、容器视图不同 |
| 目标目录中意外多一个链接 | 最后参数被当成目录，应该评估 `-T` |
| 发布链接替换了目录内对象 | `-n/-T` 语义不清 |

诊断：

```bash
ls -l -- link
readlink -- link
readlink -e -- link
stat -- link
stat -L -- link
findmnt -T link
```

## 13. 退出状态与部分成功

| 状态 | 含义 |
|---:|---|
| `0` | 所有链接创建成功 |
| 非 `0` | 至少一个目标失败 |

批量创建时可能部分成功。回滚需要记录每个实际创建或替换的路径。

## 14. 动手实验

1. 创建硬链接和符号链接，比较 inode、链接计数和 `readlink`。
2. 删除原名称，观察硬链接与符号链接差异。
3. 创建相对链接并整体移动目录树，验证可移植性。
4. 比较 `-L`、`-P` 对“源是符号链接”的硬链接结果。
5. 构造指向目录的目标链接，比较默认、`-n`、`-T`。
6. 在两个实验文件系统之间尝试硬链接并解释错误。
