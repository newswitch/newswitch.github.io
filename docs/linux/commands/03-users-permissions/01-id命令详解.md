# id 命令详解：UID、GID、补充组与安全上下文

`id` 报告当前进程或指定用户的身份信息。它是权限排障的第一条证据，但“查询当前进程”和“查询用户名对应的账户数据库”并不是同一件事。

## 1. 命令档案与语法

| 项目 | 内容 |
|---|---|
| 实现 | GNU coreutils |
| 文档基线 | GNU coreutils 9.11 |
| 权限影响 | `[R]`，只查询；可能触发 NSS/目录服务访问 |
| 关键数据 | 真实/有效 UID、真实/有效 GID、补充组、SELinux context |

```text
id [OPTION]... [USER]...
```

无 `USER` 时读取当前进程凭据；指定用户后通过 NSS 查询账户与组数据库。脚本应先检查本机版本：

```bash
env id --version
env id --help
```

## 2. GNU coreutils 9.11 全部参数

| 短参数 | 长参数 | 作用与约束 |
|---|---|---|
| `-a` | 无 | 历史兼容参数，GNU 中忽略 |
| `-Z` | `--context` | 只输出当前进程安全上下文；不能与指定 `USER` 共用 |
| `-g` | `--group` | 只输出有效 GID |
| `-G` | `--groups` | 输出全部组 ID |
| `-n` | `--name` | 将 `-u/-g/-G` 的数字转换为名称 |
| `-r` | `--real` | 配合 `-u/-g` 输出真实而非有效 ID |
| `-u` | `--user` | 只输出有效 UID |
| `-z` | `--zero` | 以 NUL 而非空白结束各项；默认完整格式不允许使用 |
| 无 | `--help` | 显示帮助并退出 |
| 无 | `--version` | 显示版本并退出 |

`-u/-g/-G/-Z` 是互斥输出模式；`-n/-r/-z` 是修饰符，但组合仍受对应模式限制。用 `--` 结束参数可避免以 `-` 开头的用户名被当作选项。

## 3. 真实、有效和保存身份

- 真实 UID/GID 通常表示谁启动了进程。
- 有效 UID/GID 主要参与 DAC 权限判断；setuid/setgid 程序可使其不同。
- 保存 set-user-ID/set-group-ID 允许程序在特权与非特权身份间切换。
- filesystem UID/GID 是 Linux 的文件访问凭据，通常跟随有效身份。

默认 `id` 在真实与有效值不同时会同时显示，但不会完整展示保存 ID 与 fsuid。检查具体进程：

```bash
id
grep -E '^(Uid|Gid|Groups|Cap|NoNewPrivs):' /proc/self/status
```

## 4. 常用与机器可读查询

```bash
id -u
id -un
id -g
id -gn
id -G
id -Gn
id -- user_name
```

不要解析默认的人类可读句子。需要逐项传递组名时，优先传数字 ID 或使用 NUL：

```bash
id -Gz -- user_name | while IFS= read -r -d '' gid; do
  printf 'gid=%s\n' "$gid"
done
```

名称可以包含空格，组名也可能解析失败；数字 ID 更稳定。NUL 输出是否支持取决于 coreutils 版本。

## 5. NSS 与组列表边界

`id USER` 会查询 NSS，可能访问 `/etc/passwd`、`/etc/group`、SSSD、LDAP 或 winbind。远端目录超时会让一条看似本地的 `id` 卡住。`id USER` 展示账户数据库推导的组；无参数 `id` 展示当前进程实际持有的组，两者在以下情况可能不同：

- 管理员刚执行 `usermod -aG`，旧会话尚未重新登录；
- 容器/user namespace 映射了 ID；
- 目录服务缓存未刷新或节点配置不一致；
- 进程主动调用 `setgroups(2)` 改变补充组。

```bash
id
id -- "$USER"
getent passwd "$USER"
getent initgroups "$USER"
```

## 6. SELinux context

在支持并启用 SELinux 的系统上：

```bash
id -Z
ps -eZ | head
ls -Zd -- /path
```

`id -Z` 是当前进程的安全上下文，不是 Unix 用户记录的一个字段。DAC 允许但 SELinux 拒绝时仍会出现 `Permission denied`；需要结合 audit 日志分析。

## 7. 退出状态与排障

成功返回 `0`；参数组合非法、用户不存在或 NSS 查询失败返回非 `0`。不要把 stderr 文本当稳定 API。

| 现象 | 检查 |
|---|---|
| `id USER` 卡住 | `nsswitch.conf`、DNS、SSSD/LDAP 状态与超时 |
| 组刚添加却无权限 | 比较无参数 `id` 与 `id USER`，重新登录或重启服务 |
| 显示数字没有名字 | NSS 无对应记录或 user namespace 映射 |
| `id -Z` 报错 | SELinux 未启用、实现不支持或参数组合错误 |
| 容器内外 UID 不同 | `/proc/self/uid_map`、运行时 user namespace 配置 |

## 8. 动手实验与掌握标准

1. 比较 `id`、`id "$USER"` 与 `/proc/self/status`。
2. 用 `setpriv` 或安全实验环境观察真实/有效身份差异。
3. 在测试用户新增补充组后，比较旧 shell、新登录 shell 与账户数据库。
4. 模拟一个 NSS 查询失败，记录延迟、退出码和 stderr。

掌握标准：能解释每个字段来自进程还是账户数据库；能列出全部参数；能证明“数据库中属于某组”不等于“现有进程已携带该组”。
