# S3 访问寻址签名与授权

知道 Bucket 和 Key，还不足以访问一个私有对象。客户端还需要知道请求送往哪里、怎样验证服务器身份、使用哪个调用身份，以及这个身份有没有权限执行当前操作。

这些环节彼此关联，但不能相互替代。TLS 证书验证成功不表示调用者有权限；Access Key 正确不表示签名内容正确；签名正确也不表示允许读取任意对象。

本章使用 AWS SigV4 和 Amazon S3 通用桶作为具体示例。MinIO、Ceph RGW、华为 OBS 的接入地址、支持的认证方式和权限模型，应按实际部署及接口核对；不要把 AWS 身份体系整体当成 S3 协议的一部分。

## 1. 从对象标识生成网络请求

```text
逻辑对象：s3://example-ai-models/models/demo/r1/config.json

需要补充：
Endpoint      请求发往哪个服务入口
Region        服务要求的地域和签名范围
Addressing    Bucket 放在主机名还是路径里
Credentials   使用哪个身份及凭证
Operation     GET HEAD LIST 或其他操作
```

Endpoint 是服务入口，不是 Bucket 本身。换一个 Endpoint 可能是在访问另一套集群，即使两边的 Bucket 名和 Key 都一样。

Region 也不只是延迟优化标签。在 SigV4 中，它通常参与凭证范围和签名；自建服务可以采用自己的约定，不能因为服务部署在本地就随意填写一个值。

## 2. 两种常见寻址方式

以示例入口 `s3.lab.example.com`、Bucket `example-ai-models` 和 Key `models/demo/r1/config.json` 为例：

| 方式 | URL 形式 | 需要关注 |
| --- | --- | --- |
| Path-style | `https://s3.lab.example.com/example-ai-models/models/demo/r1/config.json` | 桶名在路径中，后端必须支持这种寻址 |
| Virtual-hosted-style | `https://example-ai-models.s3.lab.example.com/models/demo/r1/config.json` | 桶名在主机名中，需要相应 DNS、证书和服务路由 |

它们可以表达同一逻辑资源，但 HTTP Host 与路径不同，签名输入也随之不同。不能在签名完成后随意把第一种 URL 改成第二种。

Amazon S3 的地域入口有其正式命名规则；上表域名只是自建实验入口示意。AWS 通用桶与其他桶类型的支持范围也不完全相同。参见 [S3 虚拟主机寻址](https://docs.aws.amazon.com/AmazonS3/latest/userguide/VirtualHosting.html)。

### 2.1 DNS与证书需要一起匹配

虚拟主机寻址要求 Bucket 对应的域名能解析到正确入口，TLS 证书也必须覆盖实际使用的主机名。例如，`*.s3.lab.example.com` 不能按普通单层通配符规则覆盖 `team.models.s3.lab.example.com`。

因此，桶名包含点时要额外检查证书匹配。修复方法应是正确的寻址、证书或服务配置，而不是默认关闭 TLS 验证。

### 2.2 反向代理不能随意改写签名内容

对象服务前面可以有负载均衡和 TLS 终止，但客户端签名涉及的 Host、路径、查询参数及请求头必须与服务端验签所依据的内容一致。

如果代理去掉路径前缀、替换 Host、改变编码或丢失查询参数，就可能出现 SignatureDoesNotMatch。需要核对客户端、入口和后端的实际请求表示；不能只确认“代理能够转发普通网页”。

## 3. TLS 签名和存储加密分别保护哪里

| 机制 | 保护对象 | 不负责什么 |
| --- | --- | --- |
| TLS | 连接上的传输机密性、完整性及服务器身份验证 | 不自动授予对象读取权限 |
| SigV4 | 基于凭证验证请求身份及签名所覆盖的内容 | 不把对象正文或 URL 本身加密 |
| 服务端存储加密 | 服务端持久化数据的加密保护 | 不代替 TLS，也不防止有权限的正常读取 |
| 权限策略 | 哪个身份可以对哪些资源执行哪些操作 | 不保证客户端缓存中的内容是最新版本 |

如果 TLS 在入口代理终止，还要明确代理到对象服务之间是否加密。不能因为客户端使用 `https://`，就认为整个内部转发路径自动受到同一条 TLS 连接保护。

## 4. 凭证包含什么

| 内容 | 用途 | 是否可以公开 |
| --- | --- | --- |
| Access Key ID | 帮助服务端识别使用哪组凭证 | 不是密码，但仍应脱敏 |
| Secret Access Key | 客户端计算签名所需秘密 | 不可以 |
| Session Token | 临时凭证的会话信息 | 不可以 |
| 到期时间 | 临时凭证何时失效 | 需要监控及提前刷新 |

长期 Access Key 通常是一对 ID 与 Secret；临时凭证还需要 Session Token。临时凭证只复制前两项，往往仍然无法访问。客户端应把会话信息按相应签名方式放进请求，参见 [临时凭证与签名](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_sigv-create-signed-request.html)。

优先让 SDK、CLI 或平台的身份机制取得并刷新临时凭证。Kubernetes 中的对象存储身份不是 Pod 能访问网络后就自动拥有的，需要平台明确配置；不同云和自建系统的身份联合方式也不同。

还要检查客户端实际选择了哪组凭证。环境变量、配置文件、挂载 Secret 和平台身份机制可能同时存在；优先级取决于客户端。不要只修改某个文件，就假定正在运行的进程已经改用新身份。

## 5. SigV4怎样证明请求来自这个身份

### 5.1 请求示意

下面是使用请求头签名的结构示意。占位符不构成可发送的有效签名，日期也不是运行时应固定使用的值。

```http
GET /models/demo/r1/config.json HTTP/1.1
Host: example-ai-models.s3.us-east-1.amazonaws.com
X-Amz-Date: 20261119T080000Z
X-Amz-Content-Sha256: <payload-hash-or-supported-payload-mode>
Authorization: AWS4-HMAC-SHA256 Credential=<access-key-id>/20261119/us-east-1/s3/aws4_request, SignedHeaders=host;x-amz-content-sha256;x-amz-date, Signature=<redacted>
```

使用临时凭证时还要附带并按规则处理会话 Token。实际 payload 签名可能使用正文摘要、允许的未签名正文模式或流式模式，由 SDK 和服务支持情况决定，不应机械套用一个固定字符串。

### 5.2 签名输入与计算关系

可以把过程理解成三步：

1. **规范化请求**：把方法、URI、查询参数、参与签名的请求头和 payload 信息组织成确定形式。
2. **建立签名上下文**：加入时间、Region、服务名等范围信息，并包含规范化请求的摘要。
3. **计算签名**：使用从 Secret 派生的签名密钥计算 HMAC，把结果随请求发送。

服务端使用相应凭证和同一规则校验。Secret 不应作为普通参数直接发送；客户端发送的是凭证 ID、签名和相关上下文。详细字段见 [签名元素](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_sigv-signing-elements.html)。

从这个过程可以直接推出几类故障：

- 方法、路径、Host 或被签名的请求头变了，签名输入就可能不同。
- Region、服务名或时间范围不对，也可能无法通过验签。
- Secret 不对，或临时凭证缺少 Token，同样不能完成正确认证。

时间戳和有效期用于限制请求适用范围，不表示一个有效请求天然只能使用一次。实际程序应使用 SDK 或 CLI 签名，避免自行维护 URI 编码、流式正文等易错细节。

## 6. 验签通过后还要授权

认证回答“这是哪个身份的请求”，授权回答“这个身份是否被允许执行这次操作”。

AWS 中可能涉及身份策略、资源策略、显式拒绝、权限边界、组织策略以及 KMS 权限等约束。不同类型策略之间的组合不能简化成“任意一处写了 Allow 就一定允许”。参见 [IAM 策略评估](https://docs.aws.amazon.com/IAM/latest/UserGuide/reference_policies_evaluation-logic.html)。

### 6.1 桶权限与对象权限不是同一个资源范围

| 需求 | AWS 常见操作权限 | 资源示例 |
| --- | --- | --- |
| 列举桶中的 Key | `s3:ListBucket` | `arn:aws:s3:::example-ai-models` |
| 读取当前对象 | `s3:GetObject` | `arn:aws:s3:::example-ai-models/models/demo/*` |
| 读取指定历史版本 | `s3:GetObjectVersion` | 对应对象范围 |
| 上传对象 | `s3:PutObject` | 对应对象范围 |

API 名与权限名不总是一一对应。比如 HEAD 对象通常使用相关读取权限，而不是一个叫 `s3:HeadObject` 的标准授权动作。准确映射见 [S3 API 所需权限](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-with-s3-policy-actions.html)。

### 6.2 受限只读身份策略示例

下面是 AWS **身份策略**示例，不是可以直接提交的 Bucket Policy。它允许列举 `models/demo/` 前缀并读取这个范围内的当前对象，不包含写入和删除权限。

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "ListDemoPrefix",
      "Effect": "Allow",
      "Action": "s3:ListBucket",
      "Resource": "arn:aws:s3:::example-ai-models",
      "Condition": {
        "StringLike": {
          "s3:prefix": ["models/demo/*"]
        }
      }
    },
    {
      "Sid": "ReadDemoObjects",
      "Effect": "Allow",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::example-ai-models/models/demo/*"
    }
  ]
}
```

这个范围设计带来一个有用的现象：按 `models/demo/` 列举可以被允许，列举桶根目录则未被这份策略允许。挂载工具如果还需要其他探测操作，就要按真实请求评估最小权限，而不是直接授予全桶管理权限。

这份策略也不是最终权限全景。其他策略的显式拒绝、跨账号资源约束、KMS 要求等仍然可能阻止访问。对于 MinIO 或 RGW，应检查其策略支持范围和身份管理方式，不能只把 AWS JSON 文件名改一下就视为配置完成。

## 7. 预签名URL怎样授权另一个访问者

预签名 URL 把特定操作和签名信息放入 URL。持有者在有效条件内访问时，使用的是签名者的相关权限，不需要同时获得签名者的 Secret。

它不是公开 Bucket 的同义词，也不是一次性链接。Amazon S3 的预签名 URL 可以在有效期内多次使用；实际有效时间还受签名凭证的到期和撤销等条件限制。参见 [预签名 URL](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)。

例如，已经准备好受限读取身份后，可以用 AWS CLI 生成短时下载链接。在可访问相应对象的测试环境中执行：

```bash
export AWS_PROFILE=object-lab
export AWS_REGION=us-east-1
export S3_ENDPOINT='https://s3.lab.example.com'
export BUCKET='your-owned-test-bucket'
export AWS_PAGER=''

DOWNLOAD_DIR="$(mktemp -d)"
SIGNED_URL="$(aws --endpoint-url "$S3_ENDPOINT" s3 presign \
  "s3://$BUCKET/models/demo/r1/config.json" --expires-in 300)"

curl --fail --silent --show-error --connect-timeout 5 --max-time 30 \
  "$SIGNED_URL" --output "$DOWNLOAD_DIR/config.json"
unset SIGNED_URL
```

前提是 Profile、SigV4、Endpoint、Region、权限和测试对象均已正确准备。`presign` 本身可以在本地生成链接；生成成功不证明对象存在，也不证明服务端最终会授权。

链接应当作临时凭证保护，避免进入访问分析日志、聊天截图和 `set -x` 输出。代理也不能任意重写其 Host、路径和查询参数。若是预签名上传，还应控制允许上传的 Key 和内容约束；同 Key 写入可能覆盖已有对象，见 [预签名上传](https://docs.aws.amazon.com/AmazonS3/latest/userguide/PresignedUrlUploadObject.html)。

## 8. 浏览器还多了一层CORS检查

相同的下载请求在 CLI 成功，在浏览器失败，不一定是对象权限不同。浏览器跨源访问还受到 CORS 规则约束，包括来源、方法、请求头和可暴露的响应头。

CORS 是浏览器相关访问控制的一环，不会把无权限的对象读取变成合法读取。配置允许来源后，签名和服务端权限仍然要正确；扩大 IAM 权限也不能自动修好错误的 CORS。参见 [S3 CORS 配置](https://docs.aws.amazon.com/AmazonS3/latest/userguide/ManageCorsUsing.html)。

## 9. 按层次验证访问

### 9.1 先确认网络与TLS

以下使用实际服务主机名替换示例：

```bash
getent ahosts s3.lab.example.com

openssl s_client -connect s3.lab.example.com:443 \
  -servername s3.lab.example.com \
  -verify_hostname s3.lab.example.com -verify_return_error </dev/null

curl --head --connect-timeout 5 --max-time 10 https://s3.lab.example.com/
```

证书信任成功的输出中，通常能看到类似 `Verify return code: 0 (ok)` 的结果；内部 CA 需要配置对应信任链。`curl` 对匿名请求收到 403，至少说明收到了一次 HTTP 响应，不证明指定桶存在或业务身份有权限。

### 9.2 再确认身份和实际操作

```bash
aws configure list --profile object-lab

aws --endpoint-url "$S3_ENDPOINT" s3api head-object \
  --bucket "$BUCKET" --key models/demo/r1/config.json

aws --endpoint-url "$S3_ENDPOINT" s3api list-objects-v2 \
  --bucket "$BUCKET" --prefix models/demo/ \
  --max-keys 1 --no-paginate
```

`configure list` 帮助识别凭证和配置来源，不要公开原始配置文件。对于 AWS 身份还可以使用 `aws sts get-caller-identity --profile object-lab`；自建 S3 服务不一定实现 AWS STS，不能把这条命令当作所有服务的前置健康检查。

HEAD 与限定前缀 LIST 分别验证对象访问和列举路径。直接 GET 正常但挂载失败时，再核对挂载进程的真实身份及它额外发出的请求。

### 9.3 根据错误缩小范围

| 现象或错误 | 优先检查 | 不应直接采取的动作 |
| --- | --- | --- |
| DNS 解析失败 | 实际 Host、解析范围、网络环境 | 修改桶数据 |
| 证书校验失败 | CA、主机名、时间与证书有效期 | 永久禁用验证 |
| InvalidAccessKeyId | 目标服务、凭证 ID、身份是否仍有效 | 把密钥写进 URL |
| SignatureDoesNotMatch | Region、Secret、Token、时间及签名输入是否改写 | 不加分析地授予管理员权限 |
| ExpiredToken 等 | 临时凭证到期与刷新链路 | 不断重启所有服务 |
| AccessDenied | 操作、资源范围、策略条件和显式拒绝 | 自动改为匿名公开桶 |
| HEAD 403 或 404 | 对象、版本与权限一起核对 | 仅凭状态码断言对象存在与否 |

Amazon S3 对不存在对象返回 403 还是 404，可能取决于调用者是否有相应列举权限；HEAD 也不能像有响应正文的请求一样提供全部错误细节。参见 [HeadObject 错误与权限](https://docs.aws.amazon.com/cli/latest/reference/s3api/head-object.html)。

排查记录保留时间、脱敏请求 ID、API、资源标识、HTTP 状态、错误码和客户端版本。调试日志可能含敏感请求信息，应先脱敏再共享。

## 10. 练习与答案

### 10.1 TLS正常为什么仍然AccessDenied

答案：TLS 验证的是连接及服务器身份，不授予调用者对象权限。还要确认实际使用的调用身份、操作、资源范围和策略约束，以及可能涉及的 KMS 权限。

### 10.2 密钥没有改为什么加代理后签名失败

答案：Secret 只是签名输入的一部分。代理若改写被签名的 Host、路径、查询或请求头，服务端计算的签名可能不同。还要检查实际 Endpoint、Region 和时间，不应靠关闭证书验证解决签名问题。

### 10.3 有GetObject为什么不能列出模型目录

答案：读取已知对象与列举 Bucket 是不同操作。AWS 通常分别涉及对象范围的 GetObject 和桶范围的 ListBucket，并可能限制 Prefix。挂载工具需要列举时，就会暴露这类权限差异。

### 10.4 生成300秒预签名URL是否一定能下载300秒

答案：不一定。对象、权限和请求必须正确，签名凭证也可能先到期或被撤销。链接生成不等于服务端访问已经成功；它也不是默认只能使用一次。

### 10.5 浏览器CORS失败能否靠扩大桶权限修复

答案：不能把两者混为一谈。应分别核对浏览器请求的来源、方法和头是否符合 CORS，以及对象请求的认证与授权。不要为了修复跨源配置而公开私有 Bucket。
