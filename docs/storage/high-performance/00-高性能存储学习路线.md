# 高性能存储学习路线

存储性能不能只看 SSD 标称 IOPS。应用到介质之间还存在系统调用、文件系统、页缓存、块层、调度、驱动、队列和中断；任何一层都可能成为瓶颈。

## 1. 推荐顺序

```text
VFS 与页缓存
→ 块层、Direct I/O、AIO 与 io_uring
→ NVMe Controller、Namespace 与 Queue Pair
→ DMA、IOMMU、HugePage 与 NUMA
→ SPDK Reactor、Poller 和用户态 NVMe Driver
→ bdev、Blobstore、NVMe-oF 与 vhost
→ 压测、容量、监控和故障恢复
```

| 阶段 | 入口 |
|------|------|
| Linux I/O | [Linux VFS 与一次 read 的完整路径](../linux-io/01-Linux%20VFS与一次read的完整路径.md) |
| 缓存与 Direct I/O | [页缓存、预读、回写与 Direct I/O](../linux-io/02-页缓存预读回写与Direct%20IO.md) |
| NVMe | [NVMe 队列、Namespace 与性能模型](../local-storage/01-NVMe队列Namespace与性能模型.md) |
| SPDK | [SPDK 从零到生产学习路线](./spdk/00-SPDK从零到生产学习路线.md) |
| 技术选型 | [DPDK、SPDK、io_uring 与 RDMA](./01-DPDK-SPDK-io_uring与RDMA.md) |

## 2. 完成后的能力

- 能画出 Linux 内核 I/O 和 SPDK 用户态 I/O 两条路径；
- 能解释 Queue Depth、并发、块大小、IOPS、带宽与尾延迟；
- 能安全处理 NVMe 设备绑定、VFIO、HugePage 和 NUMA；
- 能使用 JSON-RPC 构建 bdev 和 NVMe-oF Target；
- 能用 bdevperf、fio、spdk_top 和 Trace 建立证据链；
- 能判断应该选内核 NVMe、io_uring、SPDK、NVMe-oF TCP 还是 RDMA。
