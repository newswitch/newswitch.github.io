# 存储命令参考库学习路线

存储命令不能按“磁盘命令大全”来背。一次 I/O 可能经过应用、VFS、文件系统、页缓存、device-mapper、块层、驱动、本地设备，也可能继续进入 NFS、Ceph 或 S3 服务端。正确学习顺序是先确定对象和数据路径，再选择能够证明假设的命令。

```text
应用文件/对象请求
  ├─ VFS / 文件系统 / mount ── findmnt、mount、df、du、fsck
  ├─ 块设备拓扑 ─────────────── lsblk、blkid
  ├─ device-mapper / MD ─────── pvs、vgs、lvs、mdadm
  ├─ 性能与介质 ─────────────── iostat、fio、smartctl、nvme
  ├─ NFS/RPC ────────────────── exportfs、showmount、nfsstat、rpcinfo
  ├─ Ceph/RADOS ─────────────── ceph、rados、rbd、cephfs-shell
  └─ S3 API / 数据搬运 ──────── aws s3api、s5cmd、rclone、mc
```

## 1. 安全级别

| 标记 | 含义 | 典型命令 |
|---|---|---|
| `[R]` | 只读观察 | `lsblk`、`findmnt`、`iostat`、`ceph status` |
| `[W]` | 修改配置或数据 | `mount`、`exportfs -r`、上传对象、创建 RBD |
| `[D]` | 可能丢数据、中断 I/O 或破坏集群 | `fsck -y`、`mdadm --create`、`rados rm`、递归对象删除 |

生产存储变更必须先确认四个边界：精确设备/池/bucket、当前挂载和打开句柄、数据备份与副本、可验证的回滚路径。命令返回 0 只表示工具认为请求成功，不表示数据已经满足业务持久性和一致性要求。

## 9. 固定排障顺序

```bash
# 1. 先确定对象、拓扑、签名和挂载所有者
lsblk -e 7 -o NAME,TYPE,SIZE,FSTYPE,FSVER,UUID,MOUNTPOINTS
blkid
findmnt --real --output TARGET,SOURCE,FSTYPE,OPTIONS

# 2. 容量和 inode
df -hT
df -ih
du -x -h --max-depth=1 /path | sort -h

# 3. 性能和设备健康
iostat -x -d -y 1 5
smartctl -x /dev/sdX
nvme smart-log /dev/nvme0

# 4. 卷与阵列
pvs --reportformat json
vgs --reportformat json
lvs -a -o +devices,data_percent,metadata_percent
mdadm --detail /dev/md0

# 5. 远端文件/对象系统按实际技术栈选择
nfsstat -m
nfsstat -rc 1 5
ceph status --format json-pretty
aws s3api head-object --bucket BUCKET --key KEY
```

先执行只读命令保存现场，再从“应用 → 文件系统/对象 API → 网络客户端 → 服务端 → 后端设备”逐层验证。不要一开始就 remount、清缓存、强制卸载、修文件系统、重建阵列、删除对象或重启整个存储集群。

## 10. 实验原则

- 块设备实验只用明确创建的 loop device 或一次性虚拟机磁盘；禁止拿系统盘做格式化、fsck 修复和 RAID 实验。
- `fio` 优先使用测试目录中的文件；使用裸设备必须有双重确认和可销毁数据声明。
- NFS 实验使用独立导出目录和测试客户端，不开放 `*` + `no_root_squash`。
- Ceph 使用独立 pool/namespace/client，删除前保存对象清单和 pool ID。
- S3 使用启用版本控制的测试 bucket、测试前缀和最小权限凭据。

## 11. 文档基线

- util-linux 2.42.2：`lsblk`、`blkid`、`findmnt`、`mount`、`umount`、`fsck`。
- GNU coreutils 9.11：`df`、`du`。
- sysstat、fio、smartmontools、nvme-cli：按各自当前上游文档，并要求以本机 `--version/--help/man` 复核。
- LVM2 与 mdadm：按上游主线对象模型，选项以发行版 LVM2/mdadm 版本为准。
- nfs-utils 2.9.1：`exportfs`、`showmount`、`nfsstat`、`rpcinfo`。
- Ceph Tentacle 20.2.2：生产集群也可能使用 Squid/Reef，命令执行前必须确认集群版本和 mixed-version 状态。
- AWS CLI v2、s5cmd 2.3.0、当前 rclone 与 MinIO Client：云服务、S3 兼容实现和客户端版本均可能改变能力。

完整参数的最终事实来源始终是目标机器上的 `--help`、man page、子命令帮助和服务端 API 文档。本库重点给出稳定对象模型、参数族、危险边界、输出判读和可复现实验，避免把某个版本的帮助输出机械复制成很快过期的长表。
