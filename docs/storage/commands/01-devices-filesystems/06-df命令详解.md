# df 命令详解：文件系统块、inode、保留空间与容量排障

`df` 通过文件系统统计接口报告整个已挂载文件系统的 block/inode 使用情况。它不遍历目录，所以速度通常快，也不知道每个目录是谁占用。

## 1. 版本与语法

```bash
df --version
df [OPTION]... [FILE]...
```

给出 FILE 时，`df` 报告包含该路径的文件系统，而不是该文件自身大小。本文按 GNU coreutils 9.11。

## 2. 全部 GNU 专用选项

| 短参数 | 长参数 | 作用 |
|---|---|---|
| `-a` | `--all` | 包含 pseudo、重复和 0 block 文件系统 |
| `-B SIZE` | `--block-size=SIZE` | 指定显示 block size |
| `-h` | `--human-readable` | 1024 进制人类可读单位 |
| `-H` | `--si` | 1000 进制单位 |
| `-i` | `--inodes` | 显示 inode 而不是数据 block |
| `-k` | 无 | 等价 `--block-size=1K` |
| `-l` | `--local` | 只显示本地文件系统 |
| 无 | `--no-sync` | 不先 sync，通常为默认 |
| 无 | `--output[=FIELD_LIST]` | 自定义字段 |
| `-P` | `--portability` | POSIX 单行格式 |
| 无 | `--sync` | 先 sync，可能明显阻塞 |
| 无 | `--total` | 增加总计行 |
| `-t TYPE` | `--type=TYPE` | 只包含类型，可重复 |
| `-T` | `--print-type` | 显示文件系统类型 |
| `-x TYPE` | `--exclude-type=TYPE` | 排除类型，可重复 |
| `-v` | 无 | 被忽略的兼容参数 |
| 无 | `--help/--version` | 帮助/版本 |

`DF_BLOCK_SIZE`、`BLOCK_SIZE`、`BLOCKSIZE` 和 `POSIXLY_CORRECT` 会影响默认单位；脚本显式使用 `-B1` 或 `--output`。

## 3. 输出判读

```bash
df -hT --output=source,fstype,size,used,avail,pcent,target
df -ih --output=source,itotal,iused,iavail,ipcent,target
```

`Avail` 是普通用户可用空间，可能不包含 ext 文件系统为 root 保留的 block；因此 `Size-Used` 不一定等于 `Avail`。thin pool、snapshot、quota、reserved block 和远端服务端也会改变“可用”的实际边界。

## 4. df 与 du 为什么不同

```text
df：文件系统分配器视角
du：可从目录项遍历到的文件视角
```

差异常见原因：

- 文件已 unlink，但进程仍打开：`lsof +L1`；
- mount 覆盖了原目录内容；
- sparse file 的 apparent size 与 allocated block 不同；
- hard link 计数、snapshot/reflink、元数据和 journal；
- 统计对象不是同一 mount namespace；
- NFS/CephFS 服务端配额或延迟更新。

```bash
findmnt -T /path
df -B1 /path
du -x -B1 -s /path
lsof +L1
```

## 5. 生产排障

- `Use%=100%`：先看 inode，再定位大目录和已删除打开文件；不要立即删除未知数据。
- `df` 卡住：可能在访问失联网络挂载；用 `timeout` 辅助并逐个 source 定位。
- 容器结果不同：mount namespace 和 overlay writable layer 不同。
- inode 满但容量充足：大量小文件，删除/归档前先查业务语义和目录性能。

## 6. 标准

完成标准：能同时给出 block、inode、文件系统类型、mountpoint，并能用至少五种原因解释 `df != du`。
