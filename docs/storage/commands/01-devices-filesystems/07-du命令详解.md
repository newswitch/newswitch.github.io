# du 命令详解：目录占用、稀疏文件、硬链接与跨挂载统计

`du` 遍历目录树并汇总文件占用 block。它会产生大量 metadata I/O；在数百万小文件、NFS/CephFS 或故障磁盘上，全盘执行可能给生产系统增加明显压力。

## 1. 核心语义

```bash
du --version
du [OPTION]... [FILE]...
```

默认统计 allocated space，而非逻辑文件长度：

```bash
du -h sparse.img
du -h --apparent-size sparse.img
stat sparse.img
```

## 2. GNU 参数

| 参数 | 作用 |
|---|---|
| `-0, --null` | 每行以 NUL 结尾 |
| `-a, --all` | 输出所有文件，不只目录 |
| `--apparent-size` | 使用逻辑长度，不是已分配 block |
| `-B, --block-size=SIZE` | 设置显示单位 |
| `-b, --bytes` | 等价 `--apparent-size --block-size=1` |
| `-c, --total` | 输出 grand total |
| `-D, --dereference-args` | 跟随命令行参数中的 symlink |
| `-d, --max-depth=N` | 只输出到指定深度；0 类似 summarize |
| `--files0-from=FILE` | 从 NUL 列表安全读取目标，`-` 表示 stdin |
| `-H` | 等价 dereference command-line symlink |
| `-h, --human-readable` | 1024 进制单位 |
| `--inodes` | 统计 inode 数而非 block |
| `-k` / `-m` | 1 KiB / 1 MiB block size |
| `-L, --dereference` | 跟随全部 symlink，可能产生循环/越界 |
| `-l, --count-links` | hard link 每次遇到都计数 |
| `-P, --no-dereference` | 不跟随 symlink，默认 |
| `-S, --separate-dirs` | 目录值不包含子目录 |
| `--si` | 1000 进制单位 |
| `-s, --summarize` | 每个参数只输出总计 |
| `-t, --threshold=SIZE` | 按大小阈值过滤；负值语义相反 |
| `--time[=WORD]` | 显示树中最新时间，可选 mtime/ctime/atime |
| `--time-style=STYLE` | 控制时间格式 |
| `-X, --exclude-from=FILE` | 从文件读取 exclude pattern |
| `--exclude=PATTERN` | 排除匹配名称 |
| `-x, --one-file-system` | 不跨文件系统 |
| `--help/--version` | 帮助/版本 |

hard link 默认只计一次，但“哪一个路径获得计数”取决于遍历顺序；不能据此做逐目录计费。

## 3. 安全而有用的查询

```bash
# 限制同一文件系统和深度
du -x -h --max-depth=1 /var | sort -h

# 找大文件，保留特殊字符安全性
find /var -xdev -type f -size +1G -print0 \
  | du --files0-from=- -h --apparent-size

# inode 密度
du --inodes -x --max-depth=2 /srv | sort -n

# 精确字节总量
du -x -B1 -s /srv/models
```

不要把 `du | sort | tail` 当成完整故障结论：被删除打开文件、snapshot、文件系统元数据和被 mount 遮蔽的数据不会正确出现在当前遍历中。

## 4. 性能与一致性

- 热目录扫描会竞争 dentry/inode cache 和后端 metadata IOPS。
- 遍历期间文件持续变化，总计不是事务快照。
- NFS attribute cache、权限和 stale handle 会造成慢或不完整。
- bind mount/硬链接可能造成业务视角与物理占用视角不同。
- reflink/shared extent 的“每个文件占用”不能简单相加。

先限定 mount 和目录，再分层扩大范围；需要周期报表时使用存储后端 quota/telemetry，而不是频繁全树 `du`。

## 5. 完成标准

能解释 allocated/apparent、hard link、symlink、one-file-system、inode 与并发变化，能在不扫描整个根文件系统的前提下定位容量热点。
