# `rm` 命令详解：删除、递归边界、交互保护与文件系统隔离

`rm` 删除目录项；普通文件的最后一个硬链接被删除且没有进程继续打开时，数据块才会被文件系统回收。它属于最高风险 `[D]` 命令之一：默认没有回收站，也不提供事务回滚。

## 1. 命令档案

| 项目 | 内容 |
|---|---|
| 命令 | `rm` |
| 实现 | GNU coreutils |
| 文档基线 | GNU coreutils 9.11 |
| 软件包 | `coreutils` |
| 安全级别 | `[D]` 删除文件和目录项 |
| 默认边界 | 删除文件；默认不删除目录 |

```bash
type -a rm
rm --version
rm --help
```

先确认是否存在 Alias：

```bash
type rm
alias rm 2>/dev/null
```

不要依赖某台机器的 `rm='rm -i'` 保护脚本；非交互环境、其他用户和其他节点可能没有该 Alias。

## 2. 完整语法

```text
rm [OPTION]... [FILE]...
```

默认不删除目录。最后一个路径组件为 `.` 或 `..` 的目标会被拒绝，不能用参数绕过。

## 3. GNU coreutils 9.11 全部参数

| 短参数 | 长参数 | 是否带值 | 作用 |
|---|---|---:|---|
| `-d` | `--dir` | 否 | 删除列出的空目录 |
| `-f` | `--force` | 否 | 忽略不存在目标和缺少操作数，并且不提示 |
| `-i` | `--interactive=always` | 否 | 每个目标删除前询问 |
| `-I` | `--interactive=once` | 否 | 超过三个目标或递归删除时只询问一次 |
| 无 | `--interactive[=WHEN]` | 可选 | `never`、`once`、`always` |
| 无 | `--one-file-system` | 否 | 递归时跳过位于其他文件系统的目录 |
| 无 | `--preserve-root[=all]` | 可选 | 递归时保护 `/`；`all` 还保护与父目录不同文件系统的命令行目标 |
| 无 | `--no-preserve-root` | 否 | 取消根目录特殊保护；极度危险，不建议使用 |
| `-r` / `-R` | `--recursive` | 否 | 递归删除目录及全部内容 |
| `-v` | `--verbose` | 否 | 删除前输出目标名称 |
| 无 | `--help` | 否 | 显示帮助并退出 |
| 无 | `--version` | 否 | 显示版本并退出 |

这就是 GNU `rm` 的完整选项集合。

## 4. 交互与强制选项的覆盖顺序

- `-f` 忽略之前的 `-i/-I`。
- `-i` 或 `-I` 忽略之前的 `-f`。
- 后出现的交互/强制选项决定最终提示行为。

```bash
rm -i -f file    # 最终 force，不提示
rm -f -i file    # 最终 interactive，每个目标提示
```

不要堆叠冲突参数。生产自动化应明确一种策略，并通过精确目标和预演完成安全控制，而不是依赖人工提示。

## 5. `-f` / `--force`

作用：

- 不存在目标不报错。
- 没有操作数也不报错。
- 永不提示。

它不会绕过内核权限、只读文件系统、immutable 属性或安全策略：

```bash
lsattr file
findmnt -T file
namei -l file
```

`-f` 最大风险是把路径变量为空、拼写错误和目标已不存在等信号一起压掉。

## 6. `-i`、`-I` 与 `--interactive`

```bash
rm -i -- file1 file2
rm -I -- file1 file2 file3 file4
rm --interactive=once -r -- test-tree
```

- `always`：每个目标询问。
- `once`：超过三个目标或递归时只问一次。
- `never`：完全不询问。

`-I` 比 `-i` 更适合人工批量操作，但一次确认后整个递归范围仍会继续，不能代替目标检查。

## 7. 递归删除与文件系统边界

### 7.1 `-r` / `-R`

递归遍历目录并删除所有内容。风险包括：

- 变量解析到意外父目录。
- 目录中包含挂载点或 bind mount。
- 并发创建的新文件被一起删除。
- 网络文件系统带来巨大元数据压力。
- 删除范围跨越租户、容器或数据卷。

### 7.2 `--one-file-system`

```bash
# [D] 仅在已经验证的实验树中示意
rm -r --one-file-system -- "$lab_tree"
```

递归过程中遇到不同文件系统的目录会诊断并跳过。它可保护挂入 chroot 的 `/home` 等路径，但存在边界：

- 如果危险内容与目标属于同一文件系统，无法保护。
- bind mount 的设备标识和文件系统关系需实际验证。
- 命令行本身直接指定的多个目标分别形成边界。

执行前先用：

```bash
findmnt -R /target/tree
find /target/tree -xdev -maxdepth 3 -print
```

### 7.3 `--preserve-root`

递归删除时保护 `/` 是 GNU 默认行为。`--preserve-root=all` 还会拒绝命令行中位于不同于父目录文件系统的目标，有助于识别意外挂载点。

`--no-preserve-root` 会取消关键保护。本参考库不提供其执行示例；生产环境不应使用。

## 8. 删除前四步验证

### 8.1 验证变量非空

```bash
: "${target:?target must be set}"
```

### 8.2 解析绝对路径

```bash
resolved=$(realpath -e -- "$target") || exit 1
printf 'target=%s\n' "$resolved"
```

### 8.3 验证允许前缀与对象类型

```bash
case "$resolved" in
  /srv/myapp/cache/*) ;;
  *) printf 'refuse target: %s\n' "$resolved" >&2; exit 1 ;;
esac

test -d "$resolved" || exit 1
```

字符串前缀检查本身也要正确设计边界，`/srv/app` 与 `/srv/app-old` 不能混淆。

### 8.4 预览真实范围

```bash
find "$resolved" -xdev -mindepth 1 -maxdepth 3 -print
findmnt -R "$resolved"
```

确认 owner、挂载、文件数量和业务停写状态后，才进入授权的删除步骤。

## 9. 特殊文件名与 Shell 展开

名称以 `-` 开头：

```bash
rm -- -cache
rm ./-cache
```

变量必须引用：

```bash
rm -- "$file"
```

通配符由 Shell 在 `rm` 启动前展开：

```bash
printf '<%s>\n' ./*.log
```

先打印展开结果。注意 `*` 默认不匹配隐藏文件，而开启 `dotglob` 后行为会改变：

```bash
shopt -p nullglob dotglob failglob
```

脚本中优先使用 `find` 的明确范围、类型和 NUL 分隔，而不是依赖环境可变的 Glob。

## 10. 符号链接与硬链接

- 删除符号链接本身不会递归删除其目标。
- 删除一个硬链接只减少 inode 链接数；其他硬链接仍可访问数据。
- 删除正在被进程打开的最后目录项，空间可能等进程关闭 FD 才释放。

```bash
stat -c '%i %h %n' file hardlink
lsof +L1
```

“文件已删除但磁盘空间没释放”时，`lsof +L1` 是重要证据。

## 11. 权限模型

删除文件主要需要对父目录具有写和执行权限，不要求对文件内容有写权限。sticky bit 目录还限制删除者身份：

```bash
ls -ld /tmp
namei -l /path/to/file
getfacl /path/to
lsattr /path/to/file
```

常见错误：

| 错误 | 方向 |
|---|---|
| `Permission denied` | 父目录权限、ACL、SELinux |
| `Operation not permitted` | sticky bit、immutable 属性、Capability |
| `Read-only file system` | 挂载只读或文件系统错误 |
| `Device or resource busy` | 挂载点、进程 cwd、内核引用 |
| `Directory not empty` | 并发变化、挂载、仅使用 `-d` |

## 12. 删除与恢复的现实

删除后不要继续向同一文件系统写入，因为新数据可能覆盖可恢复块。恢复能力取决于文件系统、快照、备份、存储层和是否仍有打开 FD。

优先恢复来源：

1. 应用/对象存储版本和回收站。
2. 文件系统或卷快照。
3. 备份与异地副本。
4. 仍打开文件的进程 FD。
5. 最后才是离线文件系统恢复工具。

`shred` 也不能保证 SSD、写时复制、快照、RAID 和分布式存储中的所有副本不可恢复。

## 13. 退出状态与部分删除

| 状态 | 含义 |
|---:|---|
| `0` | 所有目标按规则处理成功；`-f` 下不存在目标也成功 |
| 非 `0` | 至少一个目标失败 |

递归操作可能删除了一部分后才失败。非零不代表“没有删除”，成功也不代表数据仍可从备份恢复。

## 14. 更安全的替代流程

根据场景优先考虑：

- 将目标原子移动到同文件系统隔离目录，延迟清理。
- 使用应用自己的生命周期 API。
- 使用对象存储版本、回收站或快照。
- 使用 `find -delete` 时先执行同条件 `-print`，并理解遍历顺序。
- 对周期清理使用 systemd-tmpfiles 或明确保留策略。

移动到隔离目录也不是备份：跨文件系统可能变成复制后删除，同一存储故障也会一起丢失。

## 15. 动手实验

所有实验只在 `mktemp -d` 返回的目录中进行：

1. 删除普通文件、空目录和非空目录，比较默认、`-d`、`-r`。
2. 创建四个文件，比较 `-i` 和 `-I`。
3. 删除名为 `-f` 的实验文件，掌握 `--`。
4. 创建硬链接，删除一个名称后观察 inode 和链接计数。
5. 打开文件后删除目录项，用 `lsof +L1` 观察空间释放条件。
6. 在实验树挂载独立 tmpfs，使用 `findmnt` 理解 `--one-file-system`，不要操作业务挂载。
