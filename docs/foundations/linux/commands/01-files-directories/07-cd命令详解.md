# `cd` 命令详解：工作目录、逻辑物理路径与 CDPATH

`cd` 修改当前 Shell 进程的工作目录。它必须是 Shell Builtin：如果启动一个外部子进程改变目录，子进程退出后无法改变父 Shell 的状态。

## 1. 命令档案

| 项目 | 内容 |
|---|---|
| 命令 | `cd` |
| 类型 | Shell Builtin |
| 文档基线 | GNU Bash 5.3 |
| 安全级别 | `[W]` 修改当前 Shell 状态，但不直接修改文件系统 |
| 主要对象 | 当前工作目录、`PWD`、`OLDPWD`、`CDPATH` |

```bash
type -a cd
command -V cd
help cd
```

`which cd` 通常找不到外部程序，或者只能反映不相关包装器。识别 Builtin 应使用 `type`、`command -V` 和 `help`。

## 2. 完整语法

Bash 5.3：

```text
cd [-L] [-@] [DIRECTORY]
cd -P [-e] [-@] [DIRECTORY]
```

还支持两个重要操作数行为：

- 不提供 `DIRECTORY`：使用 `$HOME`。
- `DIRECTORY` 为 `-`：使用 `$OLDPWD`，并输出切换后的目录。

## 3. Bash 5.3 全部参数

| 短参数 | 长参数 | 是否带值 | 作用 |
|---|---|---:|---|
| `-L` | 无 | 否 | 逻辑路径模式，先处理 `..`，保留符号链接路径；默认 |
| `-P` | 无 | 否 | 物理路径模式，遍历时解析符号链接，再处理 `..` |
| `-e` | 无 | 否 | 仅与 `-P` 配合；切换成功后若无法确定当前目录则返回失败 |
| `-@` | 无 | 否 | 在支持的平台上把文件扩展属性呈现为目录 |

这就是 Bash 5.3 `cd` Builtin 的完整选项集合。`--` 可用于结束选项解析：

```bash
cd -- -directory
```

`-@` 高度依赖操作系统和文件系统，典型 GNU/Linux 环境未必支持；不应写入通用脚本。

## 4. 默认目录与两个状态变量

```bash
cd             # 切到 $HOME
cd -           # 切到 $OLDPWD
printf '%s\n' "$PWD" "$OLDPWD"
```

- `PWD`：当前逻辑工作目录。
- `OLDPWD`：上一次 `cd` 前的工作目录。

`cd -` 适合在两个目录间切换，但脚本中显式保存路径通常更清楚。

## 5. `-L` 与 `-P`

建立实验：

```bash
lab_dir=$(mktemp -d) || exit 1
mkdir -p "$lab_dir/real/child"
ln -s "$lab_dir/real" "$lab_dir/link"
```

逻辑模式：

```bash
cd -L "$lab_dir/link/child" || exit 1
printf '%s\n' "$PWD"
cd ..
printf '%s\n' "$PWD"
```

`..` 从逻辑路径中的 `child` 回到 `link`。

物理模式：

```bash
cd -P "$lab_dir/link/child" || exit 1
printf '%s\n' "$PWD"
cd -P ..
printf '%s\n' "$PWD"
```

符号链接先解析为 `real`，因此父目录语义依据物理目录树。

Shell 选项也可全局影响默认行为：

```bash
set -o physical
set +o physical
```

生产脚本需要固定语义时在每次关键 `cd` 上显式写 `-P` 或 `-L`，不要依赖调用环境。

## 6. `-e` 的失败语义

`cd -P` 可能已经通过系统调用进入目录，但 Shell 随后无法构造当前目录名称。例如目录在并发中被删除或父路径不可解析。

```bash
cd -P -e /target/path
```

使用 `-e` 后，不能确定切换后的物理路径就返回非零。这对脚本很重要：它避免后续操作在“已经切换但路径身份不清楚”的状态继续运行。

## 7. CDPATH 搜索路径

`CDPATH` 类似目录版 `PATH`。当参数不是绝对路径时，Bash 按冒号分隔项搜索：

```bash
export CDPATH=/srv/projects:/opt/apps
cd myapp
```

如果 `/srv/projects/myapp` 存在，可能切换到那里，并输出实际目录。空条目表示当前目录：

```bash
CDPATH=:/srv/projects
```

风险：脚本中 `cd config` 可能被调用者的 `CDPATH` 重定向到意外位置。安全写法：

```bash
CDPATH= cd -- "$target" || exit 1
```

或者只使用已验证的绝对路径。

## 8. Shell 可选行为

Bash `shopt` 还能改变交互行为：

| 选项 | 作用 | 建议 |
|---|---|---|
| `cdspell` | 交互 Shell 尝试修正轻微拼写错误 | 仅交互便利，脚本不要依赖 |
| `dirspell` | 目录补全时尝试修正拼写 | 仅交互 |
| `autocd` | 直接输入目录名也执行 cd | 容易隐藏命令来源，仅交互使用 |
| `cdable_vars` | 目录不存在时把参数当变量名查找 | 脚本不建议依赖 |

```bash
shopt -p cdspell dirspell autocd cdable_vars
```

## 9. 为什么管道和子 Shell 中的 cd 不会保留

```bash
( cd /tmp && pwd )
pwd
```

圆括号启动子 Shell，目录变化只在子 Shell 中有效。这恰好适合临时切换：

```bash
( cd -- "$build_dir" && make ) || exit 1
```

执行结束后父 Shell 仍在原目录，无需手工 `cd -` 恢复。

管道的各段在 Bash 中通常也运行于子 Shell 环境，不能依赖管道内部 `cd` 改变外层状态。

## 10. 脚本安全模式

### 10.1 切换失败立即停止

危险：

```bash
cd "$target"
rm -rf cache
```

如果 `cd` 失败，后续命令会在原目录执行。正确模式：

```bash
cd -P -- "$target" || {
  printf 'cannot cd to %s\n' "$target" >&2
  exit 1
}
```

也可以把操作限制在子 Shell：

```bash
(
  CDPATH= cd -P -- "$target" || exit 1
  # 在已经验证的目录执行后续操作
)
```

### 10.2 获取脚本所在目录

```bash
script_dir=$(
  CDPATH= cd -P -- "$(dirname -- "$0")" && pwd -P
) || exit 1
```

通过符号链接启动脚本时，`$0` 表示的逻辑入口和真实脚本位置可能不同；是否解析链接必须按部署语义决定。

## 11. 权限与路径解析

进入目录需要对路径每一级目录具有搜索/执行权限：

```bash
namei -l /srv/app/data
getfacl /srv/app/data
```

常见失败：

| 错误 | 方向 |
|---|---|
| `No such file or directory` | 路径组件不存在、链接断裂、Namespace 不同 |
| `Permission denied` | 某一级目录缺少执行权限、ACL 或安全策略拒绝 |
| `Not a directory` | 中间组件是普通文件或错误链接 |
| `Too many levels of symbolic links` | 符号链接环 |

容器、chroot 和 Mount Namespace 中的同一字符串可能指向不同对象。

## 12. 退出状态

| 状态 | 含义 |
|---:|---|
| `0` | 成功切换并满足选项要求 |
| 非 `0` | 切换失败、参数无效，或 `-P -e` 无法确定最终目录 |

检查失败后还要确认当前目录是否变化，特别是 `-P -e` 的极端场景。

## 13. 动手实验

1. 比较 `cd -L`、`cd -P` 后的 `PWD` 和 `pwd -P`。
2. 在符号链接路径中执行 `cd ..`，解释逻辑/物理差异。
3. 设置 `CDPATH`，观察相对目录搜索和输出。
4. 在子 Shell 中 `cd`，确认父 Shell 不变。
5. 移除某一级执行权限，使用 `namei -l` 定位失败层。
6. 创建名为 `-data` 的目录并用 `cd -- -data` 进入。
