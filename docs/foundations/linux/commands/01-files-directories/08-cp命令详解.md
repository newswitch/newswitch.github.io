# `cp` 命令详解：递归复制、属性保留、链接、稀疏文件与 Reflink

`cp` 创建独立副本，也可以选择创建硬链接、符号链接或写时复制 Reflink。它属于 `[W]` 操作；覆盖、删除目标和跟随不可信符号链接时具有 `[D]` 风险。

## 1. 命令档案

| 项目 | 内容 |
|---|---|
| 命令 | `cp` |
| 实现 | GNU coreutils |
| 文档基线 | GNU coreutils 9.11 |
| 软件包 | `coreutils` |
| 安全级别 | `[W]` 创建副本；覆盖与目标删除为 `[D]` |
| 主要对象 | 文件内容、目录树、权限、owner、时间、链接、xattr、ACL、稀疏布局 |

```bash
type -a cp
cp --version
cp --help
```

检查 Alias，尤其不要假设交互式 `cp -i` 会存在于脚本：

```bash
type cp
alias cp 2>/dev/null
```

## 2. 三种语法与目标判断

```text
cp [OPTION]... [-T] SOURCE DEST
cp [OPTION]... SOURCE... DIRECTORY
cp [OPTION]... -t DIRECTORY SOURCE...
```

- 两个路径：复制 SOURCE 到 DEST。
- 多个 SOURCE：最后参数必须是目标目录。
- `-t DIRECTORY`：显式目标目录。
- `-T`：强制把最后参数当作普通目标路径，不按目录展开。

目标语义是事故高发点：

```bash
cp -R source-dir existing-dir
```

通常结果是 `existing-dir/source-dir/...`；而：

```bash
cp -RT source-dir dest-dir
```

把 `dest-dir` 作为目标本身。操作前先用临时目录验证目标布局。

## 3. GNU coreutils 9.11 全部参数

### 3.1 复制类型、递归和符号链接

| 短参数 | 长参数 | 值 | 作用 |
|---|---|---|---|
| `-a` | `--archive` | 无 | 等价于 `-dR --preserve=all`，尽量保留结构和属性，部分属性失败减少诊断 |
| 无 | `--attributes-only` | 无 | 只复制属性，不复制文件内容；目标已存在时内容不变 |
| 无 | `--copy-contents` | 无 | 递归时读取特殊文件内容；通常危险，可能阻塞或写满目标 |
| `-d` | 无 | 无 | 等价于 `--no-dereference --preserve=links` |
| `-H` | 无 | 无 | 递归时跟随命令行直接给出的符号链接 |
| `-L` | `--dereference` | 无 | 跟随源树中所有符号链接 |
| `-P` | `--no-dereference` | 无 | 不跟随源符号链接，把链接复制为链接 |
| `-r` / `-R` | `--recursive` | 无 | 递归复制目录 |
| `-l` | `--link` | 无 | 为非目录创建硬链接而不是复制数据 |
| `-s` | `--symbolic-link` | 无 | 为非目录创建符号链接而不是复制数据 |
| 无 | `--keep-directory-symlink` | 无 | 跟随目标树中已有的目录符号链接；仅可信目标可用 |

### 3.2 覆盖、备份和更新

| 短参数 | 长参数 | 值 | 作用 |
|---|---|---|---|
| `-b` | `--backup[=METHOD]` | 可选 | 覆盖前备份目标 |
| `-f` | `--force` | 无 | 目标无法打开写入时先删除再创建；并非无条件先删 |
| `-i` | `--interactive` | 无 | 覆盖前询问，覆盖之前的 `-n` |
| `-n` | `--no-clobber` | 无 | 不覆盖已有目标；已弃用，跨平台退出状态不一致 |
| 无 | `--remove-destination` | 无 | 尝试打开目标之前先删除已有目标，比 `-f` 更激进 |
| `-u` | `--update[=WHICH]` | 可选 | 按 `all/none/none-fail/older` 决定是否替换 |
| `-S SUFFIX` | `--suffix=SUFFIX` | 是 | 设定备份后缀 |

### 3.3 属性与文件布局

| 短参数 | 长参数 | 值 | 作用 |
|---|---|---|---|
| `-p` | `--preserve[=ATTR_LIST]` | 可选 | 保留指定属性；`-p` 等价 mode、ownership、timestamps |
| 无 | `--no-preserve=ATTR_LIST` | 列表 | 明确不保留指定属性 |
| 无 | `--reflink[=WHEN]` | 可选 | `always/auto/never`，尝试 COW Reflink |
| 无 | `--sparse=WHEN` | 关键字 | `auto/always/never`，控制目标稀疏文件 |
| `-x` | `--one-file-system` | 无 | 递归时不跨文件系统 |
| `-Z` | `--context` | 无 | 按默认策略设置目标 SELinux 上下文 |
| 无 | `--context[=CTX]` | 可选 | 按默认策略或显式上下文设置 SELinux/SMACK 上下文 |

### 3.4 路径、目标与输出

| 短参数 | 长参数 | 值 | 作用 |
|---|---|---|---|
| 无 | `--parents` | 无 | 在目标目录保留源路径前缀并创建中间目录 |
| 无 | `--strip-trailing-slashes` | 无 | 移除源参数末尾 `/` |
| `-t DIR` | `--target-directory=DIR` | 目录 | 显式指定目标目录 |
| `-T` | `--no-target-directory` | 无 | 把 DEST 当普通目标，不把它解释为目录 |
| `-v` | `--verbose` | 无 | 输出每个复制关系 |
| 无 | `--debug` | 无 | 输出复制实现选择等调试信息，并隐含 verbose |
| 无 | `--help` | 无 | 显示帮助并退出 |
| 无 | `--version` | 无 | 显示版本并退出 |

以上构成 GNU coreutils 9.11 `cp` 的完整选项集合。

## 4. 递归与符号链接

默认不复制目录；目录需要 `-R/-r/-a`。

### 4.1 三种跟随策略

```bash
cp -RP source dest    # 保留所有源符号链接
cp -RH source dest    # 仅跟随命令行直接给出的链接
cp -RL source dest    # 跟随遍历中遇到的所有链接
```

`-H/-L/-P` 多次出现时最后一个生效。`-L` 可能走出预期目录树、重复复制同一目标或触发循环；从不可信源复制时优先 `-P`。

`-r` 在非 GNU 系统可能具有历史差异，便携脚本使用 `-R -P` 明确链接策略。

### 4.2 `--copy-contents` 风险

递归默认会在目标创建对应特殊文件，而不是读取设备/FIFO 的字节。`--copy-contents` 会尝试读取它们：

- FIFO 可能永久等待写端。
- `/dev/console` 等设备可能阻塞。
- `/dev/zero` 会持续输出并写满目标。

生产目录复制通常不应使用此参数。

### 4.3 目标目录符号链接

默认不会信任目标树中预先放置的目录符号链接。`--keep-directory-symlink` 会跟随它们，攻击者可能借此让 `cp` 写入目标树以外位置，只能对完全可信且已验证的目标使用。

## 5. Archive 与属性保留

```bash
cp -a source/ dest/
```

`-a` 等价于：

```text
-d -R --preserve=all
```

但对 SELinux context 和 xattr 等保留失败减少诊断。它并不保证所有文件系统都能保存所有属性，也不保留目录项内部顺序。

`--preserve=ATTR_LIST` 支持：

| 属性 | 含义 |
|---|---|
| `mode` | 权限位和 ACL |
| `ownership` | owner/group；可能需要特权 |
| `timestamps` | atime、mtime |
| `links` | 保留源文件之间的硬链接关系 |
| `context` | SELinux 安全上下文 |
| `xattr` | 扩展属性 |
| `all` | 上述全部 |

```bash
cp --preserve=mode,ownership,timestamps,xattr source dest
cp --preserve=all --no-preserve=ownership source dest
```

复制后验证：

```bash
stat source dest
getfacl source dest
getfattr -d source dest
ls -Z source dest
```

文件内容一致还需校验和，而不是只看大小和时间：

```bash
sha256sum source dest
```

## 6. 覆盖策略

### 6.1 `-f` 与 `--remove-destination`

- `-f`：先尝试正常打开目标；失败时删除并重建。
- `--remove-destination`：复制前先删除已有目标。

删除重建会改变 inode、硬链接关系、ACL/xattr、owner 和被其他进程打开时的可见性。目标存在硬链接时，直接写入原 inode 与删除重建语义完全不同。

### 6.2 `-i`、`-n` 和 update

`-n` 已因跨平台退出状态差异被 GNU 标记为不推荐。新脚本使用：

```bash
cp --update=none source dest        # 已存在则跳过，成功退出
cp --update=none-fail source dest   # 已存在则诊断并失败
cp --update=older source dest       # 仅源更新时覆盖
cp --update=all source dest         # 全部覆盖
```

不带值的 `-u/--update` 等价于 `older`。时间戳比较不能证明内容一致，跨文件系统还受时间精度影响。

### 6.3 备份

```bash
cp -b --suffix=.before-copy source dest
```

METHOD：`none/off`、`numbered/t`、`existing/nil`、`simple/never`。环境变量 `VERSION_CONTROL` 和 `SIMPLE_BACKUP_SUFFIX` 也会影响默认值，生产脚本应显式指定。

## 7. Reflink、硬链接和普通复制

| 模式 | 数据关系 | 修改隔离 | 跨文件系统 |
|---|---|---:|---:|
| 普通复制 | 独立数据块 | 是 | 可以 |
| `--reflink` | 初始共享块，写时复制 | 逻辑上是 | 通常要求文件系统支持 |
| `--link` | 同一 inode | 否 | 不可以 |
| `--symbolic-link` | 保存路径 | 取决于目标 | 可以 |

```bash
cp --reflink=always source dest
cp --reflink=auto source dest
cp --reflink=never source dest
```

Reflink 副本后续修改互不影响，但底层未分裂前可能共享物理块，同一介质错误可同时影响两者。它不是独立备份。

`--reflink` 会被 `--link`、`--symbolic-link`、`--attributes-only` 覆盖。

## 8. 稀疏文件

稀疏文件逻辑大小很大，但中间空洞不实际分配块：

```bash
stat -c 'size=%s blocks=%b' sparse-file
du -h sparse-file
```

`--sparse`：

- `auto`：默认，启发式检测输入空洞。
- `always`：长零字节序列也尝试转成空洞。
- `never`：不创建空洞；制作 swap 文件等场景需要。

```bash
cp --sparse=always source dest
cp --sparse=never source swap-backing-file
```

文件系统、压缩和 Reflink 会影响实际占用，复制后同时比较 `stat` 和 `du`。

## 9. `--parents` 与目标目录

```bash
cp --parents a/b/c existing-dir
```

结果是 `existing-dir/a/b/c`，缺失中间目录自动创建。源为绝对路径时可能复制很长路径前缀，自动化应先检查展开结果。

显式 `-t` 适合批量来源：

```bash
cp -t /backup -- file1 file2 file3
```

`-T` 适合明确一对一路径：

```bash
cp -T source-file destination-path
```

## 10. SELinux、ACL 与 xattr

`-Z/--context` 根据策略设置目标默认类型；`--context=CTX` 可显式设置上下文。固定上下文会把策略细节写死在脚本中，通常优先使用策略、正确目标目录和 `restorecon`。

```bash
ls -Z source dest
getfacl source dest
getfattr -d source dest
```

跨文件系统、NFS、对象网关挂载或容器卷时，目标可能不支持相同 xattr/ACL。`cp -a` 成功也应按业务要求验证关键属性。

## 11. 一致性与原子替换

直接复制到业务正在读取的最终路径，读者可能看到部分写入文件。常见模式：

1. 在目标同一目录创建临时文件。
2. 复制并校验内容和关键属性。
3. `fsync`/应用级持久化要求满足后。
4. 使用同文件系统原子 rename 替换最终名称。

`cp` 本身不承诺多文件目录树快照一致性；源在复制期间变化会产生混合时点副本。数据库、虚拟机磁盘和活跃模型目录应使用应用快照、文件系统快照或停写流程。

## 12. 退出状态与部分成功

| 状态 | 含义 |
|---:|---|
| `0` | 所有目标按规则复制成功或按允许策略跳过 |
| 非 `0` | 至少一个复制失败或 `none-fail` 等策略判定失败 |

多源和递归复制不是事务：非零退出时，一部分目标可能已经完整或部分创建。恢复前记录 `--debug/--verbose` 输出，并逐对象校验。

## 13. 常见故障

| 现象 | 检查方向 |
|---|---|
| `Permission denied` | 父目录、owner、ACL、SELinux、只读挂载 |
| `No space left` | 容量、inode、配额、临时峰值 |
| `Operation not supported` | xattr、ACL、reflink、特殊文件能力 |
| 复制后权限不同 | umask、未 preserve、目标 FS 不支持、特权不足 |
| 目录层级多一层 | 目标目录与 `-T` 语义理解错误 |
| 脚本卡住 | `--copy-contents` 读取 FIFO/设备、网络 FS 阻塞 |
| 数据量异常小 | 稀疏/Reflink/硬链接，需要区分逻辑与物理占用 |

## 14. 动手实验

1. 比较 `cp source dest`、`cp -R dir existing-dir`、`cp -RT dir dest` 的布局。
2. 创建源符号链接树，比较 `-H/-L/-P`。
3. 建立硬链接源，比较普通复制、`-a` 和 `--preserve=links`。
4. 创建 ACL/xattr，在支持的两个文件系统之间复制并验证。
5. 创建稀疏文件，比较 `--sparse=always/never`。
6. 在支持 COW 的测试文件系统比较 reflink 与普通复制的时间和占用。
7. 比较 `--update=none` 与 `none-fail` 的输出和退出码。

## 15. 掌握标准

- 能按复制类型、覆盖、属性、布局和目标五类解释全部参数。
- 能准确预测 `-R`、`-T`、`-t` 的目标布局。
- 能解释 `-H/-L/-P` 以及目标目录符号链接风险。
- 能区分普通副本、Reflink、硬链接和符号链接。
- 能验证内容、权限、ACL、xattr、上下文和硬链接关系。
- 能解释多文件复制为何不是一致性快照或事务。
