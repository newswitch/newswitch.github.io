# `fg` 命令详解：恢复前台进程组与终端控制

`fg` 是 Bash builtin，把指定作业的 process group 设为控制终端前台组，必要时发送继续信号，然后等待它再次停止或结束。

## 1. 语法与参数

```text
fg [jobspec]
```

没有命令专属选项；省略 jobspec 使用当前作业。一次只恢复一个作业，避免“多个前台 process group”这种不成立的概念。

```bash
type fg
help fg
jobs -l
fg %1
```

## 2. Shell、TTY 与 foreground PGID

控制终端记录一个 foreground process group。Shell 进入前台作业时把终端交给该 PGID并等待；作业停止/结束后，Shell 取回终端并恢复自己的 termios 状态。

```bash
ps -o pid,pgid,sid,tty,tpgid,stat,comm -p $$,$!
```

程序异常修改终端模式后退出，可能留下“无回显/乱码”终端；可先 `stty sane`，但仍应调查应用退出和信号处理。

## 3. 与直接发送 CONT 的区别

`kill -CONT PID` 只让目标继续；`fg` 同时完成 jobspec 解析、终端前台组切换、作业状态维护和等待。因此需要交互输入的作业应使用 `fg`，不是先 `bg` 再争抢 stdin。

## 4. 返回状态和失败

作业最终退出时，`fg` 通常返回其 pipeline 的状态（受 `pipefail` 等 Shell 规则影响）；jobspec 无效、job control 关闭或没有控制终端时返回非零。作业再次停止时 Shell 报状态并恢复提示符。

## 5. 实验与掌握标准

运行交互程序和 pipeline，Ctrl-Z 后比较 `kill -CONT`、`bg`、`fg`；观察 TPGID 和 termios；在非交互 Bash 中验证限制。

掌握标准：能说明 `fg` 的全部语法；能画出终端交给作业、作业停止/退出、终端归还 Shell 的状态序列。
