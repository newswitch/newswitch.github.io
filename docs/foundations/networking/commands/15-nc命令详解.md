# `nc` 命令详解：TCP、UDP、端口与 Unix Socket 验证

`nc`（netcat）可以建立 TCP/UDP 连接、监听端口、经代理连接、访问 Unix Domain Socket，或在不引入完整应用协议客户端时收发原始字节。它适合验证“网络和传输层能否建立基本通信”，不等于应用、TLS 或认证一定正常。

## 1. 最先解决：你安装的是哪个 `nc`

Linux 上常见实现包括：

- OpenBSD `nc`（许多发行版的 `netcat-openbsd`）；
- traditional/GNU netcat；
- Nmap Ncat（命令通常也可叫 `ncat`）；
- BusyBox `nc`。

它们的参数、监听语法、代理、TLS 和退出行为并不完全一致。本文以 Linux 常见的 OpenBSD `nc` 兼容语法为主，执行前必须检查本机：

```bash
command -V nc
nc -h 2>&1 | head -n 30
readlink -f "$(command -v nc)"
```

不要根据另一台机器的命令行直接推断当前机器支持 `-q`、`-N`、`-e`、TLS 或代理选项。

## 2. 语法、能力边界与安全

常见语法：

```text
nc [选项] 目标主机 目标端口
nc -l [选项] [监听地址] [监听端口]
nc -U [选项] Unix-Socket路径
```

| 项目 | 说明 |
|---|---|
| 客户端连接 | `[R]`，但会向目标产生真实 TCP/UDP 流量 |
| 临时监听 | `[W]`，会在主机开放入口；必须限定地址、端口、时间和防火墙 |
| 端口范围探测 | 可能被视为扫描；只对获授权目标和必要端口执行 |
| 加密 | 普通 `nc` 是明文传输，不验证 TLS 证书 |
| 禁止做法 | 不把 shell、解释器或敏感文件接到网络连接上；本文不提供远程 shell 用法 |

`nc` 的目标是最小传输层验证。HTTPS、数据库、消息队列等协议应继续使用相应客户端完成握手和认证检查。

## 3. 地址族、解析与连接参数

| 参数 | 作用 |
|---|---|
| `-4` | 只使用 IPv4 |
| `-6` | 只使用 IPv6 |
| `-n` | 不解析名称和服务名；自动化推荐，避免 DNS 干扰 |
| `-v` | 详细输出；可重复增加详细程度，取决于实现 |
| `-z` | Zero-I/O 模式，只测试连接/端口，不发送应用数据 |
| `-w SECONDS` | 连接和空闲超时；监听模式的具体语义存在实现差异 |
| `-i SECONDS` | 每行发送或端口探测之间的间隔 |
| `-r` | 随机化目标端口顺序，扫描用途应受控 |
| `-C` | 将行尾转换为 CRLF，适合部分文本协议 |
| `-d` | 不从标准输入读取 |
| `-N` | 标准输入 EOF 后对网络 socket 执行 `shutdown(SHUT_WR)` |
| `-q SECONDS` | 标准输入 EOF 后等待指定时间再退出；常见于 Linux OpenBSD 移植版，但不是所有实现都有 |

最常用的 TCP 端口检查：

```bash
nc -4 -n -v -z -w 3 192.0.2.10 443
echo $?
```

这能证明一次 TCP 连接尝试得到成功结果，但不能证明 TLS 证书、HTTP 路由和后端业务正常。

## 4. 源地址、源端口与 socket 缓冲

| 参数 | 作用 |
|---|---|
| `-s ADDRESS` | 绑定本地源地址 |
| `-p PORT` | 指定本地源端口；监听语法是否使用它取决于实现 |
| `-I LENGTH` | 设置接收 socket 缓冲区大小 |
| `-O LENGTH` | 设置发送 socket 缓冲区大小 |
| `-T KEYWORD` | 设置 IP TOS / IPv6 Traffic Class 相关值，关键字集合取决于实现 |
| `-M TTL` | 设置出站 IPv4 TTL / IPv6 Hop Limit |
| `-m MINTTL` | 要求入站报文满足最小 TTL，平台支持情况不同 |
| `-V RTABLE` | 选择 routing table/rtable；OpenBSD 能力，Linux 构建通常未必支持 |

```bash
ip route get 192.0.2.10 from 192.0.2.20
nc -4 -n -v -z -w 3 -s 192.0.2.20 192.0.2.10 443
```

绑定源端口可能与本地已有 socket 冲突，也可能触发防火墙/NAT 的特殊策略。普通验证不需要固定源端口。

## 5. TCP、UDP 与 Unix Socket

| 参数 | 作用 |
|---|---|
| `-u` | 使用 UDP；默认使用 TCP |
| `-U` | 使用 Unix Domain Socket |
| `-l` | 监听模式 |
| `-k` | 一个连接结束后继续监听；通常与 `-l` 使用，行为因实现而异 |
| `-W COUNT` | 接收指定数量的数据包后退出；并非所有实现支持 |

### TCP 临时实验

只在实验主机或受控命名空间内监听回环地址：

```bash
# 终端 A：[W] 临时监听
nc -l 127.0.0.1 18080

# 终端 B：连接并输入文本
nc 127.0.0.1 18080
```

完成后用 `Ctrl+C` 终止并确认端口消失：

```bash
ss -lntp 'sport = :18080'
```

监听语法在实现间差异明显。有的实现要求 `nc -l -p 18080`，因此一定先看 `nc -h`。

### UDP 验证的局限

```bash
nc -u -n -v -z -w 2 192.0.2.53 53
```

UDP 无连接。命令“成功”可能只表示本机成功发送 datagram，并没有收到目标应用响应；ICMP Port Unreachable 也可能被防火墙丢弃。验证 UDP 服务应发送合法协议请求并检查响应，例如 DNS 使用 `dig`，NTP 使用专用客户端。

### Unix Domain Socket

```bash
nc -U /run/example/service.sock
```

访问 socket 需要文件权限。不要删除未知 socket 文件；它可能由正在运行的服务持有。

## 6. 代理参数

| 参数 | 作用 |
|---|---|
| `-x proxy[:port]` | 指定代理地址 |
| `-X protocol` | 指定代理协议；常见 `4`、`5`、`connect`，以实现帮助为准 |
| `-P username` | 提供代理用户名；通常不包含安全的密码交互能力 |

```bash
nc -n -v -x 192.0.2.20:1080 -X 5 198.51.100.10 443
```

代理连通只证明代理建立了到目标的通道。普通 `nc` 不会完成 TLS 证书验证，也不会替你验证 HTTP 状态码。

## 7. 其他平台相关参数

OpenBSD 手册和不同移植版本还可能提供下列选项：

| 参数 | 作用与兼容性说明 |
|---|---|
| `-D` | 启用 socket 调试，平台相关 |
| `-F` | 通过标准输出传递已连接 socket，常用于代理链；平台/实现相关 |
| `-S` | 启用 TCP MD5 签名等安全选项；高度平台相关，不是通用 TLS |
| `-Z` | 设置某些平台的 socket 安全标签/域，Linux 常见构建可能没有 |
| `-h` | 显示本实现的帮助 |

较新的 OpenBSD `nc` 还包含 TLS 相关选项，但大量 Linux 发行版的 `nc` 并不具备。需要 TLS 测试时优先使用：

```bash
openssl s_client -connect example.com:443 -servername example.com
curl -v https://example.com/
```

## 8. 端口范围检查

```bash
# 仅检查获授权的少量连续端口
nc -4 -n -v -z -w 2 192.0.2.10 8000-8010
```

注意：

- 范围语法不是每个实现都支持；
- 大范围、高并发探测可能被视为安全扫描；
- `refused` 通常说明目标主机返回 RST，路径可达但没有监听或被主动拒绝；
- `timed out` 可能是路径、ACL、安全组、静默丢弃、地址错误或回程问题；
- 一次成功不代表端口持续健康。

## 9. 文本协议的最小验证

对明文、人工可读协议，可以发送最小合法请求。不要发送密码、Token 或生产敏感数据。

```bash
printf 'HEAD /health HTTP/1.0\r\nHost: example.com\r\n\r\n' | \
  nc -N -w 3 example.com 80
```

若实现不支持 `-N`，可尝试实现提供的 `-q`，或使用 `curl`。HTTP/1.1、TLS、重定向、代理和认证应交给 `curl` 处理，避免手写协议造成误判。

## 10. 如何理解退出状态

常见规律：

```text
0     -> nc 认为操作成功
非 0  -> 解析、连接、超时、协议或参数失败
```

但具体退出码及 `-z`/UDP/端口范围的聚合行为因实现而异。脚本必须在目标发行版上验证：

```bash
if nc -4 -n -z -w 2 192.0.2.10 443; then
  printf '%s\n' 'tcp connect succeeded'
else
  rc=$?
  printf 'tcp connect failed, rc=%s\n' "$rc"
fi
```

更完整的服务健康判断应继续检查 TLS、应用协议、认证和业务响应。

## 11. 一套分层排障方法

```bash
# 1. DNS/NSS
getent ahosts api.example.com

# 2. 内核选路
ip route get 192.0.2.10

# 3. 端口与本地 socket
ss -lntup
nc -4 -n -v -z -w 3 192.0.2.10 443

# 4. 路径
mtr -4 -n -r -T -P 443 -c 50 192.0.2.10

# 5. TLS 与应用
openssl s_client -connect 192.0.2.10:443 -servername api.example.com
curl -v --connect-timeout 3 https://api.example.com/health

# 6. 必要时受控抓包
sudo tcpdump -i any -nn -c 100 'host 192.0.2.10 and tcp port 443'
```

### 根据 TCP 结果缩小范围

| 现象 | 能说明什么 | 下一步 |
|---|---|---|
| 立即 `Connection refused` | 常见为收到 RST，三层路径大概率可达 | 检查监听地址、端口、服务进程、防火墙 reject |
| 超时 | 没有得到成功或明确拒绝 | 路由、ACL、安全组、静默 drop、回程、服务主机 |
| 连接成功后应用失败 | TCP 建连完成，不代表上层成功 | TLS SNI、证书、HTTP/协议、认证、后端 |
| 本机可连、远端不可连 | 服务可能仅绑定回环/本地地址，或入口策略不同 | `ss -lntp`、防火墙、监听地址、路由 |

## 12. 常见误区

| 误区 | 正确认识 |
|---|---|
| `nc -z` 成功就证明应用健康 | 它通常只验证传输层连接 |
| UDP `nc -z` 成功就证明端口开放 | UDP 无连接，必须有合法请求与响应 |
| 所有 Linux 的 `nc` 参数相同 | OpenBSD、traditional、BusyBox、Ncat 差异明显 |
| `nc` 可以验证 HTTPS | 普通 nc 不做 TLS、SNI 和证书验证 |
| 没写 `-w` 也不会卡住 | 连接或读等待可能持续很久，自动化必须设超时 |
| 临时监听绑定 `0.0.0.0` 没关系 | 会扩大暴露面，应优先回环或专用实验地址 |
| 用 nc 传敏感文件很方便 | 普通连接是明文且缺少完整认证、完整性和审计机制 |
