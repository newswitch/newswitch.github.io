# 数据库 SLI/SLO、Dashboard、告警与变更关联

数据库可用不等于端口可连。对用户来说，服务是“在期限内返回正确结果并满足一致性要求”。

## 1. SLI 分层

### 用户层

- 成功请求比例；
- 读写延迟分布；
- 数据新鲜度和一致性；
- 超时、重复和错误提交。

### 数据库服务层

- 成功事务比例；
- 查询/提交 P95、P99；
- 连接池获取成功和等待；
- 只读路由新鲜度；
- failover 恢复时间。

### 原因指标

CPU、锁、I/O、脏页和复制线程用于解释 SLI，不宜全部直接成为用户 SLO。

## 2. SLO 与错误预算

示例而非通用值：

```text
结算写入：99.95% 在 300 ms 内成功
订单读取：99.9% 在 200 ms 内，数据延迟 ≤ 5 s
月度可用性：99.95%
```

明确窗口、排除条件、测量点和一致性语义。平均延迟不能表达尾部用户；监控端到端结果，也保留数据库内部拆分。

## 3. Dashboard 结构

第一屏回答“用户是否受损”：流量、成功率、P50/P95/P99、超时、复制新鲜度。

第二屏回答“数据库哪里饱和”：连接/运行线程、Top digest、锁等待、Buffer Pool/redo、磁盘、复制、备份。

第三屏回答“发生了什么变化”：发布、DDL、参数、故障切换、备份、流量活动、云盘和节点事件。

所有面板统一时区、实例角色和聚合口径；切主后不能让旧主与新主的指标混在一起。

## 4. 告警：症状优先

优先页人：持续错误预算消耗、关键写失败、P99 超标、无可用主库、复制新鲜度违反契约、磁盘即将耗尽。

原因告警用于辅助或工单：缓存命中下降、某缓冲区偏高、单次临时表增长。避免每个状态变量都直接叫醒值班人员。

采用持续时间、相对基线和多窗口 burn rate，降低瞬时尖峰与静态阈值噪声。

## 5. 告警必须带上下文

```text
影响的服务/租户/实例角色
开始时间和当前值
SLO 与 burn rate
最近发布/DDL/参数/切换
Top digest 与锁阻塞者
Dashboard、Runbook、回滚入口
```

告警中避免包含完整 SQL 参数和敏感数据。

## 6. 变更关联

为这些事件写统一标记：应用部署、Schema 变更、索引可见性、参数、实例重启、切换、备份恢复、扩缩容。没有变更时间线，团队只能靠记忆猜测。

变更审计至少记录 who/what/when/why/before/after/rollback，并把标记投射到 Dashboard。

## 7. 合成探测

端口探活只能证明 TCP/认证。建立低成本的读、写、提交和读回探测，验证路由、权限、事务和数据可见性；使用专用小表、受限账户和清理策略，防止探测本身成为负载。

## 8. Runbook 驱动告警

每条高优告警必须能回答：

```text
如何确认是真故障
先看哪三张图/三条查询
安全止血动作
危险动作
升级路径
恢复与关闭条件
```

季度故障演练验证告警是否及时、路由正确、Runbook 可执行，而不只是“规则存在”。

## 9. 验收

注入慢查询、锁等待、复制停顿、磁盘水位和主库故障。测 MTTD、告警噪声、上下文完整度、MTTR 和 SLO 计算是否与用户感受一致。
