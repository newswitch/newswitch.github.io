# 备份不是复制：RPO、RTO、一致性与保留策略

复制会快速传播误删、错误 DDL 和逻辑损坏；快照可能与源同故障域；“备份任务成功”也不证明文件可恢复。备份的唯一验收是恢复后数据满足目标。

## 1. 四个目标

- RPO：最多允许丢多少时间的数据；
- RTO：从事故开始到业务恢复多久；
- 一致性：恢复点是否是可用事务状态；
- 保留：能回到多远、能抵抗多久后才发现的错误。

不同数据分类可有不同目标，资金、配置、日志和缓存不应共用一套默认值。

## 2. 威胁模型

```text
单表误删/误更新
错误发布延迟发现
实例/磁盘损坏
可用区或地域故障
凭据泄露后删除备份
勒索与密钥丢失
版本/Schema 不兼容
人员操作错误
```

每种故障都要映射到恢复来源和演练，而不是只写“每日全备”。

## 3. 备份组合

| 类型 | 优点 | 代价/边界 |
|---|---|---|
| 逻辑备份 | 可读、对象级恢复、迁移方便 | 大库慢、恢复需重建索引 |
| 物理备份 | 大库复制/恢复快 | 版本平台兼容与 prepare 流程 |
| Binlog | 精细 PITR | 必须有基线备份、日志连续 |
| 存储快照 | 快速、节省传输 | 必须保证数据库一致性和故障域 |
| Clone | 快速供应实例 | 不是长期离线保留策略 |

成熟方案通常是周期物理全备 + 连续 Binlog 归档 + 必要对象逻辑导出 + 跨故障域不可变副本。

## 4. 一致性点

备份必须记录：开始/结束、服务器 UUID、版本、GTID/位点、Schema、工具版本、加密密钥标识和校验和。多库业务若要求同一事务快照，不能分别在不同时刻导出后宣称全局一致。

## 5. 3-2-1 只是起点

至少多份副本、不同介质/系统、异地一份；再增加：独立权限、对象锁/不可变保留、删除保护、密钥备份、访问审计和恢复账户。若攻击者用同一管理员凭据能删生产和所有备份，副本数量没有意义。

## 6. 保留模型

```text
每日：近 14 天
每周：近 8 周
每月：近 12 月
binlog：覆盖最长发现时间 + 恢复余量
```

这是示例，真实值由法规、业务和成本决定。删除前确认最慢副本、最老恢复点和正在进行的恢复；不要手工删活动 Binlog 文件。

## 7. 恢复演练

每次抽取真实备份到隔离环境：验证校验和与解密 → 恢复 → 应用日志到目标点 → 启动 → 业务不变量/抽样/权限检查 → 记录实际 RTO。演练还应覆盖密钥不可用、文件损坏和跨账号恢复。

## 8. 备份 SLI

成功率、最新可恢复点年龄、Binlog 归档延迟、校验失败、备份大小异常、恢复演练通过率和实测 RTO。只监控 cron exit code 不够。
