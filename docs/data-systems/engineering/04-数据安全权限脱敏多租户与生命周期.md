# 数据安全、权限、脱敏、多租户与生命周期治理

数据平台权限跨多层：用户能在 SQL Catalog 看表，不代表无法用对象存储凭据直接下载文件；Kubernetes 能启动 Pod，也不应默认获得整个 warehouse。安全必须贯穿身份、网络、Catalog、存储、计算和日志。

## 1. 数据分类

建立公开、内部、机密、受限等等级，标记 PII、账号、财务、凭据和训练敏感数据。每类定义访问审批、加密、脱敏、保留、地域和审计。标签应随血缘传播，派生表不能因换表名降低等级。

## 2. 身份与最小权限

人和 workload 使用独立身份，禁止共享长期 access key。统一身份联合和短期凭据；按 namespace/table/column/row 与对象前缀最小授权。管理面、读、写、maintenance、删除分离职责。

ServiceAccount/RBAC 只管理 Kubernetes 对象；对象存储 IAM/Ceph 用户管理数据字节；Catalog策略管理表语义。三层都要收紧。

## 3. 加密

传输使用 TLS/mTLS，静态存储使用服务端/磁盘加密，敏感字段可额外 tokenization。密钥在 KMS/HSM 管理，轮换和吊销演练；密钥不可写配置仓库、镜像、SQL、日志和指标标签。

加密不替代权限：有解密权限的错误查询仍会泄漏。

## 4. 脱敏

- 静态脱敏：生成不可逆测试/分析副本；
- 动态脱敏：查询时按角色遮罩；
- Tokenization：映射为令牌，映射服务单独保护；
- 聚合/差分等：减少个体暴露，需明确攻击模型。

Hash 手机号并不一定匿名，低熵空间可枚举。Salt/HMAC和密钥治理更可靠，但是否满足法规由合规评估。

## 5. 多租户

权限隔离之外还需资源隔离：队列、quota、并发、扫描字节、内存、Kafka quota、对象请求和成本归属。一个租户补数不应拖垮实时任务。关键租户可使用独立故障域/集群。

## 6. 生命周期与删除

定义 hot/warm/cold、在线/归档和删除时间。表 snapshot、备份、Kafka retention、缓存、训练 shards、日志和下游 OLAP 都可能保留副本。“删除表当前行”不等于完成数据主体删除。

删除流程：定位血缘副本 → 冻结新传播 → 表逻辑删除 → 过期合法 snapshots → 对象/备份按策略删除 → 缓存失效 → 记录不可篡改审计与例外。

## 7. 审计与告警

记录谁在何时以什么身份访问哪个 dataset/列、执行什么操作、结果/字节量和审批单。审计日志本身包含敏感信息，要防篡改和限权。告警异常大扫描、跨域访问、连续拒绝、密钥使用异常和批量下载。

## 8. 威胁演练

测试过期账号、被盗 workload token、绕过 Catalog直读对象、日志泄密、跨租户查询和误删。验证拒绝、告警、吊销、影响范围、恢复与审计证据。只在授权隔离环境执行。

## 9. 掌握验收

- 画出身份到 Catalog、存储和计算的权限链；
- 解释为什么 RBAC 不能替代对象 IAM；
- 为 PII 选择脱敏/tokenization 并说明限制；
- 同时设计访问与资源多租户隔离；
- 追踪 snapshot/备份/缓存完成可证明删除。
