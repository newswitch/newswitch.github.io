# 数据系统学习地图

数据系统解决的不是同一个问题。关系数据库保存事务事实，缓存降低访问延迟，消息系统传播变化，搜索和向量数据库提供不同形式的检索，OLAP 与大数据平台承担规模化分析和计算。学习时先理解每类系统的职责和数据一致性边界，再深入具体产品。

## 2. 一条数据如何经过不同系统

```text
业务请求
  │
  ├─ 同步事务 ───────────────→ MySQL / PostgreSQL
  │                               │
  ├─ 低延迟读取 ←────────────── Redis
  │                               │
  └─ Binlog / WAL ─→ Debezium ─→ Kafka ─┐
      Transactional Outbox ──────────────┤
                   业务消息 ─→ RocketMQ / RabbitMQ
                                         │
              Airflow按数据区间编排批任务│
                                  │
                  ┌───────────────┼────────────────┐
                  ▼               ▼                ▼
           Elasticsearch       Milvus      ClickHouse / 数据湖
             全文搜索          向量检索       分析与离线计算
```

关系数据库通常保存权威事务状态。Redis、Elasticsearch、Milvus 和分析系统多为可以重建的派生视图，消息系统则把源端变化可靠地传播给下游。Kafka/RocketMQ 更强调分区日志、保留与重放，RabbitMQ 更强调 Exchange 路由、队列投递和灵活拓扑；选择时要先明确是否需要长期重放、路由复杂度和消费模型。系统设计还必须明确谁是事实源、允许多大延迟、重复事件如何幂等处理，以及派生数据损坏后怎样重建。

## 3. 分类边界

- MySQL/PostgreSQL 保存事务事实，所以属于关系数据库，不属于大数据工程。
- Redis 的主问题是低延迟内存访问、缓存与临时状态，所以归入缓存。
- Kafka、RocketMQ 与 RabbitMQ 负责事件传输和异步解耦，所以归入消息与事件；三者在日志保留、路由模型和消费语义上各有侧重。
- Debezium 负责把数据库事务日志转换成可恢复的 CDC 事件，Offset 和 Schema History 是其运行状态，所以归入数据集成。
- Airflow 负责任务依赖、数据区间、补数和执行状态，不执行持续流计算，所以归入工作流调度。
- Elasticsearch 面向倒排、全文与混合搜索；Milvus 面向大规模向量检索，两者的数据模型和索引目标不同。
- ClickHouse、Trino、Doris 面向列式聚合、MPP 和交互式分析，但存储计算关系与适用场景并不完全相同。
- Hadoop、Spark、Flink、Iceberg、Airflow 与数据治理共同构成大数据工程主线。

一个组件可能参与多条链路，但核心职责仍要明确。例如 Kafka 经常出现在大数据平台中，它首先解决的仍是事件日志、缓冲、顺序、重放和消费者解耦问题。

## 4. 推荐学习顺序

1. 先学 MySQL 或 PostgreSQL，建立表、索引、事务、锁、日志和恢复基础；
2. 再学 Redis，理解缓存模式、数据一致性、穿透/击穿/雪崩和持久化边界；
3. 学习 Kafka/RocketMQ 的分区日志模型，再学习 RabbitMQ 的 Exchange、Binding 与 Queue 路由模型，掌握投递语义、幂等和消息积压；
4. 根据业务进入 Elasticsearch 或 Milvus，理解文本检索与向量检索的差异；
5. 学习 ClickHouse、Trino、Spark 和 Flink，建立批处理、流处理和 OLAP 模型；
6. 学习 Debezium，把数据库 Binlog/WAL 与 Kafka、Schema 演进和下游幂等串起来；
7. 学习 Airflow，掌握数据区间、补数、Executor、Metadata DB 和批处理生产运维；
8. 最后串联缓存更新、搜索索引、实时数仓和数据湖治理。

单项产品掌握后，再阅读[数据库、缓存、消息、搜索、控制面与网关学习地图](../learning/02-数据库缓存消息搜索控制面与网关学习地图.md)，理解一次业务写入怎样从网关进入 MySQL/PostgreSQL，经消息系统传播，再构建 Redis、Elasticsearch、ClickHouse 或 Milvus 派生视图。
