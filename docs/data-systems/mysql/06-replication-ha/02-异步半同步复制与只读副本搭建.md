# 异步复制、半同步复制与只读副本搭建

复制的目标不是看到两个线程为 `Yes`，而是得到一个来源明确、可追赶、受保护、可监控且经过数据验证的副本。

## 1. 模式与承诺

异步复制：源提交不等待副本。延迟低，但源突然丢失时可能有尚未传出的已提交事务。

半同步复制：源在返回提交前等待所需数量副本确认已接收并写入日志；确认不等于事务已在副本执行。网络 RTT 和副本 I/O 会进入提交路径，超时还可能退化，必须监控当前是否真的处于半同步状态。

半同步不是跨地域强同步，也不消除 failover 数据选择问题。

## 2. 搭建前设计

```text
唯一 server_id/server_uuid
版本兼容
GTID 与 binlog 策略
复制账户最小权限 + TLS
网络和 DNS
一致性备份/Clone 来源
副本用途：HA/读取/备份/延迟副本
容量与保留窗口
```

## 3. 从一致性种子开始

推荐流程：

```text
选择健康源或副本
→ 创建一致性物理/逻辑备份或 Clone
→ 保存 GTID/位点元数据
→ 恢复到目标
→ 配置复制通道
→ 启动并追赶
→ 数据与负载验收
```

GTID 自动定位示意：

```sql
CHANGE REPLICATION SOURCE TO
  SOURCE_HOST='db-source.internal',
  SOURCE_PORT=3306,
  SOURCE_USER='repl',
  SOURCE_PASSWORD='REDACTED',
  SOURCE_AUTO_POSITION=1,
  SOURCE_SSL=1;

START REPLICA;
SHOW REPLICA STATUS\G
```

密码不要进入工单、历史和代码；使用密钥管理与轮换。精确选项应按目标版本官方文档和组织自动化执行。

## 4. 只读保护

```sql
SHOW VARIABLES WHERE Variable_name IN ('read_only','super_read_only');
```

`read_only` 不是绝对安全边界，具有高权限的会话和复制线程存在特殊行为。副本还需要应用账户最小权限、网络隔离和路由层禁止写入。定期检查 errant transaction。

## 5. 读写分离的一致性

写完立刻读副本可能读不到：

```text
write commit at source
→ response
→ replica receive/apply later
→ read routed too early
```

方案按业务选择：写后粘主、携带 GTID 并等待副本追到、会话一致性路由、或接受明确的最大陈旧时间。不要把所有 SELECT 无条件发副本。

## 6. 半同步运行检查

确认插件/组件、源和副本开关、等待副本数、超时、ACK 状态和 fallback 次数。具体变量随实现版本变化，以 `SHOW PLUGINS`、目标文档和状态变量为准。

测试：停止半同步副本、制造网络延迟、观察提交延迟和退化；恢复后确认自动回到预期模式。没有演练就不知道故障时实际承诺。

## 7. 上线验收

```text
[ ] receiver/applier 健康，无 last error
[ ] GTID 集合与数据抽样一致
[ ] 复制账户 TLS 和最小权限
[ ] 副本只读与路由保护
[ ] 峰值写入下可追赶
[ ] 大事务/DDL/重启测试
[ ] 监控、告警、备份和 failover 演练
```
