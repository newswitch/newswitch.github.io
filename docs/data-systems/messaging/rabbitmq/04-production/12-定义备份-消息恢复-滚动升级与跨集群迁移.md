# 定义备份、消息恢复、滚动升级与跨集群迁移

导出 Definitions 只能保存用户、VHost、Exchange、Queue、Binding、Policy 等声明，不能等同于消息备份。RabbitMQ 的恢复设计应先回答 RPO/RTO，再选择应用重放、队列副本或跨集群复制。

## 1. 三类需要保护的状态

| 状态 | 保护方式 |
| --- | --- |
| 配置与拓扑 | Definitions、IaC、Secret 管理 |
| 消息数据 | Quorum/Stream 副本、上游事实源重放、跨集群链路 |
| 消费进度与业务副作用 | 应用数据库、幂等表、Stream Offset |

直接复制运行中的节点数据目录不是通用在线备份方案；文件可能不一致，且恢复时受节点身份、Cookie、版本和集群状态约束。

## 2. 恢复设计

关键业务优先采用“事务事实源 + Outbox + 可重放发布”，这样即使 Broker 集群不可恢复，也能从事实源重新生成事件。无法重建的消息需要明确副本、跨站 RPO 和演练方法。

Definitions 导出后应加密保存并在隔离环境导入验证。用户密码哈希、证书和外部 Secret 不应无控制地进入仓库。

## 3. 滚动升级

1. 阅读目标版本兼容与 Feature Flag 要求；
2. 备份 Definitions、Policy 和版本信息；
3. 检查集群健康、磁盘空间和 Quorum Critical；
4. 先升级一个非关键节点；
5. 等待节点加入、副本追平和指标稳定；
6. 逐节点继续，最后启用不可逆特性；
7. 在回滚窗口内不要改变不兼容数据格式。

升级前必须验证客户端库和 Erlang 版本兼容。跨大版本按官方允许的跳跃路径进行，不能默认任意跨级滚动升级。

## 4. 跨集群迁移

Shovel 适合明确源/目标的消息搬运，Federation 适合松耦合的跨集群转发，应用双写/重放则能提供最清晰的业务校验。迁移步骤：

```text
部署目标集群
→ 导入并核对Definitions
→ 建立复制/双写
→ 比较发布、消费和积压
→ 灰度消费者
→ 切换生产者
→ 排空旧集群
→ 保留回滚窗口
```

要验证重复、顺序、TTL、死信和 Header 在迁移链路中的行为，不能只比较队列条数。

## 5. 灾难演练

在隔离环境模拟集群完全丢失：从 IaC 创建新集群、恢复身份和 TLS、导入 Definitions、重放消息、启动消费者，并以业务数据库核对完整性。最终记录实际 RPO/RTO；没有演练过的备份只是一个未经验证的文件。

参考：[RabbitMQ Backup and Restore](https://www.rabbitmq.com/docs/backup)、[Blue-Green Deployment](https://www.rabbitmq.com/docs/blue-green-upgrade)。
