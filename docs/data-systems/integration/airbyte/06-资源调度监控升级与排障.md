# Airbyte 资源调度、监控、升级与排障

Airbyte 的运维对象不仅是常驻平台服务，还包括临时同步工作负载、源端限流、目标提交与恢复状态。本篇依据 **2026-11-14 文档**分析方法；组件名、日志位置和资源字段以实际平台与 Chart 为准。

## 1. 先建立任务关联

记录 Connection、Job、Attempt、Workload、Pod、Source/Destination 镜像版本及开始时间。UI 中一个失败状态可能经历多次 Attempt；只看最后一次错误容易遗漏前一次已写入的数据。

| 阶段 | 典型证据 | 优先定位 |
| --- | --- | --- |
| 未创建 Workload | 平台调度与队列日志 | 任务计划、控制服务、授权 |
| Pod Pending | Events、节点资源和约束 | 配额、调度、PVC、节点选择 |
| ImagePullBackOff | 具体容器与拉取事件 | tag、仓库认证、网络、架构 |
| 启动后 OOM | Last State、退出原因、容器峰值 | 源/目标/中间容器与批次 |
| 有读无写 | 目标日志、提交耗时、背压 | 目标认证、锁、限流、落盘 |
| 重试后重复 | State 与提交时间线 | 目标模式与安全确认点 |

## 2. Kubernetes 只读检查

先确认 kube-context 与命名空间，替换实际 Pod 名：

```bash
kubectl config current-context
kubectl get pods -n airbyte -o wide
kubectl describe pod "$AIRBYTE_POD" -n airbyte
kubectl logs "$AIRBYTE_POD" -n airbyte --all-containers --tail=200
kubectl get events -n airbyte --sort-by=.metadata.creationTimestamp
```

abctl 的本地命名空间与 kubeconfig 不一定是这里的 `airbyte`，应先从 `abctl local status` 和工具配置确认，避免查询或操作错集群。读取日志也可能接触密钥和业务内容，导出前脱敏。

## 3. 性能先分源、通路与目标

源 API 429、分页串行、数据库扫描、宽行序列化和目标 merge 都会限制吞吐。Socket 模式只能改变其中的数据传输路径，不会消除源端配额或目标锁。

至少观察 records/bytes、源速率、目标提交速率、已确认状态年龄、每流耗时、错误/拒绝数和每容器 CPU/内存。指标名和可用性依版本/授权变化，不应在没有实际 exporter 的环境中写一组猜测的 PromQL。

增量计划每 15 分钟触发一次，如果每次稳定运行需 20 分钟，就已没有足够余量。应检查任务重叠/排队策略与最大同步时长，缩短输入范围、调整并发或提高瓶颈能力，而不只是改成每 5 分钟一次。

## 4. 用同一单位算容量

假设单个同步实际持续需要 1 CPU 的源、2 CPU 的目标与 1 CPU 的中间处理，再并行跑五个同类任务，则仅这些任务的 CPU 需求示例就约 20 CPU，尚未计常驻服务、init、系统与安全余量。真实值必须取具体容器配置和测量，不能把示例当默认 requests。

内存需要分容器看峰值，尤其是批次、解压、类型转换和目标合并。一个容器 OOM 不代表给 Web 服务加内存有用。对象存储请求数、网络出口、源端日志和数据库连接也需要纳入容量。

## 5. 升级与恢复要分层

分别记录 Chart、平台镜像、Connector、协议、数据库和对象存储配置。连接器升级可能改变 schema、主键、类型和 State 格式；平台升级可能迁移数据库，旧版本未必能直接读取迁移后的状态。

先备份并验证恢复所需资产，在隔离环境测试已确认状态恢复、更新删除、错误记录和重复。Refresh/Reset 的覆盖范围先核对，不能把删除状态当作普通重启。回退还要考虑新版本已写目标数据与源日志保留，不只是保留一个旧镜像。

## 6. 练习与答案

**问题一：同步 OOM，为什么不先给平台 Web Pod 加内存？**

答案：内存瓶颈可能发生在临时 Workload 的源、目标或中间容器，应先确认实际 OOM 容器及其峰值和批次。

**问题二：Pending 是否证明源数据库无法连接？**

答案：不能。连接器可能尚未启动，应先看调度、资源、镜像、PVC 与 Events。

**问题三：每次同步需 20 分钟，改为每 5 分钟触发能降低延迟吗？**

答案：不必然，可能只增加排队或争用。先解决任务处理能力与计划窗口不匹配的问题。

**问题四：平台镜像可回退，是否意味数据库迁移和 State 都可逆？**

答案：不是。需要检查数据迁移与状态格式兼容，并验证备份恢复、目标数据与日志衔接。
