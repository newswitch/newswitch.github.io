# DataX 学习路线

DataX 把一次异构数据同步拆成读取、传输和写入三个部分。学会它，不只是能够修改 JSON 中的库名和表名，还要能回答：读取的是哪个时间范围的数据，多个并发查询是否共享快照，目标已提交一半时能否重跑，以及如何证明目标没有漏数或改错字段。

本系列以开源 `alibaba/DataX` 的独立进程运行方式为主，不把商业 DataWorks 的托管调度、运维界面或连接器能力当作开源包自带功能。源码基线固定为 **2026-11-12 核对的提交 `80ec23d5c5328eb90ca364d2749e92dfaf44541e`**；它的提交日期为 2026-07-07，不是另一个名为“2026 版”的产品版本。

## 1. 先知道 DataX 放在哪里

| 需求 | DataX 的位置 | 还需要谁配合 |
|---|---|---|
| 定期把业务表复制到分析库 | 批量读取与写入 | 调度、数据区间、目标表和校验 |
| 把冻结的历史文件导入数据库 | 文件解析与批量加载 | 文件清单、类型契约和发布机制 |
| 按更新时间抽取变化行 | 执行带筛选条件的查询 | 外部水位、补数与幂等 |
| 持续捕获更新和硬删除 | 不是本系列 DataX 任务的职责 | Binlog/WAL CDC，例如 Debezium |
| 整库零丢失迁移 | 可承担其中的批量阶段 | 一致性快照、日志衔接、DDL、割接与回滚 |

先读[定位与边界](./01-DataX定位与批量同步边界.md)，再与 [Debezium](../debezium/00-Debezium从零到精通学习路线.md)、[Canal 与 Maxwell](../canal-maxwell/00-Canal与Maxwell定位和学习路线.md)对照。它们不是只换一下名称就能互相替代的工具。

## 5. 配套示例怎样使用

仓库的 `examples/datax/sync-lab/` 提供四行订单数据、文件复制与 MySQL 任务模板、配置渲染器和标准库校验程序。示例把金额保留为十进制文本，把业务时间明确约定为 UTC，便于暴露精度和时区问题。

在仓库根目录执行以下检查，只运行本地 Python，不连接数据库：

```bash
python examples/datax/sync-lab/sync_contract.py summarize examples/datax/sync-lab/fixtures/orders.csv
python -m unittest discover -s examples/datax/sync-lab -p "test_*.py" -v
```

实际执行 DataX 需要另行准备审核过的运行包、JRE、Python 和目标插件；数据库示例还需要匹配的驱动、权限与 TLS 信任链。配置语法检查、离线数据校验和目标环境集成测试是三件不同的事。

## 6. 学习顺序与验收

先在本地文件间完成一次可核对的复制，再接入只读测试库，最后加入 staging 表、失败重跑和调度。不要一开始就把生产全库作为实验输入。

学习完成时，应能独立解释一条记录经过哪些组件；针对给定数据量估算窗口；辨认任务结束前哪些数据已经提交；对重复、迟到、删除、精度和发布失败分别给出处理办法。涉及现代数据库兼容性时，以实际发行物和对应驱动的测试结果为准。

## 7. 练习与答案

**问题一：为什么 DataX 每分钟执行一次，也不能直接叫 Binlog CDC？**

答案：运行频率没有改变读取方式。普通查询只看到执行时满足条件的行，不天然拥有事务日志位置、删除事件和日志顺序；这些能力必须由另一条机制提供。

**问题二：JSON 能被解析，是否意味着任务可上线？**

答案：不能。插件加载、JDBC/TLS、字段语义、并发负载、重跑结果和发布一致性都还没有被证明。

**问题三：一共读到四行，目标也有四行，为什么还要核对字段？**

答案：丢一行再重复一行，行数仍相等；金额精度、客户编号前导零或 NULL 被改写也不改变行数。

**问题四：哪个模块负责保存上一次成功抽取的时间？**

答案：本系列由外部调度与控制状态保存，DataX 只执行本次确定的查询。推进状态必须发生在写入、校验和发布完成以后。
