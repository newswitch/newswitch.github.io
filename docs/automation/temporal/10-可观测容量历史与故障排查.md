# Temporal 可观测、容量、History 与故障排查

## 1. 延迟拆分

```text
Client 到 Service
+ Workflow Task Schedule-to-Start/执行
+ Activity Task Schedule-to-Start
+ Activity 执行/重试
+ Timer/外部等待/人工审批
+ 可见性与查询
```

Workflow 总耗时长可能是合法等待，不等于平台慢。

## 2. 指标

- Workflow 启动、完成、失败、超时和端到端时长；
- Workflow/Activity Task Schedule-to-Start；
- Worker Poller、槽位、CPU/内存、Sticky Cache；
- Activity Attempt、重试、Heartbeat Timeout 和下游错误；
- Event History 长度/大小和 Continue-As-New；
- Service 请求延迟、Persistence、可见性和配额；
- 按 Namespace/Task Queue 的到达率与积压。

## 3. “卡住”故障树

```text
Workflow 无推进
├── 等待 Timer/Signal/Update/Child（可能正常）
├── Workflow Task 无 Worker/代码未注册
├── Activity Task 无 Worker/队列名错误
├── Worker容量不足/频繁崩溃
├── Activity重试/下游不可用
├── 非确定性/反序列化/Codec错误
├── History过大/Workflow Task超时
└── Service/Persistence/可见性故障
```

## 4. History 分析

从最后一个成功 Event 向后看：已调度什么、是否已开始、Attempt、Timeout、Failure Type 和下一步等待。不要只看 Worker 最后一行日志；Worker 重启后日志可能分散。

## 5. 容量模型

```text
Workflow 启动率
× 每个 Workflow Task/Activity 数
× 平均 History Event/Payload
+ 重试与峰值
```

分开计算 Workflow Task、各 Activity 队列、下游配额和可见性查询。压测加入真实重试、Signal、Codec 和日志。

## 6. 告警与 Runbook

告警关注 Schedule-to-Start、无 Poller、非确定性、Activity 重试风暴、History 接近限制和配额拒绝。Runbook 先停止新流量/扩容/修复 Worker，再决定 Terminate、Reset、补偿或人工处理；不要默认重启 Service。
