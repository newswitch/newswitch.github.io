# SOPS / External Secrets 可观测、容量与故障排查

## 1. SOPS 故障树

```text
无法解密
├── 未命中/错误 Creation Rule
├── KMS IAM、age/PGP 私钥不可用
├── 网络、TLS、区域或 KMS 配额
├── Metadata/MAC 被破坏
├── 工具版本/能力不兼容
└── 接收者更新或轮换不完整
```

记录文件路径、Commit、SOPS 版本、接收者 ID 和脱敏错误；不要为排障输出明文或私钥。

## 2. ESO 故障树

```text
应用拿不到新值
├── ExternalSecret Spec/Store 引用
├── Controller RBAC/Scope/队列
├── Provider 认证、权限、网络、配额
├── 远端 Key/Version/Property
├── 模板/解码/目标 Secret 冲突
├── kubelet Volume/环境变量语义
└── 应用重载、连接池或旧凭据撤销
```

## 3. 指标

- Reconcile 成功率、时长、队列深度和重试；
- Ready/NotReady 对象数、距上次成功刷新时间；
- Provider 请求错误、429、延迟和配额；
- 目标 Secret 更新数量与异常突增；
- 后端版本到应用加载版本的端到端延迟；
- KMS 解密调用量、拒绝和异常身份。

避免用 Secret 名称/远端 Key 作为无限高基数标签，详细定位放在受控日志。

## 4. 容量模型

```text
ExternalSecret 数量 ÷ 刷新间隔
× 每次远端请求数
+ 错误重试
+ 批量轮换峰值
```

同时考虑 Controller Worker、API Server 写入、etcd、Provider 限流和应用重启容量。分批轮换并加入抖动。

## 5. 恢复

备份 ExternalSecret/Store 声明、后端数据/版本、IAM/Policy、KMS Key 和配置。恢复在隔离环境验证：能认证、能读正确版本、能创建目标 Secret、应用能重载。仅备份 Kubernetes Secret 不是完整恢复方案。
