# SOPS KMS、age、PGP 与 Key Group

## 1. 接收者类型

| 类型 | 适合 | 运营重点 |
| --- | --- | --- |
| 云 KMS | 云上团队与 CI 工作负载身份 | IAM、区域、删除保护、审计 |
| age | 轻量个人/离线/文件密钥 | 私钥文件权限、备份和轮换 |
| PGP | 已有成熟 PGP 基础设施 | Key 生命周期和实现复杂度 |
| Key Group/阈值 | 多方或多信任域授权 | 阈值、恢复和人员变更演练 |

现代新项目通常优先云 KMS 或 age；选择取决于身份、审计、离线和恢复要求，而不是命令长度。

## 2. `.sops.yaml`

Creation Rule 按路径/文件选择接收者。更具体的生产规则应优先匹配，避免测试密钥加密生产文件。配置本身进入 Git 评审，CI 对代表性路径验证实际接收者集合。

## 3. 人员与自动化分离

开发者只解密自己负责的开发路径；CI 身份只解密特定仓库/环境；生产解密由受保护 Environment 或 GitOps 控制器身份完成。不要共享一个 age 私钥或云 KMS 管理员身份。

## 4. Key Group 与阈值

Key Group 可把接收者按组组织，并要求达到多个组的阈值才能恢复数据密钥，适合职责分离。复杂度会增加日常编辑和灾备要求，采用前必须演练成员离职、密钥失效和异地恢复。

## 5. 轮换概念

- 更新接收者：重新包装现有或新数据密钥，使新增/移除身份生效。
- 轮换数据密钥：生成新 DEK 并重新加密值。
- 轮换业务 Secret：在目标系统生成新密码/Token。

三者不是同一动作。移除 SOPS 接收者也不能撤回其过去已读取的明文，因此高风险事件还要轮换业务 Secret。

## 6. 灾难恢复

至少保留一个受控恢复路径，并定期在隔离环境解密测试样本。云 KMS Key 启用删除保护和变更审批；age/PGP 私钥采用加密、分离和异地备份。
