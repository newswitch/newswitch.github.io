# SOPS 信封加密、Metadata 与 MAC

## 1. 信封加密

```text
随机数据密钥（DEK）加密文件值
→ KMS/age/PGP 等主密钥加密 DEK
→ 密文值 + 加密后的 DEK + Metadata 写入同一文件
```

拥有任一授权接收者私钥/解密权限的人可恢复 DEK，再解密值。增加多个接收者不会重复加密所有业务数据。

## 2. 为什么仍能 Review

SOPS 通常保留 YAML/JSON 的键和结构，只加密值，因此能看到哪些配置项变化。但键名、层级、注释、文件路径和接收者 Metadata 仍可能泄漏业务信息，不能把密文仓库视为公开数据。

## 3. Metadata

Metadata 记录加密方法、接收者包装后的数据密钥、创建/修改信息、版本和 MAC 等。手工删除或复制 Metadata 会让文件无法解密或完整性校验失败。

## 4. MAC 的意义

MAC 用于发现密文/结构被未经授权地删除、交换或修改。仅成功解密某个字段不代表整个文件可信；正常工具链应验证完整性，不用跳过 MAC 的方式绕过错误。

## 5. 选择性加密

可按键或正则选择加密范围，但规则错误可能把新字段明文提交。生产仓库优先采用“默认加密值，只显式排除确定非敏感字段”，并用 CI 扫描明文模式和 SOPS Metadata。

## 6. Git 历史

若明文曾提交，后来加密不能消除历史泄漏。立即轮换 Secret，限制仓库访问，并按风险决定是否重写历史。历史清理不能替代凭据撤销。

## 7. 恢复边界

密文文件和解密主密钥必须分离备份。只备份 Git 而 KMS Key 被删除，数据不可恢复；只保留主密钥而丢失密文也没有业务数据。
