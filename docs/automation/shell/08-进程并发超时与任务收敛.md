# Shell 进程、并发、超时与任务收敛

在命令后添加 `&` 只是启动后台进程，不代表实现了可靠并发。生产脚本还要限制并发、保存 PID、Wait 所有任务、汇总失败、响应信号并避免孤儿进程。

## 1. 后台任务和 Wait

```bash
run_one node01 &
pid=$!

if wait "$pid"; then
  printf 'success\n'
else
  rc=$?
  printf 'failed rc=%d\n' "$rc" >&2
fi
```

如果不 Wait，父脚本可能先返回成功，CI 以为任务结束，而后台修改仍在继续。

## 2. 有界并发

简单 Worker Pool 可以使用固定数量 Worker 从输入读取任务。核心要求：

- 并发数由参数控制且有上限。
- 每个任务有独立结果文件或安全通道。
- 主进程收集所有 Worker 状态。
- 收到停止信号后不再领取新任务。
- 失败阈值触发停止扩散。

对于简单、参数边界清晰的命令，可使用 NUL 分隔配合 `xargs -0 -P`：

```bash
find "$root" -type f -print0 |
  xargs -0 -r -P 4 -n 1 checksum_one
```

函数是否能被子 Shell 找到、退出状态怎样聚合以及不同平台的 `xargs` 参数差异，都必须验证。复杂任务应使用 Python、Ansible 或工作流引擎。

## 3. 超时

GNU Coreutils `timeout` 示例：

```bash
timeout --signal=TERM --kill-after=5s 30s run_probe "$target"
rc=$?
```

需要区分：命令自身失败、超时退出、外部信号和 `timeout` 启动失败。具体退出码以当前版本帮助为准，并在脚本中映射为稳定公共状态。

超时不是取消完成。子进程可能再次派生进程或忽略信号，必须验证进程组和清理策略。

## 4. 收敛所有任务结果

```bash
pids=()
names=()

for target in "${targets[@]}"; do
  run_one "$target" &
  pids+=("$!")
  names+=("$target")
done

failed=0
for i in "${!pids[@]}"; do
  if ! wait "${pids[$i]}"; then
    printf 'target=%q status=failed\n' "${names[$i]}" >&2
    ((failed += 1))
  fi
done

((failed == 0)) || exit 6
```

示例没有限制并发，适合解释 Wait，不适合无限目标。生产实现要使用固定 Worker 或平台级并发限制。

## 5. 失败策略

| 策略 | 场景 |
| --- | --- |
| Fail Fast | 后续执行会扩大风险或前置依赖失败 |
| Continue and Report | 只读巡检、各目标独立 |
| Failure Threshold | 批量变更，少量失败即停止新批次 |
| Retry Selected | 只重试明确的暂时错误 |

重试必须具备次数、退避、抖动和幂等前提。权限错误、输入错误和配置校验失败通常不应重试。

## 6. Shell 并发的升级边界

出现以下需求时迁移：

- 动态优先级和复杂依赖图。
- 分布式 Worker 和持久化队列。
- Exactly-once 业务语义。
- 大量结构化结果聚合。
- 跨重启断点续跑。
- 多租户配额和审批。

Shell 适合受控的小规模并发，不应自制完整调度平台。
