# Shell 临时文件、文件锁与原子更新

直接 `echo > /etc/app.conf` 会先截断文件；进程崩溃、磁盘满或两个实例并发时，服务可能读到空文件或半成品。安全发布需要候选文件、校验、权限、原子切换和回退。

## 1. 使用 mktemp

```bash
tmpdir=$(mktemp -d) || exit 3
readonly tmpdir
candidate=$tmpdir/app.conf
```

不要根据 PID 或时间自行拼接 `/tmp/name.$$`，攻击者可能预先创建路径或符号链接。设置合理 `umask`：

```bash
umask 077
```

临时文件是否包含 Secret 决定权限、存储位置和清理要求。

## 2. 清理目标验证

```bash
cleanup() {
  local rc=$?
  if [[ -n ${tmpdir-} && -d $tmpdir && $tmpdir == /tmp/tmp.* ]]; then
    rm -rf -- "$tmpdir"
  fi
  return "$rc"
}
trap cleanup EXIT
```

实际项目应保存“由本次运行成功创建”的标志，并尽量用明确路径而非宽松模式判断。清理函数不能对空变量、`/`、工作区根或未解析路径执行递归操作。

## 3. 使用文件锁防止重复实例

在支持 `flock` 的 Linux 环境：

```bash
exec 9>/run/lock/app-config.lock
if ! flock -n 9; then
  printf 'another deployment is running\n' >&2
  exit 7
fi
```

文件描述符保持打开期间锁有效。网络文件系统、容器和不同主机之间的锁语义可能不同；分布式任务需要数据库、etcd、Consul 或工作流平台的租约机制。

锁只解决互斥，不解决进程崩溃后的业务状态恢复。

## 4. 渲染和校验候选配置

```bash
render_config >"$candidate"
chmod 0640 "$candidate"
chown root:app "$candidate"
app --check-config "$candidate"
```

在覆盖正式文件前完成：

- 内容生成成功。
- 语法和语义校验成功。
- Owner、Group、Mode 和安全上下文正确。
- 文件不为空且大小合理。
- 差异符合预期。

## 5. 原子 Rename 的前提

同一文件系统内，把完整候选文件 Rename 到目标通常可避免读到半文件。候选文件应在目标目录创建：

```bash
target=/etc/app/app.conf
target_dir=$(dirname -- "$target")
candidate=$(mktemp --tmpdir="$target_dir" '.app.conf.XXXXXX')
```

验证后：

```bash
mv -f -- "$candidate" "$target"
```

边界：

- 跨文件系统移动不具备相同原子性。
- Rename 不会自动刷新服务内存配置。
- 文件的 SELinux Label、ACL、Owner 和 Mode 仍需验证。
- 多文件配置无法靠单次 Rename 获得整体事务。

多文件场景可以发布新版本目录，再原子切换经过验证的符号链接，但必须验证程序如何解析链接和打开文件。

## 6. 备份与回退

```bash
backup_dir=/var/lib/app-config/backups
install -d -m 0700 "$backup_dir"
backup=$backup_dir/app.conf.$(date -u +%Y%m%dT%H%M%SZ)
cp --preserve=mode,ownership,timestamps -- "$target" "$backup"
```

备份文件可能包含 Secret，需要权限、保留期限和加密策略。回退前同样校验备份，并在切换后执行服务健康验证。

## 7. 路径安全

```bash
target=$(readlink -f -- "$requested_target") || exit 2
case $target in
  /etc/app/*) ;;
  *) printf 'target outside allowed root\n' >&2; exit 2 ;;
esac
```

路径解析和允许范围必须在任何写入或删除之前完成。不要让用户输入直接成为递归删除、Chown 或覆盖目标。
