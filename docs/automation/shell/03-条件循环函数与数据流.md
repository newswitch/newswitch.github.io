# Shell 条件、循环、函数与数据流

Shell 中 `0` 表示成功/真，非零表示失败/假。函数既可以输出数据，又会返回退出状态；如果不加约束，两者很容易混在一起。

## 1. 条件测试

POSIX 风格：

```bash
if [ -r "$config" ]; then
  printf 'readable\n'
fi
```

Bash 中优先使用 `[[ ... ]]` 组合字符串和模式条件：

```bash
if [[ -r $config && $environment == prod* ]]; then
  printf 'matched\n'
fi
```

`[[ ]]` 内的展开规则与普通命令不同，但右侧模式和正则仍要根据是否需要字面含义谨慎引用。

整数判断可以使用：

```bash
if (( retries >= 1 && retries <= 10 )); then
  :
fi
```

## 2. Case 适合有限状态

```bash
case $action in
  plan)  run_plan ;;
  apply) run_apply ;;
  *)
    printf 'unsupported action: %s\n' "$action" >&2
    return 2
    ;;
esac
```

当输入来自用户或平台时，先白名单分支，再调用固定函数，不把输入拼接为命令。

## 3. 循环

遍历数组：

```bash
hosts=(node01 node02 node03)
for host in "${hosts[@]}"; do
  probe_host "$host"
done
```

读取文件：

```bash
while IFS= read -r host || [[ -n $host ]]; do
  [[ -z $host || $host == \#* ]] && continue
  probe_host "$host"
done < hosts.txt
```

不要使用 `for line in $(cat file)`，它会丢失原始行边界并触发通配符展开。

## 4. 函数接口

```bash
is_healthy() {
  local endpoint=$1
  curl --fail --silent --show-error \
    --connect-timeout 2 --max-time 5 \
    "$endpoint" >/dev/null
}
```

函数约定：

- 参数从 `$1...` 接收并立即赋给有意义的局部变量。
- 数据结果写 stdout。
- 日志和诊断写 stderr。
- 用退出状态表达成功、业务不满足和执行错误。
- 避免修改未声明的全局变量。

调用：

```bash
if is_healthy "$endpoint"; then
  printf 'healthy\n'
else
  rc=$?
  printf 'health check failed rc=%d\n' "$rc" >&2
fi
```

## 5. 不要用输出代替状态

错误模式：函数打印 `true` 或 `false`，调用方再做字符串比较。更自然的 Shell 接口是退出状态：

```bash
has_command() {
  command -v "$1" >/dev/null 2>&1
}

if has_command jq; then
  :
fi
```

需要同时返回数据和状态时，命令替换接收 stdout，并单独检查退出状态。

## 6. 管道中的循环作用域

```bash
count=0
printf '%s\n' a b | while read -r _; do
  ((count += 1))
done
printf '%s\n' "$count"
```

许多 Bash 环境会让管道中的循环运行在子 Shell，循环后的 `count` 仍为原值。可以改为重定向或进程替换：

```bash
count=0
while read -r _; do
  ((count += 1))
done < <(printf '%s\n' a b)
```

## 7. 函数测试边界

把外部命令调用包在小函数中，使测试可以替换边界：

```bash
fetch_status() {
  curl --fail --silent --show-error "$1"
}

evaluate_status() {
  local body=$1
  [[ $body == ok ]]
}
```

这样业务判断不必每次都启动真实网络请求。
