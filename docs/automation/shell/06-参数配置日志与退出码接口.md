# Shell 参数、配置、日志与退出码接口

脚本一旦被 Cron、CI、Ansible 或其他程序调用，它的参数、输出和退出码就是公共接口。随意打印、交互询问或改变默认值都会破坏调用方。

## 1. 定义接口契约

至少写清楚：

```text
命令名称与版本
必需参数和可选参数
配置优先级
默认是否只读
stdout 数据格式
stderr 日志格式
退出码
超时与重试
是否允许交互
```

## 2. 短参数使用 getopts

```bash
usage() {
  cat <<'EOF'
Usage: baseline-check -e ENV [-n] [-v]
  -e ENV  target environment
  -n      dry run
  -v      verbose
EOF
}

environment=''
dry_run=false
verbose=false

while getopts ':e:nvh' option; do
  case $option in
    e) environment=$OPTARG ;;
    n) dry_run=true ;;
    v) verbose=true ;;
    h) usage; exit 0 ;;
    :) printf 'option -%s requires an argument\n' "$OPTARG" >&2; exit 2 ;;
    \?) printf 'unknown option: -%s\n' "$OPTARG" >&2; exit 2 ;;
  esac
done
shift "$((OPTIND - 1))"
```

`getopts` 主要处理短选项。需要长选项时可以使用严格的 `while/case` 解析器，或升级到更适合复杂 CLI 的语言。不要用 `eval` 重新解释参数。

## 3. 长参数解析

```bash
while (($#)); do
  case $1 in
    --environment)
      (($# >= 2)) || { printf 'missing value for %s\n' "$1" >&2; exit 2; }
      environment=$2
      shift 2
      ;;
    --dry-run)
      dry_run=true
      shift
      ;;
    --)
      shift
      break
      ;;
    -* )
      printf 'unknown option: %s\n' "$1" >&2
      exit 2
      ;;
    *) break ;;
  esac
done
```

参数解析后进行类型、枚举、路径和组合关系校验。

## 4. 配置优先级

建议明确：

```text
内置安全默认值
< 配置文件
< 环境变量
< CLI 参数
```

必需配置不应依靠危险默认值。例如生产环境和写模式必须显式选择：

```bash
: "${environment:?environment is required}"
case $environment in
  test|staging|production) ;;
  *) printf 'invalid environment\n' >&2; exit 2 ;;
esac
```

不要直接 `source` 不可信配置文件，因为 Source 等价于执行代码。简单配置应采用受限格式和显式解析；复杂配置使用 JSON/YAML 解析工具或 Python。

## 5. stdout 与 stderr

约定：

- stdout：调用方需要的数据。
- stderr：日志、进度和诊断。

```bash
log() {
  local level=$1
  shift
  printf '%s level=%s message=%q\n' \
    "$(date -u +'%Y-%m-%dT%H:%M:%SZ')" "$level" "$*" >&2
}

printf '%s\n' "$result"       # stdout
log info 'check completed'      # stderr
```

机器可读 JSON 应由能够正确转义的工具生成，不要用字符串拼接用户数据：

```bash
jq -n --arg host "$host" --arg status "$status" \
  '{host: $host, status: $status}'
```

## 6. Dry Run

Dry Run 应输出计划，而不是简单跳过所有操作：

```bash
run_change() {
  if [[ $dry_run == true ]]; then
    printf 'plan action=%q target=%q\n' "$1" "$2" >&2
    return 0
  fi
  "$@"
}
```

通用包装器只能用于参数已经作为数组或独立参数传递的命令。涉及重定向、管道和复杂业务检查时，应为具体动作实现 Plan。

## 7. 退出码

稳定分类比透传任意外部状态更重要：

```bash
readonly RC_USAGE=2
readonly RC_DEPENDENCY=3
readonly RC_VALIDATION=4
readonly RC_EXTERNAL=5
readonly RC_PARTIAL=6
```

调用方可以据此决定：不重试、有限重试、需要人工介入或回滚。

## 8. 非交互要求

生产脚本默认不得等待 `read`、密码提示或确认输入。需要危险动作时使用显式参数、审批平台和目标摘要，而不是在无人值守环境中永久等待 TTY。
