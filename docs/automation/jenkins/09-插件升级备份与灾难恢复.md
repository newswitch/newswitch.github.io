# Jenkins 插件、升级、备份与灾难恢复

## 1. 插件治理

每个插件都是 Controller 供应链和兼容面。维护允许列表、版本、来源、依赖、Owner 和替代计划，删除长期不用插件前在克隆环境验证配置影响。

## 2. 升级

```text
备份与恢复演练
→ 克隆生产配置到测试 Controller
→ 升级 Java/Jenkins/插件中的一个合理批次
→ 核心 Pipeline 回归
→ 维护窗口升级
→ 观察与回滚
```

不要同时大幅升级运行时、核心、所有插件和 Agent 镜像。

## 3. 备份范围

- JENKINS_HOME 中配置、Job、构建元数据和密钥材料。
- JCasC、插件清单、Shared Library 和 Agent 镜像代码。
- 外部数据库/制品仓库按自身方式备份。
- 恢复所需加密 Key 和 Secret 存储。

Workspace 和 Cache 通常可重建，不作为核心备份。

## 4. 一致性

在线复制可能得到互不一致文件。使用受支持快照/停写策略并校验。备份加密、最小权限、异地和定期恢复测试。

## 5. DR

恢复新 Controller 时使用相同受支持版本，先隔离 Webhook/定时触发，验证身份、凭据、Job、插件和 Agent，再逐步恢复流量，防止重复部署。

Jenkins Controller 通常不应被简单当成可多副本 Active-Active 服务；根据所选部署方案设计明确 RTO/RPO。
