# Jenkins 并发、锁、超时、重试与可靠性

## 1. 并发

限制同一分支/环境并发，避免旧版本后发布覆盖新版本。构建可并行，生产环境发布通常需要串行和环境锁。

## 2. 锁

锁保护外部环境或稀缺设备，不只是 Executor。锁名称使用稳定环境 ID；人工审批不要无必要占用 Agent。

## 3. Timeout

为 Queue 等待、Stage、外部命令和整条 Pipeline 分别设预算。取消后确认子进程、Pod 和远端操作是否真正结束。

## 4. Retry

只重试明确临时错误，限定次数、退避和总时间。发布写操作先查询实际状态，不能因客户端超时盲重试。

## 5. 防旧构建

使用顺序门禁或里程碑思路阻止旧 Pipeline 越过新 Pipeline。目标系统也应验证期望版本，不能只靠 Jenkins 时间顺序。

## 6. Controller 重启

可恢复 Pipeline Step 与外部进程语义不同。重启演练覆盖 Queue、Agent、人工审批、上传制品和部署中状态。

## 7. 部分失败

矩阵任务保留逐项结果，最终区分 Unstable/Partial/Failed/Aborted/Unknown，不能用一个总体绿色掩盖漏测目标。
