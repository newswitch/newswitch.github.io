# Go 类型、接口、错误与包边界

## 1. 领域模型

```go
type Task struct {
	ID       string
	Target   string
	Deadline time.Time
}

type Result struct {
	TaskID   string
	State    string
	Duration time.Duration
	Err      error
}
```

外部 JSON 进入后先校验，再转换为领域对象。零值是否有效必须明确；Secret 不放入可被默认格式化的结构。

## 2. 接口由使用方定义

```go
type Prober interface {
	Probe(ctx context.Context, target string) (Result, error)
}
```

接口保持小而稳定，应用层依赖接口，HTTP/SSH/Kubernetes 包实现它。不要提前为每个结构体创建巨型接口。

## 3. 错误链

```go
var ErrUnauthorized = errors.New("unauthorized")

result, err := client.Query(ctx)
if err != nil {
	return Result{}, fmt.Errorf("query inventory: %w", err)
}
```

调用方用 `errors.Is/As` 分类，不解析错误字符串。错误消息提供上下文但不包含 Token 和响应正文。

## 4. 值、指针与复制

- 小型不可变值可按值传递。
- 需要共享身份或修改接收者时使用指针。
- Slice、Map 和 Channel 即使按值传递也引用共享底层状态。
- 并发读取前冻结配置，或显式同步修改。

不要把 Mutex 保护的结构体无意复制。

## 5. 包依赖

```text
cmd → application → domain
             ↓
          adapters → external SDK
```

领域层不导入具体 HTTP、日志或数据库 SDK。日志通常在应用和边界记录，避免同一错误每层重复打印。

## 6. 配置校验

```go
func (c Config) Validate() error {
	if c.Workers < 1 || c.Workers > 100 {
		return fmt.Errorf("workers outside allowed range")
	}
	return nil
}
```

环境变量和 Flag 解析后生成一次不可变配置，不让业务代码到处读取全局环境。

## 7. 序列化

公共 JSON 使用独立 DTO 和明确 Tag；字段删除、类型变化和默认值都是兼容性变化。不要直接暴露内部错误和结构体所有字段。
