# Go 任务队列、限流、幂等与恢复

## 1. 任务状态

```text
Pending → Running → Succeeded/Failed
                  ↘ Unknown
Pending/Running → Cancelled
```

Worker 失联后无法仅凭心跳判断远端副作用是否发生，因此必须保留 Unknown 状态并查询确认。

## 2. 有界资源

一起限制：

- 输入队列长度。
- Worker 数。
- 每下游并发和 QPS。
- 单任务 Deadline。
- 重试次数与总预算。
- 结果大小和保留期。

无限队列只会把拒绝变成更晚的超时和内存故障。

## 3. 限流

令牌桶适合平滑请求速率；并发 Semaphore 限制同时执行数。两者解决不同问题。下游返回 429 时尊重服务端提示并共享退避预算。

## 4. 租约和心跳

任务领取写入 Worker、租约到期时间和尝试次数。续租必须早于到期，并处理控制面不可用。租约过期允许重领，不代表前 Worker 已停止，所以执行动作还需要幂等键。

## 5. 幂等

幂等键关联业务动作而不是某次网络尝试：

```text
operation + target + desired_version
```

服务端保存结果或唯一约束；客户端超时后先查询，不直接盲重试写操作。

## 6. 停止扩散

批量变更定义失败阈值、金丝雀、批次和观察窗口。超过阈值后停止领取新任务，保留已运行任务状态，按业务选择完成、取消或补偿。

## 7. 恢复

控制面重启后从持久化状态恢复：

1. 找出 Running 且租约过期任务。
2. 查询外部实际状态。
3. 已达期望则标记成功。
4. 未执行且安全则重新排队。
5. 无法判断则标记 Unknown 并人工处理。

内存 Channel 不提供跨重启恢复；需要持久化队列时使用成熟系统。
