# Go 性能、构建、发布与供应链

## 1. 先分层测量

区分队列等待、连接池、下游响应、锁竞争、GC、CPU、内存和序列化。固定输入、目标规模、错误率和缓存状态。

## 2. Benchmark

```bash
go test -bench=. -benchmem ./...
```

比较前后保存多次结果和环境。微基准不能替代端到端容量测试。

## 3. pprof 与 Trace

采集 CPU、Heap、Goroutine、Mutex 和 Block Profile。生产暴露调试端点必须认证、限时和隔离，因为 Profile 可能包含敏感调用与消耗资源。

```bash
go tool pprof profile.pb.gz
go tool trace trace.out
```

## 4. 常见瓶颈

- 无界 Goroutine 和队列。
- 每请求创建 Client/Transport。
- 锁包围网络 I/O。
- 结果全部驻留内存。
- 高频字符串和 JSON 分配。
- 重试风暴和下游 429。

## 5. 构建

```bash
go test ./...
go test -race ./...
go build -trimpath -o bin/ops-agent ./cmd/ops-agent
go version -m bin/ops-agent
```

固定 Toolchain、依赖、CGO 和平台。交叉编译后必须在目标平台验证。

## 6. 供应链

受保护源码、干净构建、依赖审查、SBOM、签名、Digest 和部署证据形成闭环。构建来自不可信合并请求时不注入发布密钥。

## 7. 发布

灰度 Agent 时关注旧新协议兼容、任务租约、正在执行任务和回滚。控制面先支持两代 Worker，再逐步升级；不直接同时替换全部执行节点。
