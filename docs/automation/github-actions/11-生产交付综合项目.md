# GitHub Actions 生产交付综合项目

## 1. 目标

为一个 Kubernetes API 服务建立可追踪交付：Fork PR 可安全测试但接触不到生产权限；合并后只构建一次；运行中的镜像能反查源码、Workflow、SBOM、签名、审批和 GitOps 变更。

## 2. 工作流分层

```text
pull_request（低权限）
→ lint/unit/SAST/build-test

push main（受保护）
→ build once
→ SBOM/扫描/来源证明
→ Push Harbor 候选项目并签名 Digest
→ 更新 staging GitOps
→ 自动验证
→ production Environment 审批
→ 更新 production GitOps
→ Argo CD 渐进同步和健康验证
```

## 3. 权限设计

| Job | 权限与身份 |
| --- | --- |
| PR Test | `contents: read`，无 Secret，临时托管 Runner |
| Build | 只写 Harbor 候选项目，短期凭据 |
| Attest/Sign | OIDC 绑定默认分支和工作流 |
| Promote | 生产 Environment 审批，只更新指定 GitOps 路径 |
| Argo CD | 集群内持续协调，Workflow 不持有 Cluster Admin |

## 4. 制品证据

记录源码 SHA、Workflow/Action SHA、Runner 镜像、依赖锁、测试报告、SBOM、扫描策略、OCI Digest、签名和 GitOps Commit。任何阶段只引用 Digest，不通过浮动 Tag 传递生产制品。

## 5. 可靠性

- 同一 PR 新提交取消旧验证；生产发布按应用和环境串行。
- 外部写操作带 `run-id + digest + purpose` 幂等键。
- Harbor、云 API 和 GitHub API 使用有限退避。
- 发布超时先查询 GitOps/集群实际状态，不能直接重跑。
- 失败保留报告和日志，清理任务不删除唯一证据。

## 6. 故障演练

- Fork 修改 Workflow 尝试读取 Secret，应被阻断。
- 第三方 Action 漂移，固定 SHA 保证行为不变。
- 自托管 Runner 丢失，确认没有重复发布。
- Harbor 扫描/签名失败，候选不能晋级。
- Environment 审批后健康指标恶化，回滚到旧 Digest。
- GitHub 控制面暂时不可用，线上状态由 Argo CD 和集群继续维持。

## 7. 验收

交付架构图、权限矩阵、Workflow、复用模板、Runner 威胁模型、容量报告、制品证据、回滚和泄漏应急 Runbook。能解释每个身份、数据和失败边界，才算完成生产交付。
