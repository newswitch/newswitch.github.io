# Backstage 搜索、运营、升级与故障排查

## 1. 搜索质量

索引 Catalog、TechDocs 等内容时保留 Entity Ref、Owner、类型、权限和更新时间。权限过滤必须在查询/结果层生效，不能让无权用户通过标题或摘要发现敏感文档。

关注零结果率、点击率、查询延迟、索引陈旧度和最常失败查询。搜索不是“能输入关键字”就完成。

## 2. 平台 SLO

- 登录和核心页面成功率/延迟；
- Catalog 刷新与陈旧度；
- 模板成功率和 P95；
- TechDocs 构建/读取成功率；
- 插件外部 API 错误与降级；
- 搜索索引延迟；
- 目录覆盖率和活跃用户。

将外部系统故障与 Backstage 自身故障分开。

## 3. 容量

按 Entity、Relation、文档页、模板任务、并发用户和外部请求计算。大规模 Provider 刷新、搜索重建和模板任务会争用数据库/CPU；分批、限速并在压测中加入真实插件。

## 4. 故障树

```text
页面/功能异常
├── DNS/TLS/Ingress/静态资源
├── Auth/Resolver/Session/Permission
├── Frontend与Backend版本/路由
├── Catalog/Database/迁移
├── Plugin配置/外部API/Token/限流
├── TechDocs/Search存储与索引
└── Scaffolder Worker/Workspace/外部副作用
```

## 5. 升级

锁定依赖，阅读兼容和迁移说明，在生产数据副本验证数据库、插件、认证、权限、模板和关键页面。逐步发布，保留旧镜像和可执行回退；数据库迁移后按演练方案恢复。

## 6. 备份恢复

备份 PostgreSQL、配置、Secret 引用、TechDocs 对象、模板仓库和插件清单。Catalog 可从来源重建，但恢复时间、Provider 权限和孤儿实体需实际演练。

## 7. 事故复盘

门户事故不仅记录“页面恢复”，还检查开发者是否绕过平台、模板是否重复创建资源、权限是否 Fail Open，以及哪些线上系统错误地依赖门户可用性。
