# Backstage 插件架构与集成开发

## 1. 先判断是否需要插件

简单链接、Entity Card 配置或现有插件能解决时，不创建新插件。新插件意味着依赖、权限、数据库、升级和 SLO 的长期维护责任。

## 2. 前后端边界

```text
Frontend Plugin
→ 展示、路由、用户交互、调用 Backend API
Backend Plugin
→ 认证授权、Secret、数据库、缓存、外部 API
```

浏览器不能持有外部系统长期 Token，也不能接受实体 Annotation 后任意请求内网 URL。

## 3. API 合约

定义请求/响应 Schema、错误码、分页、超时、缓存和版本。前端显示数据来源及时间；后端把外部 401、429、5xx 分类，而不是统一返回“插件失败”。

## 4. Entity 驱动集成

插件从稳定 Annotation/Relation 获取外部资源标识，并验证格式和允许范围。找不到映射时显示配置建议，不猜测或扫描所有外部资源。

## 5. 权限

后端路由在服务端检查 Permission，不依赖前端隐藏按钮。高风险动作使用用户委托身份或受控工作流，并再次验证资源 Owner、环境和操作范围。

## 6. 测试

- 单元测试数据转换与授权；
- 契约测试外部 API；
- 组件测试 Loading/Empty/Error/Forbidden；
- 集成测试真实插件路由、数据库和身份；
- 故障注入超时、429、过期 Token 和部分数据；
- 性能测试大目录与慢外部 API。

## 7. 生命周期

固定插件依赖，跟踪 Backstage 兼容性和安全更新。记录 Owner、用户量、SLO、升级计划和弃用迁移。社区插件先评估维护活跃度、权限、数据流和供应链，再进入生产。
