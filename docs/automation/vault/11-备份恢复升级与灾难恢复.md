# Vault 备份、恢复、升级与灾难恢复

## 1. 完整恢复条件

Vault 数据快照只是恢复的一部分。还需要：

- 与目标版本兼容的软件、配置和插件；
- TLS 证书、网络、DNS 和负载均衡配置；
- Shamir Share 或 Auto Unseal KMS/HSM 的访问能力；
- 审计、身份源、数据库和云平台等外部依赖；
- 具备受控权限的恢复人员和 Runbook。

快照和解封材料要分离、加密、异地保存；不要把二者放在同一失效域。

## 2. Raft 快照与恢复

定期创建快照，记录集群版本、时间、校验和、存储位置和测试结果。恢复在隔离环境进行，防止恢复出的集群同时与生产下游交互并创建/撤销真实凭据。

验收：解封、Leader 选举、认证、Policy、KV 版本、动态凭据、PKI、Transit 解密和审计均正常。

## 3. 升级

1. 阅读版本兼容矩阵和升级路径。
2. 备份并在克隆环境演练。
3. 检查插件、Agent、CSI/Injector 和客户端 SDK。
4. 保持 Raft 多数派，逐节点升级 Standby。
5. 切换/升级 Active，持续观察选举与请求。
6. 完成冒烟、性能和恢复验证后再结束变更窗口。

存储格式或数据库迁移发生后，回退不能只替换二进制。

## 4. 灾难类型

| 灾难 | 重点 |
| --- | --- |
| 单节点损坏 | 维持多数派并替换节点 |
| 多数派丢失 | 从受验证快照建立新集群 |
| KMS/Seal 不可用 | 恢复外部密钥访问，避免误建新集群 |
| 凭据/CA 泄漏 | 吊销、轮换、审计和下游清理 |
| 区域故障 | DNS/流量切换、数据 RPO、外部依赖可达性 |

## 5. 演练标准

每次演练记录 RTO/RPO、实际人工操作、数据差异、下游副作用和未自动化环节。没有做过隔离恢复的快照不能视为可靠备份。
