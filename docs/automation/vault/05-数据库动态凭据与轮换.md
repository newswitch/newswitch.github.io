# Vault 数据库动态凭据与轮换

## 1. 工作原理

```text
应用使用 Vault 身份认证
→ 请求 database/creds/<role>
→ Vault 用受控管理连接执行创建语句
→ 返回唯一用户名、密码和 Lease
→ TTL 到期或主动 Revoke
→ Vault 执行撤销/删除语句
```

动态凭据缩短泄漏窗口并提升归因，但依赖数据库管理连接和可靠撤销。

## 2. Role 设计

每个 Role 绑定允许的数据库连接、创建/撤销语句、默认 TTL 和最大 TTL。只创建业务需要的只读或读写权限，禁止授予管理员权限。

不要直接复制未经验证的 SQL 模板到生产。不同数据库对用户名长度、引号、事务、复制、对象权限和连接终止的语义不同，需在隔离实例测试创建与撤销。

## 3. 应用连接池

凭据有 TTL，而连接池可能长期持有连接。应用必须协调：

- 续租成功时继续使用；
- 无法续租时在过期前获取新凭据；
- 建立新连接池并排空旧连接；
- 避免所有实例同一时刻轮换形成连接风暴；
- 凭据撤销后旧连接是否立即失效由数据库行为决定。

## 4. Root/管理凭据

Vault 用管理账户创建子账户，因此这个账户本身要最小化权限、限制来源、审计并定期轮换。轮换前确认 Vault 版本、数据库插件和数据库权限，保留受控恢复入口。

## 5. 故障模式

| 现象 | 可能原因 |
| --- | --- |
| 生成失败 | 管理连接、TLS、SQL 模板、用户名限制 |
| Revoke 失败 | 数据库不可达、权限变化、撤销语句错误 |
| 账户堆积 | Lease 过期处理失败或手工创建未纳管 |
| 应用周期性断连 | 续租/连接池切换与 TTL 不匹配 |

监控 Lease 创建和撤销失败、数据库插件错误、管理连接延迟和异常账户数量。定期对账 Vault Lease 与数据库实际账号。
