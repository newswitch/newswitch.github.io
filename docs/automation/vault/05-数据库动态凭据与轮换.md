# Vault 数据库动态凭据与轮换

Database Secret Engine 不代理应用 SQL 流量。它使用一条受控管理连接，在目标数据库中创建短期账号，并用 Lease 管理其生命周期。

## 1. 完整数据流

```text
应用使用平台身份登录 Vault
→ 请求 database/creds/payments-readonly
→ Vault Policy 允许读取该 Role
→ Database Plugin 选择 Connection 配置
→ 使用管理身份连接 MySQL/PostgreSQL 等数据库
→ 执行 creation_statements 创建唯一账号
→ Vault 返回用户名、密码、lease_id 和 TTL
→ 应用建立新连接池
→ Lease 到期或主动 Revoke
→ Plugin 执行 revocation_statements
```

“Vault 已撤销 Lease”与“数据库账号已被成功删除”必须分别验证。下游数据库不可达时，Vault 无法通过意志让外部账号消失。

## 2. Connection 与 Role

Connection 定义目标数据库、插件、TLS 和管理身份；Role 定义怎样创建某类凭据：

```text
database/config/payments-mysql
  ├── plugin_name
  ├── connection_url / TLS
  ├── allowed_roles
  └── 管理身份

database/roles/payments-readonly
  ├── db_name = payments-mysql
  ├── creation_statements
  ├── revocation_statements
  ├── default_ttl
  └── max_ttl
```

一个 Connection 只允许明确列出的 Role。Role 按业务权限拆成只读、读写和迁移等用途，不应创建管理员账号。

## 3. SQL 模板必须按数据库验证

概念示例：

```sql
CREATE USER '{{name}}'@'10.%' IDENTIFIED BY '{{password}}';
GRANT SELECT ON payments.* TO '{{name}}'@'10.%';
```

真实语句要根据插件文档和目标数据库验证：

- 用户名最大长度和字符集；
- 引号、转义和 SQL 注入边界；
- Host、Schema、Role 和 Default Privilege；
- 创建和授权是否具有事务语义；
- 删除用户前是否必须终止连接；
- 主从复制和只读节点上的 DDL 行为。

不要直接从博客复制 SQL 到生产。先在与生产版本一致的隔离实例完成“创建 → 登录 → 权限拒绝 → 撤销 → 登录失败”的闭环。

## 4. 管理身份是最高风险点

Vault 的数据库管理身份需要创建、修改或删除受控子账号，但不应拥有业务表数据的无限访问权或实例级超级权限。

控制措施包括：

- 只允许 Vault 节点来源地址连接；
- 启用数据库 TLS 并验证服务端身份；
- 每个环境和数据库实例独立管理身份；
- 在数据库审计中标记 Vault 创建动作；
- 定期轮换 Root/Management Credential；
- 保留受控的脱离 Vault 恢复入口。

执行 Root Credential 轮换前，确认数据库插件、连接池和权限都支持该动作。轮换成功后，旧密码通常不再由 Vault 返回，失败恢复必须提前设计。

## 5. Dynamic Role 与 Static Role

- Dynamic Role：每次请求创建唯一账号，TTL 到期后撤销，最适合应用和临时任务；
- Static Role：轮换一个已存在的固定数据库账号，适合无法频繁换用户名的旧应用。

静态凭据的轮换、Rootless 管理等能力在不同 Vault 版本和版本许可中存在差异，实施前要核对当前官方文档和许可证，不能把企业版能力写进开源版上线方案。

## 6. TTL 怎样选

过短会增加创建/撤销写入和数据库账号抖动，过长会扩大泄漏窗口。需要同时考虑：

```text
应用发现旧凭据失效的时间
+ 获取新凭据的时间
+ 建立并预热新连接池的时间
+ 失败重试余量
< Lease 剩余有效期
```

批处理可以按任务窗口签发；长运行服务通常续租或在到期前创建新 Lease。给所有实例相同 TTL 会形成同时轮换，应加入安全范围内的抖动。

## 7. 连接池无损轮换

```text
旧 Lease / 旧连接池仍提供服务
→ 提前申请新凭据
→ 创建新连接池并执行健康查询
→ 新请求切到新池
→ 排空旧连接
→ 主动撤销旧 Lease
```

不能先撤销旧凭据再创建新连接池。还要验证数据库在删除用户后如何处理已有会话：有些系统允许现有连接继续运行，撤销账号并不等于立即终止会话。

## 8. Lease 续租还是重新签发

是否支持续租取决于 Engine、Role 和 Lease。即使可续租，也不意味着应该永久续租同一数据库账号。常见策略是：

- 短任务：不续租，到期自动撤销；
- 服务：续租保持稳定，但在最大 TTL 前轮换新账号；
- 高安全场景：固定周期重新签发，限制单个账号存活时间。

应用必须区分“续租临时失败”和“Lease 已不可续租”，后者要立即进入换证流程。

## 9. 撤销失败为什么危险

故障链：

```text
Lease 到期
→ Vault 尝试 Revoke
→ 数据库不可达/权限被改/SQL 失败
→ Vault 记录撤销失败并重试
→ 外部账号仍可能有效
```

监控不能只看 Vault Lease 数量，还要看：

- 撤销错误和重试队列；
- 数据库中符合 Vault 命名规则但无有效 Lease 的账号；
- 超过预期年龄的动态用户；
- 管理连接延迟、TLS 和认证错误；
- 创建成功率与数据库 DDL 负载。

定期对账 Vault 与数据库实际账号，使用明确前缀和创建时间提高归因能力。

## 10. 高可用与容量

Vault Server 高可用不等于 Database Engine 可用。还要确认：

- Active 节点到数据库网络和 DNS；
- 管理连接池上限；
- 数据库能承受的账号 DDL 和认证缓存失效；
- 批量 Pod 重启造成的凭据签发风暴；
- 数据库主从切换后管理连接地址和 TLS 身份。

可以通过 Agent 缓存、分批发布和带抖动的重试减少登录与签发风暴，但不能缓存超过 Lease 生命周期的凭据。

## 11. 排障路径

| 现象 | 优先检查 |
| --- | --- |
| `creds/role` 返回 403 | 应用 Policy 和 Role Path |
| 返回 500/插件错误 | Connection、Plugin、TLS、管理权限、SQL |
| 凭据签发成功但不能查表 | Creation Statement 权限和默认 Schema |
| 固定周期断连 | Lease、连接池切换、最大 TTL |
| 账号堆积 | Revoke 失败、数据库不可达、手工账号混入 |
| 轮换后 Vault 自身失去连接 | 管理密码更新不一致或插件轮换失败 |

排障日志只记录 Role、Lease ID、数据库实例、用户名和 Request ID，不记录密码。

## 12. 上线验收

1. 使用新凭据只能执行允许 SQL；
2. 禁止访问其他 Schema 和管理操作；
3. 主动 Revoke 后新连接失败；
4. 到期自动撤销成功；
5. 数据库短时不可达后撤销能重试恢复；
6. 应用能在旧 Lease 到期前无损切池；
7. 管理凭据轮换和故障回退已演练；
8. Vault Lease 与实际数据库账号可以自动对账。

## 13. 练习与答案

**问题：把数据库密码放入 KV 并每月更新，是否等同动态凭据？**

答案：不等同。KV 不会为每个工作负载创建唯一账号，也不能随 Lease 自动删除数据库用户；共享静态密码的归因和泄漏窗口更差。

**问题：Vault 显示 Lease 已过期，为什么数据库连接还在执行 SQL？**

答案：撤销外部账号可能失败，而且部分数据库删除用户后不会立刻终止已建立会话。必须同时验证撤销执行结果和数据库会话语义。
