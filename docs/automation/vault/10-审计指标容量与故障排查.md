# Vault 审计、指标、容量与故障排查

## 1. 审计是安全边界

Audit Device 记录认证和 Secret 请求的结构化证据，敏感字段通常经过 HMAC 处理。至少启用多个独立审计目标或可靠收集链，监控写入失败和磁盘容量。审计目标不可写时，Vault 可能拒绝请求以避免无审计操作。

审计日志仍包含 Path、身份、来源和行为等敏感元数据，必须加密传输、限制读取和定义保留期。

## 2. 四类指标

| 类别 | 关注内容 |
| --- | --- |
| 请求 | 吞吐、错误率、P50/P95/P99、并发 |
| 核心 | Seal 状态、Active 切换、Token/Lease 数量 |
| Raft/存储 | Quorum、Leader、复制延迟、磁盘延迟和容量 |
| 下游 | KMS、数据库、云 API、LDAP/OIDC、审计设备延迟 |

客户端失败可能发生在 Vault 之前或之后。仅看 Vault CPU 很低不能说明系统健康。

## 3. 容量压测

按真实比例压测认证、KV、动态凭据、Transit 和续租，使用与生产相似的 TLS、Policy、审计和存储。逐步增加并发，观察延迟拐点、Raft 写入、审计吞吐、下游配额和恢复后的惊群。

容量模型应包含正常峰值、Pod 批量重建、证书集中轮换和节点故障后的余量。

## 4. 故障树

```text
请求失败/变慢
├── DNS/TCP/TLS/代理
├── Sealed/无 Active/失去 Quorum
├── Auth Method/外部身份源
├── Token过期/Policy/Namespace/Path
├── Raft磁盘/存储/审计设备
└── Database/KMS/PKI/云 API 等下游
```

## 5. 排障证据

记录请求时间、Vault 集群/Namespace、Auth Mount、Role、脱敏后的 Entity/Accessor、Path、Operation、状态码和 Request ID。关联客户端、Vault 审计、服务日志和下游日志。

不要为排障开启会打印 Secret 的全局 Debug，或复制生产 Token 到个人终端。使用最小权限测试身份复现。
