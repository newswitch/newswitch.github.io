# Python 日志、指标、追踪与审计证据

自动化工具不仅要报告“成功或失败”，还要回答：针对哪些目标、使用哪个版本、执行了什么、失败在哪一层、是否发生部分成功、结果是否新鲜以及能否安全重跑。

## 1. 四类输出

| 输出 | 消费者 | 用途 |
| --- | --- | --- |
| stdout | 人、Shell、流水线 | 正式结果和机器可读 JSON |
| stderr/日志 | 运维与日志平台 | 过程和诊断 |
| 指标 | Prometheus 等监控 | 趋势、容量和告警 |
| 审计证据 | 变更、合规、复盘 | 谁在何时对什么执行了什么 |

不要把调试日志当正式结果，也不要把完整结果塞进指标 Label。

## 2. 标准 logging

```python
import logging

logger = logging.getLogger("ops_audit")

def check_target(target: str) -> None:
    logger.info("target check started", extra={"target": target, "operation": "probe"})
```

库模块不应调用 `basicConfig()`；由应用入口统一配置 Handler、Formatter、Level 和输出位置。

## 3. 结构化事件

统一字段：

```text
timestamp
level
service
version
run_id
task_id
operation
target_id
attempt
duration_seconds
result_state
error_type
```

`target_id` 使用稳定资产标识，不把完整 URL、查询、异常栈或 Secret 放进高基数索引字段。

## 4. 任务关联

为一次运行生成 `run_id`，每个目标和检查生成 `task_id`。并发环境可使用 `contextvars` 传递日志上下文：

```python
from contextvars import ContextVar

run_id_var: ContextVar[str] = ContextVar("run_id", default="unknown")
```

线程池和进程池的上下文传播方式不同，必须用测试验证，而不是假设自动继承。

## 5. 指标

建议：

```text
automation_runs_total{operation,result}
automation_tasks_total{operation,result,error_type}
automation_task_duration_seconds{operation}
automation_inflight_tasks{operation}
automation_queue_depth{queue}
automation_retries_total{operation,reason}
```

避免把主机名、请求 ID、错误原文和文件路径作为 Label，防止时间序列爆炸。详细目标结果保留在日志和证据包。

短生命周期 CLI 如何上报指标需要架构选择：Pushgateway、任务平台事件、日志转指标或由常驻控制面采集。不要让一次性进程假装是长期可抓取服务。

## 6. 追踪

当一次任务跨越 API 网关、队列、Worker 和下游服务时，Trace 可以关联调用链。Span 至少记录受控的操作名、下游类型、耗时和状态，不记录 Token 和完整业务载荷。

是否采用 OpenTelemetry 取决于现有平台。即使没有追踪系统，也应把 `run_id`、远端 Request ID 和变更单 ID 串起来。

## 7. 异常与脱敏

异常可能携带：

- URL Query 和 Header。
- API 响应体。
- 文件路径和用户名。
- SSH 命令与远端输出。
- Secret 和证书信息。

适配器先转换为受控错误，再记录原始异常到受限渠道。使用允许字段白名单比尝试替换所有敏感模式更可靠。

## 8. 审计证据包

```text
evidence/<run_id>/
├── manifest.json
├── inputs.redacted.json
├── targets.json
├── results.jsonl
├── errors.jsonl
├── versions.json
└── SHA256SUMS
```

Manifest 包含：

```json
{
  "schema_version": "1",
  "run_id": "<uuid>",
  "tool_version": "<version>",
  "source_commit": "<commit>",
  "started_at": "<UTC timestamp>",
  "finished_at": "<UTC timestamp>",
  "mode": "read-only",
  "result": "partial"
}
```

Hash 用于发现证据被修改，不自动证明生成者身份；需要不可抵赖时结合签名、可信时间和受控存储。

## 9. 自监控

自动化平台需要告警：

- 成功率突然下降。
- 任务排队和耗时超出 SLO。
- 429、超时和重试激增。
- Worker 心跳丢失。
- 证据写入失败。
- 版本或配置漂移。

监控还要区分“没有任务”和“监控采集失败”。

## 10. 验收

- [ ] stdout 只包含正式结果。
- [ ] 日志中每个任务都能关联 run_id。
- [ ] 指标 Label 基数有明确预算。
- [ ] 错误分类稳定，原始异常经过脱敏。
- [ ] 证据包包含来源、版本、时间和 Hash。
- [ ] 部分失败不会被总体成功掩盖。
