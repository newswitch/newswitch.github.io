# Python 解释器、虚拟环境、项目与依赖

“我已经安装了这个包”不能证明当前程序能导入它。操作系统可能同时存在系统 Python、虚拟环境、用户安装、IDE 解释器和容器解释器。第一步始终是把 Python 与 pip 绑定到同一个解释器。

## 1. 定位当前运行时

```bash
command -v python3
python3 --version
python3 -c 'import sys; print(sys.executable); print(sys.prefix); print(sys.base_prefix)'
python3 -m pip --version
```

使用 `python -m pip` 比直接调用 `pip` 更能说明包将安装到哪个解释器。

## 2. 创建虚拟环境

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
```

虚拟环境隔离安装位置，但不是安全沙箱，也不隔离网络、进程和文件权限。它通常不应提交到 Git，应由声明文件重建。

诊断：

```bash
python -c 'import sys; print(sys.executable)'
python -m site
python -m pip list
python -m pip check
```

## 3. 使用 src 布局

```text
ops-audit/
├── pyproject.toml
├── README.md
├── src/
│   └── ops_audit/
│       ├── __init__.py
│       ├── cli.py
│       ├── models.py
│       └── service.py
└── tests/
```

`src/` 布局可以减少“测试误导入仓库当前目录而不是已安装包”的风险。

## 4. pyproject.toml

最小示意：

```toml
[build-system]
requires = ["setuptools>=77"]
build-backend = "setuptools.build_meta"

[project]
name = "ops-audit"
version = "0.1.0"
requires-python = ">=3.11"
dependencies = []

[project.scripts]
ops-audit = "ops_audit.cli:main"
```

示例版本约束只是演示，真实项目要根据测试矩阵选择，并固定构建环境。不要从文章复制一个版本后永久不维护。

开发安装：

```bash
python -m pip install --editable .
ops-audit --help
```

## 5. 直接依赖与传递依赖

- `pyproject.toml` 声明项目直接依赖和兼容范围。
- 锁文件或带 Hash 的约束记录某个部署环境的完整解析结果。
- 传递依赖也会改变行为和供应链风险。

至少保存：

```bash
python -m pip freeze
python -m pip check
```

`freeze` 是当前环境快照，不等于精心设计的项目依赖。团队可以选择受维护的锁定工具，但必须理解其平台标记、Hash、索引和更新流程。

## 6. 可复现安装

生产流水线应：

1. 从干净环境开始。
2. 使用受信索引和 TLS。
3. 按锁定结果安装。
4. 校验包 Hash 或制品签名能力。
5. 执行 `pip check`、测试和漏洞扫描。
6. 保存解释器、平台、依赖和源码版本。

高安全环境可先构建 Wheelhouse：

```bash
python -m pip download --dest wheelhouse -r requirements.lock
python -m pip install --no-index --find-links wheelhouse -r requirements.lock
```

离线不代表可信，Wheelhouse 本身仍需要来源、Hash、扫描和访问控制。

## 7. 导入不产生副作用

模块导入阶段不要：

- 发起网络请求。
- 读取生产 Secret。
- 创建线程或进程。
- 修改系统文件。
- 解析 CLI 并调用 `sys.exit()`。

入口使用：

```python
def main() -> int:
    return 0

if __name__ == "__main__":
    raise SystemExit(main())
```

这样模块可以安全导入和测试。

## 8. 升级策略

依赖更新按小批量进行：

```text
更新声明或锁
→ 查看 Changelog 和安全公告
→ 单元、集成和兼容测试
→ 构建新制品
→ 测试环境与金丝雀
→ 生产推广
```

不要在生产启动时自动运行无上限的 `pip install --upgrade`。
