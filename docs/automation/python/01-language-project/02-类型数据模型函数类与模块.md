# Python 类型、数据模型、函数、类与模块

自动化工具最常见的复杂度不是算法，而是“一个字典在不同函数里代表不同东西”。把配置、目标、任务、结果和错误显式建模，可以让校验、测试和序列化边界清晰。

## 1. 基础数据与可变性

```python
targets: list[str] = ["node01", "node02"]
labels: dict[str, str] = {"environment": "test"}
ports: tuple[int, ...] = (22, 443)
```

列表和字典可变，元组和字符串不可变。函数默认参数不要使用可变对象：

```python
def add_target(target: str, targets: list[str] | None = None) -> list[str]:
    result = [] if targets is None else list(targets)
    result.append(target)
    return result
```

## 2. Dataclass 表达配置与结果

```python
from dataclasses import dataclass, field
from enum import StrEnum

class ResultState(StrEnum):
    OK = "ok"
    DEGRADED = "degraded"
    FAILED = "failed"

@dataclass(frozen=True, slots=True)
class Target:
    name: str
    address: str
    labels: dict[str, str] = field(default_factory=dict)

@dataclass(frozen=True, slots=True)
class CheckResult:
    target: str
    check: str
    state: ResultState
    message: str
    duration_seconds: float
```

`frozen=True` 降低配置被执行过程意外修改的风险，但嵌套字典本身仍可变；需要更强不可变语义时选择只读映射或在边界复制。

## 3. 类型提示不是运行时校验

```python
def load_timeout(raw: object) -> float:
    if not isinstance(raw, (int, float)):
        raise TypeError("timeout must be numeric")
    value = float(raw)
    if not 0 < value <= 300:
        raise ValueError("timeout outside allowed range")
    return value
```

类型检查器分析代码，外部 JSON、YAML、环境变量和 API 响应仍需运行时验证。不要把 `typing.cast()` 当数据验证。

## 4. 函数边界

推荐函数：

- 输入和输出类型明确。
- 单一职责。
- 不从全局隐式读取配置。
- 不同时完成网络请求、业务判断和打印。
- 副作用集中在适配器。

纯业务判断：

```python
def classify_latency(seconds: float, warning: float, critical: float) -> ResultState:
    if seconds >= critical:
        return ResultState.FAILED
    if seconds >= warning:
        return ResultState.DEGRADED
    return ResultState.OK
```

这种函数无需网络和文件即可充分测试。

## 5. Protocol 定义端口

```python
from typing import Protocol

class TargetProbe(Protocol):
    def probe(self, target: Target) -> CheckResult: ...
```

业务服务依赖 Protocol，而不是直接依赖具体 SSH 或 HTTP 库：

```python
class AuditService:
    def __init__(self, probe: TargetProbe) -> None:
        self._probe = probe

    def run(self, target: Target) -> CheckResult:
        return self._probe.probe(target)
```

测试可提供简单 Fake，生产注入真实适配器。

## 6. 模块和包

```text
ops_audit/
├── models.py       领域数据
├── errors.py       稳定异常分类
├── ports.py        Protocol
├── service.py      用例编排
├── adapters/
│   ├── http.py
│   └── ssh.py
└── cli.py          输入输出映射
```

避免双向导入和巨型 `utils.py`。如果一个“工具函数”只服务某个适配器，应放回该适配器模块。

## 7. 类还是函数

使用函数：

- 无需长期状态。
- 输入决定输出。
- 资源生命周期由调用者管理。

使用类：

- 需要注入客户端、配置和策略。
- 多个操作共享连接池。
- 要实现 Protocol 的一组行为。

不要为了“面向对象”给每个函数套一个只有静态方法的类。

## 8. 序列化边界

内部模型不能直接随意 `__dict__` 输出。建立显式公共 Schema，控制字段、时间、枚举和错误信息：

```python
def result_to_dict(result: CheckResult) -> dict[str, object]:
    return {
        "target": result.target,
        "check": result.check,
        "state": result.state.value,
        "message": result.message,
        "duration_seconds": result.duration_seconds,
    }
```

公共 JSON 结构变化要进行版本和兼容性管理。
