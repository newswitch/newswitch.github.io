# Python 异常、上下文管理与资源生命周期

异常不是日志字符串。自动化系统需要根据异常类别决定：不重试、有限重试、停止批次、回滚还是人工介入。因此要在适配器边界把库异常转换为稳定的领域错误，同时保留原始异常链。

## 1. 建立异常分类

```python
class AutomationError(Exception):
    """Public base error for the tool."""

class ConfigurationError(AutomationError):
    pass

class AuthenticationError(AutomationError):
    pass

class TemporaryDependencyError(AutomationError):
    pass

class ValidationError(AutomationError):
    pass

class PartialFailure(AutomationError):
    pass
```

不要用消息字符串包含某个单词来决定重试。

## 2. 转换并保留异常链

```python
try:
    response = client.get(endpoint, timeout=timeout)
except TimeoutError as exc:
    raise TemporaryDependencyError("inventory request timed out") from exc
```

对外信息不包含 Token、完整响应体和隐私数据；详细异常链写入受控日志。不要无差别 `except Exception: pass`。

## 3. Try 的范围要小

```python
try:
    raw = path.read_text(encoding="utf-8")
except OSError as exc:
    raise ConfigurationError(f"cannot read config: {path}") from exc

config = parse_config(raw)
```

如果 Try 包住大量业务代码，就难以知道哪个动作失败，也容易捕获本应暴露的编程错误。

## 4. 上下文管理器

```python
from pathlib import Path

with Path("result.json").open("w", encoding="utf-8") as stream:
    stream.write("{}\n")
```

`with` 保证正常和异常路径都执行退出逻辑。网络客户端、数据库会话、临时目录和锁也应使用上下文生命周期。

自定义：

```python
from contextlib import contextmanager
from collections.abc import Iterator

@contextmanager
def task_scope(task_id: str) -> Iterator[None]:
    record_start(task_id)
    try:
        yield
    except Exception:
        record_failure(task_id)
        raise
    else:
        record_success(task_id)
    finally:
        release_task_resources(task_id)
```

Cleanup 失败时不能悄悄覆盖原始业务异常，应分别记录并定义优先级。

## 5. ExitStack 处理动态资源

```python
from contextlib import ExitStack

with ExitStack() as stack:
    streams = [
        stack.enter_context(path.open("rb"))
        for path in input_paths
    ]
    process(streams)
```

适合资源数量运行时才确定的情况。资源按注册相反顺序释放。

## 6. 临时资源

```python
from tempfile import TemporaryDirectory

with TemporaryDirectory(prefix="ops-audit-") as directory:
    build_evidence(directory)
```

临时目录仍需考虑权限、磁盘空间、异常保留证据和 Secret。需要排障保留时，复制经过脱敏和校验的证据，而不是直接禁止清理全部临时内容。

## 7. 取消不是普通失败

异步任务取消需要向上传播，并在 `finally` 中释放资源。不要把取消捕获后当成功返回，也不要无限等待不响应取消的子任务。

同步 CLI 收到中断时通常映射为明确退出状态，并停止创建新任务。复杂信号、子进程和线程生命周期必须由顶层入口统一管理。

## 8. 顶层异常映射

```python
def main() -> int:
    try:
        run_application()
    except ConfigurationError as exc:
        log_error(exc)
        return 2
    except AuthenticationError as exc:
        log_error(exc)
        return 3
    except TemporaryDependencyError as exc:
        log_error(exc)
        return 5
    except KeyboardInterrupt:
        return 130
    return 0
```

只在顶层把异常映射为 CLI 退出码。领域层不要调用 `sys.exit()`。

## 9. 测试失败路径

- 文件打开失败后没有遗留临时文件。
- HTTP 超时转换为可重试错误且保留 Cause。
- 认证错误绝不重试。
- Cleanup 失败不会隐藏原始故障。
- Ctrl+C 或取消后没有继续运行的任务。
- 部分目标失败返回结构化结果而不是丢失成功项。
