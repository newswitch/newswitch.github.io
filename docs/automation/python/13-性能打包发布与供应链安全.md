# Python 性能、打包、发布与供应链安全

自动化工具慢不一定是 Python 计算慢。常见瓶颈是串行网络请求、连接池过小、下游限流、重复分页、日志 I/O 和无界结果聚合。先分层测量，再决定并发、缓存或算法优化。

## 1. 性能分解

```text
启动与导入
配置和 Inventory
DNS/TCP/TLS/连接池
下游响应
重试和退避
序列化与压缩
文件写入
CPU 和内存
```

记录目标规模、缓存状态、并发、错误率和依赖版本，否则两次结果不可比较。

## 2. 基准测试

```python
from time import perf_counter

started = perf_counter()
result = run_operation()
elapsed = perf_counter() - started
```

微基准使用标准库 `timeit`；系统基准需要固定输入和环境并多次运行。不要用一次终端计时得出容量结论。

## 3. CPU Profiling

```bash
python -m cProfile -o profile.out -m ops_audit scan --config lab.json
python -m pstats profile.out
```

Profile 会增加开销，结果反映本次工作负载。先确认高耗时函数是在 CPU 计算还是等待外部 I/O。

## 4. 内存

```python
import tracemalloc

tracemalloc.start()
run_operation()
current, peak = tracemalloc.get_traced_memory()
```

目标很多时使用生成器、分页和流式 JSON Lines，避免把全部对象、响应体和日志同时保存在内存。

进程 RSS 还包含 Python 分配器、原生库和内存映射，不能只看 `tracemalloc`。

## 5. 缓存

缓存必须定义：

- Key 包含哪些配置和身份范围。
- TTL 和数据新鲜度。
- 失败是否缓存。
- 权限变更后如何失效。
- 多进程/多节点一致性。

诊断工具输出必须标记缓存时间，不能把旧结果当当前状态。

## 6. 构建 Wheel

```bash
python -m build
python -m pip install --force-reinstall dist/*.whl
```

构建在干净、固定依赖环境中进行。测试最终 Wheel，而不是只测试源码目录。保存文件 Hash、源码 Commit、构建器版本和依赖清单。

## 7. 容器交付

容器注意：

- 固定基础镜像 Digest。
- 使用非 root 用户。
- 构建阶段与运行阶段分离。
- 不把编译缓存和凭据带入最终层。
- 只安装运行依赖。
- 设置只读根文件系统和最小 Capability。
- 支持 SIGTERM 与有限退出时间。

镜像标签是可变名称，部署证据记录 Digest。

## 8. 供应链

```text
受保护源码
→ 锁定构建依赖
→ 干净构建
→ 单测/集成/安全扫描
→ Wheel 或镜像
→ SBOM 和来源证明
→ 签名
→ 按 Digest 晋级
```

审查 Typosquatting、Dependency Confusion、恶意构建后端和不可信包索引。构建环境不得无条件执行来自外部合并请求的代码并持有生产凭据。

## 9. 发布与兼容

版本变化包括：

- CLI 参数和默认值。
- JSON Schema。
- 配置文件 Schema。
- 插件 API。
- Python 最低版本。
- 外部 API 兼容范围。

发布说明必须记录不兼容变化、迁移和回退。旧制品保留期应覆盖生产回滚窗口。

## 10. 容量验收

- [ ] 分别测量下游等待、CPU、内存和写盘。
- [ ] 并发提升没有造成 429 和重试风暴。
- [ ] 结果可以流式处理并限制最大规模。
- [ ] 最终制品在干净环境安装和运行。
- [ ] 制品关联 Commit、依赖、SBOM、测试和 Digest。
- [ ] 旧版本仍可在回滚窗口内取得并验证。
