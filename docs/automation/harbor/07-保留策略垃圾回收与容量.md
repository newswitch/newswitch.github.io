# Harbor 保留策略、垃圾回收与容量

## 1. 为什么删除后空间不立即下降

多个 Manifest 可能引用同一 Layer。删除 Tag 或 Artifact 后，Blob 只有在没有任何有效引用并完成垃圾回收后才可释放。对象存储版本控制和生命周期还可能让账单空间继续保留。

```text
保留策略选择 Artifact
→ 删除未保留的引用
→ 形成无引用 Blob
→ GC 扫描并删除
→ 存储端版本/生命周期最终释放
```

## 2. 保留策略设计

从业务语义出发组合规则：

- 永久保留发布、合规和基线 Tag；
- 保留每个服务最近 N 个成功构建；
- 临时分支/PR 制品按天数过期；
- 保留当前运行 Digest 及可回滚窗口；
- 生产项目启用不可变，删除走审批；
- 先 Dry Run 并审查命中集合。

规则优先级和 OR/AND 语义要通过测试项目验证，不能凭名字推断。

## 3. 容量模型

```text
净新增 Layer/天
× 保留天数
× 地域副本数
+ 上传临时空间
+ 扫描与元数据
+ GC 延迟余量
+ 存储版本开销
```

关注每日净增长、物理/逻辑容量、最大 Repository、上传失败率、GC 时长和未引用数据趋势。只看磁盘使用率会发现得太晚。

## 4. GC 安全

- 在维护窗口运行，确认版本支持的在线/只读行为。
- GC 前备份元数据并确认对象存储保护策略。
- 避免与大规模 Push、复制、保留任务同时争用。
- 先评估可回收量，再监控 Registry、Jobservice 和存储错误。
- 完成后抽样 Pull 关键 Digest，并对比存储实际变化。

## 5. 容量告警

告警应基于耗尽时间而不只固定阈值。例如按过去 7 天增长率预测 30 天内耗尽，并同时提示是构建量增加、保留失效、GC 未运行，还是对象存储版本未清理。
