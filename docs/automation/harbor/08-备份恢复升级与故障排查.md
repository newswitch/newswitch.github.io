# Harbor 备份、恢复、升级与故障排查

## 1. 备份对象

| 对象 | 作用 | 注意事项 |
| --- | --- | --- |
| PostgreSQL | 项目、用户、策略和制品元数据 | 与制品存储保持可解释的一致点 |
| Registry 存储 | Manifest、Config 和 Layer | 大容量、对象版本与校验 |
| Harbor 配置 | 外部地址、认证、扫描、复制等 | 配置版本与软件版本绑定 |
| Secret/证书 | 数据库、Redis、TLS 和加密相关材料 | 独立加密保管和访问审计 |

只备份数据库会恢复出指向不存在 Blob 的元数据；只复制对象存储也无法恢复用户、策略和任务状态。

## 2. 恢复演练

1. 在隔离环境部署兼容版本和依赖。
2. 恢复 Secret、配置、数据库和制品存储。
3. 校验项目、权限、Repository、Tag 与 Digest 数量。
4. 抽样执行匿名/认证 Pull、Push、扫描和复制。
5. 校验关键生产 Digest、签名和 SBOM。
6. 记录实际 RTO/RPO、人工步骤和缺失监控。

备份成功日志不能替代恢复演练。

## 3. 升级方法

- 阅读目标版本升级路径、破坏性变更和依赖要求。
- 备份并在预生产用生产数据副本演练。
- 检查 Helm Values/Installer 配置差异和数据库迁移。
- 暂停高风险管理操作，升级后执行端到端冒烟。
- 保留可执行回退方案；数据库已迁移时不能只回滚镜像版本。

## 4. 分层故障树

```text
客户端错误
├── DNS/TCP/TLS/代理
├── 认证挑战/Token/RBAC
├── Core/Portal/API
├── Registry/Controller
├── PostgreSQL/Redis
├── 对象存储
└── Jobservice/扫描/复制/GC
```

先用时间、请求 ID、Repository 和 Digest 收窄范围。对照健康请求，检查状态码、延迟、队列、连接池、存储限流和组件版本。

## 5. 常见现象

| 现象 | 优先检查 |
| --- | --- |
| 登录循环/Token 失败 | 外部 URL、代理头、时间、Core、Redis |
| 小镜像成功大镜像失败 | 代理超时、Body 限制、存储和链路 |
| Push 成功但看不到/扫描不跑 | Manifest 提交、Jobservice、扫描器 |
| Pull 偶发 5xx | Registry 副本、共享存储、LB、连接池 |
| 删除后空间不降 | 保留/GC、共享 Layer、对象版本 |
