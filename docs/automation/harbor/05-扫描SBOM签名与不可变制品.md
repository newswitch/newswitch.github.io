# Harbor 扫描、SBOM、签名与不可变制品

## 1. 五种能力解决不同问题

| 能力 | 回答的问题 | 不能独自证明什么 |
| --- | --- | --- |
| Digest | 内容是否相同 | 谁构建、是否可信 |
| SBOM | 包含哪些组件 | 组件当前是否有漏洞 |
| 漏洞扫描 | 漏洞库认为有哪些已知风险 | 没有未知漏洞或运行时不可利用 |
| 签名/证明 | 谁对哪个 Digest 作出声明 | 签名者的构建过程一定安全 |
| 不可变规则 | Tag 是否可被覆盖 | 初次上传的内容一定正确 |

## 2. 推荐链路

```text
受控源码提交
→ 隔离构建
→ 生成镜像 Digest 与 SBOM
→ 扫描并按策略评估
→ 签名 Digest、附加来源证明
→ 推入受保护项目
→ Admission 验证签名、来源和策略
→ 按 Digest 部署
```

## 3. 扫描策略

扫描器漏洞库必须持续更新并监控更新时间。门禁应考虑严重级别、修复版本、是否在运行路径、临时豁免责任人和过期时间。不要只用“高危数量大于零就永久阻塞”，也不要为了交付全部忽略。

基础镜像更新后应触发下游重建。旧的扫描结果需要随漏洞库变化重新评估，而不是一次通过永久有效。

## 4. 签名密钥

- 优先短期 OIDC 身份或受 HSM/KMS 保护的密钥。
- 私钥不进入 Runner 文件系统、仓库和普通变量。
- 记录证书、透明日志或证明验证证据。
- 明确密钥轮换、吊销和历史制品验证方式。
- 验证策略绑定仓库、签名者、工作流和 Digest，不能只检查“存在任意签名”。

## 5. 误区

“Harbor 扫描通过”不等于生产准入完成。最终准入通常由 Kubernetes Admission/策略引擎执行，并校验制品不可变身份和可信证明；Harbor 负责保存、发现和提供相关元数据。
