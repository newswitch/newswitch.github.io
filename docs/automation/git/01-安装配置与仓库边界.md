# Git 安装、配置与仓库边界

Git 的第一个生产问题通常不是合并冲突，而是“不知道当前命令读了哪份配置、使用了哪个身份、操作了哪个仓库”。安装后不要急着全局复制一组配置，先建立作用域意识。

## 1. 确认程序与帮助来源

```bash
git --version
git --exec-path
git help -a
git help config
```

文章讲解语义，当前安装版本支持的完整参数以 `git help <command>` 为准。

## 2. 配置作用域

常见作用域由低到高包括系统、全局、仓库本地和命令级配置。最终值可能来自多个文件：

```bash
git config --list --show-origin --show-scope
git config --get-regexp '^(user|core|init|pull|fetch)\.'
```

| 作用域 | 常见位置 | 适合内容 |
| --- | --- | --- |
| system | 系统 Git 配置 | 组织统一的基础默认值 |
| global | 用户配置 | 个人身份、编辑器、常用行为 |
| local | `.git/config` | 当前仓库的远端和特殊设置 |
| worktree | 工作树配置 | 多 Worktree 的差异化设置 |
| command | `git -c key=value` | 单次、显式、可审计的覆盖 |

排障时先看来源，不要只看最终值。

## 3. 提交身份不是访问权限

```bash
git config --global user.name "Example User"
git config --global user.email "user@example.invalid"
```

`user.name` 和 `user.email` 写入 Commit 的作者/提交者元数据，不负责远端认证。SSH Key、HTTPS Token、OIDC 或部署凭据才决定是否能访问远端。

自动化账号应使用独立身份，不与个人凭据混用。不同组织身份可以通过仓库本地配置或条件包含管理：

```ini
[includeIf "gitdir:~/work/company/"]
    path = ~/.gitconfig-company
```

## 4. 初始化和克隆

创建新仓库：

```bash
git init --initial-branch=main automation-demo
cd automation-demo
git rev-parse --show-toplevel
git status --short --branch
```

克隆已有仓库：

```bash
git clone https://example.invalid/team/automation-demo.git
git -C automation-demo remote -v
```

`clone` 通常完成四件事：创建本地仓库、配置 `origin`、获取对象与引用、检出默认分支。它不是简单下载目录。

## 5. 普通仓库与 Bare 仓库

| 类型 | 工作区 | 常见用途 |
| --- | --- | --- |
| 普通仓库 | 有 | 开发、审查和构建 |
| Bare 仓库 | 无，仓库数据位于目录本身 | 远端中转或服务器端仓库 |

本地模拟远端：

```bash
mkdir remote.git
git -C remote.git init --bare --initial-branch=main
git remote add origin ../remote.git
```

生产团队通常使用 GitLab、GitHub 或 Gitea，而不是直接把 Bare 仓库暴露给多人 SSH 写入。

## 6. 换行符与文件模式

跨平台仓库应优先用 `.gitattributes` 声明仓库策略：

```gitattributes
* text=auto
*.sh text eol=lf
*.ps1 text eol=crlf
*.png binary
```

检查实际属性：

```bash
git check-attr --all -- scripts/deploy.sh
```

不要在不了解现有团队策略时随意修改 `core.autocrlf`。属性规则进入版本控制，比依赖每个开发者的全局配置更容易审计。

Linux 仓库还要理解 `core.fileMode`：Git 主要跟踪可执行位，不跟踪完整 POSIX 权限。

## 7. 仓库边界与发现

```bash
git rev-parse --show-toplevel
git rev-parse --git-dir
git rev-parse --is-inside-work-tree
```

Git 会从当前目录向上发现仓库。自动化脚本应显式确认仓库根目录，避免在意外仓库中执行提交或清理命令：

```bash
repo_root=$(git rev-parse --show-toplevel) || exit 2
printf 'repository=%s\n' "$repo_root"
```

## 8. 最小验收

```bash
printf '# automation-demo\n' > README.md
git add README.md
git commit -m "docs: initialize repository"
git show --stat --oneline HEAD
git config --list --show-origin --show-scope
```

验收时确认提交身份、默认分支、文件换行符和配置来源都符合预期。
