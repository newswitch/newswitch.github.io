# Argo Workflows 重试、超时、同步、退出与幂等

## 1. 重试先分类

| 故障 | 是否重试 | 示例 |
| --- | --- | --- |
| 瞬时基础设施错误 | 有限重试 | 节点短暂不可用、对象存储 503 |
| 限流 | 遵循 Retry-After 并退避 | API 429 |
| 确定性输入/代码错误 | 不重试 | Schema 错误、依赖不存在 |
| 外部副作用结果未知 | 先查询再决策 | 请求超时但订单可能已创建 |

配置次数、退避、最大间隔和重试条件。无限重试会占用资源并隐藏故障。

## 2. 四类时间边界

- 单个容器命令超时；
- Template 活动期限；
- 整个 Workflow 截止时间；
- 等待资源、审批或锁的超时。

取消时容器需处理终止信号、停止新工作、保存可恢复检查点并在 Grace Period 内退出。

## 3. 同步与互斥

对数据库迁移、单模型发布等不可并行操作使用 Mutex/Semaphore。但锁只控制 Argo 调度，不替代外部系统的并发控制。锁名应包含环境/资源标识，等待有上限，异常后能确认锁状态。

## 4. 幂等键

每次业务操作使用稳定键，例如 `dataset-version + model-config + workflow-purpose`。任务开始先查询结果：存在且校验通过则复用；存在部分结果则清理或续跑；未知状态则停止并人工确认。

## 5. Exit Handler 与 Hook

Exit Handler 适合发送最终通知、释放临时资源和汇总状态，但它也可能失败。清理操作要幂等、可重复并有独立告警。不要依赖 Exit Handler 删除唯一诊断证据。

## 6. 故障注入

测试 Pod 被驱逐、Controller 重启、对象存储超时、API 限流、任务执行后响应丢失和取消。验收标准不是最终“绿了”，而是没有重复副作用、无泄漏资源、状态可解释。
