# Rundeck 重试、超时、并发、错误处理与幂等

## 1. 部分失败模型

批量 Job 可能 100 台成功 97 台。定义成功阈值、是否立即停止、失败节点如何重试、已成功节点是否重复，以及最终报告如何表达 Partial Success。

## 2. 重试分类

| 故障 | 处理 |
| --- | --- |
| 连接超时、429、短时 5xx | 有限退避、抖动 |
| 权限、参数、脚本语法 | 不重试，直接修复 |
| 远端执行后响应丢失 | 查询实际状态再决策 |
| 节点不可达 | 标记并按批次策略继续/停止 |

Rundeck 级重跑可能重复整个 Workflow，优先让危险 Step 自身幂等。

## 3. 超时层级

连接、命令、Step、Job 和外部任务都要有时间边界。取消后远端进程是否仍运行需要验证；仅将 Execution 标记 Aborted 不一定终止目标副作用。

## 4. 并发与批次

线程数受 Rundeck Worker、网络、目标 CPU、数据库和外部 API 配额共同限制。生产发布按故障域小批执行，每批健康验证后推进；设置最大目标数和失败比例。

## 5. 幂等模式

- 读取实际状态，仅在有差异时修改；
- 使用 Execution/事件 ID 作为外部幂等键；
- 原子写临时文件再替换；
- 发布按不可变 Digest；
- 数据库操作有迁移记录/锁；
- 不可逆操作前保存备份和审批证据。

## 6. 错误处理

Error Handler 可清理、收集证据、释放锁和通知，但自身也可能失败。清理可重复，不删除唯一日志；补偿不假装强事务，记录需要人工处理的残留。

## 7. 故障注入

测试中途断网、节点重启、Rundeck Server 重启、命令成功但回执丢失、取消、锁超时和日志存储失败。验收结果是状态可解释且无重复破坏。
