# Rundeck 日志、指标、容量与故障排查

## 1. 时间拆分

```text
触发/审批等待
+ Execution 排队
+ Node Source/Filter
+ 连接与文件传输
+ 远端执行
+ 日志回传
+ Workflow 聚合/通知
```

总时长高但 CPU 低，可能是审批、目标网络或日志存储，不应只扩 Rundeck 节点。

## 2. 指标

- Job 成功、失败、取消、超时和 P95；
- 排队深度、执行线程、并发和调度延迟；
- Node 成功率、连接/命令耗时和失败分布；
- 插件调用、外部 API、429/5xx；
- 数据库连接池、查询和容量；
- 日志上传延迟、积压、失败和磁盘；
- 按团队/项目/风险级别的执行量。

Job/Node 名称可能高基数，指标用受控标签，详细 ID 放日志。

## 3. 故障树

```text
Job 未按预期完成
├── 触发/Schedule/Webhook/API/ACL
├── Job版本/Option/Node Filter
├── Queue/Thread/HA调度
├── Executor/网络/认证/权限
├── 远端脚本/退出码/部分失败
├── Key Storage/Vault/外部API
├── 数据库/日志存储/插件
└── 通知/回调/状态聚合
```

## 4. 证据

记录 Execution ID、Job UUID/版本、触发身份、Options 脱敏摘要、实际节点快照、失败 Step、插件版本、状态码、外部 Request ID 和日志存储位置。

## 5. 容量压测

使用隔离节点模拟真实 Job 长度、输出量和失败率，逐步增加并发。观察线程、内存、数据库、日志写入、SSH 连接、外部 API 和目标负载的拐点。设置平台、Project、Job 和下游四层上限。

## 6. 日志安全

脚本禁用敏感调试，平台配置掩码和访问控制。日志外发前脱敏，保留期按审计和成本分级。检测私钥、Token 和密码模式并触发泄漏响应。
