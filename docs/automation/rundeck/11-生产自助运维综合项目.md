# Rundeck 生产自助运维综合项目

## 1. 目标

将“重启服务”“采集诊断证据”“扩容节点”做成受控 Job。应用团队能处理低风险操作，但不能修改命令、扩大目标或获得生产凭据。

## 2. Job 分层

```text
01-diagnose（只读、自动）
→ 获取 Owner/环境/当前状态
→ 采集 CPU、网络、日志、Kubernetes Event
→ 生成证据包

02-restart（写操作、审批）
→ 验证告警与变更窗口
→ 小批重启
→ 健康门禁
→ 推进或回滚

03-scale（IaC/GitOps PR）
→ 生成差异和容量证据
→ 审批
→ 外部流水线执行
```

## 3. 输入与权限

用户只选择其拥有的 Service、Environment 和允许动作。Node Filter 由 Catalog/CMDB 解析并限制最大目标数。生产写 Job 绑定 On-call/审批组；Rundeck 使用 Vault 动态身份或受限 ServiceAccount。

## 4. 可靠性

- 每次 Execution 创建业务幂等键和目标快照；
- 按故障域小批执行，失败比例超过阈值停止；
- 重启前后检查真实健康和 SLO，而不只看进程；
- 取消后查询远端状态；
- 清理/回滚可重复且保留证据；
- 外部 API 有超时、限速和有限退避。

## 5. 审计页面

展示申请人、审批人、Job Git 版本、Options、实际目标、凭据路径、每节点结果、制品/配置版本、健康指标和关联事故/变更号。Secret 全部脱敏。

## 6. 故障演练

- CMDB 返回过多节点，最大目标数阻断；
- 一批节点失败，Workflow 停止且不重做成功节点；
- Vault 暂时不可用，Job Fail Closed；
- Rundeck Server 重启，Execution 状态可解释；
- 健康指标恶化，自动停止并回滚；
- 重复 Webhook 使用同一事件 ID，不创建第二次操作。

## 7. 验收

交付权限矩阵、Job 源码、目标规则、容量报告、Runbook、恢复演练和 Toil 指标。自助化后的事故率、平均执行时间和人工升级率持续观察，不能只统计运行次数。
