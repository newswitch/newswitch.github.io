# AI 平台安全从零到生产学习路线

AI 平台同时处理高价值模型权重、训练数据、通用代码执行和昂贵加速器。安全设计不能只停留在 Kubernetes RBAC，还要覆盖设备、网络、制品、缓存和推理协议。

```text
身份与API
→ 调度与Pod
→ 容器与设备
→ GPU/NPU与RDMA
→ Dataset/Model/Checkpoint
→ 推理Endpoint
→ 日志、审计和检测
```

## 2. 保护目标

| 资产 | 主要风险 |
| --- | --- |
| 模型权重 | 未授权下载、缓存泄漏、恶意替换 |
| Dataset | 越权读取、污染、跨租户泄漏 |
| Checkpoint | 泄漏训练状态、回滚到恶意版本 |
| GPU/NPU | 跨租户访问、DoS、设备状态残留 |
| RDMA Fabric | 绕过主机网络策略、错误 VF/队列暴露 |
| 推理 API | Token 消耗攻击、越权模型、流式连接耗尽 |
| 控制面身份 | 高权限 Token 泄漏、Controller 越权 |

## 3. 完成标准

- 能画出用户、平台、节点、训练/推理任务和外部存储之间的信任边界；
- 能把人身份、工作负载身份和节点身份分离；
- 能验证模型来源、Digest、签名和反序列化边界；
- 能解释 MIG、MPS、整卡、vGPU 的隔离差异；
- 能设计 RDMA VF、Namespace、NetworkAttachment 和交换 Fabric 的租户边界；
- 能限制设备、HostPath、Syscall 和 Linux Capability；
- 能将一个可疑推理请求关联到身份、模型、副本、GPU 和审计日志。
