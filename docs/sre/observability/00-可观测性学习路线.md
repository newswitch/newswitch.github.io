# 可观测性学习路线

AI Infra 的可观测性需要跨越多层信号：

```text
业务请求与 SLO
→ 网关排队和模型服务批处理
→ Pod、节点与调度事件
→ GPU 利用率、显存、功耗、Xid
→ 网络吞吐、丢包、RDMA 计数器
→ 存储延迟、吞吐与队列深度
```

## 1. 四条学习主线

| 主线 | 首先要回答的问题 | 学习入口 |
| --- | --- | --- |
| 指标、规则与告警 | 指标如何产生、抓取、存储、查询，并形成可操作告警 | [Prometheus 监控体系学习路线](./prometheus/00-Prometheus监控体系学习路线.md) |
| 日志、Trace 与统一采集 | 一次请求怎样携带上下文，Logs、Metrics、Traces 如何汇合 | [日志、链路追踪与 OpenTelemetry 学习路线](./telemetry/00-日志链路追踪与OpenTelemetry学习路线.md) |
| GPU 与 AI 服务 | GPU 指标怎样与 TTFT、TPOT、吞吐和请求失败关联 | [GPU 可观测性](./gpu/01-DCGM%20Exporter%20GPU%20监控指标详解.md) |
| Kubernetes | 告警怎样下钻到工作负载、Pod、节点和控制面事件 | [Kubernetes 可观测性](./kubernetes/00-本章导读.md) |

## 2. 推荐顺序

1. 先理解 Counter、Gauge、Histogram、日志字段、Trace/Span 与上下文传播；
2. 再完成 Prometheus 抓取、PromQL、Recording Rule、Alertmanager 与 Grafana；
3. 学习 OpenTelemetry SDK、OTLP 与 Collector，把应用信号统一接入 Loki、Tempo 和指标后端；
4. 最后进入 GPU 和 Kubernetes 专项，把业务 SLO 与平台资源证据关联起来。

同时使用[可观测性命令参考库](./commands/00-可观测性命令参考库.md)，掌握 `promtool` 规则检查与单元测试、`amtool` 告警路由与 Silence、`logcli` 日志检索和证据导出。最终目标是从一条 SLO 告警快速缩小到具体层级，而不是仅仅收集更多指标。

## 3. 学成后的验收标准

- 能从请求 ID 或 Trace ID 还原一次失败请求的跨组件路径；
- 能区分采集缺失、标签爆炸、远端写入积压与真实业务异常；
- 能设计 SLI、SLO、告警窗口、抑制和分组策略；
- 能把 TTFT 超标定位到排队、推理、GPU、网络或存储中的具体一层；
- 能在观测后端故障时判断业务是否受影响，并恢复遥测管道。
