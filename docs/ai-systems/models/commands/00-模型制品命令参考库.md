# 模型制品命令参考库

模型制品不是一个普通目录。一次可复现发布至少要固定：仓库ID、revision或提交哈希、文件清单、文件大小与哈希、下载工具版本、缓存位置、模型配置和Tokenizer文件。只固定模型名称或使用 `main`、`latest`，无法证明两次部署使用同一份权重。

## 1. 学习顺序 {/* #学习顺序 */}

1. [Hugging Face hf CLI](./01-HuggingFace-hf命令详解.md)：模型和数据集的检索、下载、上传、缓存与鉴权。
2. [Git LFS](./02-Git-LFS命令详解.md)：理解指针文件、LFS对象、fetch/checkout/pull以及缓存清理。

## 2. 模型进入服务的证据链 {/* #模型进入服务的证据链 */}

```text
逻辑模型ID
→ 不可变 revision / commit
→ 文件清单与 LFS/OID
→ 本地缓存 blob 与 snapshot
→ 容器挂载/对象存储路径
→ tokenizer/config/weights
→ 推理服务启动参数
→ 运行实例模型身份指标
```

## 3. 安全边界 {/* #安全边界 */}

- 下载与查询通常只读，但会消耗磁盘、inode、网络和出口流量。
- 登录、上传、创建仓库和删除制品会改变远端状态；令牌不得出现在命令历史、日志和URL中。
- `cache delete/prune`、`git lfs prune` 必须确认没有在线服务通过缓存路径或硬链接引用对象。
- 模型仓库中的自定义代码具有执行风险；下载文件不等于允许 `trust_remote_code`。

## 4. 验收 {/* #验收 */}

能从部署实例反查精确 revision；能区分 LFS 指针与真实对象；能验证缓存是否完整；能构建离线模型包；能在不影响在线实例的情况下回收缓存。
