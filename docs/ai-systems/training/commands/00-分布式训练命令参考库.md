# 分布式训练命令参考库

训练启动器不负责替你证明网络、GPU和代码正确。它们的共同职责，是把一组节点扩展成若干worker进程，为每个进程注入rank/world size等上下文，并监控进程生命周期。排障必须把“调度到哪些节点”“启动了哪些进程”“进程如何会合”“collective卡在哪里”分开。

## 学习顺序

1. [torchrun](./01-torchrun命令详解.md)：掌握PyTorch原生进程拓扑、rendezvous与Elastic。
2. [DeepSpeed](./02-DeepSpeed命令详解.md)：学习hostfile、资源过滤、ZeRO配置与环境报告。
3. [Accelerate](./03-Accelerate命令详解.md)：学习配置生成、环境检查以及对DeepSpeed/FSDP的统一启动。

## 统一概念

| 概念 | 含义 |
|---|---|
| node rank | 节点在作业中的编号 |
| local rank | 进程在本节点的编号，通常映射一张GPU |
| global rank | 进程在整个world中的唯一编号 |
| local world size | 单节点worker数 |
| world size | 全部节点worker总数 |
| rendezvous | 各节点发现成员并形成worker group的会合过程 |
| agent | 启动与监控本节点worker的父进程 |

## 固定排障顺序

```text
调度对象/Pod与节点
→ 镜像、代码、模型与数据revision
→ GPU与网卡可见性
→ MASTER_ADDR/PORT或rdzv端点
→ rank与world size
→ 进程是否全部启动
→ NCCL bootstrap与拓扑
→ 第一个collective
→ checkpoint与重启语义
```

## 安全边界

启动器命令属于主动负载，会占用全部指定GPU、CPU、网络和存储。先在单机小模型/小数据上验证，再逐步扩大world；调试变量会产生大量日志，必须设置时间窗与保留策略；Elastic重启不等于业务级从checkpoint恢复。

## 验收

能从任一rank日志还原world；能定位是调度、rendezvous、worker启动还是collective卡住；能证明每个rank使用唯一GPU；能解释重启、失败和checkpoint之间的关系。
