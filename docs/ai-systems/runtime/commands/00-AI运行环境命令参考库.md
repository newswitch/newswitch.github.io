# AI 运行环境命令参考库

AI 作业报错时，日志里的 `CUDA unavailable`、`undefined symbol` 或 `No module named` 只是表象。排障前必须先回答四个问题：当前进程由哪个 Python 启动、包从哪里导入、解析到哪一组依赖、动态链接器最终装载了哪一个 CUDA/NCCL/cuDNN 库。

```text
Shell PATH
→ Python 可执行文件与 sys.path
→ site-packages 中的发行包
→ PyTorch / 推理框架的二进制扩展
→ ELF 的 NEEDED 与 RPATH/RUNPATH
→ ld.so 搜索路径
→ libcuda / libcudart / NCCL / cuDNN
→ 内核驱动与 GPU
```

## 1. 学习顺序 {/* #学习顺序 */}

1. [Python 与 pip 运行环境诊断](./01-Python与pip运行环境诊断.md)：先确认解释器、导入路径、包元数据和依赖一致性。
2. [uv 与 Conda 环境管理](./02-uv与Conda环境管理.md)：再学习创建、锁定、导出和复现环境。
3. [ldd、ldconfig、readelf 与 objdump](./03-动态链接库诊断命令详解.md)：最后定位 CUDA/NCCL/cuDNN 的 ABI 与装载问题。

## 2. 固定取证顺序 {/* #固定取证顺序 */}

```bash
type -a python python3 pip
python -VV
python -c 'import sys; print(sys.executable); print("\n".join(sys.path))'
python -m pip --version
python -m pip check
python -m pip inspect > pip-inspect.json
python -c 'import torch; print(torch.__file__); print(torch.__version__); print(torch.version.cuda)'
```

若 Python 能导入框架但 CUDA 扩展报错，再进入 ELF 和动态链接器检查；不要一开始就重新安装驱动。

## 3. 安全边界 {/* #安全边界 */}

| 等级 | 操作 | 规则 |
|---|---|---|
| R | `--version`、`show`、`list`、`inspect`、`ldd`、`readelf` | 可直接取证，但避免输出令牌和私有索引地址 |
| W | 安装、升级、同步、修改环境 | 先记录锁文件、解释器路径与现有包清单 |
| D | 删除环境、清理全部缓存 | 确认没有在线进程引用，保留可重建依据 |

## 4. 模块验收 {/* #模块验收 */}

- 能证明当前 Shell、Notebook、systemd 服务和容器分别使用哪个解释器。
- 能区分“发行包版本”“导入模块路径”和“二进制实际链接库”。
- 能生成可审计的依赖快照并在干净环境中复现。
- 能解释 `LD_LIBRARY_PATH`、RPATH、RUNPATH 与 `ld.so.cache` 的优先关系。
- 遇到 `undefined symbol` 时能定位缺少符号的调用方与提供方，而不是盲目重装。
