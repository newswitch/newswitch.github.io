# 线上质量漂移与反馈回流闭环

模型上线不是生命周期结束。即使权重不变，用户、Prompt、工具、知识库和业务目标都会变化：

```text
线上请求与结果
→ 质量/安全/性能信号
→ 采样与脱敏
→ 人工/规则/模型评审
→ 问题聚类与根因
→ 新评测集或训练数据
→ 候选模型/模板/RAG变更
→ 离线门禁与灰度
```

反馈闭环的目标不是“自动收集所有对话再训练”，而是形成可审计、低偏差、保护隐私的改进流程。

## 1. 三类线上变化

### 1.1 输入漂移 {/* #输入漂移 */}

Prompt语言、长度、主题、Tool使用和多轮深度发生变化。

### 1.2 概念/目标漂移 {/* #概念目标漂移 */}

同样输入的正确答案或业务策略发生变化，例如产品规则、法规、知识和工具接口更新。

### 1.3 系统漂移 {/* #系统漂移 */}

模型没变，但Tokenizer、模板、推理引擎、量化、RAG索引、工具或路由变化造成输出和性能变化。

三类漂移的修复不同：不一定都需要重新训练模型。

## 2. 观测维度

| 维度 | 信号 |
| --- | --- |
| 性能 | TTFT、TPOT、E2E、错误率、成本 |
| 输入 | Token长度、语言、主题、工具、租户分布 |
| 输出 | 长度、拒答、格式、工具调用成功率 |
| 质量 | 正确性、相关性、完整性、事实性 |
| 安全 | 越权、敏感信息、提示注入、违规内容 |
| 业务 | 任务完成率、人工接管、转化、用户修正 |

平均分数会掩盖某个高风险切片，应按业务场景和版本分组。

## 3. 没有即时标签怎么办

LLM任务经常缺少实时真值，可以组合：

- 用户显式反馈；
- 用户是否重复提问或立即修正；
- 工具执行结果；
- 格式/Schema校验；
- 规则与知识库一致性；
- 抽样人工评审；
- 多评审器模型评分；
- 延迟业务结果。

代理指标只能作为证据之一。例如“用户没有点差评”不等于答案正确。

## 4. 版本是所有分析的前提

每条被采样记录至少关联：

```text
served_model/release_id
模型与Tokenizer Revision
Chat Template/Prompt版本
推理引擎与参数摘要
RAG索引和Embedding版本
Tool定义版本
路由/实验组
请求时间与业务切片
```

否则无法判断质量变化来自模型、Prompt、知识库还是引擎。

## 5. 隐私与最小化

默认不应把全部原始Prompt/Response无限期保存。设计：

- 业务允许的采样率；
- PII识别、脱敏或Token化；
- 敏感租户不进入训练回流；
- 分级访问、审计和保留期；
- 用户删除与退出机制；
- 加密传输和存储；
- 人工标注平台不暴露多余字段；
- 训练前再次进行数据治理。

指标尽量使用聚合统计，原始内容进入受控数据域。

## 6. 反馈偏差

用户反馈不是随机样本：

- 极好/极差结果更容易被评价；
- 不同用户群反馈习惯不同；
- 人工标注规则可能漂移；
- 模型评审器偏爱特定文风；
- 只回流失败样本可能让模型过度优化少数场景。

需要保存采样策略和倾向权重，维持稳定对照集，并定期做评审者一致性分析。

## 7. 问题先归因再选择修复层

| 问题 | 可能优先修复 |
| --- | --- |
| 知识过期 | RAG语料/索引 |
| 工具参数错误 | Tool Schema、模板、Parser、训练 |
| 格式不稳定 | Structured Output、模板、评测 |
| 领域能力不足 | 微调/继续训练/更强模型 |
| TTFT恶化 | 容量、调度、输入长度 |
| 量化后质量降 | 量化制品/校准 |
| 某版本拒答增加 | Safety/Prompt/模型版本回归 |

不要把所有线上问题都转成训练数据。

## 8. 构建线上评测集

```text
线上采样
→ 脱敏和去重
→ 问题聚类
→ 分层抽样
→ 人工确认输入与期望
→ 冻结Evaluation Snapshot
→ 记录来源、许可和摘要
```

评测集应包含：

- 稳定核心集；
- 新发现回归集；
- 安全红队集；
- 长尾和边界集；
- 性能Token分布；
- 不同租户/语言/领域切片。

## 9. 再训练或优化流水线

```text
问题获得足够证据
→ 确定修复层
→ 生成候选变更
→ 离线质量/安全/性能门禁
→ Shadow
→ Canary
→ 按版本在线比较
→ 晋级或回滚
→ 将结果写回问题库
```

线上反馈不能绕过评测和审批直接触发自动训练并全量发布。

## 10. 漂移检测

可监控：

- Token长度Histogram；
- 语言/主题/意图分布；
- Tool调用比例和失败；
- Embedding分布距离；
- 拒答/格式错误/人工接管；
- 按切片质量分；
- 模型与业务结果的时间趋势。

阈值应结合季节性、活动和版本变更。统计显著不一定具有业务意义，业务下降也可能尚未达到统计显著。

## 11. 自动化边界

适合自动：

- 采样、脱敏、去重和聚类；
- 评测集构建候选；
- 离线评测和报告；
- Canary分析与SLO回滚；
- 血缘和审计记录。

需要人工或策略审批：

- 敏感数据进入训练；
- 新许可证或外部数据；
- Safety策略变化；
- 大规模模型自动晋级；
- 无可靠真值的质量结论。

## 12. 闭环验收

```text
[ ] 每条信号关联完整Release坐标
[ ] 原始内容采集有合法性与保留策略
[ ] 反馈偏差和采样策略可解释
[ ] 问题能够归因到模型/Prompt/RAG/工具/系统
[ ] 线上样本转评测集有审核和摘要
[ ] 再训练数据与评测数据防止泄漏
[ ] 候选变更通过质量/安全/性能门禁
[ ] Canary按Revision观测并可自动回滚
[ ] 线上结果回写到问题和血缘系统
```
