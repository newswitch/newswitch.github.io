# 推理服务命令参考库

一次推理发布不是“进程启动成功”就结束。必须证明模型身份、加载参数、GPU拓扑、健康与就绪、协议语义、流式完成率、容量边界和故障恢复均符合预期。

## 学习顺序

1. [vLLM serve](./01-vLLM-Serve命令详解.md)：模型、显存、并行和服务进程。
2. [AI HTTP与gRPC接口诊断](./02-AI-HTTP与gRPC接口诊断.md)：健康、模型元数据、流式响应和超时边界。
3. [vLLM bench](./03-vLLM-Bench命令详解.md)：用目标Token分布建立吞吐、延迟和Goodput曲线。
4. [GenAI-Perf](./04-GenAI-Perf命令详解.md)：对OpenAI兼容、Triton等端点做统一生成式AI压测。
5. [tritonserver](./05-tritonserver命令详解.md)：模型仓库、控制模式、协议、指标和Trace。
6. [perf_analyzer](./06-perf-analyzer命令详解.md)：Triton并发、请求率和稳定窗口测试。
7. [model-analyzer](./07-model-analyzer命令详解.md)：搜索实例数、动态Batch等配置并生成报告。

## 固定实验条件

每次结果必须携带：模型与revision、Tokenizer与chat template、dtype/量化、GPU型号与数量、驱动/CUDA、服务镜像摘要、TP/PP/DP/EP、显存参数、输入/输出Token分布、并发或到达率、缓存冷热、服务和压测机拓扑。

## 安全边界

- 服务启动和压测都是主动负载；压测只能打到明确授权的环境。
- `trust_remote_code`、动态模型仓库和加载API可能执行仓库代码，只允许受控制品。
- 压测先设最大并发、请求数、超时和停止条件，不能用无限请求率冲击共享网关。
- 日志、请求样本和Trace可能包含Prompt、Token和凭据，默认脱敏并限制保存时间。

## 验收

能区分存活、就绪与业务正确；能解释TTFT、TPOT/ITL、E2E、输出吞吐和Goodput；能得到饱和点而不是单次峰值；能把客户端、排队、模型执行和网络延迟分层。
