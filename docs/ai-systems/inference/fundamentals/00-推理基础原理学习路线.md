# 推理基础原理学习路线

无论使用vLLM、vLLM-Ascend、SGLang还是MindIE，请求进入设备前后的公共语义基本一致。本模块先建立模型与请求的公共语言，再进入各框架源码和生产参数。

## 1. 阅读顺序

| 顺序 | 文章 | 学习成果 |
| --- | --- | --- |
| 1 | [Prompt从输入到输出](./01-Prompt-从输入到输出.md) | 建立请求、Token、Prefill、Decode和输出的整体流程 |
| 2 | [Tokenizer、Chat Template与工具调用](./02-Tokenizer-Chat-Template与工具调用链路.md) | 能从messages追到最终Token，并区分模板与Parser职责 |
| 3 | [Hugging Face模型目录与制品完整性](./03-Hugging-Face模型目录与制品完整性.md) | 能判断权重、配置、Tokenizer和量化文件是否构成完整模型 |
| 4 | [BF16、FP16、INT8与量化制品](./04-BF16-FP16-INT8与量化制品.md) | 能解释精度、内存、Kernel和质量之间的关系 |
| 5 | [Transformer、MoE与Mamba混合模型推理](./05-Transformer-MoE与Mamba混合模型推理.md) | 能按层类型分析状态、计算、通信和Cache |

## 2. 学习时追踪四条线

```text
语义线：messages → 模板 → Token → 输出协议
制品线：config → 权重 → Tokenizer → 量化 → Manifest
计算线：Prefill → Decode → Attention/Mamba/MoE → Sampling
资源线：权重 → Cache → 激活 → Graph → 通信
```

## 3. 掌握标准

- 能打印模板渲染文本和最终Token ID。
- 能解释模型目录每个核心文件的作用并生成Manifest。
- 能说明W8A8名称没有包含哪些关键量化信息。
- 能区分Attention KV与Mamba/SSM状态。
- 能判断一个问题属于模型语义、制品、框架还是硬件执行层。
- 能在进入特定框架前固定模型、Tokenizer、模板和精度坐标。

完成后进入[大模型推理学习路线](../00-大模型推理学习路线.md)，选择目标框架继续学习。
