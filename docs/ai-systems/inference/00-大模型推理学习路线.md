# 大模型推理学习路线

## 1. 理解共同原理 {/* #第一阶段理解共同原理 */}

先学习[推理基础原理](./fundamentals/01-Prompt-从输入到输出.md)，再从
[vLLM 与大模型推理学习路线](./vllm/00-vLLM学习路线.md)建立源码主线，重点掌握：

- 请求从 HTTP、Tokenizer 到首个 Token 的生命周期。
- Prefill、Decode、KV Cache、Continuous Batching 和 PagedAttention。
- TP、PP、DP、EP 的通信与显存代价。

## 2. 分别掌握四套框架 {/* #第二阶段分别掌握四套框架 */}

四套框架都使用相同的学习模板：架构与请求生命周期 → 参数 → 性能与故障。

| 框架 | 学习入口 | 重点 |
|---|---|---|
| vLLM | [vLLM 学习路线](./vllm/00-vLLM学习路线.md) | V1 EngineCore、Scheduler、KVCacheManager、GPUModelRunner |
| vLLM-Ascend | [vLLM-Ascend 学习路线](./vllm-ascend/00-vLLM-Ascend学习路线.md) | Platform Plugin、NPUModelRunner、ACLGraph、CANN、HCCL |
| SGLang | [SGLang 学习路线](./sglang/00-SGLang学习路线.md) | Tokenizer/Scheduler/Detokenizer 管线、RadixAttention、Kernel Backend |
| MindIE | [MindIE 学习路线](./mindie/00-MindIE学习路线.md) | Server、LLM Manager、Text Generator、ATB/CANN |

完成后阅读[vLLM、vLLM-Ascend、SGLang、MindIE 框架对比与选型](./01-vLLM-vLLM-Ascend-SGLang-MindIE框架对比与选型.md)，把组件和参数映射到同一套 Prefill、Decode、KV、Graph 与 SLO 模型。

## 3. 构建生产服务 {/* #第三阶段构建生产服务 */}

继续学习 `serving/` 中的 Kubernetes 部署、显存容量、多卡部署、探针、
优雅退出和指标体系。

## 4. 掌握运维命令与容量验证 {/* #第四阶段掌握运维命令与容量验证 */}

进入[推理服务命令参考库](./commands/00-推理服务命令参考库.md)，依次掌握：

1. vLLM、vLLM-Ascend、SGLang、MindIE 与 Triton 服务端的模型、显存/HBM、并行和安全边界。
2. `curl`、`grpcurl` 对健康、模型身份、SSE完整性和gRPC协议分层验证。
3. `vllm bench`、GenAI-Perf、Perf Analyzer建立TTFT、ITL、吞吐和Goodput容量曲线。
4. Model Analyzer搜索候选配置，再用真实流量和SLO进行二次验证。

学习完成的标准不是“能启动 vLLM”，而是能根据模型、上下文长度、并发目标、
GPU 型号和 SLO 设计容量，并定位请求排队、OOM、NCCL 超时和尾延迟问题。
