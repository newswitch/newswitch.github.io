# Go 学习路线：从基础到原理、工程与排障

本系列先建立语言与类型基础，再理解 I/O、并发与 Runtime，最后使用测试和性能工具验证工程行为。共有 **49 篇技术正文**，与 Gin 系列形成语言到服务的完整路径。精通依赖持续编码、实验与故障分析，不能仅用阅读篇数衡量。

## 1. 版本与实验基线

| 项目 | 基线与说明 |
| --- | --- |
| Go | 1.27.3，go.mod 语言版本 1.27.0 |
| Gin | 1.12.0，仅框架工程依赖 |
| x/sync | 0.23.0，验证 errgroup 的真实取消与准入语义 |
| 语言实验 | examples/go/core-lab，无第三方中间件 |
| 框架工程 | examples/gin/service-lab，默认 SQLite，独立 Worker |
| 外部联调 | PostgreSQL、Redis、Kafka 与 Collector 分别验证，不能由替身测试代替 |

固定版本用于让源码和实验对应，不意味着所有版本内部实现一致。特别注意新版 Map、Timer、泛型方法、JSON 与 GC 的变化；维护旧工程时同时检查工具链和 go.mod。

## 3. 学习顺序与验证

先按语言基础和类型顺序学习；遇到接口、Slice 和错误链时实际修改实验观察结果。随后掌握 Reader/Writer、HTTP 与资源关闭，再进入 Channel、同步和取消。Runtime 章节用于解释调度、分配与 GC，不用实现细节替代语言保证。

工程阶段实际运行表驱动测试、Fuzz 和 Benchmark；诊断阶段生成 CPU、heap、mutex、block 和 trace 文件，学会说明一个热点或等待意味着什么。完成这些后进入 [Gin 学习路线](../gin/00-Gin学习路线.md)，不需要先背完所有 Runtime 字段。

```bash
git clone https://github.com/newswitch/newswitch.github.io.git
cd newswitch.github.io/examples/go/core-lab
go version
go test ./... -count=1 -timeout=60s
```

进入仓库根目录后，可运行 `node scripts/verify-go-gin-labs.mjs --go /path/to/go`，将参数换为实际 Go 1.27.3 可执行文件。完整步骤、Windows 命令与清理说明见 [Go 实验工程](https://github.com/newswitch/newswitch.github.io/tree/main/examples/go/core-lab)。

## 4. 已验证与环境边界

本机测试覆盖有限语言实验、Handler 契约、真实回环 HTTP/SSE、事务失败注入、租约 fencing、三次耗尽恢复、消息确认丢失去重及 OTLP Protobuf 父子关系。独立进程实验验证 Worker 处理与 API 重启后状态保留。

真实 PostgreSQL/Redis/Kafka 联调、Docker/Collector/Kubernetes 运行、Race 与 Linux SIGTERM 排空需在具备条件的环境单独完成。外部联调测试编译成功不是服务已验证；Windows 终止进程也不等于 Unix 优雅退出。

运行时实验通过 trace、相同分配量的 GC 对照及小切片保留案例解释机制；编码实验保持输出字节一致，再比较每操作成本与 CPU 样本。Gin 配套 SQL Session、密钥轮换和事务迁移实验，不承担完整身份提供方、通用工作流或持久事件重放平台的职责。

并发与 HTTP 章节进一步沿固定版本源码解释 Channel 等待队列、Mutex/RWMutex、Once 与 Cond；通过确定交错验证 atomic 不等于事务，通过真实回环 HTTP 验证连接池等待和 Shutdown 边界。逃逸与编译章节把调用点报告、0/1 次分配和循环边界检查对应起来，避免只凭语法猜测优化效果。

生命周期实验覆盖 Context 原因、errgroup 成功与失败取消、SetLimit 阻塞提交、AfterFunc 的停止与 Join 差异，以及流式流水线的处理失败、消费者失败和处理中途取消。有限阻塞实验采集并解除 8 个等待发送者，失败写入 profile 的路径也会先回收任务。

值与协议实验进一步区分 Slice 容量限制与复制、Map 值副本与嵌套共享、接口方法集与 typed nil；I/O 实验对照复制快速路径与上限错误，JSON 实验验证三态字段、重复键、名称匹配和数字精度。使用固定兼容 API 的实测行为，不把内部引擎变化当作协议自动升级。
