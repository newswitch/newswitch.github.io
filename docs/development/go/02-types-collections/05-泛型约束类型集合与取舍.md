# Go 泛型：类型参数、约束、类型集合与适用边界

泛型用于复用带静态类型约束的算法，不是把所有业务对象都抽象为任意类型。先分清接口行为与类型参数，再决定如何减少重复。

## 1. 类型参数与约束

`func Sum[T ~int | ~int64](v []T) T` 中 T 是类型参数，约束给出允许的类型集合。`~int` 包含底层类型为 int 的命名类型，`int` 仅表达该具体类型。运算必须对约束内所有类型有效。

`any` 是空接口别名，不赋予任意运算能力；`comparable` 允许相等比较和作为 Map key，但经由接口承载不适合比较的动态值仍需要谨慎设计。

## 3. Go 1.27 的版本边界

本系列使用 Go 1.27.3。Go 1.27 引入方法自身的类型参数支持，旧文章中“方法绝不能声明自己的类型参数”不能无条件沿用；接口方法仍不能声明类型参数。语言特性是否可用也受 go.mod 的 go 指令约束。

基础实验采用已广泛使用的泛型函数，便于对照旧工程。若维护较旧工具链，不要看到新文档就把新语法直接放入旧模块。

## 4. 如何选择接口或泛型

需要对不同实现调用同一种业务行为时，用小接口；需要在多种元素类型上复用集合算法时，泛型常更自然。约束不等于业务验证，`T ~int` 不保证金额为正，也不避免溢出。

不要把仓储、事务、缓存、权限全部塞入一个多类型参数基类。若抽象导致错误语义不清、测试矩阵爆炸，适量重复通常更可维护。

## 5. 约束给出允许的操作，不只是一张类型名单

约束中的并集表示允许的成员，嵌入多个约束则进一步收窄集合。T ~int | ~int64 允许相应命名整数类型，但不允许任意结构体，仅仅有一个名为 Value 的字段也不够。

函数体必须在约束保证的范围内合法。any 不保证可排序、可相加或存在某个方法；需要调用行为时把方法写进约束，需要顺序比较时选择合适的 ordered 约束。不要用运行期反射掩盖一个本可在编译期表达的要求。

comparable 解决相等操作的类型约束，不自动保证业务身份正确；当类型参数通过接口包含不可比较的动态值时，仍有相应运行期边界。选择明确键类型通常更稳妥。

## 6. 保留命名集合类型与类型推断

```go
func SameTypeMap[S ~[]E, E any](in S, f func(E) E) S {
    if in == nil { return nil }
    out := make(S, len(in))
    for i, v := range in { out[i] = f(v) }
    return out
}
```

S 表示整个切片类型，E 表示元素类型，所以输入 type Counts []int64 时，返回仍是 Counts，而不是退回普通 []int64。~[]E 表达底层切片形状，不能简单删成 []E 后认为所有类型信息相同。

推断依据调用参数与目标上下文，而不是猜业务含义。类型无法从 nil、空实参或歧义上下文推断时，显式给出参数更清楚。nil 与非 nil 空切片的返回策略也应由算法契约决定。

## 7. 方法自己的类型参数需要新的语言基线

foundation.Doubler 的 Twice 方法自己声明 T ~int | ~int64，在 Go 1.27.3、go.mod 的 go 1.27.0 下实际编译并返回 6。这与泛型类型的方法复用其接收者类型参数，是两种相关但不同的声明位置。

Go 1.27 的接口方法仍不能声明自己的类型参数，也不能用泛型方法直接满足普通接口的相应方法要求。维护旧模块时必须核对最低语言版本，不能根据新工具链支持就忽略 go.mod。

可以运行 go run ./cmd/foundation-lab -mode types，核对 named_slice_kept=true 与 generic_method=6；这比只列一段未经编译的新语法更容易发现版本差异。

## 8. 泛型实例化不等于零成本业务抽象

编译器可能结合类型形状共享实现，并通过字典等机制提供类型相关操作；具体布局属于实现，不应在应用中依赖。泛型不保证所有调用都单独生成完整代码，也不保证比接口更快。

比较成本时保证输入、输出、精度和错误语义相同，再看生成代码、分配与端到端比例。一个泛型仓储若把事务、缓存、权限和错误处理都抽成钩子，可能只是把可理解的业务顺序拆散。

适合泛型的常是有稳定性质的容器和算法；适合接口的是可替换行为。可以组合两者，但应让类型参数数量与真实变化维度对应，避免为减少几行重复扩大理解和测试成本。

## 9. 练习与答案

### 9.1 ~int 与 int 相同吗

不同，前者还接纳底层为 int 的命名类型。

### 9.2 any 能直接相加吗

不能，约束没有保证加法适用于所有成员。

### 9.3 泛型可以替代所有接口吗

不能，两者解决的替换与算法复用问题不同。
