# Go 比较、排序与数据建模：从值相等到业务身份

程序里的相等不一定等于业务里的同一对象。集合键、稳定排序、时间和浮点数需要各自的判定规则，才能形成可靠的数据模型。

## 1. 可比较不等于适合当身份

结构体字段全部可比较时，可以使用 == 并作为 Map key；Slice 通常需要 slices.Equal，结构化嵌套数据要明确比较深度。函数除 nil 比较外不支持一般相等比较。

指针相等比较地址，不比较对象内容。把数据库对象的指针作为业务 key，会把同一行的两个加载结果当作不同对象。适合的身份往往是 tenant 与 ID 的组合。

## 2. 复合 key 与排序实验

cd examples/go/core-lab

```text

```

完整实现和断言见 [core-lab](https://github.com/newswitch/newswitch.github.io/tree/main/examples/go/core-lab)。

复合结构体 key 避免手工用冒号连接字符串产生歧义。slices.Sort 修改原 Slice；需要保留输入时先 Clone。排序比较函数必须自洽，不可用有溢出风险的 a-b 草率实现所有整数比较。

## 3. 稳定、时间与金额

稳定排序保持比较相等项原有顺序，但如果输入来自无序 Map，仍不能保证跨次运行稳定。分页排序应有唯一的 tie-breaker，例如创建时间相同再按 ID。

时间用 time.Time.Equal 比较同一时刻，不能把含 Location 和单调钟信息的结构体 == 当作通用语义。金额优先定点整数或明确精度的十进制方案，浮点数的 NaN 与舍入不能靠 == 随意处理。

## 4. 把非法状态限制在边界

使用有意义的命名类型和构造函数表达单位、状态及校验。Go 的命名 string 状态仍可能被显式转换成非法值，入站 JSON、数据库读取与事件消费仍需验证。

业务对象与传输 DTO 不必完全相同。密码散列、租约 token、内部租户字段应从公开 JSON 中排除；这不是单纯把所有字段导出就能解决的。

## 5. 定义相等关系，再选择比较工具

== 适用于可比较类型，但不保证符合业务意义。指针比较对象地址，结构体比较各字段，time.Time 还含表示细节；slices.Equal 按元素比较，Map 和嵌套对象又需要明确更深的规则。

reflect.DeepEqual 可以辅助测试，却不自动定义业务相等：nil Slice 与空 Slice 等细节可能与接口契约不同，数值容差也不会自动出现。金额、测量误差、集合无序与时间时刻应各自写出比较规则。

业务身份常用 tenant+ID；状态相等则还可能包含 version。先区分“同一实体”“同一版本”和“相同展示内容”，才能选择缓存键、幂等依据与更新条件。

## 6. 排序比较函数必须满足一致的顺序

SortFunc 的比较器应对相等、先后与传递性保持一致。用 a-b 返回结果可能整数溢出；跨字段应先比较主键，再比较次键，最后对真正相等返回 0。比较过程中不要修改元素或读取不稳定外部状态。

稳定排序仅保存比较相等项的原输入顺序；若输入本身来自无序 Map，该顺序仍可变化。跨请求分页需要唯一的 tie-breaker，而不是只靠稳定算法。

配套 types 模式按 Score 再按 ID 排序，输出 sorted_ids=["c","a","b"]。同分的 a、b 具有明确次序，不依赖输入偶然顺序。

## 7. 浮点、时间和单位不要混进同一种身份模型

NaN 不等于自身，浮点舍入会使十进制预期与二进制结果不同。排序与相等应该明确 NaN 策略；金融数量优先使用约定精度的表示，不能对所有领域都套固定 epsilon。

time.Time.Equal 比较时刻，== 同时比较表示中的其他信息。数据库和 JSON 往返又可能改变时区或去掉单调钟；不要直接把未经规范化的 Time 当作跨系统身份键。

用命名类型区分秒、毫秒和字节，有助于减少混用，但显式转换仍能制造非法值。构造、解码与持久化边界需要验证，类型命名只是辅助，不是完整校验。

## 8. 从比较规则推导稳定游标与更新条件

分页若按 created_at 排序，时间相同的行可能在多次请求间换序，应使用 (created_at,id) 联合键，并让排序、游标编码和查询条件保持同一方向。游标还要带上必要的租户与过滤上下文约束。

乐观更新不应只比较对象内容“看起来一样”，而是通过 tenant、ID 与 expected_version 的条件更新保证仍作用于读到的版本。幂等键则需要与规范化请求内容关联，防止同一键被悄悄用于不同操作。

这些规则比选择哪个排序函数更重要：先写出稳定身份与不变量，再让比较器、数据库索引、缓存键和协议 DTO 都表达同一套含义。

## 9. 练习与答案

### 9.1 稳定排序能把 Map 输出变成跨次固定顺序吗

仅稳定不足够，还需完整且确定的排序键。

### 9.2 两个对象指针不同代表业务实体不同吗

不代表，业务身份通常由稳定 ID 定义。

### 9.3 JSON DTO 应直接包含全部数据库字段吗

不应，公开契约与内部状态应分离。
