# Go 文件、路径、权限与原子替换：成功写入之后还缺什么

读写配置和落地结果文件不只是 os.WriteFile。路径约束、权限、临时文件、原子可见性与崩溃持久性，需要分别设计。

## 1. 打开、关闭与权限

os.Open 返回需要关闭的文件。os.ReadFile 适合已知大小的小文件；输入不可信时使用有上限的流式读取。Unix 新建文件权限受 umask 影响；Windows 的 ACL 不等同于 0600 的完整语义。

filepath 按本机文件系统处理路径，path 用于斜杠分隔的逻辑路径。HTTP URL 与本地目录不能混用同一套清理规则。

## 2. 临时目录实验


```text

```

完整实现和断言见 [core-lab](https://github.com/newswitch/newswitch.github.io/tree/main/examples/go/core-lab)。

实验创建随机临时目录、写入小文件、读取，再由创建者清理这个确定的目录。它验证基础文件生命周期，不宣称已实现原子替换或断电恢复。

## 3. 原子替换的完整步骤

更新配置常使用：在目标同目录创建临时文件 → 写入全部内容 → 检查写入错误 → 按持久性要求 Sync → 关闭 → Rename 替换 → 按平台语义同步目录。

同文件系统的 Rename 常能提供原子可见性，但各平台对覆盖已有文件、打开句柄和目录同步有差异。跨文件系统移动通常不能假装为一次原子操作。任何中间失败都要保留旧文件并清理自己创建的临时文件。

## 4. 路径穿越与竞态

清理 `../` 字符串不等于完整安全边界，符号链接和检查后使用竞态仍可能越出根目录。Go 的 os.Root 提供根目录限定的文件操作，按版本与平台文档理解其保证；也不能借此接受任意文件类型和无限大小。

上传文件名只作为展示元数据，存储名由服务生成。目录权限、可执行位、文件数、总配额和恶意压缩包展开大小都需要约束。

## 5. 打开方式、游标与关闭责任

Open 只读，Create 可能截断已有文件，OpenFile 允许明确组合创建、追加与权限。不能把 Create 当成“存在则保持原内容”的函数。修改配置前先确定是原地覆盖还是生成新版本，再选择操作。

同一个 *os.File 含有当前偏移；Read、Write 与 Seek 会影响后续基于偏移的操作。ReadAt/WriteAt 适合按明确位置访问，但并发写入相同范围仍需协议，不能因为方法可并发调用就认定业务结果原子。

Close 的所有者默认是创建者；转交给流式下载或解析器时，需要确认谁负责最终关闭。读取成功后写出失败，也要分别处理两个资源，不能只在成功分支关闭文件。

## 6. 原子可见性与崩溃持久性分别验收

直接覆盖目标可能让并发读者看到空文件或部分内容；写同目录临时文件再 Rename，可以在受支持的平台和同一文件系统中组织完整内容的可见切换。

但 Sync 临时文件、关闭它和重命名完成，不代表目录项在突然断电后必然存在。Unix 文件系统通常还需按持久性要求处理目录同步，设备缓存与存储保证也影响最终结果；Windows 对打开句柄与覆盖已有目标有不同约束。

不要在 Rename 失败后先删除旧目标再重试，却仍称为原子替换。那会制造目标不存在的窗口，也改变失败后的恢复条件。生产实现应按目标平台建立替换与恢复契约。

## 7. 路径约束需要约束实际文件操作

filepath.Clean 只做词法整理，无法决定符号链接最终指向哪里。先检查路径再按另一路径打开，检查与使用之间还可能变化；应优先选择受根目录约束的操作 API，并查明其平台保证。

文件名、扩展名与 Content-Type 是元数据，不是内容证明。业务存储名由服务生成；原名只做受控展示，目录权限、文件数、总配额和临时文件保留期分别管理。

权限 0600 只表达 Unix 模式请求，还受 umask 和已有文件影响；Windows ACL 需要相应权限模型。不要把文件权限数字当作跨所有系统的一致访问策略。

## 8. 有限实验能验证到哪一步

```bash
go run ./cmd/foundation-lab -mode resources
go test ./internal/foundation -run TestResources -v -count=1
```

resources 在自建随机临时目录里创建文件，检查 Write、Sync、Close 与 Rename，最后读到 renamed_body="complete" 并清理自己的目录。目标起初不存在，所以该实验只验证这条完整文件生命周期。

它没有验证覆盖已打开目标、跨文件系统移动、目录同步或真实断电恢复。需要持久化承诺时，应在目标操作系统与文件系统上分别建立正常更新、每步失败、进程中断和恢复检查，不能从这次读取成功外推全部存储保证。

## 9. 练习与答案

### 9.1 WriteFile 成功等于断电后文件一定存在吗

不等于，还涉及同步、文件系统与存储设备持久性。

### 9.2 filepath.Clean 能阻止所有越界路径吗

不能，符号链接和竞态需更强的目录边界。

### 9.3 临时文件应放系统任意目录吗

原子替换一般要求放在目标同文件系统，通常为同目录。
