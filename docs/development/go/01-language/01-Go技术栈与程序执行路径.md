# Go 技术栈与程序执行路径

Go 代码不是由 Gin 执行的。源文件先经 Go 工具链编译和链接，再由操作系统装载为进程；Runtime 在进程中管理调度、内存和垃圾回收。先分清这些层次，才能解释编译错误、启动失败与请求失败为何不是一类问题。

## 1. 从源文件到进程

一个目录中的普通源文件组成包，包通过 import 建立依赖。编译器检查类型并生成目标代码，链接器组合所需代码和 Runtime，产物按目标操作系统与 CPU 架构运行。main 包中的 main 函数是普通可执行程序的业务入口，但包变量和 init 已经在它之前初始化。

```text
源码与 go.mod → 包依赖图 → 编译 → 链接 → 可执行文件 → OS 进程 → Runtime → main
```

go run 会先构建再运行，不是解释执行；go build 只生成或检查产物，不证明应用配置、端口与依赖正确。

先看一个完整程序，位于实验工程的 `cmd/hello/main.go`：

```go
package main

import "fmt"

func main() {
    answer := 20 + 22
    fmt.Println("hello, Go")
    fmt.Printf("answer=%d\n", answer)
}
```

package 声明包，import 引入标准库，main 是入口，`:=` 在函数内声明并赋值。运行 `go run ./cmd/hello` 得到两行 `hello, Go` 与 `answer=42`；fmt.Println 自动换行，Printf 按格式输出，`%d` 表示十进制整数。

## 2. 亲自构建并运行

```bash
cd examples/go/core-lab
go run ./cmd/lab -case execution
```

```text
package=main
entry=main.main
result=42
```

这三行是 execution 实验主动打印的教学标记，不是 Go 自动产生的启动日志，也不是对 Runtime 内部初始化顺序的完整追踪。

完整实现见 [core-lab](https://github.com/newswitch/newswitch.github.io/tree/main/examples/go/core-lab)，命令应在仓库根目录进入该工程后执行。

再执行 go build -o out/lab ./cmd/lab，Windows 使用 out/lab.exe 更容易识别产物。运行二进制时仍需 -case execution。比较第一次构建与缓存命中只能说明本机工作量变化，不能用一次耗时给语言性能排名。

## 3. 语言 标准库 Runtime 与框架

语言规范决定类型、求值与同步保证；标准库提供文件、HTTP、测试等接口；Runtime 是具体实现；Gin 组织 HTTP 路由与中间件。一个 Goroutine 在等待 SQL，不能据此说“Gin 没分配 CPU”。先定位实际等待资源，再看相应层。

二进制并非无条件“复制到任何机器就能运行”。GOOS/GOARCH、动态链接、CGO、证书和配置都会影响交付。容器镜像架构也必须匹配宿主平台。

## 4. 练习与答案

### 4.1 go run 成功是否证明交付的二进制可以运行

不能。还要构建目标产物，检查架构、运行依赖和实际配置，再独立启动验证。

### 4.2 程序还没进入 main 就报错可能在哪里

包初始化、动态库装载或 Runtime 启动等阶段。沿报错阶段检查，不先修改 HTTP Handler。

### 4.3 学习 Gin 能否替代学习标准库

不能。Gin 建立在 Go 类型、并发和 net/http 之上，连接、取消和资源关闭仍需要理解底层契约。
