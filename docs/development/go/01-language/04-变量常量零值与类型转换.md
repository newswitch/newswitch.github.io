# Go 变量 常量 零值与类型转换

Go 的零值让变量可以先被安全读取，但零值不一定具有业务有效性。整数、指针、Slice、Map 和接口的零值不同；理解这些差异比机械记住 var 或短变量声明更重要。

## 1. 声明与零值

var 声明可以显式指定类型，短变量声明用于函数内的声明和初始化。数值零值是 0，布尔为 false，字符串为空；指针、Map、Slice、Channel、函数和接口可能为 nil。nil Slice 可以 append，nil Map 可以读取和 delete，却不能直接写入键。

无类型常量在上下文中才确定相应类型，编译期不可表示的转换会失败；运行时变量的整数运算和转换又有不同规则。不能把浮点数转整数当成四舍五入，更不能用普通整数溢出代替金额范围校验。

```go
var retries int             // 0
enabled := true             // bool，短声明仅用于函数内
const secondsPerMinute = 60 // 无类型整数常量
var timeout int64 = secondsPerMinute
small := int8(127)
small++                     // 运行时变为 -128
_ = retries
_ = enabled
_ = timeout
```

这段为函数内语法片段。`_` 是空白标识符，可明确忽略值；真实业务不要为了消除编译错误把重要结果一律丢弃。未使用的局部变量和导入通常会被编译器拒绝，能提前暴露遗漏。

## 2. 观察零值与运行时溢出

```bash
cd examples/go/core-lab
go run ./cmd/lab -case types
```

```text
zero=0 nil=true/true/true
int8=-128
```

完整实现见 [core-lab](https://github.com/newswitch/newswitch.github.io/tree/main/examples/go/core-lab)，命令应在仓库根目录进入该工程后执行。

实验对 int8 变量从 127 自增，得到 -128。若写成无法表示的常量赋值，编译器会直接拒绝，两者不能混说。实际代码应在业务边界检查范围，而不是依赖溢出后的数值判断输入。

## 3. 局部声明与配置缺失

短变量声明中，至少有一个非空白变量是当前作用域的新变量；内部块里相同名字可能创建新对象。配置解析中的 err 被意外遮蔽，可能让外层错误一直为 nil。

JSON 的字段缺失与显式 0 也不同。需要区分时使用指针或明确的可选类型，再校验；不能因 0 是合法 Go 零值就认定它是合法业务数量。

## 4. 练习与答案

### 4.1 nil Map 读取不存在的键会 panic 吗

不会，返回值类型零值及可选的存在标记；向 nil Map 写入才会失败。

### 4.2 int8 的运行时溢出说明常量 128 也能赋给 int8 吗

不能。常量可表示性由编译器检查，不能把运行时结果套用到常量规则。

### 4.3 数量字段为 0 就说明用户传了 0 吗

不一定，可能字段缺失后保留零值。协议需要区分时必须保留存在性信息。
