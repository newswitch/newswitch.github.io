# Go 变量 常量 零值与类型转换

Go 的零值让变量可以先被安全读取，但零值不一定具有业务有效性。整数、指针、Slice、Map 和接口的零值不同；理解这些差异比机械记住 var 或短变量声明更重要。

## 1. 声明与零值

var 声明可以显式指定类型，短变量声明用于函数内的声明和初始化。数值零值是 0，布尔为 false，字符串为空；指针、Map、Slice、Channel、函数和接口可能为 nil。nil Slice 可以 append，nil Map 可以读取和 delete，却不能直接写入键。

无类型常量在上下文中才确定相应类型，编译期不可表示的转换会失败；运行时变量的整数运算和转换又有不同规则。不能把浮点数转整数当成四舍五入，更不能用普通整数溢出代替金额范围校验。

```go
var retries int             // 0
enabled := true             // bool，短声明仅用于函数内
const secondsPerMinute = 60 // 无类型整数常量
var timeout int64 = secondsPerMinute
small := int8(127)
small++                     // 运行时变为 -128
_ = retries
_ = enabled
_ = timeout
```

这段为函数内语法片段。`_` 是空白标识符，可明确忽略值；真实业务不要为了消除编译错误把重要结果一律丢弃。未使用的局部变量和导入通常会被编译器拒绝，能提前暴露遗漏。

## 2. 观察零值与运行时溢出

```bash
cd examples/go/core-lab
go run ./cmd/lab -case types
```

```text
zero=0 nil=true/true/true
int8=-128
```

完整实现见 [core-lab](https://github.com/newswitch/newswitch.github.io/tree/main/examples/go/core-lab)，命令应在仓库根目录进入该工程后执行。

实验对 int8 变量从 127 自增，得到 -128。若写成无法表示的常量赋值，编译器会直接拒绝，两者不能混说。实际代码应在业务边界检查范围，而不是依赖溢出后的数值判断输入。

## 3. 局部声明与配置缺失

短变量声明中，至少有一个非空白变量是当前作用域的新变量；内部块里相同名字可能创建新对象。配置解析中的 err 被意外遮蔽，可能让外层错误一直为 nil。

JSON 的字段缺失与显式 0 也不同。需要区分时使用指针或明确的可选类型，再校验；不能因 0 是合法 Go 零值就认定它是合法业务数量。

## 4. 常量的精度与变量的位宽不是同一层

无类型数值常量可以在编译期保留高精度，但一旦赋给具体类型，就必须能够表示。int 的位宽与目标架构相关；网络协议、数据库字段和文件格式通常应选择明确位宽，并定义单位。

显式转换表示允许按该类型规则转换，不代表自动进行业务范围校验。例如把一个较大的运行时整数转为 int8 会丢弃超出位宽的信息，而浮点转整数会截去小数部分，不是四舍五入。越界与金额舍入应在转换前按业务规则检查。

命名类型如 type Milliseconds int64 能表达不同单位，但底层仍是整数；显式类型转换仍能构造出负数。需要非负、上限或相互约束时使用构造函数与边界验证。

## 5. 短变量声明里最危险的是名字相同而对象不同

```go
var err error
if value, err := load(); err != nil {
    _ = value
    return err
}
// if 中的 err 是新作用域的变量，不是上面的 err
```

这是说明作用域的片段，load 与返回值需由所在函数提供。避免让外层 err 的 nil 被误认为内层操作成功；嵌套较深时，优先在失败分支就返回，使错误不会靠外层变量猜测。

同一块中的短声明允许部分变量已存在，但至少有一个新的非空白变量。不能只搜索 := 就认定全部变量都是新建，也不能只看同名就认定一定是赋值。

## 6. 零值可读取，不代表各种操作都可执行

nil Slice 可以 append，nil Map 读返回零值但不能插入，nil Channel 的发送接收会阻塞，nil 函数不能调用，nil 接口则没有动态类型。类型相同的“空”在序列化与业务语义上也可能不同。

对配置字段，区分“不提供则使用默认值”和“明确提供 0”的常见办法是先保存存在性，再应用默认和校验。先把 0 改成默认值、随后才判断是否提供，会丢掉信息。

运行 foundation-lab 的 language 模式可对照共享与作用域；JSON 的缺失/null/零值则在独立协议章节展开。零值是语言提供的起点，不应承担全部业务有效性。

## 7. 练习与答案

### 7.1 nil Map 读取不存在的键会 panic 吗

不会，返回值类型零值及可选的存在标记；向 nil Map 写入才会失败。

### 7.2 int8 的运行时溢出说明常量 128 也能赋给 int8 吗

不能。常量可表示性由编译器检查，不能把运行时结果套用到常量规则。

### 7.3 数量字段为 0 就说明用户传了 0 吗

不一定，可能字段缺失后保留零值。协议需要区分时必须保留存在性信息。
