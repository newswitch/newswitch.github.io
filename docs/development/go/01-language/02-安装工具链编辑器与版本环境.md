# Go 安装 工具链 编辑器与版本环境

入门环境首先要保证终端、编辑器和自动化构建使用同一套工具链。系统里有 go.exe 不等于当前项目正在使用它；Module 的 go 与 toolchain 指令、环境变量和 PATH 都可能影响最终选择。

## 1. 安装而不混淆目录

本系列固定 Go 1.27.3 的正式功能。根据操作系统和 CPU 架构从官方站点取得安装包，校验对应 SHA256，再解压或安装到独立目录。Windows 将该目录的 bin 加入当前终端 PATH；Linux 可以使用独立版本目录，不覆盖已有团队工具链。

GOROOT 是工具链本身；GOPATH 常承载模块下载缓存和 go install 的程序，不再要求项目源码都放入 GOPATH/src。不要为了让导入成功，把业务文件复制到标准库目录。编辑器可选择支持 gopls 的工具，诊断和补全也应匹配项目版本。

Windows/amd64 可在自己新建的工具目录使用官方 ZIP。以下只改变当前 PowerShell 的 PATH，不替换已有系统安装；目标目录已存在时先检查内容，不合并覆盖旧工具链：

```powershell
Invoke-WebRequest https://go.dev/dl/go1.27.3.windows-amd64.zip -OutFile go1.27.3.windows-amd64.zip
$goArchiveHash = (Get-FileHash -Algorithm SHA256 -LiteralPath .\go1.27.3.windows-amd64.zip).Hash.ToLowerInvariant()
if ($goArchiveHash -ne 'f26081f438319757f8a1b46d7d0b2c5ec7583d4038e485e0aa725cfde7885fff') { throw 'SHA256 mismatch' }
Expand-Archive -LiteralPath .\go1.27.3.windows-amd64.zip -DestinationPath .\toolchains\go1.27.3
$goToolBin = (Resolve-Path .\toolchains\go1.27.3\go\bin).Path
$env:PATH = "$goToolBin;$env:PATH"
go version
```

Linux/arm64、Linux/amd64、macOS 等必须选择各自包与校验值，不能套用这份 Windows 摘要。编辑器启动后也需确认工具链位置；格式化使用 gofmt，跳转与诊断可使用 gopls，运行与测试以终端命令为最终证据。

## 2. 确认实际使用的版本

```bash
go version
go env GOROOT GOPATH GOMOD GOWORK GOTOOLCHAIN GOOS GOARCH
go help environment
```

本系列测试环境的版本输出为：

```text
go version go1.27.3 windows/amd64
```

GOROOT 和缓存的绝对路径因机器而异，不应逐字照抄。切换终端目录后再看 GOMOD；它应指向当前工程的 go.mod，而不是另一个仓库。

## 3. 自动工具链与网络边界

go 指令标明模块最低 Go 版本，toolchain 可以表达建议工具链。GOTOOLCHAIN 的自动选择可能触发下载，离线环境要预先准备版本；GOTOOLCHAIN=local 则使用当前工具链，不会凭空获得新语法支持。

依赖下载遇到网络问题，先分别检查 GOPROXY、校验服务、企业代理与证书。不能为“先跑起来”长期关闭校验。把临时代理只设置在测试进程，不在文章中写入私人凭据，也不修改全局配置掩盖原因。

## 4. 一次工具链选择要核对四个来源

先用 Windows 的 Get-Command go -All 或 Unix 的 command -v go 找到实际命令，再看 GOTOOLCHAIN、当前 GOWORK/GOMOD，以及文件中的 go/toolchain 指令。编辑器、终端和 CI 是不同进程，可能继承不同环境。

go 指令决定模块最低工具链及相关语言语义；toolchain 表达作为主模块开发时的首选工具链。依赖模块不会简单替应用强制采用其 toolchain 建议，但它的最低 Go 要求仍然影响可构建性。把首选版本与硬性最低版本混在一起，会误判自动下载的原因。

环境变化后重新启动相关终端或编辑器，并再次查看 go env。只改配置界面的显示字符串，不会更换正在运行的编译器。

## 5. 缓存与网络分别存放什么

GOCACHE 保存可复用构建结果，模块下载缓存通常在 GOPATH/pkg/mod；GOBIN 控制部分工具安装位置，GOROOT 则是工具链自身。它们不能相互替代，删除构建缓存也不会修好模块路径错误。

代理负责取得模块内容，校验机制负责验证内容身份；企业私有模块还涉及 GOPRIVATE、GONOPROXY、GONOSUMDB 的访问策略。私有域名应按组织策略配置，不把私有凭证拼入可公开复制的 URL。

诊断按 DNS/TLS/代理连通、访问权限、版本是否存在、内容校验依次分开。不要一上来清空全部缓存、关闭校验或覆盖系统 Go，这些动作会丢掉有用证据，也扩大影响面。

## 6. 建立可复用的环境记录

```bash
go version
go env -json GOVERSION GOROOT GOPATH GOCACHE GOMOD GOWORK GOTOOLCHAIN GOOS GOARCH CGO_ENABLED
go list -m
```

保留这份记录中的非敏感字段，能解释“同一份源码为什么只在一台机器成功”。日志和截图中仍应避免打印带凭证的代理变量或私有 DSN。

本系列使用独立 Go 1.27.3 工具链验证，不要求替换机器上其他项目使用的 Go。第一次开始学习可先运行 hello，再运行 core-lab 的测试；安装成功、语言实验成功和 Gin 外部依赖联调成功是三个不同验收点。

## 7. 练习与答案

### 7.1 GOPATH 是项目必须所在的目录吗

Module 工程不要求这样。通过 go.mod 定义模块边界，GOPATH 主要用于相关缓存和工具程序。

### 7.2 系统 go version 与编辑器显示不同怎么办

分别检查 PATH、编辑器配置、GOROOT 和工具链选择；先统一实际进程使用的工具，再看代码错误。

### 7.3 旧 Go 能靠 go.mod 中写新版本升级能力吗

不能。声明不改变旧编译器；自动模式可能下载新工具链，local 模式则应明确失败。
