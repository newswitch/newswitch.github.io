# Go 结构体 方法接收者与封装

结构体表达一组相关状态，方法表达围绕该状态的行为。Go 没有要求把所有行为装入继承层次；组合、小接口和明确的构造过程通常更容易说明依赖与资源责任。

## 1. 值接收者与指针接收者

值接收者拿到值副本，直接修改该副本字段不改变原对象；指针接收者可以修改原对象。但如果值副本中的字段引用共享数据，方法仍可能改变共享内容，因此值接收者不等于不可变。

可寻址变量调用指针方法时，语言允许某些便利写法；接口实现检查依赖方法集，不能据此认定 T 和 *T 总能实现相同接口。嵌入类型是字段组合和名称提升，不是 Java 式继承。

```go
type task struct { Name string }
func (t task) valueRename() { t.Name = "value" }
func (t *task) rename() { t.Name = "pointer" }
```

这段与实验一致：接收者写在函数名之前；valueRename 改副本，rename 改所指对象。方法集由声明决定，不是在构造函数运行后才动态绑定。

小写字段隐藏包内部实现，导出构造函数如 NewStore 可校验配置。Go 的构造函数是普通函数，不自动承担析构；文件、数据库与网络客户端仍需明确 Close 的所有者。

valueRename 只修改接收者副本，rename 通过指针修改原值。领域方法中还应验证允许的状态迁移，例如只有 NEW 任务可取消，而不是让所有调用方直接给 State 赋字符串。

## 3. 封装与构造

未导出字段保护包内不变量，构造函数可以校验配置并返回错误。零值若设计为可用，应说明它能完成哪些操作；需要外部连接或密钥的组件不能仅因字段有零值就声称可以工作。

业务对象不要自行隐藏创建数据库、启动后台任务和读取环境变量。入口显式构造依赖、失败时按逆序关闭，能让普通对象测试与框架入口测试共享同一套规则。

## 4. 构造函数校验的是不变量，而非只分配内存

NewTask 可以拒绝空名称、非法初态或缺失的执行器，并只在成功时返回可用对象。外部不能直接写内部 State，状态转换通过 Cancel/Claim/Finish 等方法完成，才有位置集中维护规则。

零值可用是设计选择，例如某些标准库缓冲与同步对象支持它；持有数据库连接、密钥或远端地址的对象通常需要显式初始化。不要让 New 函数只做一次 &T{}，却把真正初始化偷偷留到第一次请求。

对外返回错误时应避免泄露原始凭证；如果构造过程中部分资源成功，再一步失败，由构造者清理尚未交出的资源。成功交付后，关闭责任转给明确的所有者。

## 5. 组合与提升不提供传统的虚方法覆盖

嵌入字段使某些字段或方法可以通过外层对象选择，但被嵌入类型的方法仍按其自己的接收者实现执行。外层声明同名方法，不会让内层代码中的所有调用自动改成“动态覆盖”。

选择器发生重名或歧义时，需要明确写出字段路径。嵌入也会扩大对外方法集，可能使本来不想暴露的方法成为接口的一部分；跨包 API 更要审视这一兼容成本。

需要替换行为时，在实际使用点定义小接口或注入函数，比依赖嵌入制造类继承关系更清楚。源码阅读时先找字段与接收者，再判断实际调用的是哪个方法。

## 6. 接收者的复制深度与方法值

值接收者会复制外层状态，却不会递归复制其中 Map、Slice 和指针。指针接收者表达共享可变身份，但也要求调用方遵守同步和生命周期约定。

取得方法值时还会保存对应接收者：保存值接收者方法可能冻结一份外层副本，保存指针接收者方法则保留对象引用。配套 value-lab 的 interface 模式对照 captured_value=0 与 current_value=1，解释回调里为什么可能读到旧状态。

不要在含锁对象上用值接收者“保证只读”，也不要把指针接收者当成自动线程安全。方法集、对象状态与同步协议需要分别判断。

## 7. 练习与答案

### 7.1 值接收者一定不会修改任何共享数据吗

不是。如果字段包含 Map、Slice 或指针，副本可能仍引用共享对象。

### 7.2 嵌入类型相当于继承吗

不完全相同。它是组合及方法/字段提升，不提供传统类继承的同一套子类型语义。

### 7.3 为什么不把所有字段都导出

导出字段会让外部绕过校验修改不变量，也会扩大序列化和兼容边界。应明确哪些是协议，哪些是内部状态。
