# Go 构建、交叉编译、CGO 与供应链：交付的不只是一个二进制

Go 常能交付单个可执行文件，但动态库、证书、时区和操作系统行为仍会影响运行。可重复构建与可验证依赖是上线边界的一部分。

## 1. 构建输入要固定

记录工具链、go.mod/go.sum、源码提交、构建标签、GOOS/GOARCH、CGO_ENABLED 与必要链接参数。`go build -trimpath` 可去除部分本地路径，版本号可通过受控 ldflags 注入；不要把密钥注入二进制。

`go version -m` 查看内嵌构建信息，`go mod verify` 校验模块缓存，不等于所有依赖都没有漏洞。govulncheck 需要独立工具版本和数据库时间，报告也要结合可达性与部署环境。

## 2. 两个可运行项目

```bash
cd examples/gin/service-lab
go mod verify
go vet ./...
go build -trimpath -o out/taskd ./cmd/taskd
go version -m out/taskd
```

Windows 可指定 out/taskd.exe。本项目 SQLite 使用 modernc 实现，避免要求系统 SQLite C 库；但整个依赖图在特定平台是否可完全无 CGO 构建，仍要对目标进行实际编译。

## 3. 交叉编译与 CGO

纯 Go 代码通常可以设置 GOOS=linux、GOARCH=amd64、CGO_ENABLED=0 构建目标二进制；跨平台构建成功不代表已经验证目标内核、证书、DNS、文件权限与信号行为。

CGO 依赖 C 编译器、头文件、链接库与 ABI，交叉编译常需要目标工具链。静态/动态链接取决于完整配置，不能只看文件后缀或“Go 程序”标签判断。

## 4. 容器和更新

容器应以非 root 用户运行，根文件系统按需只读，写目录与数据卷权限明确。极简镜像仍需 CA 证书与必要时区；禁用 TLS 验证不是修复缺少证书的方案。

安全更新需要重建并部署二进制，更新宿主机上的 Go 并不会改造已有程序。保留可回滚制品与数据库兼容窗口，避免代码回滚后无法读取新状态。

## 5. 制品身份由哪些输入共同决定

工具链、源码提交、模块图、标签、目标平台、CGO、链接参数与生成代码共同决定产物。-trimpath 减少本地绝对路径进入制品，但不自动固定时间戳、外部生成器和所有供应链输入。

go version -m 可检查二进制内的工具链、模块与部分构建设置；发布时同时记录文件摘要和容器 digest，让“回滚上一版”指向确定内容，而不是一个可能被覆盖的 latest 标签。

依赖完整性、漏洞检查、来源授权与运行测试分别回答不同问题。下载内容校验通过不能证明逻辑安全，扫描没有可达漏洞也不能证明全部配置正确。

## 6. 交叉编译与运行验收要分两张清单

```powershell
$env:GOOS = 'linux'
$env:GOARCH = 'arm64'
$env:CGO_ENABLED = '0'
go build -trimpath -o out/hello-linux-arm64 ./cmd/hello
go version -m out/hello-linux-arm64
```

此片段在 core-lab 中、独立 PowerShell 进程执行，结束该进程即可避免影响其他构建；不要把它当成修改系统永久环境的命令。Windows 上生成 Linux 制品，只能证明目标编译路径成功。

还需在目标系统验证 CPU 指令集要求、动态装载、DNS、CA、时区、文件权限、信号与资源限制。CGO 构建则需要匹配的 C 工具链、头文件与 ABI；仅设置 GOARCH 不能解决所有交叉链接问题。

## 7. 极简镜像仍然有运行依赖

业务代码未直接调用 C，不代表完整依赖图完全无 CGO。应对真实目标执行 CGO_ENABLED=0 构建，检查失败来自哪一个包，不通过删除依赖分支伪造可用性。

HTTPS 需要可信 CA；本地日期可能需要时区数据；用户目录、临时目录和持久卷也有权限约定。把运行镜像删到只剩一个二进制之前，要确认这些依赖由何处提供。

非 root、只读根文件系统与独立管理端口是互补约束。写入结果需要明确数据卷或外部数据库；不能把所有失败都通过 chmod 777 或关闭 TLS 验证解决。

## 8. 更新与回滚必须考虑数据兼容

更新宿主机 Go 不会修改已部署二进制，标准库修复也需要重新构建和发布。构建缓存可以加速过程，但发布输入与依赖校验仍需可追溯。

数据库字段、事件 schema 和配置可能比二进制活得更久。安全回滚需要旧代码还能读取新阶段的数据，常见做法是先兼容扩展、再迁移、最后收缩，而不是更新后立即删除旧字段。

保留真实制品、迁移版本和必要运行证据。构建成功、镜像扫描、容器启动、探针成功与业务故障回归是不同层次，发布记录不应把它们合并成一个模糊的“全部通过”。

## 9. 练习与答案

### 9.1 Go 可执行文件一定不依赖外部文件吗

不一定，可能依赖 CA、时区、配置和动态库。

### 9.2 交叉编译成功等于目标环境已验证吗

不等于，只验证了部分构建兼容性。

### 9.3 升级机器上的 Go 会修复已部署二进制吗

不会，需要重新构建并部署。
