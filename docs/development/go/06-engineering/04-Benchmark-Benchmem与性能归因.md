# Go Benchmark、benchmem 与性能归因：从纳秒到服务 P99

微基准回答一个小操作的成本，不等于服务容量。有效比较需要正确计时、避免编译器消除、控制环境，并把局部收益放回真实请求链。

## 1. 计时和优化边界

使用 testing.B 构建基准，当前工具链提供 b.Loop，可减少常见循环与计时错误。准备数据与清理工作应按目标决定是否计入；结果必须被使用，避免把无用工作测成零成本。

ReportAllocs 输出每次操作分配字节与次数，不是进程峰值 RSS。RunParallel 用于观察并发争用，也不能代表真实网络负载模型。

## 2. 本机测量

```bash
cd examples/go/core-lab
go test ./internal/demos -run '^$' -bench BenchmarkSum -benchmem -count=2 -benchtime=100ms
```

Go 1.27.3、Windows/amd64、Ryzen 7 4800H、GOMAXPROCS=2 的两次短测量：

```text
BenchmarkSum-2  50592351  2.116 ns/op  0 B/op  0 allocs/op
BenchmarkSum-2  52843522  2.302 ns/op  0 B/op  0 allocs/op
```

数值只是示例，不能据此推导另一台服务器的接口 QPS。短基准受频率、后台负载和计时噪声影响，正式比较应增加时长与重复次数。

## 3. 比较要只改变一件事

固定工具链、构建标签、CPU、GOMAXPROCS、输入大小与数据分布，分别记录基线和候选。需要统计比较时使用固定版本 benchstat，查看差异及置信信息，而不是挑最快一次。

单次优化同时改变序列化、缓存命中和数据库查询，无法把端到端收益全部归因于某一个函数。逐项实验，再看组合效果。

## 4. 回到服务指标

端到端关注吞吐、P50/P95/P99、错误率、队列、CPU、内存和依赖等待。局部 CPU 下降若被数据库等待淹没，用户延迟不一定改变。

闭环客户端在服务变慢时会自动降速，可能掩盖排队。容量实验需要记录到达率、完成率、拒绝率和并发，理解 coordinated omission 等测量偏差。

## 5. 先说清楚一次 op 包含什么

一次 op 可以是编码一个 DTO，也可以是创建缓冲并编码，还可以包含网络往返；不同边界的 ns/op 不能直接比较。准备数据、复用缓冲和清理是否计入，应与真实使用方式一致。

b.Loop 帮助组织计时循环并减少部分常见优化陷阱，但不能替你定义正确实验。结果仍要校验，避免候选实现只是少做工作；并发基准还要明确共享对象、锁和每个调用者状态。

B/op、allocs/op 是按操作分配观测，不是存活对象大小或 RSS。一个方案每次分配少但长期保留大缓冲，可能使服务内存更差。

## 6. 比较前先证明输出等价

core-lab 的动态编码与强类型编码先校验 JSON 输出字节一致，特别保留 []byte 的 Base64 表示，再比较分配。若把 []byte 换成原始字符串或省略字段，快了可能只是协议改变。

固定输入规模与分布，选择有意义的冷热场景；重复运行基线与候选，记录 CPU、工具链、GOMAXPROCS、构建参数及是否有其他负载。不同机器的最快一条记录不构成稳定收益。

benchstat 可帮助比较重复测量的分布，但统计显著不自动代表业务显著；仍要确认实验独立性与实际成本占比。没有运行比较工具时，不应编造置信结论。

## 7. 从局部耗时推导端到端收益上限

假设一个串行请求原来耗时 100 ms，其中目标编码 10 ms；即便把编码降到零，其他条件不变时最多缩短到 90 ms。目标局部快一倍只能减少约 5 ms，而不是整个接口快一倍。

这是简化的串行占比推导；真实并发中，减少 CPU 也可能缓解队列，放大尾延迟收益，但需要通过同负载端到端测试证明。连接池等待或数据库锁仍主导时，局部优化可能不改变用户等待。

不要把 CPU profile 热点比例直接当作墙上时间比例。采样的分母、并行执行和 I/O 等待不同，必须先知道各指标在量什么。

## 8. 吞吐与尾延迟需要负载模型

固定并发的闭环压测在服务变慢时也会降低到达率；按计划到达的开环模型能揭示更多排队，但自身也需要有界调度和完整记录。遗漏慢请求会让延迟分布偏好看。

同时记录到达、接受、完成、拒绝、超时和在途数，并按相同工作量比较资源。把错误请求从统计中全部删掉后，只看成功 P99，可能隐藏最严重的退化。

微基准用于定位小操作成本；端到端用于评估容量和用户体验；故障负载用于评估恢复与资源收敛。三者分别得出结论，再组合，而不是只保留一个漂亮数字。

## 9. 练习与答案

### 9.1 0 allocs/op 说明进程没有内存成本吗

不是，只说明该基准操作的分配观测。

### 9.2 局部快 20% 等于接口快 20% 吗

不等于，要看该部分在完整路径中的占比及其他瓶颈。

### 9.3 选最快一次能代表优化效果吗

不能，需要重复和统计比较。
