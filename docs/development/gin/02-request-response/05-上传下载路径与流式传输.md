# Gin 文件上传与下载：正文上限、临时文件、路径和流式成本

文件接口把外部字节写入存储或返回网络，既是资源入口也是安全边界。只调用 SaveUploadedFile 或 File 不足以保证容量、路径和权限正确。

## 1. 上传内存与总大小

MaxMultipartMemory 主要控制 multipart 解析时的内存阈值，不是整个上传的总大小限制。应在读取前用 MaxBytesReader 或代理限制正文，并限制文件数、单文件大小与展开后大小。

multipart 可能生成临时文件，完成后要按所用解析方式清理。客户端断开时应停止复制并删除自己创建的不完整文件。

## 2. 有限上传实验

```bash
cd examples/gin/service-lab
go run ./cmd/webdemo -case upload
```

```text
status=200
bytes=3
```

完整代码与断言见 [service-lab](https://github.com/newswitch/newswitch.github.io/tree/main/examples/gin/service-lab)。

示例只读取有限正文，打开后关闭文件句柄，不采信客户端文件名作为本地路径。完整工程的任务 API 不开放任意文件写入，避免把演示变成无约束上传服务。

## 3. 路径、类型与持久化

存储 key 由服务生成，原文件名仅保留为受控元数据。清理 `../` 不足以应对符号链接、竞态和压缩包路径；需要根目录边界、最小权限及格式验证。

Content-Type 头不可信，必要时做内容检测和扫描。落地结果若需要崩溃安全，考虑临时文件、校验摘要、原子替换与持久性同步；写完再更新数据库状态。

## 4. 下载与慢客户端

下载先验证身份和对象归属，再选择受控文件；Range、Content-Disposition、缓存头和大小都应测试。避免 ReadFile 整个大文件后再 c.Data，优先受限流式传输。

流式降低单请求缓冲，却延长连接持有时间。仍要限制并发、带宽和写入预算，并正确处理客户端取消。敏感内容不要默认允许公共缓存。

## 5. 解析阈值、传输上限和业务配额分别控制

请求体大小上限应在首次解析前设置。MaxMultipartMemory 决定文件内容何时更多落到临时文件，不是“整个请求最多这些字节”，也不是进程只占用这些内存的绝对保证。

还应按业务限制文件数量、单文件大小与总存储；格式解析后的数据可能远大于原始压缩内容，不能只看 Content-Length。正文读取预算与并发也要独立管理，避免慢上传长时间持有许可。

配套 TestMultipartMemoryIsNotTotalLimit 把阈值设为 1 字节，正常接收 128 字节文件并观察到磁盘临时文件，明确证明“超过阈值不等于拒绝上传”。这不是生产推荐值。

## 6. 临时文件与业务文件有不同的所有者

multipart 解析可能生成临时文件；自行调用解析器的代码应明确调用 MultipartForm.RemoveAll，并关闭通过 FileHeader.Open 得到的句柄。真实 net/http 服务与 Recorder 的清理阶段不同，不能依赖测试环境替你回收全部资源。

业务落地文件要使用受控存储 key，写入中保持临时状态，校验完整后才发布可读状态。数据库提交与对象存储写入不是天然一个事务，需要孤儿文件清理或可恢复的提交协议。

上传元数据里的文件名只用于受控展示。允许的类型、摘要、租户归属与保存期限分别校验；不要为了方便把外部名称直接变成本地目标路径。

## 7. 下载权限、Range 和提交时机

认证和对象归属应在打开并发送内容之前完成。Content-Disposition、内容类型、缓存策略与 Range 支持影响客户端行为；敏感内容不应因为使用 File 辅助函数就自动进入公共缓存。

按需流式读取可以避免整文件 ReadAll，但仍占连接、缓冲、文件句柄和写入时间。要定义客户端取消、慢读与存储失败如何结束；若已经提交部分正文，就不能追加一份新的 JSON 500。

可运行 go test ./internal/requestflow -run TestMultipartMemoryIsNotTotalLimit -v -count=1 验证阈值与清理路径，再结合 Reader/Writer 章节理解分段传输，不把一次 bytes=3 演示当成完整上传系统。

## 8. 练习与答案

### 8.1 MaxMultipartMemory 等于最大上传大小吗

不是，总正文还需要独立限制。

### 8.2 文件名做 Clean 就能安全写入吗

不能，符号链接和根目录约束等仍需处理。

### 8.3 流式下载没有内存和连接成本吗

仍有缓冲与长期连接成本，需要预算。
