# Gin 文件上传与下载：正文上限、临时文件、路径和流式成本

文件接口把外部字节写入存储或返回网络，既是资源入口也是安全边界。只调用 SaveUploadedFile 或 File 不足以保证容量、路径和权限正确。

## 1. 上传内存与总大小

MaxMultipartMemory 主要控制 multipart 解析时的内存阈值，不是整个上传的总大小限制。应在读取前用 MaxBytesReader 或代理限制正文，并限制文件数、单文件大小与展开后大小。

multipart 可能生成临时文件，完成后要按所用解析方式清理。客户端断开时应停止复制并删除自己创建的不完整文件。

## 2. 有限上传实验

```bash
cd examples/gin/service-lab
go run ./cmd/webdemo -case upload
```

```text
status=200
bytes=3
```

完整代码与断言见 [service-lab](https://github.com/newswitch/newswitch.github.io/tree/main/examples/gin/service-lab)。

示例只读取有限正文，打开后关闭文件句柄，不采信客户端文件名作为本地路径。完整工程的任务 API 不开放任意文件写入，避免把演示变成无约束上传服务。

## 3. 路径、类型与持久化

存储 key 由服务生成，原文件名仅保留为受控元数据。清理 `../` 不足以应对符号链接、竞态和压缩包路径；需要根目录边界、最小权限及格式验证。

Content-Type 头不可信，必要时做内容检测和扫描。落地结果若需要崩溃安全，考虑临时文件、校验摘要、原子替换与持久性同步；写完再更新数据库状态。

## 4. 下载与慢客户端

下载先验证身份和对象归属，再选择受控文件；Range、Content-Disposition、缓存头和大小都应测试。避免 ReadFile 整个大文件后再 c.Data，优先受限流式传输。

流式降低单请求缓冲，却延长连接持有时间。仍要限制并发、带宽和写入预算，并正确处理客户端取消。敏感内容不要默认允许公共缓存。

## 5. 练习与答案

### 5.1 MaxMultipartMemory 等于最大上传大小吗

不是，总正文还需要独立限制。

### 5.2 文件名做 Clean 就能安全写入吗

不能，符号链接和根目录约束等仍需处理。

### 5.3 流式下载没有内存和连接成本吗

仍有缓冲与长期连接成本，需要预算。
