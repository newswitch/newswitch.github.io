# 事务管理器、连接与提交回滚

`@Transactional` 描述事务属性，代理拦截器决定在调用边界应用这些属性，事务管理器再操作具体资源。对于本篇的单个 JDBC DataSource，真正提交和回滚的是数据库连接上的事务，不是 Java 方法本身。

返回值正确、日志打印“完成”，都不能代替查询提交后的数据。

## 1. 一次调用的资源路径

```text
调用方 → 事务代理
       → 读取事务属性，取得或加入事务
       → JDBC 事务管理器取得连接并绑定资源
       → 目标方法 → JdbcTemplate → 取得相应连接 → SQL
       → 根据结果提交、回滚或参与外层结束
       → 清理绑定，归还或关闭连接
```

PlatformTransactionManager 定义命令式事务抽象；TransactionDefinition 表达传播、隔离、超时、只读等属性；TransactionStatus 描述本次逻辑事务状态。不同实现可以管理 JDBC、JPA 等资源，不能仅看到同一个注解就认定底层连接行为完全相同。

本例使用 JdbcTransactionManager，它建立在 DataSourceTransactionManager 的 JDBC 资源管理之上，并支持相应提交/回滚异常转换。[JDBC 事务管理器](https://docs.spring.io/spring-framework/docs/7.0.9/javadoc-api/org/springframework/jdbc/datasource/DataSourceTransactionManager.html)

## 2. 准备独立内存数据库

使用[公共 POM](./01-JDK动态代理CGLIB与调用边界.md)，增加以下支持类，供本篇及后续实验共用：

```java title="src/main/java/demo/tx/support/LabDatabase.java"
package demo.tx.support;

import java.sql.Connection;
import java.sql.SQLException;
import java.util.List;
import java.util.UUID;
import javax.sql.DataSource;
import org.h2.jdbcx.JdbcDataSource;
import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.support.JdbcTransactionManager;

public final class LabDatabase implements AutoCloseable {
    private final JdbcDataSource dataSource = new JdbcDataSource();
    private final Connection keeper;
    private final JdbcTemplate jdbc;
    private final JdbcTransactionManager manager;
    public LabDatabase() throws SQLException {
        dataSource.setURL("jdbc:h2:mem:lab_" + UUID.randomUUID() + ";LOCK_TIMEOUT=1000");
        keeper = dataSource.getConnection();
        jdbc = new JdbcTemplate(dataSource);
        manager = new JdbcTransactionManager(dataSource);
        jdbc.execute("create table entries(id int primary key, label varchar(64))");
    }
    public DataSource dataSource() { return dataSource; }
    public JdbcTemplate jdbc() { return jdbc; }
    public JdbcTransactionManager manager() { return manager; }
    public void insert(int id, String label) { jdbc.update("insert into entries values(?, ?)", id, label); }
    public int count() { return jdbc.queryForObject("select count(*) from entries", Integer.class); }
    public List<String> labels() { return jdbc.queryForList("select label from entries order by id", String.class); }
    public void clear() { jdbc.update("delete from entries"); }
    public void close() throws SQLException { keeper.close(); }
}
```

keeper 是本实验的保活连接：H2 内存数据库在最后一个连接关闭后释放，避免连接间操作时数据库提前消失。它不参与业务事务。每个 LabDatabase 使用唯一名字，关闭上下文后释放，不写持久数据文件，也不监听网络端口。

`javax.sql.DataSource` 属于 Java SE API，仍使用这个包名；不能因为 Spring 使用 Jakarta 规范，就把它机械改成不存在的 jakarta.sql.DataSource。

这里的 DataSource 每次可建立独立连接，不是生产连接池。真实池的归还、容量和超时还需另外验证。

```java title="src/main/java/demo/tx/support/TxInfrastructure.java"
package demo.tx.support;

import java.sql.SQLException;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.transaction.PlatformTransactionManager;
import org.springframework.transaction.annotation.EnableTransactionManagement;

@Configuration(proxyBeanMethods = false)
@EnableTransactionManagement
public class TxInfrastructure {
    @Bean(destroyMethod = "close") LabDatabase database() throws SQLException { return new LabDatabase(); }
    @Bean PlatformTransactionManager transactionManager(LabDatabase database) { return database.manager(); }
}
```

EnableTransactionManagement 注册事务注解所需的基础设施。只有导入 Spring JAR 或写注解，并不会自动让任意 new 出来的对象具有事务代理。

## 3. 验证连接、提交和回滚

```java title="src/main/java/demo/tx/basics/TransactionDemo.java"
package demo.tx.basics;

import java.sql.Connection;
import java.sql.SQLException;
import demo.tx.support.LabDatabase;
import demo.tx.support.TxInfrastructure;
import org.springframework.context.annotation.AnnotationConfigApplicationContext;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.Import;
import org.springframework.jdbc.datasource.DataSourceUtils;
import org.springframework.transaction.annotation.Transactional;
import org.springframework.transaction.support.TransactionSynchronizationManager;

public class TransactionDemo {
    public record Evidence(boolean active, boolean sameConnection, boolean autoCommit) { }
    public static class Ledger {
        private final LabDatabase database;
        public Ledger(LabDatabase database) { this.database = database; }
        @Transactional public Evidence write(int id, boolean fail) throws SQLException {
            Connection first = DataSourceUtils.getConnection(database.dataSource());
            Connection second = DataSourceUtils.getConnection(database.dataSource());
            try {
                Evidence evidence = new Evidence(TransactionSynchronizationManager.isActualTransactionActive(),
                        first == second, first.getAutoCommit());
                database.insert(id, "entry-" + id);
                if (fail) throw new IllegalStateException("cancel entry");
                return evidence;
            } finally {
                DataSourceUtils.releaseConnection(second, database.dataSource());
                DataSourceUtils.releaseConnection(first, database.dataSource());
            }
        }
    }
    @Configuration(proxyBeanMethods = false) @Import(TxInfrastructure.class)
    public static class Config {
        @Bean Ledger ledger(LabDatabase database) { return new Ledger(database); }
    }
    public static void main(String[] args) throws Exception {
        try (var context = new AnnotationConfigApplicationContext(Config.class)) {
            LabDatabase database = context.getBean(LabDatabase.class);
            Ledger ledger = context.getBean(Ledger.class);
            Evidence evidence = ledger.write(1, false);
            System.out.println("active=" + evidence.active());
            System.out.println("sameConnection=" + evidence.sameConnection());
            System.out.println("autoCommit=" + evidence.autoCommit());
            System.out.println("afterCommit=" + database.count());
            try { ledger.write(2, true); } catch (IllegalStateException expected) { }
            System.out.println("afterRollback=" + database.count());
            System.out.println("resourceAfter=" + TransactionSynchronizationManager.hasResource(database.dataSource()));
        }
    }
}
```

编译后运行主类 `demo.tx.basics.TransactionDemo`：

```text title="expected-output"
active=true
sameConnection=true
autoCommit=false
afterCommit=1
afterRollback=1
resourceAfter=false
```

两次 DataSourceUtils 获取的是绑定到本事务的同一连接，release 不会在事务尚未结束时把它随意关掉。JdbcTemplate 也使用 Spring 的连接协调机制，所以写入参与这次事务。

## 4. 为什么不要随手调用原始 getConnection

直接对普通 DataSource 调用 getConnection，可能得到另一个连接和另一个自动提交边界。即使同一线程上存在 Spring 事务，绕开协调机制的操作也不自动加入。

优先用 JdbcTemplate、相应 ORM 集成或明确的 DataSourceUtils 协议。必须适配传统 JDBC 代码时，再分析 TransactionAwareDataSourceProxy 等方案及包装关系，不能把所有 DataSource 当成行为相同。

## 5. 提交与回滚由谁决定

默认声明式规则通常对 RuntimeException 和 Error 回滚，对普通 checked exception 不自动回滚；可通过 rollbackFor/noRollbackFor 等明确规则，也可配置不同全局默认。最具体规则、拦截器所看到的异常以及底层资源状态共同影响结果。[回滚规则](https://docs.spring.io/spring-framework/reference/data-access/transaction/declarative/rolling-back.html)

本例用运行时异常触发回滚。方法体打印成功后，提交仍可能失败；提交成功后，返回前的其他钩子也可能再抛异常。因此最终数据库状态和完整异常阶段比“目标方法跑完”更可靠。

## 6. 只读、超时和多资源的边界

readOnly 不是业务授权机制，可能表现为驱动提示或数据库约束，取决于管理器与配置；不能由注解推导任何写 SQL 都一定被禁止。

事务 timeout 不等于能强制中断任意 Java 循环、HTTP 或文件操作。需要分别确认 SQL 超时传播、锁等待、连接等待与外部调用的预算。

一个本地 JDBC 事务不自动包含另一个 DataSource、Redis、MQ、文件或远程 API。把它们放在同一个方法里，不会凭空获得跨资源原子性。

## 7. 练习与答案

### 7.1 两个 SQL 在同一个 Java 方法里，是否一定在同一事务

不是。必须确认代理边界、事务管理器和资源获取方式；两个不同原始连接也可能各自提交。

### 7.2 调用 DataSourceUtils.releaseConnection 会立刻破坏事务吗

它会识别相应绑定资源，并按协调协议处理；不能与对连接直接 close 混为一谈。获取与释放必须配对，并交给相同 DataSource 语义。

### 7.3 RuntimeException 之前发送成功的 HTTP 请求能否随 JDBC 一起回滚

不能自动回滚。数据库回滚只撤销对应资源的事务变化，外部副作用要用幂等、补偿或可靠消息等独立机制处理。
