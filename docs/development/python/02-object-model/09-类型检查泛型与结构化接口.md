# 类型检查、泛型与结构化接口

类型注解不是给变量贴一个不会出错的标签，而是描述代码之间的契约。一个保存任务的接口应接收 Job，取回时仍然返回 Job；如果取回后悄悄变成字符串，静态检查就应该指出不一致。

先阅读[数据记录与类型建模](./08-dataclass-Enum类型注解泛型与Protocol.md)。本篇的完整文件是 `examples/python/advanced-lab/typing_good.py`，反例是同目录的 `typing_bad.py`，依赖见 `examples/fastapi/deepening.lock`。

## 1. 静态检查与运行时校验

| 机制 | 输入 | 发生时间 | 发现什么 |
| --- | --- | --- | --- |
| 类型检查器 | 源码与类型声明 | 运行前 | 调用、返回值和类型关系不兼容 |
| 普通 Python 调用 | 实际对象 | 执行时 | 操作本身不被对象支持等错误 |
| Pydantic 等校验器 | 外部数据 | 接收数据时 | 字段、范围、结构及显式业务规则 |

把外部 JSON 标注成 `JobInput` 不会让它自动变得可信。静态检查器通常假设声明成立；HTTP、文件、数据库和插件入口仍要校验。反过来，运行时验证通过也不会自动检查整个代码库的调用关系。

## 2. 从具体接口到泛型

示例先定义不可变的任务记录，再声明存取协议：

```python
class Store[T](Protocol):
    def save(self, item: T) -> str: ...
    def load(self, key: str) -> T: ...

def roundtrip[T](store: Store[T], item: T) -> T:
    return store.load(store.save(item))
```

`T` 是类型参数。`Store[Job]` 保存并加载 Job；它不是“可以随时返回任意类型”的接口。输入 item 和返回值通过同一个 T 关联，这正是泛型比全写 Any 多表达的信息。

MemoryStore 不需要显式继承 Store，只要方法结构兼容即可。这称为结构化子类型；Protocol 检查的是可调用契约，不保证数据一定落盘、不会丢失或者具备事务。

Store 同时消费和产生 T，因此不能随便把 `Store[子类]` 当成 `Store[父类]`：后者允许写入任意父类对象，可能破坏前者只保存子类的约束。只读接口与读写接口应分开设计。

## 3. 真正运行检查器

在示例目录执行，使用已经安装深化依赖的解释器：

```bash
python -m mypy --strict --no-incremental typing_good.py
python typing_good.py
python -m mypy --strict --no-incremental typing_bad.py
```

正例检查成功，运行输出 `import`。反例故意写成：

```python
wrong: str = roundtrip(MemoryStore(), Job("import"))
MemoryStore().save("not a Job")
```

应报告两类错误：Job 不能赋给 str，str 不能作为 save 所需的 Job。测试检查非零退出码和两处错误，不依赖整段诊断文本的标点永远不变。不要运行反例来代替静态检查；二者验证的阶段不同。

## 4. 经常混淆的声明

`Any` 允许较多未经证明的操作，容易让错误穿过边界；`object` 可以接收任意对象，但使用其特定能力前必须缩小类型。`Job | None` 要求调用者处理缺失，而不是在每处随手忽略检查。

TypedDict 描述字典的键与值结构，不创建具有字段验证的运行时对象。dataclass 适合内部记录，Pydantic 模型适合明确需要运行时转换和校验的边界；选择依据是责任，不是哪个写起来更短。

`Annotated[T, metadata]` 在 T 上附加元数据。静态工具主要理解 T，FastAPI 可以读取元数据里的 Depends、Query 等声明。因此 `Annotated[int, Query(ge=1)]` 中，int 是类型，范围检查由读取 Query 的框架完成。

`Callable[..., R]` 丢失了参数关系；包装函数需要保留被包装对象的参数时，可使用 ParamSpec。装饰器还要保留运行时签名和协程性质，详见[装饰器](./05-装饰器包装函数与执行时机.md)。

## 5. 练习与答案

### 5.1 独立实现一个文件 Store，满足接口就等于持久化安全吗？

答案：不等于。先实现 save/load 并通过静态检查；再测试不存在的键、损坏文件和失败后旧文件是否仍完整。类型只约束形态，文件原子替换与耐久性是另一层契约。

### 5.2 为什么把错误返回值改成 Any 后检查可能不报错？

答案：检查器获得的信息减少了，而不是实现变正确了。应让返回值保留 Job，修正接收方类型或显式进行有意义的转换。

### 5.3 给 JSON 字典加 TypedDict 注解，可以省掉字段校验吗？

答案：不能。可以故意从文件加载缺少 name 的字典，观察注解本身并不拦截；随后在边界加入明确校验，验证失败发生在数据进入业务之前。
