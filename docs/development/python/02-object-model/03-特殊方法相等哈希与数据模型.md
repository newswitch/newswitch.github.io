# 特殊方法、相等性、哈希与数据模型

`len(x)`、`x == y`、`x[key]` 看起来是不同语法，背后分别连接到对象协议。特殊方法让类型参与语言操作，但实现一个同名方法并不意味着已经履行全部协议。

## 1. 从语法到协议

| 操作 | 关键协议 | 必须考虑的语义 |
| --- | --- | --- |
| `repr(x)` | `__repr__` | 诊断表示，不泄露凭证 |
| `len(x)` | `__len__` | 非负整数，缺失不等于零 |
| `x[k]` | `__getitem__` | 索引/键缺失的异常 |
| `iter(x)` | `__iter__` 等 | 一次性还是可重复遍历 |
| `x == y` | `__eq__` 等 | 不支持的类型与比较对称性 |
| `hash(x)` | `__hash__` | 与相等关系一致且稳定 |

隐式特殊方法通常从类型查找，不应通过给某个实例随意添加 `__len__` 就期待 `len` 的行为改变。普通属性查找与语言协议入口要分开理解。

## 2. 相等与哈希实验

```python title="objects_protocol.py"
class JobKey:
    def __init__(self, tenant, name):
        self._value = (tenant, name)

    def __eq__(self, other):
        if not isinstance(other, JobKey):
            return NotImplemented
        return self._value == other._value

    def __hash__(self):
        return hash(self._value)

    def __repr__(self):
        return f"JobKey{self._value!r}"

def main():
    first = JobKey("a", "import")
    second = JobKey("a", "import")
    mapping = {first: "ready"}
    print(first == second, first is second)
    print(mapping[second])
    print(len({first, second}))
    print(first == "import")

if __name__ == "__main__":
    main()
```

```text title="objects_protocol.out"
True False
ready
1
False
```

这里两个对象身份不同，但代表相同业务键。相等对象必须拥有相同哈希；哈希相同却不保证相等，容器仍需要比较。不要把 `hash` 当成稳定的跨进程 ID 或持久化校验和。

## 3. NotImplemented 不是异常

比较方法返回 `NotImplemented` 表示“该类型组合我不处理”，让解释器尝试其他规则；这不同于抛 `NotImplementedError`。后者会直接进入异常传播。

覆盖 `__eq__` 却不定义合适的 `__hash__`，通常会使实例不可哈希。这是保护：如果相等规则已经变化，继续按身份计算哈希可能破坏字典/集合契约。

示例通过元组表达键值，但仍可以人为重新赋值 `_value`。实际使用时必须确保对象在作为键期间，相等与哈希相关状态不变；下划线命名不提供强制冻结。

## 4. 表示与比较的边界

`repr` 面向开发诊断，`str` 面向文本展示。二者都不应直接输出访问令牌。也不要把 `eval(repr(x))` 作为通用对象恢复方案。

排序是另一套契约。只实现相等，不会自动得到小于关系；用于业务排序时，显式提供 `key` 往往比给所有对象强加自然顺序更清晰。跨类型比较也不要随意通过字符串转换拼出一个貌似稳定的顺序。

## 5. 练习与答案

### 5.1 相同哈希意味着相同业务键吗？

答案：不意味着。冲突是允许的，容器还需按相等关系判断。哈希不是唯一标识。

### 5.2 修改作为字典键的字段，会出现什么问题？

答案：若这些字段影响哈希/相等，查找可能失效或出现违反预期的重复关系。应使用稳定键，而不是依赖“改完再改回”。

### 5.3 不支持比较时，为什么不直接抛异常？

答案：返回 `NotImplemented` 允许解释器协调另一侧比较或默认处理；直接抛异常会终止该协作。选择取决于协议语义，不是统一把所有失败变成 False。
