# 从输入到文件持久化的任务工具

独立运行十个示例之后，下一步是把它们组合成一个程序。本篇实现增加任务、列出任务和标记完成，使用 JSON 文件保存状态；之后的 [FastAPI 任务服务](../../fastapi/07-task-service/01-任务服务的数据模型与接口实现.md)再把相同责任接到 HTTP 和数据库。

完整程序位于 `examples/python/advanced-lab/study_tasks.py`，测试位于 `test_study_tasks.py`。先完成[函数](../01-language/08-函数参数默认值返回值与调用.md)、[容器](../01-language/07-List-Tuple-Dict-Set使用与成本.md)与[文件](../03-library-io/01-pathlib文件临时目录与原子替换.md)。

## 1. 第一阶段只计算，不读文件

任务包含正整数 id、非空 name、ready/done 状态。先实现 `add(rows, name)` 和 `complete(rows, id)`：接收旧列表，返回新列表和本次结果，不在里面打印、读环境变量或连接网络。

```python
rows = []
rows, created = add(rows, " import ")
rows, completed = complete(rows, created["id"])
```

先预测结果，再运行：名称应归一化为 import，id 为 1，最终状态为 done。重复 complete 不增加记录；完成不存在的 id 抛错，而且原列表不变。这里使用新列表和新字典，避免调用方持有旧状态时被隐式修改。

## 2. 第二阶段加入输入边界

命令行输入都是外部数据。argparse 将 id 转成整数，业务函数检查名称去掉空白后的长度。加载文件时还要检查顶层是否列表、字段是否齐全、id 是否重复、状态是否允许。

不要只在 add 时校验，因为文件可能由其他程序修改。示例限制记录数与文件大小，防止教学工具无限读取；检查文件大小后文件仍可能变化，不能据此把它当成对恶意并发修改者的完整安全隔离。

布尔值在 Python 中是 int 的子类；这里用 `type(id) is int` 明确拒绝 True 充当任务编号。这样的选择应来自数据契约，而不是看到 isinstance 更简短就替换。

## 3. 第三阶段保存状态

直接以写模式打开原文件，会先截断旧内容；进程中断可能留下半份 JSON。save 的顺序是：

```text
在目标目录创建临时文件
→ 写入完整 JSON
→ flush Python 缓冲
→ fsync 文件
→ 关闭临时文件
→ os.replace 替换目录项
```

临时文件与目标放在同一文件系统，避免跨文件系统替换失败。finally 清理未被替换的临时文件，不删除旧任务文件。

这保证的是适用文件系统语义下的原子替换，不等于跨平台断电绝不丢失。某些系统还需同步父目录元数据；网络文件系统也有自己的保证。两个进程同时读改写仍会丢失更新，本工具限定单写进程，升级并发写入时应引入适当锁或数据库事务。

## 4. 从新进程验证

在仓库根目录执行；数据只放在新建实验目录，不指向已有文件：

```powershell
New-Item -ItemType Directory -Path .python-article-checks/tasks-cli -Force
python examples/python/advanced-lab/study_tasks.py --store .python-article-checks/tasks-cli/tasks.json add import
python examples/python/advanced-lab/study_tasks.py --store .python-article-checks/tasks-cli/tasks.json list
python examples/python/advanced-lab/study_tasks.py --store .python-article-checks/tasks-cli/tasks.json complete 1
```

Linux 使用 `mkdir -p .python-article-checks/tasks-cli` 创建目录，后面的 Python 参数不变。对于空实验库，第一次 add 的输出为：

```json
{"id": 1, "name": "import", "state": "ready"}
```

三个命令分别启动进程。list 还能看到记录，说明数据来自文件，不是上一个进程遗留的内存。再次运行 add 会创建新编号，而不是永远得到 1。

## 5. 测试应覆盖什么

从示例目录执行 `python -m pytest -q test_study_tasks.py`。tmp_path 提供独立数据库文件，测试增加、完成、重复完成、坏数据与失败不改旧状态。

CLI 层负责参数与退出码，业务层负责规则，存储层负责编码和替换。以后把 print 改成 HTTP Response，不应迫使业务函数重新实现一遍。不要一开始就为三个函数搭复杂插件平台；在实际依赖和复用边界形成后再抽象。

## 6. 练习与答案

### 6.1 增加重命名功能，应该在哪一层检查名称？

答案：CLI 解析参数，业务函数检查名称规则和任务存在性，存储层保存新状态。测试空白名失败后文件与旧状态不变，成功后 id 和 state 不变；不能只在命令行入口校验。

### 6.2 文件原子替换能否解决两个终端同时 add 的问题？

答案：不能。两个进程可能读到相同旧列表，后写者覆盖先写者。原子替换避免半个文件，不提供读改写事务；需要并发控制或数据库。

### 6.3 JSON 损坏后自动改成空列表继续写，安全吗？

答案：不安全，会把损坏伪装成空库并可能覆盖可恢复数据。应失败退出，保留原文件，先确认来源并恢复；测试应断言失败后文件字节未变化。
