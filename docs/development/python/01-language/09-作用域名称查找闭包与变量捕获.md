# 作用域、名称查找、闭包与变量捕获

函数能使用外部名称，并不意味着它保存了该名称在定义时的值。理解“名称属于哪个作用域”和“对象在什么时候读取”，才能解释局部变量错误与闭包晚绑定。

## 1. 普通函数中的 LEGB

普通函数体内读取名称时，通常按下面的层次寻找：

| 层次 | 含义 | 示例 |
| --- | --- | --- |
| Local | 当前函数局部作用域 | 参数与局部绑定 |
| Enclosing | 外层函数作用域 | 嵌套函数引用外层局部名称 |
| Global | 当前模块命名空间 | 模块顶层变量 |
| Builtins | 内置命名空间 | `len`、`print` |

这是普通函数名称查找的实用模型，不是全部语法的万能规则。类体、推导式、注解作用域和属性访问有各自规则；`obj.name` 是属性查找，不是按 LEGB 依次找四个名为 `name` 的变量。

把变量命名为 `list`、`str`、`id` 可能遮蔽内置名称。之后的 `list(...)` 失败，未必是列表类型损坏，而是名称已经指向别的对象。

## 2. 为什么赋值前读取会失败

```python
count = 10

def bad():
    print(count)
    count = count + 1
```

普通函数中存在对 `count` 的绑定，且没有 `global/nonlocal` 声明时，它被判定为该函数的局部名称。执行第一行 `print(count)` 时，局部名称尚未绑定，抛出 `UnboundLocalError`，不会自动回退读取模块变量。

这个局部性判断不靠运行时“是否已经走到赋值行”；哪怕赋值在一个未执行分支里，也会影响该函数中名称的局部属性。

`count += 1` 也包含读取和重新绑定。同样，导入、循环目标、异常绑定等操作也可能形成局部名称，不只有普通等号。

## 3. 完整实验：闭包是何时读取的

```python title="scope_demo.py"
VALUE = 10

def broken():
    result = VALUE
    VALUE = 20
    return result

def make_counter():
    count = 0

    def increment():
        nonlocal count
        count += 1
        return count

    return increment

def main():
    try:
        broken()
    except UnboundLocalError:
        print("local: UnboundLocalError")
    counter = make_counter()
    print("counter:", counter(), counter())
    late = [lambda: i for i in range(3)]
    fixed = [lambda i=i: i for i in range(3)]
    print("late:", [function() for function in late])
    print("fixed:", [function() for function in fixed])
    another = make_counter()
    print("another:", another())

if __name__ == "__main__":
    main()
```

```text title="scope_demo.out"
local: UnboundLocalError
counter: 1 2
late: [2, 2, 2]
fixed: [0, 1, 2]
another: 1
```

`make_counter` 返回后，内层函数仍引用外层绑定所需的状态。外层调用的执行已经返回，不代表所有关联对象都应销毁。

每次调用 `make_counter` 会建立独立的外层状态，所以 `another` 从 1 开始；这与多个闭包共享同一次外层调用里的绑定是两件事。

## 4. global 与 nonlocal

`global name` 表示函数中的该名称绑定属于当前模块，而不是全应用唯一变量。另一个模块有自己的命名空间，不能靠 `global` 变成同一个全局存储。

`nonlocal name` 指向最近一层符合条件的外层函数绑定，不能凭空创建一个不存在的外层变量。它常用于小规模封装状态，状态较复杂时对象可能更清晰。

需要重新绑定外层名称才需要这类声明；修改外层列表对象内部通常不需要：

```python
def make_recorder():
    events = []

    def record(value):
        events.append(value)
        return len(events)

    return record
```

`events.append` 没有重新绑定 `events`。但这种共享列表不是自动线程安全的业务状态机，不能把作用域正确当成并发正确。

## 5. 循环闭包的晚绑定

`late` 中的函数在循环结束后才调用；它们读取同一绑定，看到的最后值是 `2`。`lambda` 并非特殊原因，普通嵌套 `def` 也有同样问题。

`lambda i=i: i` 利用“默认值在函数定义执行时求值”，让每个函数保存当时的对象。若当时对象是可变列表，保存的仍是该列表引用，不是深复制。

另一种方法是工厂函数：每次调用工厂都创建独立外层绑定。选择哪种取决于签名是否应该暴露参数，以及需要保存的是对象引用还是独立快照。

在普通函数里，`if`、`for`、`with` 不创建新的函数式局部作用域；推导式的循环变量则有隔离规则。不要照搬其他语言“每个花括号都是作用域”的直觉。

## 6. 状态生命周期

闭包会延长所引用状态的可达时间。回调列表长期存活时，其捕获的大对象也可能一直保留。不要为了方便，把整个请求、连接或大量缓存捕获到常驻回调里。

调试名称错误时先判断：这是局部名称、外层绑定、模块名称还是对象属性？再核对绑定发生在哪条语句。单纯加入 `global` 虽然可能消除一个异常，却也可能引入更难测试的共享状态。

## 7. 练习与答案

### 7.1 count += 1 为什么需要 nonlocal，而 events.append 不需要？

答案：前者重新绑定名称；后者通过现有引用修改对象内部。是否需要声明看绑定行为，不是看变量里有没有“变化”。

### 7.2 默认参数修复闭包后，还会共享可变对象吗？

答案：会。默认值保存当时求值所得的对象引用。如果多次保存同一个列表，后来修改列表仍会共同可见；需要快照时应明确复制策略。

### 7.3 global 可以让多个模块共享一份配置吗？

答案：它只声明当前模块的绑定位置。可以显式通过同一个配置模块或依赖对象共享，但还要处理初始化、更新与并发，不应把 `global` 当成跨模块配置系统。
