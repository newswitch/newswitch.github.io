# 数字、布尔值、运算、类型转换与精度

数字错误不总是程序崩溃。有时它只是把配置中的 `"false"` 当成真，把二进制浮点的近似值当成金额，或者把合法的零覆盖成默认值。要同时理解类型、运算和业务语义。

## 1. 先区分三种数字

| 类型 | 表达什么 | 主要边界 |
| --- | --- | --- |
| `int` | 任意精度整数 | 数字越大成本越高，仍受内存等资源限制 |
| `float` | 二进制浮点近似值 | 通常是 IEEE 754 binary64，不能精确表示所有十进制小数 |
| `Decimal` | 十进制数及上下文控制的运算 | 精度、舍入、单位和量化规则仍需明确 |

Python 整数不会像固定 32 位整数那样在边界自动回绕，但不意味着处理任意长的输入免费。服务端还要限制输入长度和数值范围。

`bool` 是 `int` 的子类，`True + True` 可以得到 `2`。如果业务不允许布尔值充当整数，`isinstance(value, int)` 不够严格，要明确排除 `bool`，或使用适合契约的严格校验。

## 2. 整数除法不是简单去掉小数

`/` 是真除法，整数相除也通常返回浮点；`//` 向负无穷取整，不是朝零截断：

```python
print(7 / 2)          # 3.5
print(7 // 2)         # 3
print(-7 // 2)        # -4
print(-7 % 2)         # 1
print(divmod(-7, 2))  # (-4, 1)
```

对非零整数除数 `b`，商余满足 `a == (a // b) * b + a % b`。负数处理、分页和分桶逻辑要先确定取整方向。

`**` 表示幂，`^` 是整数按位异或，不是幂。优先级也要注意：`-2 ** 2` 是 `-(2 ** 2)`，结果为 `-4`。边界表达式宁可加括号，不让读者猜。

## 3. 一个可运行的精度实验

```python title="numbers_demo.py"
from decimal import Decimal, ROUND_HALF_UP
import math

def main():
    print("division:", 7 / 2, -7 // 2, -7 % 2)
    print("float equal:", 0.1 + 0.2 == 0.3)
    print("float close:", math.isclose(0.1 + 0.2, 0.3))
    amount = Decimal("0.10") + Decimal("0.20")
    print("decimal:", amount)
    print("rounded:", Decimal("2.345").quantize(
        Decimal("0.01"), rounding=ROUND_HALF_UP))
    print("truth:", bool("false"), bool(""), bool(0))
    print("fallback:", 0 or 10)
    print("bool is int:", isinstance(True, int))
    print("nan equal:", math.nan == math.nan)

if __name__ == "__main__":
    main()
```

```text title="numbers_demo.out"
division: 3.5 -4 1
float equal: False
float close: True
decimal: 0.30
rounded: 2.35
truth: True False False
fallback: 10
bool is int: True
nan equal: False
```

`0.1` 与 `0.2` 转为有限位二进制表示时已经产生近似。`print` 展示得简短，不代表内部精确保存了十进制输入；`round` 可以控制舍入结果，但不能让二进制浮点变成精确十进制。

近似物理量可使用 `math.isclose`，但容差必须来自业务误差范围；接近零时通常还需要合适的 `abs_tol`。金额可以按业务用整数最小单位或从字符串创建 `Decimal`，不要先 `float` 再 `Decimal` 把近似值带进去。

Decimal 运算也会受上下文精度限制。`quantize` 明确结果的小数尺度，不自动定义税务、汇率和结算政策；例如是否四舍五入，必须按业务约定。

## 4. 真值不是文本布尔解析

零、空字符串、空容器和 `None` 通常是假，非空字符串通常是真。所以 `bool("false")`、`bool("0")` 都是 `True`。

配置需要显式解析，例如：

```python
def parse_bool(text):
    value = text.strip().casefold()
    if value in {"true", "1", "yes"}:
        return True
    if value in {"false", "0", "no"}:
        return False
    raise ValueError("unsupported boolean text")
```

这里输入契约是字符串。不要对任意对象直接 `str(value)` 再解析，这会掩盖调用方传错类型。

`and` 与 `or` 会短路，返回某个操作数，不保证返回 `bool`。`timeout = configured or 10` 会把合法的 `0` 也替换掉；若仅把缺失视为默认，应写 `10 if configured is None else configured`。

## 5. 转换不等于校验

`int("27")` 成功，`int("27.5")` 抛出 `ValueError`；`int(27.9)` 则截去小数、朝零转换。后者成功不表示业务允许丢弃小数。

`float("nan")` 与 `float("inf")` 可以成功。用于超时、配额、坐标等输入时，还要使用 `math.isfinite` 等检查有限性和范围。NaN 不等于自身，不能靠普通相等判断检查它。

输入边界建议分三步：

1. 检查来源与形态，例如参数必须是字符串或整数。
2. 按明确语法转换，捕获预期的转换错误。
3. 校验范围、有限性、单位和精度，再进入业务逻辑。

不要用一个宽泛的 `except Exception` 把程序错误也伪装成“用户输入错误”。

## 6. 练习与答案

### 6.1 为什么 timeout = value or 30 可能丢失配置？

答案：`or` 按真值判断，`0`、`0.0`、空值都会落入默认分支。若 `0` 表示禁用超时，它就是合法值；应明确只处理 `None` 或缺失字段。

### 6.2 金额保留两位，只在输出时格式化可以吗？

答案：不一定。格式化只改变展示，不定义中间计算和结算舍入。需要从正确的十进制输入构造 Decimal，或使用整数最小单位，并明确在哪一步量化、使用何种舍入。

### 6.3 isinstance(True, int) 为什么可能使参数校验失效？

答案：因为 `bool` 是 `int` 的子类。整数配额接口如果不允许布尔值，应排除 `bool`；内置整数的严格契约可以使用 `type(value) is int`，但这也会拒绝其他整数兼容类型，需要按接口决定。
