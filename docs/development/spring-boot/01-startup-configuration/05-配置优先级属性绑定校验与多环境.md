# 配置优先级、属性绑定、校验与多环境

同一个超时可能出现在代码默认值、application.properties、Profile 文件、环境变量和启动参数里。排查时不仅要问“写了什么”，更要确认“最终绑定了什么，来自哪里，是否满足约束”。

## 1. 加载位置、优先级与时点是三件事

加载位置决定读取哪些文件，优先级决定同名键由谁覆盖，时点决定某项配置能否赶上启动阶段使用。

普通运行场景中，可以先记住这组由低到高的常见关系：默认属性、配置数据、环境变量、Java 系统属性、命令行参数。测试、Servlet/JNDI、JSON 等来源还有自己的位置，不能把这组简化关系当成完整顺序表。

完整规则及 Config Data 的文件优先级见 [Externalized Configuration](https://docs.spring.io/spring-boot/reference/features/external-config.html)。同一位置同时放 properties 与 YAML、重复设置激活 Profile 或导入额外配置时，应按实际规则检查，不凭文件名猜。

`@PropertySource` 到上下文刷新时才加入，对早期读取的日志和部分启动属性可能太晚。优先级再高，也不能让一个尚未加载的来源回到过去生效。

## 2. 配置位置与导入不要混用

`spring.config.location` 可以改变默认搜索位置；`spring.config.additional-location` 用于在默认位置之外增加位置。使用前者却以为只是“多加一个文件”，可能导致打包默认配置不再按预期加载。

`spring.config.import` 表达配置数据导入；`optional:` 允许特定位置缺失，不是忽略该来源中的语法错误、绑定错误或安全要求。必要配置不宜一律改成可选来让启动通过。

位置类属性本身需要在足够早的来源提供。文件路径、目录分隔和容器挂载是否可见，应独立确认，不能用一份本地目录存在证明容器也能读取。

## 3. 类型化绑定与校验分别做什么

Environment 提供属性获取，`@Value` 适合少量简单值；一组具有共同前缀、嵌套关系和约束的配置，宜使用 ConfigurationProperties。

绑定将文本转成 Duration、URI、整数等类型；校验进一步检查范围和跨字段规则。Duration 能解析并不意味着它是正数，URI 能构造也不证明远端健康或满足业务协议白名单。

属性类要通过扫描、EnableConfigurationProperties 或明确 Bean 方式注册。给一个没有被注册的类加注解，不会自动使它在所有工程里出现。

## 4. 建立有约束的属性对象

校验实现来自 validation Starter，不只包含约束注解 API。record 使用构造绑定；下面额外验证超时为正数，避免只检查非空。

```java title="demo-app/src/main/java/demo/boot/properties/ClientProperties.java"
package demo.boot.properties;

import jakarta.validation.constraints.*;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.validation.annotation.Validated;
import java.net.URI;
import java.time.Duration;

@Validated @ConfigurationProperties("lab.client")
public record ClientProperties(@NotNull Duration timeout, @Min(1) @Max(64) int maxInFlight,
                               @NotNull URI baseUrl) {
    @AssertTrue(message = "timeout must be positive")
    public boolean isTimeoutPositive() { return timeout != null && !timeout.isNegative() && !timeout.isZero(); }
}
```

默认配置已在[第一篇](./01-第一个SpringBoot应用与工程结构.md)提供。增加两个 Profile 文件：

```properties title="demo-app/src/main/resources/application-dev.properties"
lab.client.timeout=2s
lab.client.max-in-flight=12
```

```properties title="demo-app/src/main/resources/application-prod.properties"
lab.client.timeout=3s
lab.client.max-in-flight=32
```

Profile 是配置选择，不是权限或安全隔离。prod 这个名字不会自动保护秘密，也不会自动禁止不安全端点。

## 5. 实验：默认、文件、Profile 与命令行

<details>
<summary>绑定、来源查找与最终值</summary>

```java title="demo-app/src/main/java/demo/boot/properties/PropertyDemo.java"
package demo.boot.properties;

import org.springframework.boot.*;
import org.springframework.boot.autoconfigure.EnableAutoConfiguration;
import org.springframework.boot.builder.SpringApplicationBuilder;
import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.ConfigurableApplicationContext;
import org.springframework.core.env.ConfigurableEnvironment;

public final class PropertyDemo {
    @SpringBootConfiguration @EnableAutoConfiguration @EnableConfigurationProperties(ClientProperties.class)
    public static class Config {}
    public static ConfigurableApplicationContext start(String... args) {
        return new SpringApplicationBuilder(Config.class).web(WebApplicationType.NONE)
                .properties("lab.client.timeout=10s").run(args);
    }
    public static String source(ConfigurableEnvironment environment, String key) {
        for (var propertySource : environment.getPropertySources()) {
            if (!propertySource.getName().equals("configurationProperties") && propertySource.containsProperty(key))
                return propertySource.getName();
        }
        return "missing";
    }
    public static void main(String[] args) {
        try (var context = start("--spring.profiles.active=dev", "--lab.client.timeout=750ms", "--lab.client.max-in-flight=4")) {
            var properties = context.getBean(ClientProperties.class);
            System.out.println("profiles=" + String.join(",", context.getEnvironment().getActiveProfiles()));
            System.out.println("timeoutMs=" + properties.timeout().toMillis());
            System.out.println("maxInFlight=" + properties.maxInFlight());
            System.out.println("source=" + source(context.getEnvironment(), "lab.client.timeout"));
        }
    }
}
```

</details>

运行 `demo.boot.properties.PropertyDemo`，预期输出：

```text title="expected-output"
profiles=dev
timeoutMs=750
maxInFlight=4
source=commandLineArgs
```

代码中的 10s 是默认属性，文件的 1500ms 将它覆盖，dev 文件再提供 2s，最后命令行得到 750ms。来源查找跳过 `configurationProperties` 这个适配视图，避免把统一绑定入口误当成原始来源。

配套测试分别移除高优先级条件，检查文件默认值、dev/prod 与命令行；还验证非法时长、负超时和并发数越界导致启动失败。这个程序本身不创建任何外部客户端。

## 6. 环境变量、集合与秘密

环境变量绑定有自己的名称映射规则，例如规范属性名转换时要考虑点、连字符和下划线，不宜根据某一平台的变量名随意猜。优先用一致的规范属性名定义模型，再验证部署环境中的实际绑定结果。

列表覆盖与 Map 合并也有不同规则，不能假设高优先级列表会按索引自动补齐低优先级列表。复杂配置应针对合并结果写测试。

密码、令牌和私钥不要直接提交到 Profile 文件或放进启动参数供进程列表读取。配置排障也不能靠完整打印所有属性；应限制诊断访问并做脱敏。配置更新是否热生效还取决于实际组件，不是改了文件就会自动重新创建所有 Bean。

## 7. 练习与答案

### 7.1 配置文件写了 2s，最终为什么可能是 750ms

同名键可能被更高优先级来源覆盖。检查活动 Profile、命令行、系统属性和环境变量，并核对最终绑定对象，而不是只打开一个文件。

### 7.2 Duration 绑定成功，为什么仍要验证正数

文本转换只证明它是可解析的时长，不表达业务是否接受零或负数。类型检查与业务约束应分开。

### 7.3 给属性类加注解，为什么容器中仍找不到它

还要通过属性扫描、EnableConfigurationProperties 或明确 Bean 方式注册。注解描述绑定规则，不保证这个类已经进入当前上下文。
