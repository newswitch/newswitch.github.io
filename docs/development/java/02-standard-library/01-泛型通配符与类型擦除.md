# 泛型、通配符与类型擦除

集合保存 Object 当然能放任何对象，但取出后只能强制转换，错误往往延后到运行时。泛型把“这里应该是什么类型”写进 API，让编译器提前检查输入和输出。

本篇使用 JDK 25。`List<String>` 中的类型参数不是额外创建了一种专属 String 列表机器码，而是编译期契约的一部分。

## 1. 不变性保护了什么

Integer 是 Number 的子类，但 `List<Integer>` 不是 `List<Number>` 的子类。否则把 Integer 列表当 Number 列表传入后，就能向它加入 Double，破坏原调用者“取出的必定是 Integer”的约定。

数组采用协变，因此 `Object[] a = new String[1]` 可以编译；放入 Integer 时会触发运行时 ArrayStoreException。泛型选择了不同的检查边界，不要用数组经验推断集合。

## 2. 上界与下界

| 参数 | 可以安全读取 | 可以安全写入 |
| --- | --- | --- |
| `List<T>` | T | T |
| `List<? extends Number>` | Number | 不能加入任意非 null 的 Number |
| `List<? super Integer>` | Object | Integer |
| `List<?>` | Object | 不能加入任意非 null 对象 |

`extends` 表示某个未知的 Number 子类型，不代表列表可以容纳所有 Number。`super` 表示某个未知的 Integer 父类型，因此保证能接收 Integer，但不能承诺读出的就是 Integer。

PECS 是 Producer Extends、Consumer Super：只向外提供 T 用上界，只接收 T 用下界。如果同一容器既读又写且必须保持类型一致，通常直接使用 T。通配符约束的是类型安全操作，不是只读权限；上界列表仍可能允许 clear、remove 等操作。

## 3. 泛型方法实验

```java title="GenericDemo.java"
import java.util.ArrayList;
import java.util.List;

public class GenericDemo {
    static <T> void copy(List<? extends T> source, List<? super T> target) {
        for (T value : source) {
            target.add(value);
        }
    }

    static double sum(List<? extends Number> values) {
        double result = 0;
        for (Number value : values) {
            result += value.doubleValue();
        }
        return result;
    }

    public static void main(String[] args) {
        List<Integer> source = List.of(1, 2, 3);
        List<Number> target = new ArrayList<>();
        copy(source, target);
        System.out.println("copied=" + target);
        System.out.println("sum=" + sum(source));
        List<String> words = new ArrayList<>();
        List<Integer> numbers = new ArrayList<>();
        System.out.println("sameRuntimeClass=" + (words.getClass() == numbers.getClass()));
        Object value = source;
        System.out.println("isList=" + (value instanceof List<?>));
    }
}
```

```bash
javac -encoding UTF-8 --release 25 -d out GenericDemo.java
java -cp out GenericDemo
```

```text title="expected-output"
copied=[1, 2, 3]
sum=6.0
sameRuntimeClass=true
isList=true
```

方法声明前的 `<T>` 引入类型参数，把源与目标联系起来；它不同于只写两个彼此无关的 `List<?>`。这里约定源与目标不是同一个被遍历并扩容的列表。

## 4. 擦除后还剩什么

编译器进行类型检查，并按擦除规则把类型变量替换为上界或 Object，在必要位置插入转换；覆盖泛型方法时还可能生成 bridge 方法。两个 ArrayList 的运行时类相同，不意味着编译期泛型检查失效。

不能直接使用 `new T()`、`new T[10]` 或 `instanceof List<String>`。`List<?>` 是可用于相应运行时检查的形式，但检查不验证每个元素类型。类型擦除规则见 [JLS 类型与泛型](https://docs.oracle.com/javase/specs/jls/se25/html/jls-4.html#jls-4.6)。

字段或方法签名的泛型信息可保存在类文件元数据中，反射能够读取部分声明信息；它不能据此证明一个被 raw type 污染的实例里每个元素都正确。

## 5. 堆污染从哪里来

```java
// 反例片段：会产生 unchecked 警告，不应作为正常 API 使用。
List<String> words = new ArrayList<>();
List raw = words;
raw.add(123);
String first = words.getFirst(); // 编译器插入的转换在这里失败
```

用 `javac -Xlint:unchecked` 暴露未检查转换；不要靠宽范围 SuppressWarnings 隐藏风险。只有在狭小边界上能够证明操作安全时才抑制警告，例如经过验证的底层适配。

泛型可变参数涉及数组与非具化类型，也可能污染堆。SafeVarargs 是作者对实现安全性的承诺，不是让任意写入变安全的开关。

## 6. 练习与答案

### 6.1 为什么不能向上界列表加入 1

它可能实际是 Double 列表。编译器只知道元素属于某个 Number 子类型，不知道确切是哪种，不能允许 Integer 写入。

### 6.2 类型擦除是否意味着所有泛型信息完全消失

不是。运行时对象通常不携带每个实例的实际类型参数，但声明签名可保留元数据，编译器生成的转换和桥接方法也依然影响执行。

### 6.3 List 为什么不接受 int 作为类型参数

泛型类型参数要求引用类型，应使用 Integer；拆装箱有 null 风险和对象成本。大量数值计算可考虑基本类型数组或 IntStream 等专用 API。
