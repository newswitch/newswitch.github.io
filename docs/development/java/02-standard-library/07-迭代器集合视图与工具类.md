# 迭代器、集合视图与 Collections 工具类

一个方法返回 List，并没有告诉调用者它能否增删、修改是否影响原集合、元素是否可变。很多集合故障并不是数据结构选错，而是把视图当副本、把不可修改当深度不可变。

本篇使用 JDK 25，通过同一份列表的几种暴露方式观察边界。

## 1. Iterable 提供遍历入口

Iterable 提供 iterator；Iterator 保存一次遍历的当前位置，hasNext 判断是否还有元素，next 返回并推进。增强 for 在相应对象上使用这种协议，并不意味着它会复制集合。

支持删除的迭代器，可以在 next 后调用一次 remove；不是每个集合都支持，也不能在没有对应 next 时任意 remove。需要批量按条件删除时，removeIf 往往更直接。

## 2. 四种列表不是同一种行为

| 来源 | 结构能否改变 | 是否跟随原容器变化 |
| --- | --- | --- |
| Arrays.asList(array) | 大小固定，允许 set | 与原数组共享对应元素 |
| Collections.unmodifiableList(list) | 不能经此引用修改 | 会看到底层 list 的变化 |
| List.copyOf(list) | 不可修改 | 独立的结构快照，不递归复制元素 |
| new ArrayList(list) | 可修改 | 独立容器，仍共享元素引用 |

List.of/copyOf 拒绝 null 元素；unmodifiableList 包装不因此清理 null。具体边界应查 [Collections API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/util/Collections.html)与 List API，而不是笼统说“转成不可变集合”。

## 3. 视图与删除实验

```java title="ViewDemo.java"
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Collections;
import java.util.List;

public class ViewDemo {
    public static void main(String[] args) {
        var source = new ArrayList<>(List.of("a", "b"));
        List<String> view = Collections.unmodifiableList(source);
        List<String> snapshot = List.copyOf(source);
        source.add("c");
        System.out.println("view=" + view);
        System.out.println("snapshot=" + snapshot);
        var iterator = source.iterator();
        while (iterator.hasNext()) {
            if (iterator.next().equals("b")) {
                iterator.remove();
            }
        }
        System.out.println("removed=" + source);

        String[] array = {"x", "y"};
        List<String> fixed = Arrays.asList(array);
        fixed.set(0, "z");
        System.out.println("array=" + Arrays.toString(array));
        try {
            fixed.add("q");
        } catch (UnsupportedOperationException expected) {
            System.out.println("fixedSize=true");
        }
        var part = source.subList(0, 1);
        part.clear();
        System.out.println("afterSubList=" + source);
    }
}
```

```bash
javac -encoding UTF-8 --release 25 -d out ViewDemo.java
java -cp out ViewDemo
```

```text title="expected-output"
view=[a, b, c]
snapshot=[a, b]
removed=[a, c]
array=[z, y]
fixedSize=true
afterSubList=[c]
```

## 4. fail-fast 不是线程安全协议

ArrayList 等集合的迭代器通常记录结构修改计数；发现与预期不符会抛 ConcurrentModificationException。单线程中在增强 for 内直接对列表 add/remove，也可能触发它，名字中的 Concurrent 不意味着一定有第二个线程。

这种检查是尽力发现错误，不保证检测所有未同步并发修改，也不能用“没有抛异常”证明安全。使用迭代器自身支持的修改方法，或先构建新集合，再在合适边界替换。

并发集合的弱一致迭代器、CopyOnWriteArrayList 的快照迭代器采用不同契约，不能把 fail-fast 规则套到所有容器。

## 5. subList 与工具算法

subList 是范围视图，clear 可以删除原列表对应区间。原列表绕过视图做结构修改后，不应继续依赖旧 subList；需要长期保存时复制。一个小视图还可能保留大列表及其对象，造成不必要的内存存活。

Collections.sort、reverse、shuffle 等通常会修改输入；binarySearch 要求列表按同一比较规则预先排序，否则结果无意义。synchronizedList 包装单个方法，并不自动保护整个迭代过程；遍历与复合操作需要按其同步约定协调。

## 6. 练习与答案

### 6.1 Arrays.asList(new int[]{1, 2}) 有几个元素

通常得到一个元素，元素是整个 int[]，而不是两个 Integer。可变参数推断接收基本类型数组作为一个引用；需要装箱列表时应明确转换。

### 6.2 List.copyOf 是否保证新分配一个列表

不保证。对于合适的不可修改输入，可能复用实例。它保证的是所描述的行为，不是对象身份不同，调用方不应使用 `==` 判断复制是否成功。

### 6.3 不可修改集合中保存可变对象，调用 setter 会失败吗

不一定。容器禁止的是经其 API 改变结构或元素引用，并不冻结元素。是否可改由元素类型决定。
