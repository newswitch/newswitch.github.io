# 反射、注解与动态代理的调用边界

框架能扫描类、读取注解、在方法前后加行为，并不是因为注解会自动执行。反射提供元数据和动态调用，注解提供约定信息，代理把调用导向处理逻辑。三者分工不同，组合起来才形成框架能力。

本篇使用 JDK 25，只代理自己定义的接口，理解 Spring 之前先看清一次调用。

## 1. 反射能看到什么

Class 表示运行时类型；Field、Method、Constructor 描述其成员。getMethods 包括可见的 public 继承方法，getDeclaredMethods 查声明在本类的方法但不自动授予访问权限，返回顺序也不应当作业务顺序。

查方法要提供准确参数类型，int.class 与 Integer.class 不等价，普通反射查找不会替调用方模拟所有编译期重载推断。invoke 的目标业务异常包装在 InvocationTargetException 中；访问权限或参数错误则可能在反射层直接失败。

## 2. 注解是数据，不是执行器

SOURCE、CLASS、RUNTIME 是不同保留策略；需要普通运行时反射读取时使用 RUNTIME。Target 限制注解能写在哪些位置，但不定义业务动作。

方法注解是否从实现方法、接口方法或桥接方法读取，需要消费者决定。Inherited 主要影响类注解的继承查询，不自动让方法注解跨所有继承和接口关系传播。不能看到某个注解就推断所有框架读取方式相同。

## 3. 动态代理的路径

```text
调用者 → TaskApi 代理对象 → InvocationHandler
                         → 检查接口方法注解
                         → Method.invoke(target)
                         → 目标实现
```

JDK Proxy 按接口创建代理，不是给任意具体类自动生成子类。调用目标对象本身不经过代理，目标内部的普通自调用也不会自动绕回代理，这为后续理解 AOP 的自调用问题建立基础。[Proxy API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/reflect/Proxy.html)规定了代理方法行为。

## 4. 完整实验

```java title="ProxyDemo.java"
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;
import java.lang.reflect.InvocationTargetException;
import java.lang.reflect.Proxy;
import java.util.concurrent.atomic.AtomicInteger;

public class ProxyDemo {
    @Retention(RetentionPolicy.RUNTIME)
    @Target(ElementType.METHOD)
    public @interface Measured {}

    public interface TaskApi {
        @Measured
        String submit(String title);
    }

    public static void main(String[] args) throws Exception {
        TaskApi target = title -> {
            if (title.isBlank()) throw new IllegalArgumentException("empty title");
            return "saved:" + title;
        };
        var calls = new AtomicInteger();
        TaskApi api = (TaskApi) Proxy.newProxyInstance(TaskApi.class.getClassLoader(),
                new Class<?>[]{TaskApi.class}, (proxy, method, values) -> {
                    if (method.getDeclaringClass() == Object.class) {
                        return switch (method.getName()) {
                            case "equals" -> proxy == values[0];
                            case "hashCode" -> System.identityHashCode(proxy);
                            case "toString" -> "MeasuredTaskApi";
                            default -> throw new IllegalStateException(method.getName());
                        };
                    }
                    if (method.isAnnotationPresent(Measured.class)) calls.incrementAndGet();
                    try {
                        return method.invoke(target, values);
                    } catch (InvocationTargetException failure) {
                        throw failure.getCause();
                    }
                });
        System.out.println("annotation=" + TaskApi.class.getMethod("submit", String.class)
                .isAnnotationPresent(Measured.class));
        System.out.println(api.submit("backup"));
        System.out.println("proxy=" + api);
        System.out.println("selfEqual=" + api.equals(api));
        try {
            api.submit(" ");
        } catch (IllegalArgumentException expected) {
            System.out.println("failure=" + expected.getMessage());
        }
        System.out.println("calls=" + calls.get());
    }
}
```

```bash
javac -encoding UTF-8 --release 25 -d out ProxyDemo.java
java -cp out ProxyDemo
```

```text title="expected-output"
annotation=true
saved:backup
proxy=MeasuredTaskApi
selfEqual=true
failure=empty title
calls=2
```

计数包括一次成功与一次失败调用，因为它在目标执行前增加。Object 的 equals/hashCode/toString 也会进入处理器，本例显式定义代理身份语义，避免递归或不对称地直接转发给目标。

## 5. 为什么要解开 InvocationTargetException

若把反射包装异常直接抛出，调用者可能看不到原来的 IllegalArgumentException。处理器解包后，让运行时异常与接口声明的受检异常按相应契约传播。

如果处理器抛出接口未声明的受检异常，代理可能将其包装为 UndeclaredThrowableException。不要通过 catch Throwable 后返回 null 来“消除错误”，这可能进一步触发拆箱 NPE，或把失败伪装成成功。[InvocationHandler API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/reflect/InvocationHandler.html)说明了参数、返回值和异常规则。

## 6. 模块封装与性能边界

setAccessible 不意味着可以无条件突破模块封装。普通访问受 public 和 exports 等约束；深反射还涉及 opens。trySetAccessible 可以返回失败，某些 setAccessible 调用会抛 InaccessibleObjectException。[AccessibleObject API](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/lang/reflect/AccessibleObject.html)给出具体限制。

不要用全局开放所有包掩盖依赖不兼容。先确认要访问的是自己的 API、第三方公开扩展点还是内部实现，再选择升级、调整模块声明或改用公共 API。

反射和代理增加间接调用与元数据处理，但“反射一定慢若干倍”没有通用比例。可缓存稳定元数据、避免每请求重复扫描，并在真实调用负载下测量。框架也可能使用 MethodHandle、生成代码或其他代理方案，JDK Proxy 只是其中一种。

## 7. 练习与答案

### 7.1 方法上写了 Measured，为何没出现计数

注解本身不执行。需要调用经过读取该注解的处理逻辑；若直接调用 target 或只把注解写在另一个未查询的方法上，本例都不会按预期计数。

### 7.2 target.submit 内部调用 target.other，会再经过代理吗

普通自调用不会。接收者仍是 target，不是代理。需要重新设计调用边界，不应把代理当作会拦截对象内部所有行为的魔法。

### 7.3 为什么不把 equals 直接转发给 target

可能导致 api.equals(api) 与 target 的身份判断不一致，甚至破坏对称性。代理必须明确自己的身份或业务相等契约，不能无意识沿用目标对象的规则。
