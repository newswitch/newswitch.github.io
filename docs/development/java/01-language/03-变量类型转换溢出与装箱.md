# 变量、类型转换、溢出与装箱

类型决定变量可以保存哪些值、表达式如何计算、哪些赋值允许发生。Java 中最先要分清的是基本类型的值与引用类型的值：复制整数不会让两个变量共享整数状态，复制对象引用则可能让两个变量访问同一个对象。

本篇使用 JDK 25。先把数值结果预测清楚，再运行实验；不要把“编译没有报错”当成结果一定符合业务范围。

## 1. 八种基本类型

| 类型 | 值的范围或表示 | 常见用途 |
| --- | --- | --- |
| byte | 8 位有符号整数，-128～127 | 字节数据 |
| short | 16 位有符号整数 | 有明确范围的整数 |
| int | 32 位有符号整数 | 常规计数与下标 |
| long | 64 位有符号整数 | 较大计数和整数时间值 |
| char | 16 位无符号 UTF-16 代码单元 | 字符串编码组成单元 |
| float | IEEE 754 binary32 | 有精度预算的浮点计算 |
| double | IEEE 754 binary64 | 常规浮点计算 |
| boolean | true 或 false | 条件与状态 |

`boolean` 的逻辑取值不等于规范保证每个布尔字段只占一位。一个 Unicode 字符也可能由两个 char 表示；char 数量不是所有语言文字的字符数量。

整数常量通常先按 int 处理，写较大 long 字面量时使用 `L`，例如 `3_000_000_000L`。浮点字面量默认是 double，float 通常需要 `f` 后缀。

## 2. 引用变量保存什么

```java
int count = 3;
int copied = count;
copied = 9;

int[] first = {3};
int[] second = first;
second[0] = 9;
```

执行后 count 仍是 3，而 first[0] 是 9。数组是对象；second 复制的是指向同一数组的引用。引用可以用箭头理解，但不能把它当成 Java 代码可随意做算术的物理地址。

```text
count  = 3             copied = 9
first  ─┐
        ├──→ 同一个数组对象 [9]
second ─┘
```

String、包装类型、数组和普通类都属于引用类型。`null` 表示没有指向对象，访问其成员或对其拆箱会失败。

## 3. 可运行的类型实验

保存为 `TypeDemo.java`：

```java title="TypeDemo.java"
public class TypeDemo {
    public static void main(String[] args) {
        int days = 30;
        long wrong = days * 24 * 60 * 60 * 1000;
        long correct = days * 24L * 60 * 60 * 1000;
        System.out.println("wrong=" + wrong);
        System.out.println("correct=" + correct);
        System.out.println("narrow=" + (byte) 130);
        System.out.println("fraction=" + (5 / 2));
        System.out.println("floating=" + (0.1 + 0.2));

        int[] first = {3};
        int[] second = first;
        second[0] = 9;
        System.out.println("shared=" + first[0]);

        Integer missing = null;
        try {
            int value = missing;
            System.out.println(value);
        } catch (NullPointerException expected) {
            System.out.println("unboxing=null");
        }
    }
}
```

```bash
javac -encoding UTF-8 --release 25 -d out TypeDemo.java
java -cp out TypeDemo
```

输出：

```text
wrong=-1702967296
correct=2592000000
narrow=-126
fraction=2
floating=0.30000000000000004
shared=9
unboxing=null
```

这里捕获异常只是为了让后面的实验继续，不是推荐用异常代替输入判空。

## 4. 为什么 long 接收结果仍会溢出

`days * 24 * 60 * 60 * 1000` 的操作数都是 int，所以乘法先在 int 范围计算，已经溢出的结果才扩大为 long。接收变量的类型不会倒过来改变前面每个运算。

`24L` 让运算在足够早的位置进入 long。把 `L` 加在最后一个乘数上，不能挽救更早就发生的中间溢出。

| 写法 | 能否保护前面的 int 计算 |
| --- | --- |
| `(long) (a * b)` | 不能，先乘后转 |
| `(long) a * b` | 可以使该乘法按 long 进行 |
| `a * b * 1L` | a * b 仍可能先溢出 |

对于必须拒绝溢出的业务运算，可以使用 `Math.addExact`、`Math.multiplyExact`，并明确处理 ArithmeticException。范围更大时再选择 BigInteger。

## 5. 扩大、缩小与数值提升

int 扩大为 long 保留全部 int 值；但 long 扩大为 double 虽属于允许的扩大转换，仍可能丢失整数精度。扩大并不总等于数学意义上的无损。

把 130 转成 byte 会丢弃高位，低 8 位再按有符号 byte 解释，得到 -126。强制转换表达“允许按规则改变表示”，不表达“我已经验证范围”。

byte、short 和 char 的很多算术会先提升为 int：

```java
byte small = 1;
// small = small + 1; // 编译失败：右侧是 int
small += 1;          // 复合赋值包含向左侧类型的转换
```

复合赋值也可能截断。需要业务范围保证时应先检查，不要把较少的编译错误理解为更安全。

## 6. 浮点、整数除法和金额

`5 / 2` 是整数除法，结果为 2；`5 / 2.0` 才产生 2.5。浮点能表达很大范围，但不能精确表达所有十进制小数，所以 0.1 与 0.2 相加出现上面的表示结果。

金额应根据业务选择整数最小单位或 BigDecimal，并明确小数位和舍入规则。`new BigDecimal("0.1")` 表达十进制输入；先经过 double 再构造，可能已经带入浮点误差。

## 7. 包装、拆箱和比较

Integer 把 int 值包装成对象。`Integer number = 3` 涉及装箱，`int value = number` 涉及拆箱。集合泛型通常使用引用类型，因此后续会频繁遇到包装对象。

两个 Integer 直接使用 `==` 比较可能在比较引用身份。小值缓存让部分实验恰好为 true，不是通用的数值比较方法。需要比较可能为 null 的包装值时可用 `Objects.equals`；转换为基本值前需要明确 null 的语义。

## 8. 默认值与 var

实例字段、静态字段和新数组元素有默认值，如整数 0、布尔 false、引用 null。局部变量在使用前必须能证明已赋值：

```java
int count;
// System.out.println(count); // 编译失败，而不是输出 0
var limit = 10;              // 编译期推断为 int
// limit = "ten";           // 仍然编译失败
```

var 没有把 Java 变成动态类型。它主要用于有初始化表达式的局部变量，不能单靠 null 推断所需类型，也不是字段或返回类型的通用替代写法。

## 9. 练习与答案

### 9.1 long result = 50000 * 50000 为什么不等于 2500000000

两个 int 先发生溢出。写成 `50000L * 50000`，或在乘法前把一个操作数转换为 long。

### 9.2 final 数组引用能否修改元素

可以。final 限制这个变量再次指向其他数组，不自动冻结数组元素。不可变对象需要约束其内部状态及暴露方式。

### 9.3 一个没有上报的指标应该用 int 0 还是 Integer null

需要先定义语义。0 可能是实际观测值，null 可能表示缺失，但使用时要处理拆箱风险；也可以用独立状态字段。不能让缺失在统计中悄悄变成 0。
