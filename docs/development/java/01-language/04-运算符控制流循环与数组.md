# 运算符、控制流、循环与数组

一个任务程序需要检查输入、挑选可以执行的任务，再对每项工作更新结果。控制流决定执行哪些语句，数组提供固定长度的同类型元素容器。程序正确性取决于条件是否准确、边界是否覆盖，以及每次循环是否取得进展。

前置知识是[变量与类型](./03-变量类型转换溢出与装箱.md)，实验使用 JDK 25。

## 1. 先看一次遍历

下面用整数表示任务耗时：0 表示暂不执行，负数表示输入无效，超过预算的任务跳过。

```java title="FlowDemo.java"
public class FlowDemo {
    public static void main(String[] args) {
        int[] costs = {0, 10, -1, 20, 50};
        int budget = 30;
        int selected = 0;
        int total = 0;

        for (int i = 0; i < costs.length; i++) {
            int cost = costs[i];
            if (cost <= 0) {
                continue;
            }
            if (total + cost > budget) {
                continue;
            }
            total += cost;
            selected++;
        }

        String state = switch (selected) {
            case 0 -> "EMPTY";
            case 1 -> "ONE";
            default -> "BATCH";
        };
        System.out.println("selected=" + selected);
        System.out.println("total=" + total);
        System.out.println("state=" + state);
        System.out.println("empty=" + (new int[0].length == 0));
    }
}
```

```bash
javac -encoding UTF-8 --release 25 -d out FlowDemo.java
java -cp out FlowDemo
```

输出：

```text
selected=2
total=30
state=BATCH
empty=true
```

每轮取一个元素，先排除无效值，再检查预算；只有通过两道条件才更新总量。一般容量计算还要考虑整数范围，本例的小值保证 total + cost 不溢出。

## 2. 表达式和赋值

| 运算 | 含义 | 易错点 |
| --- | --- | --- |
| `+ - * / %` | 算术 | int 除法截断，取余不是所有语言中的非负模 |
| `== != < <= > >=` | 比较 | 引用的 == 不自动调用 equals |
| `! && ||` | 逻辑 | && 和 \|\| 会短路 |
| `& \| ^` | 整数位运算，也有布尔形式 | 布尔形式不按短路逻辑跳过右侧 |
| `=`、`+=` | 赋值、复合赋值 | 赋值不是比较 |
| `++`、`--` | 自增、自减 | 前置后置影响表达式值 |
| `?:` | 根据条件选择一个表达式 | 两侧类型会参与结果类型推导 |

当表达式包含状态修改时，拆成清楚的语句比堆叠自增更容易验证。`selected++` 在本例中作为独立语句，不需要依靠前置后置差异理解结果。

## 3. 短路能保护后续访问

```java
String title = null;
boolean valid = title != null && !title.isBlank();
```

左侧为 false 时不计算右侧，所以不会对 null 调用方法。换成 `&`，右侧仍会执行并失败。

短路还影响副作用：把写文件、增加计数等操作藏在右侧，会让它们是否发生取决于左侧结果。条件表达式宜保持可观察行为简单。

Java 条件需要 boolean 或可拆箱的 Boolean。`if (count)` 不成立；`if (count != 0)` 才明确表达判断。Boolean 为 null 时仍可能在条件拆箱处失败。

## 4. if 与 switch 的选择

if 适合范围、组合和渐进校验；switch 适合根据离散值选择分支。本例用的是 switch 表达式：必须产生一个结果，箭头分支不会按传统冒号形式贯穿后续分支。

若一个分支需要多条语句，可以写块并用 yield 给出值：

```java
int code = 2;
String result = switch (code) {
    case 0 -> "idle";
    default -> {
        String prefix = "jobs=";
        yield prefix + code;
    }
};
```

别把未识别输入全部吞进一个成功的 default。协议状态应当定义未知值如何处理。null 也需要显式策略，不能因为存在 default 就认为必然覆盖 null。

## 5. for、while 与退出条件

| 形式 | 适合的场景 | 需要验证 |
| --- | --- | --- |
| 下标 for | 需要下标或修改对应元素 | 初始值、上界、增量 |
| 增强 for | 顺序读取每个元素 | 元素变量与原容器的关系 |
| while | 次数由状态决定 | 每轮是否推进到退出条件 |
| do-while | 至少执行一次 | 空输入下是否仍应该执行 |

`continue` 结束本轮，`break` 结束最近的目标循环或相应 switch，`return` 退出整个方法。在 FlowDemo 中若把第二个 continue 改成 break，遇到第一个放不下的任务就不再检查剩余任务；对于 `{40, 10}` 和预算 30，两种结果就不同。

一个无限重试的 while 即使语法正确，也可能长期占用线程。后续网络调用必须额外设置尝试次数、Deadline 和取消条件。

## 6. 数组的三个边界

```java
int[] values = new int[3];
values[0] = 7;
```

数组创建后 length 固定。合法下标是 0 到 length - 1，初始 int 元素为 0。读写下标 3 会抛出 ArrayIndexOutOfBoundsException。

要分别处理：

1. 引用为 null：没有数组对象，连 length 都不能读取。
2. 长度为 0：数组对象存在，遍历可以正常执行零轮。
3. 元素无效：容器存在且有元素，但业务需要检查元素范围。

多维数组实际是数组的数组，各行长度可以不同，行引用也可以为 null。不能用第一行长度作为所有行的可靠上界。

## 7. 复制、共享和遍历修改

```java
int[] source = {1, 2};
int[] alias = source;
int[] copied = source.clone();
alias[0] = 9;
```

此时 source[0] 为 9，copied[0] 为 1。对于引用元素数组，clone 只复制数组及其中的引用，不深度复制元素对象。

增强 for 中 `for (int value : source) { value = 0; }` 只改本轮局部变量，不会写回数组。需要写回时使用明确的下标赋值。

## 8. 练习与答案

### 8.1 为什么循环上界不能包含数组长度

length 是元素数量，不是最大下标。最后一次 i 等于 length 时读写越界，应使用 `i < values.length`。

### 8.2 预算为 30，输入为 40、10，应选择 continue 还是 break

如果要求继续选择后面的可执行任务，使用 continue，最后可以选择 10。若业务要求任务严格按序、首个任务不能执行就全部等待，则 break 可能符合要求。必须先定义业务规则。

### 8.3 新建零长度数组与 null 有什么区别

零长度数组可以安全读取 length 和遍历；null 连数组都不存在。对于“没有结果”，返回空数组往往比要求每个调用者处理 null 更简单，但仍需保持 API 契约一致。
