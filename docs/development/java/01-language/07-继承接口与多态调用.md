# 继承、接口与多态调用

任务服务不应把“执行任务”写死为某一个具体实现。它可以依赖一个执行器接口，由调用方提供本地执行或预演执行。Java 用接口表达可调用契约，用实现类提供行为；同一调用可以在运行时落到不同对象的方法上。

前置是类、对象和方法。本篇先用纯 Java 装配对象，再说明 Spring 依赖注入会接管哪一部分工作。

## 1. 声明类型与实际类型

```java
TaskExecutor executor = new LocalExecutor();
```

变量的声明类型 TaskExecutor 决定编译时能调用哪些成员；实际对象类型 LocalExecutor 决定已选定实例方法的覆盖实现。二者承担不同职责，并不矛盾。

接口可以定义方法契约；类实现接口时，要提供所需行为并满足可访问性。一个类可以实现多个接口，但只直接继承一个父类。

## 2. 完整的执行器实验

```java title="DispatchDemo.java"
public class DispatchDemo {
    interface TaskExecutor {
        String execute(String title);
    }

    static final class LocalExecutor implements TaskExecutor {
        @Override
        public String execute(String title) {
            return "local:" + title;
        }
    }

    static final class DryRunExecutor implements TaskExecutor {
        @Override
        public String execute(String title) {
            return "dry-run:" + title;
        }
    }

    static final class TaskService {
        private final TaskExecutor executor;

        TaskService(TaskExecutor executor) {
            this.executor = java.util.Objects.requireNonNull(executor);
        }

        String submit(String title) {
            if (title == null || title.isBlank()) {
                throw new IllegalArgumentException("title is required");
            }
            return executor.execute(title);
        }
    }

    static String describe(TaskExecutor executor) {
        return "interface";
    }

    static String describe(LocalExecutor executor) {
        return "local-class";
    }

    public static void main(String[] args) {
        TaskExecutor executor = new LocalExecutor();
        TaskService local = new TaskService(executor);
        TaskService dryRun = new TaskService(new DryRunExecutor());
        System.out.println(local.submit("backup"));
        System.out.println(dryRun.submit("backup"));
        System.out.println("overload=" + describe(executor));
        System.out.println("actual=" + executor.getClass().getSimpleName());
    }
}
```

```bash
javac -encoding UTF-8 --release 25 -d out DispatchDemo.java
java -cp out DispatchDemo
```

输出：

```text
local:backup
dry-run:backup
overload=interface
actual=LocalExecutor
```

接口实现方法声明 public，是因为接口中的这个抽象方法是公开契约，实现不能降低其可访问性。`@Override` 让编译器验证是否真的覆盖了所需方法。

## 3. 一次调用如何选择方法

对于 `executor.execute("backup")`：

1. 编译器根据 TaskExecutor 契约确认 execute 可调用，参数类型合法。
2. 运行时取得 executor 指向的实际对象。
3. 对这次实例方法调用，使用该对象所对应的实现。

而 `describe(executor)` 是重载选择。实参表达式声明类型是 TaskExecutor，因此编译期选定接口参数版本。运行时不会因为实际对象是 LocalExecutor 就重新换成另一个重载。

```text
编译期：可见成员、参数适用性、重载选择
运行期：实际接收者、覆盖实现
```

这套解释针对普通可覆盖实例方法。static 方法和字段访问不能照搬动态分派规则；JIT 可以在不改变语言可见行为的前提下内联调用。

## 4. 继承与抽象类

`class Child extends Parent` 建立类型关系并继承可继承成员。私有成员仍属于父类内部实现，构造方法也不作为普通方法继承。

抽象类可以保存共同状态、提供部分实现和定义抽象方法，但不能直接实例化。接口适合表达能力契约；抽象类适合确有稳定共同实现和状态的类族。

仅仅为了复用几个工具方法就建立父子关系，容易把不相关类型绑在一起。任务服务“拥有一个执行器”用组合表达更直接，不需要让 TaskService 继承 LocalExecutor。

## 5. 覆盖需要保持的契约

覆盖不仅是方法名一样。返回类型、访问范围和异常声明等都必须满足语言规则；实现还应满足业务契约。

例如 TaskExecutor 约定返回执行结果，某个实现却先永久删除任务再返回“成功”，即使类型检查通过，也破坏了调用方对能力的理解。

接口还可以有 default 方法、static 方法及相应私有辅助方法。default 方法不是自动解决所有多继承冲突：多个来源提供不兼容默认实现时，实现类可能必须显式覆盖。

## 6. 向上转换、向下转换与 instanceof

把 LocalExecutor 当成 TaskExecutor 使用是向上转换。向下转换只改变对引用可用类型的表达，不会把对象变成另一个实现：

```java
TaskExecutor executor = new DryRunExecutor();
// LocalExecutor local = (LocalExecutor) executor; // 运行时失败
if (executor instanceof LocalExecutor local) {
    System.out.println(local.execute("backup"));
}
```

如果业务处处需要检查实现类，通常应重新检查接口是否表达了实际需要的能力。对网络反序列化等外部输入也不能用强制转换代替验证。

## 7. 构造注入和框架的关系

TaskService 通过构造方法接收接口依赖，这已经是依赖注入，不需要注解才能成立。入口代码选择实现并连接对象。

以后由 Spring 根据配置创建 LocalExecutor 和 TaskService，把匹配依赖注入进去。任务服务的方法仍然执行普通 Java 调用；如果加入 AOP，实际持有的对象还可能是代理，后续需要再分析调用经过哪一层。

同一个接口也可以用测试替身实现，让测试验证任务服务的输入和结果，不必真正启动外部进程或远程任务。

## 8. 练习与答案

### 8.1 为什么接口变量可以保存不同实现

这些实现满足接口类型契约，变量保存的是引用。可见调用由接口确定，具体行为由实际对象提供。

### 8.2 describe(new LocalExecutor()) 会选择哪个重载

该表达式编译期类型是 LocalExecutor，选择更具体的重载，返回 local-class。若先赋给 TaskExecutor 变量再传入，则选择接口参数版本。

### 8.3 能否让 LocalExecutor.execute 去掉 public

不能。该接口方法是 public，降低实现可访问性会导致编译错误。使用 `@Override` 可以及时暴露名称或参数写错等问题。
