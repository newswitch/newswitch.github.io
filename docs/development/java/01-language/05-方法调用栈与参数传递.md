# 方法、调用栈与参数传递

方法把一次操作的输入、结果和内部步骤集中起来。调用时，实参的值被复制给形参：基本类型复制基本值，引用类型复制引用值。两份引用可以指向同一对象，所以修改对象能被外部看见，但给形参重新赋值不会替换调用者的变量。

理解这条规则后，就能判断一个方法到底改变了哪个状态，而不是只记一句“Java 按值传递”。前置知识是类型、数组和控制流。

## 1. 方法声明包含什么

![形参复制引用与共享对象的关系](/img/development/value-reference.svg)

先跟着两条引用箭头看：复制引用值后仍指向同一对象；只有重新给形参赋值时，该局部变量才改指向。图表达逻辑关系，不是对象真实地址。

```java
static int add(int left, int right) {
    return left + right;
}
```

`int` 是返回类型，add 是名字，括号中是参数类型和参数名，方法体给出实现。static 在本篇用于简化入口类调用，下一篇专题会解释其共享方式。

调用 `add(2, 3)` 时，两个实参被求值后复制到 left 和 right；return 把计算结果交还调用方。void 表示不返回值，不表示没有副作用，也不表示一定成功。

## 2. 一个能区分三种修改的实验

```java title="CallDemo.java"
public class CallDemo {
    static void changeNumber(int value) {
        value = 9;
    }

    static void mutate(int[] values) {
        values[0] = 9;
    }

    static void replace(int[] values) {
        values = new int[] {99};
    }

    static String choose(Object value) {
        return "Object";
    }

    static String choose(String value) {
        return "String";
    }

    static int sum(int... values) {
        int total = 0;
        for (int value : values) {
            total += value;
        }
        return total;
    }

    public static void main(String[] args) {
        int count = 3;
        changeNumber(count);
        int[] shared = {3};
        mutate(shared);
        replace(shared);
        Object text = "task";
        System.out.println("number=" + count);
        System.out.println("array=" + shared[0]);
        System.out.println("overload=" + choose(text));
        System.out.println("sum=" + sum(1, 2, 3));
    }
}
```

```bash
javac -encoding UTF-8 --release 25 -d out CallDemo.java
java -cp out CallDemo
```

输出：

```text
number=3
array=9
overload=Object
sum=6
```

## 3. 调用栈与局部变量

概念上每次方法调用有自己的栈帧，保存参数、局部变量和执行状态。对于 JVM 字节码模型，还存在操作数栈等结构；JIT 可以内联和优化实际实现，源码中的每个调用不必对应一个永久可见的物理帧。

```text
main 的变量 shared ───────────────┐
                                ├──→ 数组 A [3]
mutate 的形参 values ────────────┘
```

在 mutate 中写 values[0]，实际写的是数组 A 的元素；返回后 main 仍指向 A，自然看见 9。

调用 replace 时先复制同一个引用，然后只替换该方法的局部形参：

```text
main.shared  ───→ 数组 A [9]
replace.values ─→ 新数组 B [99]
```

main.shared 从未被重新赋值，仍然指向 A。若要让调用方使用新数组，应返回它并由调用方赋值，或定义清楚的持有者对象更新规则。

栈帧结束不等于它曾引用的对象立刻销毁。只要其他地方仍持有可达引用，对象就可能继续存在；资源的 close 也不能交给“方法返回后应该被 GC”这一假设。

## 4. 方法签名与重载

在普通非泛型示例中，方法名和参数类型列表决定可区分的重载。只改变返回类型不能声明另一个相同参数的方法；参数名称也不构成重载区分。

CallDemo 的 text 声明类型为 Object，所以重载选择 `choose(Object)`。运行时里面存着 String，并不会让编译器重新选一次 `choose(String)`。

重载是编译期选择可调用签名，实例方法的覆盖则还会根据实际对象类型动态选择实现。后续[接口与多态](./07-继承接口与多态调用.md)会把两者连起来。

含 null 的调用要注意歧义：若同时有 `choose(String)` 和 `choose(Integer)`，直接 `choose(null)` 可能无法确定哪一个更具体，应改进接口或显式表达类型。

## 5. 可变参数不是无限容量

`int... values` 表示调用方可以提供多个 int，方法内部按数组使用。它必须是参数列表最后一项，也不能同时声明与 `int[]` 参数完全相同签名的重载。

传入一个已有数组不会自动深复制它。若方法修改元素，外部同样可能看见变化。可变参数也不代表可以安全收集无限输入，内存和计算量仍有边界。

## 6. 返回值、异常和退出

一个正常返回的 int 方法必须提供相应返回值；throw 则沿异常路径退出。return 结束当前方法，不是整个进程，也不能假定会终止其他线程。

递归把规模缩小后再次调用自己，需要明确终止条件和调用深度。数学上有终止条件的算法，也可能因输入太大触发 StackOverflowError；简单累加通常优先使用迭代。

方法应当让调用方能判断副作用。例如 `calculateCost` 宜只计算；执行状态修改的操作则明确命名，并通过结果或异常表达是否成功。

## 7. 练习与答案

### 7.1 为什么 swap(a, b) 常常没有交换外部两个对象变量

方法形参只持有两份引用值。交换这两份局部引用不改变调用者变量。可以返回包含交换结果的对象，或者让调用方自己赋值；若操作数组元素则是修改数组对象，是另一种行为。

### 7.2 参数加 final 会不会禁止修改对象

不会。它禁止形参变量在方法内重新赋值，仍可以通过该引用修改允许修改的对象字段或数组元素。需要只读行为应依靠接口和对象设计。

### 7.3 choose((String) text) 会输出什么

在本例中转换成功，编译期选择 String 重载，输出 String。若 text 实际指向不兼容对象，转换会在运行时失败，不能用强制转换代替类型保证。
