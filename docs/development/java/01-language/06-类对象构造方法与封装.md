# 类、对象、构造方法与封装

把任务的标题和完成状态放进一个类，只完成了数据聚合。一个有用的对象还要保护规则：标题不能为空，任务不能在完成前得到“已完成”结果，状态变化应通过允许的操作发生。封装的作用是让调用者无法轻易绕过这些约束。

本篇使用 JDK 25，前置是[方法与参数传递](./05-方法调用栈与参数传递.md)。示例暂时只在单线程运行，并发访问将在同步专题处理。

## 1. 类、实例与引用

类描述字段、方法和构造方式；对象是运行时创建的实例；引用变量是访问对象的入口。`Task first = new Task("backup")` 包含声明变量、构造对象和保存引用三个概念。

同一类可以产生多个实例，各实例字段通常各自独立；两个变量也可以指向同一实例。实例独立与引用是否共享需要分别判断。

## 2. 用行为保护状态

```java title="TaskDemo.java"
public class TaskDemo {
    static final class Task {
        private final String title;
        private boolean completed;

        Task(String title) {
            if (title == null || title.isBlank()) {
                throw new IllegalArgumentException("title is required");
            }
            this.title = title;
        }

        String title() {
            return title;
        }

        boolean complete() {
            if (completed) {
                return false;
            }
            completed = true;
            return true;
        }

        boolean isCompleted() {
            return completed;
        }
    }

    public static void main(String[] args) {
        Task first = new Task("backup");
        Task second = new Task("index");
        Task alias = first;
        System.out.println("title=" + first.title());
        System.out.println("firstChange=" + alias.complete());
        System.out.println("secondChange=" + first.complete());
        System.out.println("otherCompleted=" + second.isCompleted());
    }
}
```

```bash
javac -encoding UTF-8 --release 25 -d out TaskDemo.java
java -cp out TaskDemo
```

输出：

```text
title=backup
firstChange=true
secondChange=false
otherCompleted=false
```

外层类用作运行入口，嵌套的 Task 用于让示例能在一个文件中编译。独立工程可以把 Task 放到自己的源文件；嵌套 static 的完整规则见[包与访问控制](./08-static-final包与访问控制.md)。

## 3. 逐步解释创建过程

对于本例，可以按以下顺序理解：

1. 为新对象准备存储，字段先有默认值，completed 为 false。
2. 执行相应的实例初始化和构造过程，检查标题。
3. 把有效标题保存到字段。
4. 构造正常结束后，把引用交给调用方。

若标题无效，构造抛出异常，调用方不会得到一次正常构造的返回结果。构造阶段也不应把 this 提前交给后台线程或全局容器，否则其他代码可能看到尚未初始化完整的对象。

实际类层次还涉及父类构造和字段初始化。JDK 25 对构造方法中显式父类构造调用之前可执行的受限代码有正式支持，因此不能沿用“所有版本中 super 必须绝对是第一条源码语句”这一过度概括；入门代码保留常规构造结构。

## 4. 构造方法与 this

构造方法与类同名，没有返回类型，`void Task()` 是普通方法而不是构造方法。若一个类没有声明构造方法，编译器可为它提供默认构造；一旦声明了自己的构造方法，就不能假设仍自动存在无参构造。

`this.title = title` 中，左边是当前实例字段，右边是同名参数。this 表示当前对象，可用于区分名字，也可用于调用同一实例的其他方法。

`this(...)` 调用同一类的其他构造方法，用于集中公共校验；不能让构造调用形成循环。继承中的 `super(...)` 调用父类构造，父类构造不是被继承的方法。

## 5. private 为什么有价值

假如公开 `completed`，调用方可以随时把它改回 false。没有入口记录操作，也无法拒绝非法状态。把字段设为 private 后，状态修改集中到 complete，可以扩展成检查、审计和持久化。

简单为所有字段生成 getter/setter，并不自动建立封装。公开 `setCompleted(false)` 仍然允许同样的非法迁移。

本例的 private 字段在类的代码中使用；Java 对同一顶层类中的嵌套类型有相应访问规则，不能把 private 当作抵御反射、调试或所有外部机制的安全隔离墙。

## 6. 实例独立与别名共享

first 和 second 指向两个对象，所以 first 完成后 second 仍未完成；alias 和 first 指向同一个对象，所以第一次 complete 修改的状态会影响第二次调用。

```text
first ─┐
alias ─┴──→ Task A {title=backup, completed=true}
second ───→ Task B {title=index, completed=false}
```

complete 在单线程中重复调用不再改变状态，具有这里定义的幂等行为；这段“检查再修改”并未保证多线程原子性。两个线程可能同时检查到 false，不能据此推导并发安全。

## 7. 对象、内存回收与外部资源

当对象不再被程序可达地使用时，内存可能在之后被 GC 回收。GC 并不等于文件句柄、数据库连接和线程都能及时释放。

管理外部资源的对象需要明确 close、生命周期或容器关闭约定。Task 目前只保存内存状态；以后增加线程池和数据库时，应把这些资源的所有者与任务数据对象分开。

## 8. 练习与答案

### 8.1 给 Task 增加 public setter 是否更灵活

调用方式更宽松，但会削弱状态约束。应从业务行为出发定义 rename、cancel 或 complete，并明确允许条件，而不是默认暴露每个内部字段的写入。

### 8.2 title 是 final，Task 就不可变了吗

不是。completed 仍可变化。final 引用本身也不保证它指向的对象不可变。本例 String 自身不可变，但整个 Task 是有状态对象。

### 8.3 为什么构造函数中拒绝空标题，而不是等执行时再检查

如果“每个有效任务必须有标题”是对象不变式，构造阶段验证能使正常创建出的对象立即满足规则。外部输入层仍需要验证和错误响应，但不能成为领域对象唯一的防线。
