# Worker 租约、重试与幂等执行

API 返回接收成功，只代表任务已经进入可恢复状态，不代表工作完成。Worker 必须解决三个独立问题：谁有权执行、失败后谁接手、结果怎样避免重复或过期写回。

## 1. 领取事务只做短操作

Worker 查询到期 pending 或租约过期 running 的任务。PostgreSQL 分支使用 FOR UPDATE SKIP LOCKED 跳过其他领取者占有的候选行；SQLite 分支用条件更新与版本判断处理竞争。

领取时产生随机 lease_token、增加 attempts 与 revision、写入 lease_until 和 running 事件，随后立即提交。真正计算发生在事务外，不让执行时间占住连接与行锁。

```text
短事务领取并提交
→ 计算期间定期续租
→ 有效所有者提交结果与 done 事件
→ 或有限退避后重新领取
```

查到候选行不等于拥有它。条件更新的受影响行数必须为一，才能继续；为零时结束本轮，不拿旧查询结果直接执行。

## 2. 租约为什么还需要所有权标识

假设 W1 领取任务后暂停，租约过期，W2 接手并完成；W1 恢复时可能仍以为自己拥有任务。finish 必须同时检查 id、running、lease_token 与有效期，不能只检查任务存在。

本项目的 token 是本次数据库所有权标识，不是跨系统通用的单调 fencing token。它能阻止旧执行者修改本库结果，不能让另一个不检查 token 的 HTTP 服务自动拒绝旧请求。外部系统需要明确的幂等键、单调栅栏或其他一致性协议。

测试用可控时钟完成这一序列：时间 100 时领取；推进到 111 让十秒租约过期；W2 再领取；W1 finish 返回 False，W2 finish 成功，重复 finish 仍被拒绝。不需要真的暂停进程十一秒，也不依赖系统调度碰巧发生。

## 3. 续租与取消如何协作

run_once 用 TaskGroup 管理执行和续租两个协程。执行结束通过 Event 通知续租退出；续租失败抛出 LostLease，使同组计算被取消。被取消计算仍要执行 finally，不能吞掉 CancelledError 继续无限工作。

API 取消时改变状态并清空 token。续租和 finish 均带条件，因此会观察到所有权消失；取消不是把线程或远端请求瞬间抹掉。对于当前纯计算，结果可以安全丢弃；对于已经付款、上传等外部动作，需要单独设计撤销或补偿。

示例默认十五秒租约，约每三分之一周期尝试续租，单项异步工作有三十秒预算。这些值用于实验。事件循环阻塞、数据库不可用、进程暂停和时钟偏差都可能影响租约；生产可统一使用数据库时间，并按最长可容忍暂停与故障恢复目标选择余量。

## 4. 重试不是无限重新执行

执行失败后，仍有效的所有者将任务转回 pending，设置 available_at，并按尝试次数有限退避；达到 max_attempts 后转 failed。若进程直接消失，没有机会调用 fail，后续领取者检查过期租约与尝试预算，耗尽时将它收敛到 failed。

真正系统需要区分可重试依赖故障、永久输入错误和程序错误。当前示例对普通执行异常使用同一有限策略，便于观察状态机；扩展时不要把取消、权限失败和任意异常全部重试。

循环 Worker 出错只记录异常类别，不输出凭证或完整载荷。失败状态还应关联脱敏错误证据，便于区分任务本身失败与执行基础设施不可用。

## 5. 幂等结果与外部副作用

finish 在同一事务里把 Job 改为 done、插入以 job_id 为主键的 Result，并写入事件。提交前失败则整体回滚；提交完成但进程未拿到成功响应时，再尝试 finish 也不会再次插入。

计算可能执行多次，因此不能说系统实现了“执行恰好一次”。项目只对同一数据库内的最终结果提供受约束的原子提交。外部消息可以通过 Outbox 把待发送记录与业务状态同事务保存，再由投递器重试；消费者仍需处理重复。

## 6. 练习与答案

### 6.1 在 claim 事务里一直计算，是否更容易保证所有权？

答案：长事务会占住连接与锁，进程暂停还会放大等待。短事务领取、租约管理、结果条件提交分别解决不同问题，不能靠长期持锁替代恢复设计。

### 6.2 W1 租约到期后 W2 已接手，W1 的外部 HTTP 请求会自动失效吗？

答案：不会。本地 token 只被检查它的系统理解；目标必须支持幂等或栅栏等协议，或者接受并处理重复与补偿。

### 6.3 怎样证明重试预算真的有效？

答案：用可控时钟重复失败与领取，检查 attempts、available_at 和终态；再模拟最后一次领取后进程消失，过期后仍应进入 failed，而非永远留在 running。
