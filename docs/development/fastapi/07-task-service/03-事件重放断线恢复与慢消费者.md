# 事件重放、断线恢复与慢消费者

把一次 JSON 响应改成 StreamingResponse，不会自动得到可靠事件系统。连接可以断、客户端可以慢、API 可以重启；恢复依赖可重放数据与明确的位置，而不是连接一直不断。

## 1. 状态快照与事件不是一回事

GET /jobs/1 返回此刻状态；事件表记录 pending、running、done 等变化。快照适合重新建立当前视图，事件适合从某个位置继续消费。没有存储的历史，仅凭 SSE 的 id 字段不能把丢失内容变回来。

事件包含租户、任务、sequence 和有限状态摘要，不包含认证令牌或任意客户端提供的大段文本。任务变化与事件在同一事务提交，防止只完成一边。

## 2. 为什么不用自增主键直接当可靠游标

在 PostgreSQL 中，事务 A 可能先取得事件 id=10 但尚未提交，事务 B 取得 11 后先提交。客户端读到 11 并把游标推进到 11，A 后来提交的 10 就可能被跳过。数字递增不等于提交可见顺序递增。

项目用 async_streams 中的每租户计数器：在写事件的事务里更新 sequence 并持有对应行锁直到提交，再写事件。后续同租户事务必须等前一个完成，才取得下一个序号；回滚不会消耗这次事务递增。代价是同租户事件写入在这个短临界区串行，不能无限提高吞吐。

它适合解释小型服务的一致性。更大规模可以使用具有明确分区顺序与 Offset 语义的日志系统，但仍需解释业务提交与日志发布之间的边界，而不是换个组件名就认为问题消失。

## 3. 客户端怎样继续读取

第一次请求不带 Last-Event-ID，从当前保留的首批事件开始；收到后保存已处理的序号，重连时带回。示例请求：

```bash
curl -N -H "Authorization: Bearer TOKEN" -H "Last-Event-ID: 1" "http://127.0.0.1:8000/events?wait=5&limit=10"
```

TOKEN 替换为本地签发的短期凭证，不把真实值写进文章或截图。返回格式示意：

```text
id: 2
event: job
data: {"id": 1, "name": "import", "state": "running", "revision": 1, "attempts": 1}

```

任务编号与事件序号分别有自己的含义。游标是租户内位置，服务端必须同时按 tenant 过滤；不能拿另一个租户的事件补足编号空缺。客户端在业务处理完成后记录位置，崩溃恢复时仍可能收到重复事件，因此处理应幂等。

浏览器原生 EventSource 不方便设置任意 Authorization 头，可使用受控 fetch 流读取，或设计有 CSRF/Origin 防护的 Cookie 认证；不要为方便把长期令牌放到 URL，避免出现在访问日志与历史记录中。

## 4. 慢客户端不应该拖住数据库事务

每轮查询最多读取三十二条或本次剩余额度，先关闭 Session，再 yield 给网络。数据库连接不跨客户端读取等待持有；每连接也没有无界内存队列，落后位置保存在数据库游标中。

当客户端很慢，服务器发送 await 会等待流控制，这叫背压；它限制的是继续推进，不保证无限慢连接会自动结束。wait 参数限制生成器继续取新事件的等待预算，不是对底层 send 的硬性墙钟超时。入口还应设置连接数、空闲/发送预算与容量上限，并测试真实断开。

示例每次连接最多一百条，最长轮询预算三十秒，没有新事件时发送注释心跳。客户端继续用新游标重连；断开后由响应框架取消并关闭生成器，finally 中的资源也要完成清理。

## 5. 保留期与多进程

事件表不能永久无界增长。引入清理时，为每租户保存最低可恢复序号；客户端请求的位置早于保留范围，应明确返回需重新获取快照的响应，例如在发送流头之前返回 410，而不是从中间继续并假装完整。

当前学习工程不自动清理事件，因此没有伪造已经实现的保留期协议。扩展时可以先取得快照与相应位置，再接后续事件；快照和位置也必须具有一致性边界，不能先读状态、隔很久再读当前最大序号。

多个 API 进程读取同一持久化事件，重连不要求回到同一进程。若改成内存广播或给每 Worker 保存连接表，就需要另行解决跨进程投递。入口 Nginx 等代理的缓冲与超时也要与流行为匹配。

## 6. 练习与答案

### 6.1 保存 Last-Event-ID 就能保证业务处理不重复吗？

答案：不能。处理成功与保存位置之间可能崩溃；需要幂等处理，或把业务变化与位置保存置于适当原子边界。

### 6.2 服务端每次只读三十二条，就能支持无限连接吗？

答案：不能。每连接仍有 socket、协程、查询和缓冲成本，需要连接与查询预算；小批次只限制单次占用。

### 6.3 删掉旧事件后，过期游标怎样处理才不误导？

答案：记录恢复下界，在响应开始前拒绝无法完整恢复的位置，并引导重新取得一致快照。不能只返回剩下事件而不说明缺口。
