# 路由、路径、查询、请求体与响应

同一个整数放在路径、查询或 JSON 里，表达的接口语义不同。FastAPI 根据声明提取与验证输入，业务代码再决定资源是否存在、操作是否允许。

## 1. 参数来自哪里

路径适合定位资源，查询适合筛选与分页，请求体适合提交结构化数据，Header/Cookie 用于相应协议元信息。不要依赖框架猜测复杂参数来源，必要时显式使用 Path、Query、Body、Header。

路由的声明顺序也可能影响固定路径与动态路径的匹配。应将 `/jobs/latest` 与 `/jobs/{job_id}` 这样的冲突作为测试场景，而不是仅检查文档能生成。

## 2. 输入与失败示例

```python title="api_routes.py"
from typing import Annotated
from fastapi import FastAPI, HTTPException, Path, Query

app = FastAPI()

@app.get("/jobs/{job_id}")
async def get_job(
    job_id: Annotated[int, Path(ge=1)],
    limit: Annotated[int, Query(ge=1, le=100)] = 20,
):
    if job_id != 1:
        raise HTTPException(404, "job not found")
    return {"id": job_id, "limit": limit}

def main():
    from fastapi.testclient import TestClient
    with TestClient(app) as client:
        print(client.get("/jobs/1?limit=5").json())
        print(client.get("/jobs/0").status_code)
        print(client.get("/jobs/2").status_code)

if __name__ == "__main__":
    main()
```

```text title="api_routes.out"
{'id': 1, 'limit': 5}
422
404
```

零不满足参数约束，通常在业务函数之前返回验证错误；合法 ID 但不存在资源，则是业务决定的 404。两者不能都改成“系统异常”。

## 3. 响应契约

GET 一般读取资源，POST 创建/触发操作，DELETE 请求删除或取消；幂等性要按业务实际效果设计。202 表示已接受，不表示后台工作已经完成；201 表示创建成功，也需要明确持久化时点。

响应模型用于约束输出，避免内部字段、密码哈希和 ORM 状态意外返回。直接返回 Response 会改变自动校验/序列化路径，应用必须自己保持文档与实际响应一致。

## 4. 输入校验不等于授权

参数合法不说明调用者有权访问这个 job_id。租户、用户与资源关系必须在数据查询/业务边界校验，不能只依赖前端隐藏按钮。

错误体要稳定，避免泄露内部路径、SQL 与令牌。分页同时限制条数、响应大小与排序规则；只设默认值不代表客户端不能传入过大值。

FastAPI 0.150 的默认 Content-Type 行为与表单边界，应按固定版本测试。JSON 客户端使用正确的 `application/json`，不要依赖缺头也能解析的历史行为。

## 5. 练习与答案

### 5.1 参数格式正确，为什么还可能返回四零四？

答案：格式合法只证明输入形态；资源是否存在仍需业务查询决定。

### 5.2 二零二是否表示任务已经执行成功？

答案：不是。它通常表示已接受，应提供任务状态查询与失败语义。

### 5.3 设置 Query 默认二十，就限制了最多二十条吗？

答案：没有。默认值不是上限，需要 le 等约束，并在数据库与响应层控制工作量。
