# 事件循环阻塞、慢请求与内存排障

“CPU 不高，但所有接口都慢”不矛盾。一个事件循环线程被阻塞、一个连接池耗尽、一个锁被长时间持有，都可能限制整个 Worker，而机器其他核心仍空闲。

## 1. 先切出受影响范围

比较同一 Worker 的简单健康接口、不同 Worker、不同 Pod 与直连下游。核对慢发生在接受前、路由前、依赖、数据库、响应发送还是客户端读取。

保存请求 ID、时间线、版本、并发、池状态与堆栈。先重启可能恢复表象，也会丢失最有价值的现场；是否应急重启要与证据保存和业务风险共同决定。

## 2. 一个不依赖时间阈值的阻塞实验

```python title="api_diagnostics.py"
import asyncio
import time

async def main():
    loop = asyncio.get_running_loop()
    callback_ran = asyncio.Event()
    loop.call_soon(callback_ran.set)
    time.sleep(0.02)
    print("while blocked:", callback_ran.is_set())
    await asyncio.sleep(0)
    print("after yield:", callback_ran.is_set())

if __name__ == "__main__":
    asyncio.run(main())
```

```text title="api_diagnostics.out"
while blocked: False
after yield: True
```

同步 sleep 期间，事件循环无法处理已排好的回调。这个有限实验展示调度关系，不代表固定的生产延迟；实际影响还取决于负载与运行环境。

## 3. 假设与证据

| 假设 | 支持证据 | 下一步 |
| --- | --- | --- |
| 事件循环阻塞 | loop lag、同 Worker 简单请求一起慢、同步热点栈 | 替换驱动或有界卸载 |
| 线程池饱和 | 同步依赖等待、令牌/执行器排队 | 缩短占用、限流与池预算 |
| 数据库池耗尽 | 获取连接慢、长事务、未归还 | 找持有者与事务边界 |
| 下游故障 | 出站跨度/状态异常 | 总 Deadline、幂等重试与隔离 |
| 内存保留 | 多轮工作后对象/任务持续增长 | 引用链、缓存、Traceback、流未关闭 |

asyncio debug 与 slow callback 日志用于受控诊断，不能无限量开高成本日志。Profile、日志和抓取局部对象都可能影响延迟与隐私。

## 4. 内存与流

比较请求结束后是否仍有 Task、Response、Session 或生成器存活。RSS 不下降可能是分配器/原生缓存，也可能是实际保留，需结合 tracemalloc 与系统指标。

大 JSON、上传、下游 aread 和无界后台任务都是常见峰值来源。设置限制并测试错误路径，不能仅通过增加内存掩盖无界设计。

## 5. 修复后验证

在相同负载下比较总延迟、尾部、成功工作量与资源；再验证取消、超时、断开和退出。关闭某个优化后问题消失，只说明执行路径改变，不自动证明根因就在该开关。

### 5.1 一次可重做的慢请求定位

先运行 compare_load.py，对比 blocking 与 asynchronous 的相同等待。若 blocking 并发提高后吞吐不再升、同 Worker 简单请求也受影响，进一步用 loop lag 和同步热点栈验证；改为真实异步等待后，在相同请求数和工作内容下重测。这个实验中关闭阻塞调用改变了明确路径，结论比“重启后不慢了”更具体。

下一组用[数据库锁实验](../03-data-security/06-PostgreSQL锁竞争与在线结构演进.md)制造有限锁等待：事件循环可能正常，但数据库 Span 和锁等待变长。再把慢等待移到事务外，观察池占用与延迟；不要把两种低 CPU 场景混成同一根因。

内存问题则固定请求大小和轮数，对比 tracemalloc 快照、残留 Task 与连接。先判断仍可达对象、原生内存或分配器保留，再实施修复。每个实验改变一个主要因素并保留失败路径断言，才能解释修改为何有效。

## 6. 练习与答案

### 6.1 机器 CPU 低，能排除事件循环阻塞吗？

答案：不能，一个线程阻塞就可能影响同 Worker 的全部请求，整机平均利用率仍很低。

### 6.2 重启恢复，是否证明问题已经修复？

答案：不能，资源泄漏或积压可能只是被清空，应继续验证机制与再次增长条件。

### 6.3 禁用某开关后不慢了，能立刻把它写为根因吗？

答案：不能，开关可能改变通信、调度或缓存路径。需要最小对照和独立证据确定真正因果。
