# 上传、下载、文件与流

UploadFile 不是“上传完全不占资源”的承诺。文件先经历服务器与 multipart 解析，可能进入内存和临时文件；路由内部的分块读取只控制后续处理的一部分成本。

## 1. 数据经过哪些层

代理/Server 接收请求，解析器处理表单与文件，应用读取 UploadFile，再写存储或交给处理器。每层都需要上限：连接时间、总请求体、文件数量、单文件大小、临时磁盘和处理并发。

客户端声明的 Content-Length、文件名和 Content-Type 都不能直接作为可信事实。未知长度和分块传输同样要受限制。

## 2. 有界读取示例

```python title="api_upload.py"
from typing import Annotated
from fastapi import FastAPI, File, HTTPException, UploadFile

app = FastAPI()

@app.post("/uploads")
async def upload(file: Annotated[UploadFile, File()]):
    size = 0
    try:
        while chunk := await file.read(65536):
            size += len(chunk)
            if size > 1024 * 1024:
                raise HTTPException(413, "file too large")
        return {"bytes": size}
    finally:
        await file.close()

def main():
    from fastapi.testclient import TestClient
    with TestClient(app) as client:
        response = client.post("/uploads", files={
            "file": ("sample.txt", b"hello", "text/plain")})
        print(response.status_code, response.json())

if __name__ == "__main__":
    main()
```

```text title="api_upload.out"
200 {'bytes': 5}
```

这个限制在路由处理阶段生效，不保证在 multipart 解析前就停止所有接收；完整防护还需入口与解析层约束。FastAPI 0.150 将浏览器未选择文件的部分按缺失处理，命名的零字节文件则不等价于缺失。

## 3. 文件名与持久化

服务端生成存储标识，不直接把用户文件名拼入目录。校验路径归属、防止覆盖、使用最小权限，并按业务检查实际格式与恶意内容。扩展名正确不是格式安全证明。

写入失败需清理本次临时对象；成功落库与对象存储之间的一致性，也要通过状态机和可恢复清理处理。不要在失败时递归删除一个由输入计算出的宽泛目录。

## 4. 下载与响应寿命

FileResponse 适合发送受控文件；StreamingResponse 适合逐块生成，但生成器持有资源直到结束/断开。提前退出临时目录作用域后再返回文件路径，会让真正发送时文件已经消失。

下载应配置合适的媒体类型、文件名处理、缓存和访问控制。Range、条件请求与断线重试需要结合实际响应类与代理测试。

## 5. 练习与答案

### 5.1 路由里限制一兆，就一定不会先写满临时盘吗？

答案：不能保证，解析阶段可能已接收或暂存数据。需要入口、解析与处理多层上限。

### 5.2 用户 filename 可以直接作为服务器路径吗？

答案：不应如此，可能越界或覆盖文件。服务端生成标识，原始名称最多作为经处理的元数据。

### 5.3 with 临时目录结束后再返回 FileResponse，安全吗？

答案：通常有生命周期问题，实际读取可能发生在返回之后。必须让文件存活到发送完成并再清理。
