# 同步、异步、线程池与事件循环阻塞

在 FastAPI 中，同步路径操作/依赖通常会被移入线程池执行，异步路径操作直接由事件循环推进。但从异步函数里普通调用一个同步工具函数，不会自动获得线程卸载。

## 1. 声明与调用位置都重要

异步函数里调用 time.sleep、同步数据库查询或 CPU 密集循环，可能占住事件循环线程；同一 Worker 的其他请求、超时回调与连接处理都会受影响。

把所有函数改成 def 也不是通用修复：线程池有容量，连接池也有限；过载会从事件循环转移到等待线程许可或数据库连接。

## 2. 验证线程身份

```python title="api_execution.py"
import asyncio
from threading import get_ident
from fastapi import FastAPI

app = FastAPI()

@app.get("/async")
async def asynchronous():
    loop_thread = get_ident()
    worker_thread = await asyncio.to_thread(get_ident)
    return {"different": loop_thread != worker_thread}

@app.get("/sync")
def synchronous():
    return {"ok": True}

def main():
    from fastapi.testclient import TestClient
    with TestClient(app) as client:
        print(client.get("/async").json())
        print(client.get("/sync").json())

if __name__ == "__main__":
    main()
```

```text title="api_execution.out"
{'different': True}
{'ok': True}
```

示例只证明这次显式 to_thread 的线程不同，不据此给出吞吐结论。线程卸载也不提供工作取消或连接线程安全的保证。

## 3. 池与预算

Starlette/AnyIO 的线程限制与 asyncio 默认执行器可能是不同资源；不要只调一个线程数就认为所有同步工作容量一起改变。应观察具体接口使用的执行器与等待时间。

使用同步 SQLAlchemy 时，Session 生命周期要遵循驱动与会话线程安全要求；并发任务不能共享同一个 Session。异步数据库驱动也有连接上限，不能因为 await 就无限并发。

## 4. 排障方法

区分事件循环延迟、线程等待、数据库池等待与下游耗时。通过并发发送一个慢请求和一个简单健康请求，观察简单请求是否一起变慢；再结合堆栈与运行时间线定位，不只看总体 GPU/CPU 利用率。

纯 Python CPU 计算可能需要进程或独立工作服务；大对象在进程之间搬运又有成本。优化要在相同正确性与负载下比较。

## 5. 练习与答案

### 5.1 async 路由里直接调用同步函数，框架会自动换线程吗？

答案：一般不会，普通函数调用仍在当前线程执行。需要明确使用合适的异步接口或受控卸载。

### 5.2 增大线程池，数据库连接数就一定够吗？

答案：不会。更多线程可能只是在等有限连接，甚至扩大内存和上下文切换成本。

### 5.3 请求取消后，线程里的工作一定停止了吗？

答案：通常不能保证。阻塞函数需要自己的超时与停止协议，外部写入还需要幂等和确认。
