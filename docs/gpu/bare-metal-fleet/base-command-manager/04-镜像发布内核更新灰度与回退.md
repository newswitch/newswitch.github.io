# 镜像发布内核更新灰度与回退

镜像是系统内容的来源，发布是把内容和配置安全地变为运行状态的过程。把两者分开，才能解释为什么“包已升级”不等于“节点已运行新驱动”。

## 1. 四个版本坐标

镜像内容版本、节点引用的镜像、节点本地文件版本、运行中的内核/模块版本可以暂时不同。系统必须允许这种过渡，同时知道过渡发生在哪一层。

教学例子：克隆镜像 A 为 B，在 B 中升级 Kernel。若分类仍引用 A，节点不会自动采用 B；若引用已改但未经过要求的同步或启动流程，实际运行状态仍可能旧；若 Kernel 已更换，模块签名或 ABI 不匹配又可能使 GPU 不可用。

## 2. 克隆与异步完成

BCM 支持从现有镜像克隆后修改，再逐步分配到节点。管理环境可用 `softwareimage` 查看和管理镜像；克隆、注册内核和生成 initramfs 需要观察对应操作是否真正完成，不能只看命令提交成功。

以下是官方 Shell 上下文的教学示例，只能在已选定的测试镜像上执行：

```text
softwareimage
clone default-image test-image
commit --wait
```

它不包括后续修改、节点切换或生产验收。异步任务报错时先保存任务和存储证据，避免再次创建同名对象导致状态更难识别。

## 3. 内核与文件不能脱节

网络引导场景中的 Kernel/initramfs 与节点根文件系统必须协调。新内核文件放进镜像，不一定已经更新管理对象引用或生成正确 initramfs。目标系统还可能采用其他引导方式，不能从一份网络引导手册推断所有机器都相同。

对比应覆盖 `uname -r`、实际模块、启动参数和目标镜像元数据。新增 initramfs 驱动、改变磁盘布局或网络接口配置，可能使节点连管理网络也起不来，必须保留带外控制台与已知可启动版本。

### 3.1 BCM 中的生成与生效链

以 BaseOS 指南描述的 PXE 启动为例，安装新 Kernel 包之后还需把镜像的 `kernelversion` 注册为目标版本，并等待 initial ramdisk 生成成功。该通知不是“命令已接收”的同义词；节点运行的内核则要到正确的下一次引导才改变。其他引导方式应另查对应契约。

BCM 11 的 `kernelmodules` 配置也有特定含义：它描述需进入早期 ramdisk 的模块及尝试装载顺序，不只是让正常 OS 以后执行一次 `modprobe`。修改软件镜像的该列表会触发 `createramdisk`；其生成与向供应节点分发仍需检查结果。

模块列表的低层覆盖不是自动并集。节点级定义可以覆盖 Category 和 Software Image 的整份列表；只在节点级“补一个模块”却遗漏原有网络或存储驱动，可能让机器在根文件系统可访问之前就失败。先查看有效配置和生成产物，再比较节点启动日志。

教学链路：镜像 B 已有新内核文件 → BCM 仍登记旧版本 → PXE 仍取旧 Kernel。修复第一处后，若新 initramfs 漏了根盘驱动 → 新 Kernel 已加载但找不到根文件系统。这两个症状的修改点不同，不能统称“重启没生效”。

### 3.2 两次同步之间也可能存在旧副本

镜像头副本、provisioner 副本和节点本地文件是三个位置。BCM 11 手册说明运行中更新的自动 provisioner 刷新有时间条件，刚修改镜像后不能仅凭默认机制推定所有源已同步。确认实际供应源、修订和任务结果，比反复执行 `imageupdate` 更有诊断价值。

启动安装的 `AUTO/FULL/NOSYNC`、运行中更新及五类排除列表见[安装模式与供应重试](./12-节点安装模式排除规则与供应重试.md)。特别注意：`NOSYNC` 不禁止运行中 `imageupdate`，FULL 重新分区也不受普通目录排除规则保护。

## 4. 灰度与容量预算

设 64 张 GPU 的池子需要至少 48 张维持业务，另留 8 张故障余量，则计划维护最多占 8 张；不能只看眼前空闲 16 张就同时下线 16 张。还要按型号与拓扑检查是否保留了足够完整的训练形状。

发布分为镜像测试、同硬件 Canary、跨硬件代表节点、有限批次和全量。每阶段保留功能、性能及错误计数基线，失败时停止扩大范围。性能回归门槛应按同型号分布建立，不使用任意统一百分比。

## 5. 回退的不同层次

重新绑定旧镜像不保证恢复全部状态。还要检查有效内核参数、模块、已生成的调度服务配置、固件、本地持久数据和数据库格式。固件及外部存储数据尤其不是 OS 镜像的一部分。

替换成一份全新镜像与在已有镜像中更新，也可能具有不同的集成重建要求。保留“镜像内容、BCM 属性、角色生成配置、外部服务状态”的组合恢复点，回退后重新验证数据面，再解除隔离。

## 6. 掌握检查

为什么 `imageupdate` 不能被解释为重启并切换所有运行中代码？因为文件内容与运行中内核、进程映射不同。为什么回退旧镜像后训练仍失败？检查是否遗漏固件、角色、持久数据或运行内核，不能只重新下载镜像。
