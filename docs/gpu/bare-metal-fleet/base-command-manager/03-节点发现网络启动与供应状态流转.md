# 节点发现网络启动与供应状态流转

“添加节点”至少包含两件事：管理系统认识这台机器，以及这台机器真正进入可交付状态。添加一条对象记录只完成前者的一部分，不能跳过硬件身份与数据保护。

## 1. 先固定身份

给一台新服务器建立资产序列号、BMC 地址、管理网 MAC、业务 NIC GUID/BDF、系统盘序列号与预期主机名的映射。DHCP 地址可能变化，接口名称可能变化，不能只凭一个 IP 地址授权擦盘或加入生产。

把管理网、供应网、训练 Fabric 与存储网分开画出。它们可以共享物理设备，但故障域、访问权限和流量目的不同。能从管理网 SSH 登录不能证明训练 HCA 已进入正确 IB Partition。

## 2. 教学状态机

```text
资产已确认 → 管理对象已配置 → 引导参数可获取
→ 内核与 initramfs 可加载 → 系统镜像可供应
→ 网络和角色生效 → GPU 软件栈就绪
→ 调度注册成功 → 资格验证通过 → 允许业务
```

这些是验收阶段，不是 BCM 状态字段的逐字枚举。每一阶段应有超时、失败证据和恢复入口。重试装机前尤其要确认目标磁盘和本地数据保留规则，不能把“节点离线”直接等同于“允许重装”。

BCM 11 的节点安装器会请求身份，未知节点可能等待分配。可用不带分配参数的 `cmsh -c "device;newnodes"` 观察，再把当前 MAC、物理资产与待分配对象核对；记录存在、身份确定和磁盘允许覆盖是三件事。上游依赖见[头节点安装与网络](./08-头节点安装网络与基础服务依赖.md)，产品的 UP/DOWN/CLOSED 含义见[真实状态模型](./10-设备状态任务结果与健康检查.md)。

## 3. 分层故障表

| 现象 | 首先验证 | 暂时不要做什么 |
| --- | --- | --- |
| 取不到引导信息 | 管理 MAC、DHCP、VLAN、启动顺序 | 重装 GPU 驱动 |
| 内核启动后找不到系统内容 | initramfs、网络、供应源和镜像绑定 | 清空管理数据库 |
| OS 正常但驱动不加载 | Kernel、模块、签名、软件基线 | 放开业务调度 |
| 调度器看不到资源 | 角色、服务注册、GRES/插件 | 重复登记相同资产 |
| 最小作业通过但多机失败 | NIC、Fabric、存储、Rank 映射 | 认定装机已经证明全集群健康 |

先确认最早失败阶段，再到下游找错误。下游大量超时可能都来自上游供应失败，不应逐项重启掩盖共同原因。

## 4. 批量供应的容量

教学条件：每节点需要传输 40 GiB，32 台同时装机；忽略去重和缓存，共需 1280 GiB。若供应源实际聚合吞吐是 8 GiB/s，纯字节传输下界为 160 秒，还未包含元数据、校验、解压、写盘和启动服务。

提高并发不增加供应源总带宽，反而可能放大超时重试。可按机架与供应源限制批次，用每阶段分位数时延而非单一平均值设置等待预算。幂等流程应识别已完成阶段，而不是每次都重新下载全量内容。

这是流程设计要求，不表示 BCM 的任意重装动作都无损幂等。实际安装器的五种模式、FULL 分支、有效排除规则和供应源副本见[节点安装模式与供应重试](./12-节点安装模式排除规则与供应重试.md)；不能把 `NOSYNC` 理解成禁止写盘或数据保护。

## 5. 调度前资格验证

节点可先保持不可接收业务的状态，再验证 GPU 数量与 UUID、驱动、容器最小计算、PCIe/NVLink、单 Rail 与多机通信、目标存储读写。某项失败应隔离并保留证据；解除不可调度状态是最后一步，不是节点上线的起点。

参考[Burn-in 与交付验收](../05-GPU服务器Burn-in压力测试与交付验收.md)。如果只有纸面学习环境，可以手工推演每阶段的输入、失败证据与重试行为，但不能把推演结论写成硬件验收结果。
