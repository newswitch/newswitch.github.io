# GPU 节点自动隔离、修复、重新入池与 RMA 判定

## 1. 自动修复不是收到告警就重启

自动化需要先保护工作负载，再保存证据，最后才决定动作：

```text
异常事件
→ 去重与关联
→ 标记Suspect
→ 停止新调度
→ 保存Pod/驱动/BMC/拓扑证据
→ 安全终止或等待Checkpoint
→ 主动诊断
→ 软恢复/固件处理/硬件维修
→ 完整复验
→ 重新入池或RMA
```

无限重启会丢失现场、重复伤害业务，并把永久硬件故障伪装成间歇性软件问题。

## 2. 隔离动作

Kubernetes 常见动作是 Cordon 加专用 Taint。Drain 是否执行取决于训练能否 Checkpoint、推理副本是否满足 N-1 和 Pod 的终止语义。执行前验证目标 Node UID，防止主机名复用导致操作错误节点。

隔离控制器应限制：

- 单次最多隔离节点数；
- 每机架/故障域最小剩余容量；
- 同一节点动作冷却时间；
- 已处于维护状态时不重复处理；
- API Server 或监控数据过旧时停止自动写操作。

## 3. 证据包

在重启前采集：

- Node、Pod、Event、设备资源和时间；
- `dmesg` 中 Xid、AER、MCE、OOM；
- DCGM/NVML 快照及 GPU UUID；
- NVLink/PCIe/NIC/RDMA 计数；
- BMC SEL、传感器、电源和固件版本；
- 受影响任务的 Rank、退出码和首个异常时间；
- 最近驱动、Kernel、固件和配置变化。

证据包使用校验和和不可变存储，敏感信息先脱敏。

## 4. 分级恢复

| 等级 | 动作 | 适用边界 |
| --- | --- | --- |
| L0 | 重启应用进程 | 明确为进程级故障 |
| L1 | GPU Reset | 设备支持、无其他使用者、错误允许复位 |
| L2 | 重载驱动/重启 OS | 驱动状态异常且证据已保存 |
| L3 | BMC Power Cycle | OS 无法恢复或设备未重新枚举 |
| L4 | 固件/线缆/部件维修 | 诊断指向硬件或链路 |
| L5 | RMA | 重复失败、不可纠正错误或厂商判定 |

每升一级都扩大影响面。恢复成功只表示设备重新出现，不代表性能和数据正确。

## 5. 重新入池门禁

至少验证：

1. 库存、Firmware 和 PCIe 拓扑与基线一致；
2. Kernel、驱动和 DCGM 无活动错误；
3. GPU 计算、显存与 P2P 诊断通过；
4. 单机 NCCL/HCCL 基线通过；
5. 多机 RDMA/Collective 与同组节点无明显偏差；
6. 持续压力下温度、功率和频率稳定；
7. 解除 Taint 后先承载 Canary 工作负载。

## 6. RMA 判定

RMA 证据应尽可能将问题定位到具体 Serial，并调查线缆、交换机端口、主板 Slot、驱动版本和应用等替代原因。不可纠正 ECC、设备持续掉线、受控环境中的重复失败和平台现场诊断结果，都是调查线索，不应直接转换成统一的自动送修规则。

DCGM Diagnostics 与正式现场硬件诊断不是同一个工具范围，也不替代厂商 RMA 流程。依据机型、错误类别和支持政策收集所需材料，取得明确处理结论；不能把一次 diag Fail 或某个 Xid 编号当作所有平台的换卡许可。详见[DCGM 插件结果与故障归因](./09-DCGM诊断插件结果与故障归因.md)及[NVSM 证据包](./10-NVSM对象树健康检查与证据包.md)。

## 7. 自动化必须防止反馈放大

告警、隔离和重试本身会改变负载：下线节点使剩余节点更忙，温度和延迟可能继续上升，触发更多隔离。应同时设置全局和故障域容量预算、动作速率、冷却时间以及监控过期时的停止条件。

同一物理故障可能被 DCGM、内核日志、NVSM 和调度器各报一次，去重键应关联 Serial/UUID、故障类型和时间窗口，而不是每条告警执行一次重启。

## 8. 幂等与执行所有权

操作记录应具有唯一动作 ID、目标身份、当前阶段和执行结果。两个控制器同时恢复同一节点时，需要受控协调，避免一个正在收集证据、另一个已切电。重试必须先读取实际状态，不能只重复上次命令。

管理员正在维护的节点不应被自动恢复器提前重新开放；节点名称复用也不能继承旧节点的动作。对 Kubernetes 使用 Node UID，对物理设备使用 Serial/UUID，明确哪份事实负责解除维护状态。

## 9. 重新入池不是清空错误

修复后以相同基线复验功能和性能，并让 Canary 覆盖此前失败路径。仅清空计数器、重启后看不到旧日志或手工清除 Drain/Taint，都不能证明故障已消失。详细管理边界见[BCM 安全与恢复](./base-command-manager/06-健康监控权限审计与管理面恢复.md)。
