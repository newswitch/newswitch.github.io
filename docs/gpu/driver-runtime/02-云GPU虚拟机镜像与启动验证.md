# 云 GPU 虚拟机镜像与启动验证

VMI 即虚拟机镜像，包含用于启动来宾操作系统的磁盘内容；容器镜像提供用户态文件系统，通常共享宿主内核。两者不是同一种制品，不能靠相同镜像 Tag 推断内核和设备栈相同。

## 1. 从实例到应用

```text
实例型号与区域容量 → 云平台设备暴露方式
→ 来宾 OS 与 Kernel → GPU 驱动
→ 容器运行时和用户态库 → 应用最小计算
→ 多机网络、存储和目标工作负载
```

直通、虚拟 GPU 和其他暴露方式具有不同功能、许可与性能边界，必须查实际云平台和目标实例说明。不从实例名称猜测 MIG、NVLink、RDMA 或 GPU Reset 支持。

## 2. 预装驱动也要验证

镜像内有驱动包，不等于运行中模块已正确加载。首次启动、自动更新 Kernel、Secure Boot、模块签名及云初始化都可能改变结果。先核对系统版本、设备枚举、驱动、用户态库和最小 CUDA 计算，再进入容器与编排。

镜像 Build ID、云镜像标识、区域、CPU 架构、实例规格和应用镜像 Digest 应一起保存。相同人类可读名称在不同区域或时间不一定指向相同内容。

## 3. 临时盘不是持久化承诺

实例本地缓存或临时 NVMe 可能随停止、迁移或销毁失去。模型缓存可以重建，唯一 Checkpoint 不能只放在不具备持久化保证的位置。OS 快照也不自动包括外部对象存储、运行中显存或一致的训练状态。

更换实例后应先重新发现设备 UUID/BDF、磁盘和网络能力，不能把前一台虚拟机的拓扑硬编码进训练启动脚本。

## 4. 多机能力单独验收

两台实例都能运行单卡 Kernel，不证明跨机 RDMA、路由、安全组和分布式启动成立。先验证基本连接与目标传输，再测试 Collective，最后加载真实应用。云平台的安全策略应只开放所需通信，不用全面放行端口替代定位。

## 5. 掌握检查

换一个“同名镜像”实例后 CUDA 失败，先比较实际镜像标识、架构、Kernel、驱动和设备暴露方式。容器镜像完全相同仍可能遇到不同宿主契约，这正是 VMI 与容器需要分别管理的原因。

进一步阅读[镜像身份与 cloud-init](./05-云GPU镜像身份cloud-init与驱动生效.md)、[云端多机通信](./06-云GPU多机通信EFA-InfiniBand与TCPX.md)和[中断恢复与重建资格](./07-云GPU中断恢复持久状态与重建资格.md)。从初始化时点、传输提供者和持久状态解释同名镜像之外的差异。
