# 云 GPU 中断恢复持久状态与重建资格

云实例可重新创建，不意味着应用状态可以恢复。恢复需要同时拥有完整 Checkpoint、可用软件基线、重新获得的资源和正确的身份授权。实例 Running 只是恢复过程的一项证据。

先读[镜像与初始化](./05-云GPU镜像身份cloud-init与驱动生效.md)。本篇讨论故障模型，不提供当前云价格建议，也不把某一种购买方式当成可用性保证。

## 1. 停止 重启 重建与回收不同

重启通常仍围绕同一实例，但设备枚举和运行状态需要复核；停止后启动、宿主维护、迁移、销毁重建和抢占回收，可能有不同的磁盘、网络和身份语义。具体资源是否保留由云平台及实例类型规定。

应为每类状态分别记录：系统盘、外部持久盘、本地临时盘、IP、实例身份、GPU UUID 和运行中显存会怎样变化。不能把系统盘快照视为 GPU 显存快照，也不能从持久盘存在推断多 Rank Checkpoint 一致。

可重建模型缓存适合失去后重新下载；唯一 Checkpoint 则必须满足所需的独立持久性和恢复范围。数据协议见[Checkpoint 一致性](../../storage/training-data-plane/07-Checkpoint-Storm-IO基准监控容量与故障排查.md)。

## 2. 通知是优化机会 不是恢复前提

以 AWS Spot 为例，官方文档描述停止或终止前通常提供两分钟通知，休眠行为有例外，而且通知是 best effort。这不能扩展成任何故障前都有两分钟保存窗口。[通知说明](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/spot-instance-termination-notices.html)。

假设 Checkpoint 需要三分钟，靠收到两分钟通知后才开始保存就不成立。即使预计只需一分钟，也可能受到存储拥塞、进程卡死或通知缺失影响。周期性持久保存是基础，通知处理只能尽量缩小损失。

收到通知后的动作要有边界：停止新工作、保存可完成的状态、发布完整版本、退出和让其他 Rank 感知失败。不能把尚未完成的分片标记为可恢复。

## 3. 保存越频繁不一定总成本越低

设一次阻塞保存成本为 `C` 秒，保存间隔内的有效计算时间为 `T` 秒，失效率为 `λ` 次/秒。假设失效独立、发生时刻近似均匀、保存已持久完成且各项开销相对较小，简化损失率可写为：

```text
L(T) ≈ C/T + λT/2
```

第一项是保存开销，第二项是失效后平均重算半个间隔。对该式求导得 `T≈sqrt(2C/λ)`；它只是教学近似，没有包含重启、排队、恢复加载、相关故障和异步保存积压。

教学参数：`C=30` 秒，`λ=1/7200` 每秒，则候选间隔约为 657 秒，即 10.95 分钟，模型损失约 9.13%。若间隔为 600 秒，约为 9.17%；改成 1200 秒，约为 10.83%。这里的失效率是假设输入，不是云平台统计。

真正策略还受 RPO、存储预算、同步代价与可恢复完整性约束。不要把近似最优间隔当作所有训练统一配置。

## 4. 多 Rank 恢复需要完整版本

一个 Rank 成功写盘，不等于全部必要分片完成。恢复端应依据 Manifest、分片集合、校验与完成条件选择版本；不能从目录名或某个 `latest` 文件推断完整性。

World Size 改变后，框架是否支持重分片、优化器状态是否可迁移、数据采样如何避免错误重放，都属于应用恢复协议。重新创建相同数量的 GPU，不会自动恢复原先通信组和随机数状态。

重试还要防止两套任务同时恢复同一训练。旧实例失联不证明已经死亡；如果新实例抢先启动并写同一位置，应有唯一执行权与提交协议。见[多集群唯一执行与重复提交防护](../../cloud-native/kubernetes/multi-cluster/11-训练任务唯一执行迁移恢复与重复提交防护.md)。

## 5. 资源获得与软件恢复独立

配额满足不等于当时有目标实例容量；镜像存在不等于新实例完成初始化；实例可登录不等于网络与存储恢复。恢复时间应沿实际关键路径分解，而不是只统计创建 API 的响应时间。

新设备可能具有不同 UUID、BDF、磁盘枚举和 NIC 关系，应重新发现。恢复旧启动脚本时，不应继承前一台机器的硬编码设备索引和管理凭据。

恢复出的身份还要重新取得最小权限。无法读取 Checkpoint 可能是身份或存储授权问题，不一定是文件损坏；有权限读取也不证明版本适合当前框架。

## 6. 重新准入有明确门槛

```text
新实例身份与软件基线确认
→ 驱动及最小计算正常
→ 网络和存储路径正常
→ 完整 Checkpoint 加载
→ 恢复步骤与结果验证
→ 取得唯一执行资格并开放工作
```

顺序应与所用协调协议配合：不能在没有唯一执行权时启动具有外部写副作用的恢复任务。图表达需满足的条件，不规定所有系统都在最后一步才申请执行权。

对推理服务，还要验证模型热身、就绪与流量准入；把未完成模型加载的实例加入负载均衡，会把基础设施恢复转成业务错误。

## 7. 掌握检查

**有中断通知是否可以停止周期 Checkpoint？** 不可以，通知不覆盖所有失效且可能来不及完成。

**系统盘恢复是否等于训练恢复？** 不等于，显存、多 Rank 状态和外部数据都另有契约。

**新实例 CUDA 通过后是否能直接写原训练目录？** 还需身份、完整状态、版本兼容和唯一执行权。
