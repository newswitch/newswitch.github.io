# GPU 集群成本与利用率分析

GPU 往往是集群最大成本项。分析目标：知道 **钱花在哪、浪费在哪、扩容是否值得**。结合 DCGM 利用率、队列配额与节点池标签，做每月 FinOps 复盘。前置：[第 41](../../../sre/observability/gpu/04-GPU%20利用率低但显存占满怎么分析.md)、[第 53](./03-GPU%20集群容量规划方法.md)、[第 52](./02-GPU%20多租户与资源配额设计.md) 篇。

## 1. 成本结构（简化）

| 项 | 说明 |
|----|------|
| 卡时费用 | 云按 GPU 型号计费，或折旧/电费摊销 |
| 网络 | IB/RoCE 交换机与专线 |
| 存储 | 模型盘、Checkpoint、数据集 |
| 人力与平台 | Operator、值班、排队系统 |

单位常用：**元 / GPU·小时**。先固定每型号单价表，再乘使用量。

## 2. 利用率怎么定义（避免吵架）

| 指标 | 含义 | 适合 |
|------|------|------|
| **时间利用率** | `avg(GPU_UTIL)` 或 GR_ENGINE_ACTIVE | 看卡是否在算 |
| **显存利用率** | FB_USED / 总量 | 推理权重是否占满 |
| **分配利用率** | 已 request 的 GPU / 物理 GPU | 调度是否把卡分出去 |
| **有效利用率** | 高 util 且业务有吞吐 | 排除空转占卡 |

单独吹「平均 util 20%」可能冤枉：推理常驻权重会拉低 util；应同时报 **分配率** 与 **浪费率**。

```text
浪费率 ≈ 时间占比：FB 高且 UTIL 低（阈值自定）
空闲率 ≈ 未分配卡 / 总卡
争用率 ≈ Pending 等待 GPU 的作业时长
```

## 3. 分摊到租户 / 池

标签来源：`namespace`（DCGM `-k`）、`pool`、Kueue Cohort、Volcano queue。

| 视角 | 问题 |
|------|------|
| 按 Namespace | 哪个团队最贵？ |
| 按池 | 推理 vs 训练 ROI |
| 按型号 | H100 是否物尽其用 |
| 按 Job/模型 | 哪个模型该量化/下线 |

月报最小集：

1. 各池 GPU·小时与费用
2. 平均时间利用率、浪费小时数
3. 排队等待小时（机会成本）
4. Top5 浪费 Namespace/Pod
5. 扩缩容建议（链到容量表）

## 4. 成本优化杠杆

| 杠杆 | 动作 | 风险 |
|------|------|------|
| 回收浪费 | 缩无流量副本、杀僵尸、睡眠模式 | 冷启动变长 |
| 降规格 | 小模型去 T4/L4；量化 | 质量回归 |
| 共享 | MIG / Time-Slicing / vGPU | 干扰与排障难 |
| 抢占与借用 | 低优填谷，高优保证 | 训练需 CKPT |
| 拓扑 | 同 rack 降低训练时长（间接省钱） | 调度复杂度 |
| 竞价/Spot Flavor | Kueue spot flavor | 中断 |
| 配额治理 | 降 nominalQuota 逼交还 | 政治成本 |

「再买 8 张 H100」前，先算：若把浪费率降一半，是否已够一个季度。

## 5. 和 SLA 的平衡

| 只追利用率 | 只追 SLA |
|------------|----------|
| 过度共享、噪声邻居 | 大量空闲缓冲 |
| 训练总被抢 | 成本失控 |

健康区间因业务而异；许多平台把 **分配率 70%～85%**、**时间利用率视负载类型分别看** 作为讨论起点，而不是唯一 KPI。

推理：允许较低 util + 高显存（权重常驻），但用「每 1k 请求成本」替代纯 util。
训练：看 **GPU·小时 / epoch** 或 / token，结合 NCCL 是否拖后腿。

## 6. 示例核算

假设：

- H100 单价 30 元/卡时
- 训练池 16 卡，月 720h → 理论 16×720=11520 卡时
- 平均分配率 80% → 计费相关使用 9216 卡时 → 约 27.6 万元
- 其中浪费（高 FB 低 util）占分配时间 15% → 约 4.1 万元「可挖潜」

把挖潜排进下月：缩容、清僵尸、调配额，再决定是否采购。

## 7. 小结

| 问题 | 方法 |
|------|------|
| 贵在哪？ | 池 × 型号 × 卡时 × 单价 |
| 浪费吗？ | 高显存低 util + 空闲常驻 |
| 该买吗？ | 挖潜后仍排队/破 SLA 再买 |
| 治理工具 | 配额、池、优先级、共享、拓扑 |

生产治理主线至此可闭环：池（51）→ 租户配额（52）→ 容量（53）→ 成本（54）。升级与巡检见 [55](./05-GPU%20集群升级与变更管理.md)、[56](./06-GPU%20节点巡检体系设计.md)。
