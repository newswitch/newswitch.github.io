# 全局队列、配额、准入与跨集群放置

## 1. 两级状态机

```text
任务进入全局Queue
→ 验证租户Quota/Priority
→ 过滤不兼容集群
→ 选择候选集群并预留
→ 委派到成员Queue
→ 成员完成本地准入与Pod调度
→ 汇总运行状态
```

全局“已放置”不代表成员 Pod 已绑定；成员 Pending 也可能需要全局撤销后换集群。

## 2. 硬约束与评分

硬约束先过滤：GPU 型号/显存、Runtime、合规地域、Dataset 可达、最小节点 Shape、网络能力。评分再考虑 Queue Wait、数据 Cache、成本、能效和故障域。

不要用加权分数掩盖硬约束。例如模型必须在某地域，低成本不能抵消合规要求。

## 3. 配额

全局配额防止租户跨集群超额使用，成员配额保护本地资源。二者必须使用一致的 Workload UID 和资源单位，处理：

- 预留但尚未启动；
- 部分失败；
- 抢占与重排；
- 成员断连；
- MIG/异构 GPU Flavor；
- 任务结束后的配额释放。

## 4. Reservation 与 Fencing

选择成员后先创建带 TTL 的 Reservation。成员接受后返回唯一 Token；只有持有有效 Token 的实例能进入 Running。超时后回收时需确认成员没有成功启动，防止双执行。

## 5. Kueue MultiKueue 心智模型

MultiKueue 可把管理集群的 Workload 委派给 Worker Cluster。实际支持的 Job Framework、字段传播、AdmissionCheck 和版本应以目标 Kueue 文档为准。排障分别观察管理集群 Workload、AdmissionCheck 和成员 Workload/Job。

## 6. 放置抖动

容量视图快速变化时，任务可能反复迁移候选。使用 Hysteresis、最短驻留时间、预留和有限重试，避免每次资源更新都重新放置。已经开始下载大模型或写数据后，迁移成本也要计入评分。

## 7. 指标

- Global Queue Wait 与 Local Queue Wait；
- Placement Decision Latency；
- Reservation 成功/过期/冲突；
- 每集群拒绝原因；
- 跨集群重试次数；
- 放置后 Time to First Step/Ready；
- 数据移动字节与成本。
