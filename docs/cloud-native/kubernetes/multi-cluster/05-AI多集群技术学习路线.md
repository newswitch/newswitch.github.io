# AI 多集群技术学习路线

AI 多集群不是把相同 YAML 分发到多个 Kubernetes 集群。真正困难的是同时管理稀缺 GPU、模型和数据位置、任务唯一执行、推理流量以及独立故障域。

```text
全局资源与健康目录
→ Queue/Quota/Policy准入
→ 选择目标集群
→ 分发镜像/模型/Runtime
→ 确认Dataset/Checkpoint位置
→ 创建训练或推理工作负载
→ 全局观测与故障切换
```

## 2. 三种架构

| 架构 | 优点 | 风险 |
| --- | --- | --- |
| 独立集群+外部平台 | 故障隔离清晰 | 需要统一资源和交付接口 |
| 多集群编排控制面 | 集中策略与分发 | Hub 故障、API 兼容、状态传播 |
| 联邦队列/委派 | 保持成员自治 | 准入和最终执行状态更复杂 |

不要让全局控制面成为所有请求的同步数据路径；成员集群应能在短时断连时继续运行已下发工作负载。

## 3. 完成标准

- 能区分资源发现、准入、放置、分发和流量路由；
- 能避免同一训练在两个集群同时执行；
- 能保证模型和数据版本与目标硬件兼容；
- 能在切换前验证目标集群的 Warm Capacity；
- 能计算 Dataset/Checkpoint 复制的 RPO 和网络成本；
- 能从全局任务追到成员集群 Pod、Rank 和 GPU；
- 能注入 Hub、成员、网络、存储和区域故障。
