# 边缘 AI 断连恢复灰度发布与数据一致性

边缘 AI 必须同时处理两个事实：管理网络可能断开，本地业务仍需要继续。Fleet Command 的历史官方架构明确区分断连时应用继续运行与远程更新、控制暂不可用；这不承诺任意依赖外部服务的应用都能无限离线。

本篇沿用[对象与安全边界](./07-Fleet-Command对象注册身份与安全边界.md)的架构基线，并区分公开 CLI 所述操作范围与通用发布设计；以下状态流不是产品内部逐步实现的声明。

## 1. 先画出离线依赖闭包

```text
本地输入 → 预处理 → 推理 → 本地输出
             ↓        ↓        ↓
        配置与字典   模型文件   业务状态
             ↘       ↓       ↙
          存储、身份、时间及外部服务
```

管理控制面不在每次推理路径上，不等于其他云服务也不在。应用若每条请求都访问云端授权、模型下载或数据库，断开这些依赖仍会失败。

把依赖按“运行时必需”“启动时必需”“发布时必需”“可延迟上传”分类。已启动的容器可继续，不证明断连后重新启动也可继续；重启可能需要未缓存的镜像、模型、凭据或配置。这个差异应进入可用性设计。

## 2. 下载 校验 激活与业务切换

发布包应把镜像、模型、预处理、配置和接口版本绑定起来。教学状态流为：

```text
获得目标修订 → 下载到候选区域 → 完整性与信任校验
→ 验证依赖和资源 → 激活候选 → 业务验证 → 提交当前版本
```

下载中断时保留仍在运行的旧版本，不能把半份模型覆盖到当前路径。校验失败不能进入激活；激活成功但输出不正确，应按明确条件停止扩大发布，而不是只看进程存活。

跨文件的发布通常不具有自动原子性。可用不可变版本目录和受控指针管理可见版本，但文件系统、进程重载与请求路由仍需协调。不同站点也不会同时完成，全球版本不一致是过程中的正常状态，应被准确呈现。

## 3. 重连应对账 而不是盲目重放

假设控制面目标从 A 改为 B，再改为 C；离线站点仍运行 A。恢复后应比较当前目标、站点实际版本和升级依赖，决定能否 A 直接到 C，或是否必须经过 B 的迁移步骤。不能把所有历史动作无条件执行，也不能默认跳过每个中间版本。

操作超时同样不能证明“没有发生”。激活响应丢失时，站点可能已切换；重试前读取实际状态，防止重复迁移数据库或重复执行外部业务动作。

### 3.1 先区分重启与重建

[NGC CLI](https://docs.ngc.nvidia.com/cli/cmd_fleet-command.html)把 `reboot-system` 与 `reset-location` 分开；后者描述的是重建位置的 Kubernetes 集群，并提醒应用会有停机。这不是把观测状态重新读一遍，也不是普通容器重启。

因此站点短暂断连时，不能仅为消除一个旧状态就触发位置重置。先定位失败发生在连接、身份、集群、制品还是业务；若确需重建，再核对持久数据、依赖和恢复入口。重新部署成功也不意味着旧现场数据自动恢复。

### 3.2 列表成功不代表更新已收敛

查询只证明当前账户在该次读取中获得了某份控制面视图。教学推演：控制面已接受新配置，离线站点尚未取得它；查询命令成功与站点旧版本继续运行并不矛盾。

应把操作身份、目标配置、逐站点实际状态和观测时间一起关联。公开 CLI 的列名不能补出完整后端状态枚举，更不能由一次列表推导所有节点的 kubelet、模型和输入源都正常。

教学上可为动作设置唯一标识、修订和幂等条件；它们不是替代业务一致性协议的魔法。某些动作无法安全重放，就需要显式人工处理或补偿过程。

CLI 的部署示例同时出现位置 `ONLINE` 与部署 `DEPLOYING`，正好说明连接状态与发布状态是不同维度。另一个系统详情示例使用 `READY`；不能把这些词拼成适用于所有对象的统一状态机，或把示例误当成完整枚举。自动化遇到新状态值应保留原值并停止作出“已完成”的推断，而不是把未知状态当作成功。

### 3.3 防止旧动作覆盖新意图

以下是用于推演的发布协议，不是 Fleet Command API。为目标对象分配身份 `E`，每次目标变更分配递增修订 `R`；即使删除后用同名重建，也必须使用新的对象身份。站点记录已接受和已完成的修订，旧身份或过期修订不能继续激活。

这里的过期是相对于站点已确认的目标。断连站点无法知道尚未送达的撤回；若新激活必须受在线控制，可要求在线授权，或在有界租约过期后停止新激活。租约有效期内的撤回仍不保证即时生效，租约也依赖时钟和执行端的失效处理。不能同时假定无限离线继续激活和云端即时撤销。

教学时间线：`E1/R7` 下载 B 时断连，管理端随后把目标改为 `E1/R8` 的 C。重连后 B 的旧任务晚到。只校验 B 的 Digest 会让内容正确但意图过期的制品生效；还需在激活提交处核对对象身份、修订和当前目标。检查与切换之间也要避免新意图插入，否则“检查时是最新”仍不能保证“提交时是最新”。

若需要从 C 回退到 B，应创建新意图 `E1/R9→B`，不是把修订降回 R7。制品版本可以回退，控制意图的顺序不应因此倒退。旧任务取消失败时，提交处的拒绝过期写入能力比单纯发送取消请求更重要。

Kubernetes 对自己的对象更新提供基于 `resourceVersion` 的条件写入和冲突检测，可对照[声明式变更与并发](../../kubernetes/commands/03-kubectl声明式变更与安全删除.md)理解。但保护 API 对象免遭并发覆盖，不会自动使模型切换、数据库迁移和外部业务动作成为一个原子事务；也不能假定 Fleet Command 暴露相同字段。

### 3.4 重试必须覆盖执行与记账之间的崩溃

幂等表示同一操作重复执行不会额外改变结果，不是“请求里带了一个 ID”。假设动作 K 会迁移数据，系统还维护动作完成记录，崩溃点决定重试风险：

| 崩溃位置 | 恢复后的不确定性 | 协议需要保证什么 |
| --- | --- | --- |
| 副作用前 | 动作可能尚未执行，也可能仍有旧执行者在途 | 核对持久状态、执行所有权与前置条件，再决定重试 |
| 副作用已完成 完成记录未保存 | 查不到完成记录，但再做可能重复迁移 | 副作用与去重记录同事务，或从目标系统可靠识别 K 的结果 |
| 完成记录已持久化 响应丢失 | 调用者不知道完成，目标已知道 | 用同一 K 返回原结果，不把重试当成新动作 |
| 外部系统已成功 本地未记账 | 本地事务无法覆盖外部副作用 | 使用对方支持的幂等键或结果查询；否则保留未知并人工核对 |

这说明“超时就重试”和“永远不重试”都不完整：前者可能重复副作用，后者可能永久停在未完成状态。结果未知时应暂停有风险的扩大发布并查询；没有可靠去重或查询能力，就不能承诺恰好一次执行。去重记录若早于允许的重放窗口被删除，旧请求仍可能被误认成新动作。

安全性要求旧动作不覆盖新目标、未校验制品不激活；活性要求依赖恢复后任务还能推进。只有安全没有恢复路径会一直停住，只有重试没有安全条件会错误推进。持续断网、容量不足或迁移不兼容时，不存在无条件的最终收敛保证。

## 4. 发布进度需要完整分母

教学例子：100 个目标站点中，90 个报告 C 且业务通过，5 个报告 B，5 个失联。只能说已确认完成 90%，不能把失联项去掉后写成全部成功。

继续区分制品就绪、激活完成、业务通过和观测过期。一个站点曾报告成功，随后失联 3 天，不应被误写成“当前持续健康”；也不必自动当作当前业务停止。控制状态和业务状态要分别保存。

对代表性 Canary，应覆盖弱网络、低存储、高负载以及不同硬件和输入源。只挑最快站点会低估发布时长和资源问题。

## 5. 带宽与磁盘决定能否安全灰度

教学条件：某站点需下载 12 GiB 新制品，有效带宽 8 MiB/s，不考虑重试，则传输下界为 `12×1024/8=1536` 秒，即 25.6 分钟。此时把两分钟未完成视为应用启动失败，超时策略就与物理条件不匹配。

本地存储还要容纳当前版本、候选版本、回退版本与缓存。若三份各 12 GiB，再需 4 GiB 临时空间和 20% 空闲比例，则预算为 `(3×12+4)/0.8=50 GiB`。这是未考虑层共享的保守教学模型，不是某产品固定要求。

不能为下载新版本先删除唯一可运行的旧版本。容量不足应停止发布并报告，而不是让系统在断连与断电后没有可恢复版本。

## 6. 业务门禁不能只看 HTTP 存活

AI 应用的门禁至少包括输入能否获取、模型与预处理匹配、代表性结果正确、延迟与错误率满足要求，以及现场输出副作用正确。模型可以成功装载但标签字典错位，健康接口仍返回成功。

失败后也不应无限重启。若错误源是同一错误制品或配置，重启会重复读取它，增加磁盘、网络和现场影响。应限制尝试次数、扩大发布速率和同一故障域影响，保存原始失败材料。

## 7. 数据格式回退与制品回退不同

假设 B 将本地状态格式从 v1 迁移为 v2，A 只能读取 v1。将应用镜像切回 A 并不恢复数据。迁移应选择兼容读写、可逆转换、独立备份恢复或明确不可回退边界之一。

离线期间产生的业务数据还要定义上传语义。至少一次传输可能重复，接收端需要事件身份与幂等处理；仅依赖本地递增序号在设备重装后可能冲突。删除缓存前应确认已确认的持久副本，而不是只看网络发送完成。

例如重装前后都产生事件 42，仅用站点名和序号会把两件事误当成一件。可把受控的设备实例身份与序号绑定，接收端在同一事务中提交业务结果和去重记录；实例标识也须可靠保存或重新签发，不能在每次重试时重新生成。这样的业务协议是应用责任，远程管理链路恢复不会自动提供它。

## 8. 掌握检查

**离线应用仍运行，能否证明断电重启也可用？** 不能，启动所需制品与身份可能不同。

**站点从 A 到 C 能否跳过 B？** 先看兼容及迁移依赖，不能从版本顺序直接回答。

**回退容器是否足以恢复状态？** 对存在格式迁移或外部副作用的应用不够。

**从 C 回退到 B 为什么仍需新修订？** 要允许新的回退意图，同时拒绝先前未完成的 B 任务；制品内容身份与控制意图身份解决不同问题。

**带操作 ID 能否保证不重复迁移？** 不能。必须解释执行副作用、保存去重结果和返回响应之间的崩溃窗口如何处理。

**修订号能否让离线站点获知云端刚发生的撤回？** 不能。排序已知意图与获知新意图是两件事，在线授权或租约也需要明确失效边界。
