# 服务注册、订阅、健康检查、客户端缓存与负载均衡

```text
provider ready → register instance → maintain heartbeat/connection
→ Nacos updates service view → push/notify subscribers
→ consumer local cache → filter healthy/enabled → load balance → RPC
```

## 临时与持久实例

临时实例存活与客户端心跳/连接相关，超时后被摘除；持久实例由服务端主动检查并保留注册语义。具体协议随 3.x 版本变化，按 SDK/Server 兼容矩阵验证。

## 优雅上下线

启动：依赖/缓存初始化 → readiness → 注册可用。下线：标记不接新流量/注销 → 等待推送和连接排空 → 终止。直接 Kill 会在健康超时窗口内继续被调用。

## 订阅和缓存

客户端先取全量再接收变更，并保存本地缓存。Nacos 不可用时可继续用旧端点，提高可用却可能访问已失效实例。监控 server view、client cache version 和实际 RPC destination。

## 负载均衡

权重、Cluster/zone、metadata 和健康只提供候选信息，最终算法在 SDK/框架/网关。验证是否支持权重、同区优先、慢启动和异常摘除。

## 验收题

- Nacos 故障为何已有 RPC 可能继续？
- 强制终止与优雅下线差在哪？
- 控制台实例正常为何客户端仍调用旧 IP？
- Weight 由谁真正执行？
