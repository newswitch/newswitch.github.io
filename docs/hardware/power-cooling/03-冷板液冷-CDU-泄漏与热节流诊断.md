# 冷板液冷、CDU、二次环路、泄漏与热节流诊断

冷板液冷把主要热量直接带到液体，但服务器并不会因此“没有风扇”。DIMM、NIC、SSD、VRM 和主板仍可能依赖空气，液冷系统也增加了泵、阀、接头、水质和泄漏等新故障域。

## 1. 典型架构

```text
Facility Water（一次侧）
→ CDU Heat Exchanger
→ Pump / Filter / Expansion / Sensor（二次侧）
→ Rack Manifold
→ Quick Disconnect
→ Server Cold Plate
→ Return Manifold
→ CDU
```

CDU 通过换热器隔离设施水与 IT 二次冷却液，并控制温度、压力、流量和水质。

## 2. 冷板怎样带走热量

冷板与 CPU/GPU 通过 TIM 接触，内部微通道让冷却液吸收热量。简化热量关系：

```text
带走热功率 ≈ 质量流量 × 比热容 × 供回水温差
```

供回水温差升高可能表示负载增加，也可能是流量不足。必须同时看流量、温度和设备功率。

## 3. 流量与压差

- 泵提供压差；
- 冷板、软管、接头、过滤器和阀门形成阻力；
- 并联支路流量可能不均；
- 气泡、堵塞、折管或阀门未全开会降低流量；
- 泵冗余失效后剩余泵要满足最坏负载。

只看 CDU 总流量会漏掉单台服务器或单个冷板的局部堵塞。

## 4. 供水温度与露点

冷却液温度并非越低越好。如果任何表面温度低于空气露点，可能产生冷凝。设计需要：

- 监测机房温度和相对湿度；
- 计算并保留露点裕量；
- 控制 CDU 供水温度；
- 避免冷管路暴露或做好保温；
- 处理传感器异常和控制失效。

Warm-water Cooling 常用较高供水温度减少冷凝和制冷能耗，但需匹配芯片与设施能力。

## 5. 水质与材料兼容

长期可靠性取决于：

- 冷却液配方、pH、电导率；
- 腐蚀抑制和生物控制；
- 铜、铝、镍、密封件等材料兼容；
- 颗粒、过滤器和微通道堵塞；
- 维护补液是否使用相同规范。

不同厂商冷却液不能凭颜色或名称随意混合。

## 6. 泄漏检测与联动

检测方式可包括 Leak Rope、Drip Tray、压力下降、流量异常和接头传感器。告警后的动作需要预先定义：

```text
轻微告警 → 定位支路、隔离阀、迁移任务
确认泄漏 → 关闭支路/服务器、断电边界、收集液体
修复后 → 压力测试、排气、流量与绝缘检查、受控上电
```

不能让不可靠的单传感器直接无条件切断整个集群，也不能只告警不设计隔离阀和任务迁移。

## 7. 液冷服务器仍需风冷

冷板通常覆盖 CPU/GPU，但以下部件仍发热：

- DIMM；
- NIC/DPU 与光模块；
- NVMe SSD；
- VRM、Retimer、PCIe Switch；
- PSU 和 BMC。

减少风扇转速前必须验证所有非冷板部件的最坏稳态温度。

## 8. 热节流证据链

```text
业务吞吐下降
→ CPU/GPU 实际频率与 Throttle Reason
→ 芯片/内存/VRM 温度
→ 单机流量、供回水温差和压差
→ CDU 泵、过滤器、阀门和总环路
→ 同机柜/同支路节点对比
```

若同一支路多个节点同时变慢，优先看 Manifold/CDU；只有单 GPU 异常，更像冷板接触、支路流量或芯片本身问题。

## 9. 运维与变更

- 接入前冲洗、排气并检查颗粒；
- Quick Disconnect 操作遵循厂商步骤；
- 记录支路、阀门、服务器和冷板资产映射；
- 固件或控制参数变更后做泵故障和稳态验证；
- 定期采样冷却液并更换过滤器；
- 维护前迁移任务，确认断电和压力释放边界；
- 泄漏演练要覆盖 IT、设施和安全团队。

## 10. 练习与答案

**问题：某台液冷服务器供回水温差突然增大，能否直接判断负载升高？**

答案：不能。热功率、质量流量和温差共同决定；流量下降也会使温差增大，应同时看设备功率、流量和压差。

**问题：CPU/GPU 已液冷，是否可以拆掉机箱风扇？**

答案：通常不可以。DIMM、NIC、SSD、VRM、PSU 等仍需要风冷，且风扇也维持机箱内部温度和传感器工作范围。
