# 风冷、后门换热、冷板液冷与浸没式液冷

冷却的目标不是“让机房更冷”，而是把芯片产生的热量稳定地送到室外，并让结温、功耗和可靠性保持在设计范围内。随着单机和单柜功率增加，冷却方式从空气逐步延伸到后门换热、冷板和浸没式液冷。

## 1. 完整热路径

```text
晶体管结温
→ Die / TIM / Heat Spreader
→ Heat Sink 或 Cold Plate
→ 空气或冷却液
→ 机柜/行级换热
→ 机房水系统/制冷系统
→ 室外散热
```

任何一段热阻、流量或换热能力不足，都会提高芯片温度。

## 2. 风冷

### 2.1 结构

```text
冷通道空气
→ 服务器前部
→ 风扇墙
→ Heat Sink / DIMM / GPU / NIC
→ 服务器后部热风
→ 热通道
→ CRAC/CRAH
```

### 2.2 优点

- 技术成熟、维护熟悉；
- 与传统服务器兼容；
- 无服务器内部液路；
- 对中低功率密度经济。

### 2.3 限制

- 高功率芯片需要更大 Heat Sink 和风量；
- 风扇功耗、噪声和风阻上升；
- 高密度机柜需要大量空气和制冷能力；
- Cable、DIMM 和加速卡会造成局部热点。

## 3. Rear-door Heat Exchanger

后门换热器安装在机柜排风侧，用水盘管吸收热风中的热量：

```text
服务器热风
→ Rear-door Coil
→ 空气降温后回到机房
→ 热量进入 Facility Water
```

它可以降低机房显热负担，但服务器内部仍靠风冷。需关注：

- 后门压降对服务器风扇的影响；
- 水温、流量和凝露；
- 门体重量、铰链和软管；
- 漏水检测和维护空间；
- 主动式还是被动式风扇设计。

## 4. 单相冷板液冷

冷却液经过 CPU/GPU 上方冷板，吸热后温度上升但保持液态：

```text
Facility Water
↔ CDU Heat Exchanger
↔ Secondary Loop
↔ Rack Manifold
↔ Hose / Quick Disconnect
↔ Cold Plate
```

优点：

- 直接带走高热流密度部件热量；
- 降低服务器风量需求；
- 可支持更高机柜功率密度；
- 温水冷却可能提高设施效率。

限制：

- 仍需风冷 DIMM、NIC、VRM、SSD 等部件；
- 需要泵、CDU、Manifold 和水质维护；
- 接头、软管和材料兼容是新故障域。

## 5. 两相冷板

两相冷板利用流体在冷板内沸腾/相变吸热，再在系统中冷凝。潜在优势是较高换热能力，但设计需要控制：

- 工作流体压力和饱和温度；
- 流动不稳定和干涸风险；
- 冷凝器和泵/压缩系统；
- 密封、材料兼容和维护；
- 环境与流体法规。

不能把单相 CDU 参数直接套到两相系统。

## 6. 单相浸没式液冷

服务器组件浸入绝缘液体中，流体保持液态并循环到换热器：

```text
IT Component
→ Dielectric Liquid
→ Tank Circulation
→ Heat Exchanger
→ Facility Water
```

优势是消除大部分风扇、覆盖更多板级部件，并支持较高密度。主要挑战：

- 服务器和材料必须适配液体；
- 光模块、硬盘、线缆和标签兼容；
- 维护时的沥液、清洁和人员操作；
- 液体寿命、过滤、消防和泄漏管理；
- 原厂保修和更换流程。

## 7. 两相浸没式液冷

设备浸入低沸点绝缘液体，芯片热量使液体汽化，蒸汽在冷凝器上恢复为液体：

```text
芯片热量
→ 液体沸腾
→ 蒸汽上升
→ 冷凝器
→ 液体回流
```

它可利用相变高效带走热量，但槽体密封、流体损失、材料兼容、冷凝器和环境影响要求更高。

## 8. Direct Expansion 与制冷剂路径

某些方案让制冷剂直接在靠近 IT 设备处蒸发/冷凝。与水基二次环路相比，它把制冷循环更靠近设备，需要专业评估：

- 压力和制冷剂安全；
- 泄漏检测；
- Compressor/Condenser 故障域；
- 环境法规；
- 维护技能与备件。

## 9. CDU 的边界

CDU（Coolant Distribution Unit）通常承担：

- 一次侧与二次侧换热隔离；
- 泵和流量控制；
- 供回液温度与压力控制；
- 过滤、补液和水质监控；
- Leak/Alarm 与 BMS/BMC 集成。

CDU 可以是 Row-level、Rack-level 或其他形态。N+1 泵不代表 Manifold、控制器和电源都已冗余。

## 10. 一次侧与二次侧

- FWS/一次侧：Facility Water System；
- TCS/二次侧：Technology Cooling System，靠近 IT 冷板；
- Heat Exchanger：在两侧之间传热但隔离水质和压力。

一次侧供水正常，不表示二次侧每台服务器流量正常。局部气堵、阀门、Quick Disconnect 或冷板堵塞都可能制造热点。

## 11. 露点与凝露

当表面温度低于空气露点，水汽可能凝结。液冷系统并非越冷越好：

```text
供液温度
> 当前环境露点 + 安全裕量
```

应监测进风温湿度、供液温度，并设计联锁。高温水冷却还能减少机械制冷，但必须满足芯片结温和流量要求。

## 12. 水质和材料兼容

关注：

- 铜、铝、不锈钢和焊料的电化学腐蚀；
- pH、电导率和颗粒；
- 微生物与添加剂；
- 软管、密封圈和塑料老化；
- 浸没液体对标签、Cable、TIM 和光学器件的影响。

不能只根据“液体不导电”判断长期兼容。

## 13. 可观测性

至少采集：

```text
芯片 Junction/Edge 温度
进风与出风温度
供液与回液温度
流量、压差和泵速
CDU/Manifold Valve 状态
Leak Sensor
风扇转速
CPU/GPU Power 与 Throttling Reason
```

热量估算：

```text
Q ≈ mass_flow × specific_heat × ΔT
```

同样的供回液温差，流量不同代表的带走热量不同。

## 14. 选型对照

| 条件 | 常见方向 |
| --- | --- |
| 中低机柜功率、传统机房 | 风冷 |
| 希望降低机房热负担但保留风冷服务器 | Rear-door |
| CPU/GPU 热流密度高 | Cold Plate |
| 极高密度、可接受专用维护流程 | Immersion |
| 改造存量机房 | 先评估供水、承重、空间和风险 |

最终选择要比较 IT 功率密度、设施改造、可维护性、材料兼容、冗余、保修和全生命周期成本。

## 15. 故障矩阵

| 现象 | 优先检查 |
| --- | --- |
| 单个 GPU 热 | 冷板接触、局部流量、TIM、功耗 |
| 一组节点同时热 | Manifold、阀门、CDU 分支 |
| 所有节点温升 | 一次侧供水、CDU、泵、设施负载 |
| 风扇全速但芯片仍热 | 风阻、热回流、Heat Sink 接触 |
| 压差升高、流量下降 | 过滤器、堵塞、阀门、液体黏度 |
| 漏液告警 | 先执行联锁和隔离，不要只清告警 |

## 16. 练习与答案

**问题：CPU/GPU 已采用冷板，服务器风扇能否全部取消？**

答案：通常不能。DIMM、VRM、NIC、NVMe、Retimer 和主板器件仍可能依赖气流，除非整机按全液冷或浸没式方案专门设计。

**问题：液冷供液温度越低是否性能越好？**

答案：不一定。低于露点可能凝露，过低水温增加制冷能耗；只要结温和功耗不受限，应在安全、能效和可靠性之间选择合适温度。
