# 从机房供电、PDU、PSU 到 VRM 的电力路径与功率预算

服务器铭牌、BMC 功耗和芯片 TDP 分别描述不同边界。可靠的功率预算必须沿完整路径计算，并考虑冗余故障、瞬态和环境降额。

## 1. 电力路径

```text
Utility / Generator
→ UPS
→ 配电柜 / Busway
→ Rack PDU A/B
→ PSU A/B
→ 12V/48V 主电源平面
→ VRM / Point-of-Load
→ CPU、GPU、DIMM、NIC、SSD、Fan
```

A/B 路供电只有在上游真正独立时才构成故障隔离。两个 PDU 插头接到同一上游回路，不是完整双路。

## 2. 功率、电流与能量

直流近似：

```text
P = U × I
```

交流还涉及功率因数：

```text
有功功率 ≈ 电压 × 电流 × 功率因数
```

kW 是瞬时功率，kWh 是一段时间消耗的能量。机柜容量关注功率和电流，计费常关注能量。

## 3. PSU 标称与效率

PSU 将 AC 转换为 DC，会产生损耗：

```text
效率 = DC 输出功率 / AC 输入功率
```

若服务器内部需要 2000 W，PSU 效率为 94%，上游输入会高于 2000 W。效率随负载和输入电压变化，标称峰值效率不能代替实际曲线。

## 4. 冗余模式

| 模式 | 含义 | 风险 |
| --- | --- | --- |
| N | 所有 PSU 都用于满足当前负载 | 任一失效可能掉电 |
| N+1 | 多一个 PSU，可承受一个失效 | 剩余 PSU 需满足降额后负载 |
| 2N | 两套完整独立容量 | 成本高，上游也需独立 |

负载分担不等于冗余。故障时剩余 PSU 可能瞬间过载，必须验证 Failover 和 Power Capping 行为。

## 5. 功率预算步骤

1. 收集 CPU/GPU、DIMM、NIC、SSD、风扇和主板最大允许功耗；
2. 加入 PSU 效率、风扇随温度增长和瞬态余量；
3. 计算正常和失去一路电源后的负载；
4. 应用输入电压、温度和海拔 Derating；
5. 检查 PDU 插座、支路、相位和整柜限制；
6. 设置平台功率上限和容量告警；
7. 使用真实峰值工作负载验收。

不要简单相加 TDP 后认为等于整机最大 AC 功耗，也不要用日常平均功耗代替故障场景。

## 6. 瞬态与浪涌

GPU/CPU 负载可在很短时间内变化，启动时风扇、磁盘和电容也会产生浪涌。瞬态可能导致：

- PSU 保护触发；
- 电压跌落和设备 Reset；
- BMC 记录 Power Fault；
- 平台主动限制 GPU/CPU；
- 多台服务器同步启动冲击机柜电源。

错峰上电、功率封顶和合理余量都是系统设计的一部分。

## 7. VRM 与 Rail

VRM 将主电源转换为芯片需要的低电压大电流，并随负载快速调节。关注：

- 电流与温度限制；
- 多相供电和负载均衡；
- Voltage Droop 与瞬态响应；
- Power Good、过流/过压/欠压保护；
- VRM 散热和 BMC Sensor。

芯片温度正常但 VRM 过热，仍可能限频或关机。

## 8. PDU 与机柜

- 单相 PDU 关注支路电流和插座额定；
- 三相 PDU 需要保持相位平衡；
- A/B 路容量应分别计算失效接管；
- C13/C19 等连接器有各自额定边界；
- 高温、线缆束和接触电阻会增加风险；
- 监控应覆盖单插座、支路、相位和总进线。

持续负载可用比例应遵循当地电气规范和设施设计，不应照搬一个固定百分比。

## 9. 证据与排障

```text
BMC Power Sensor / PSU Status
→ SEL 的 AC Lost、Power Fault、VRM 事件
→ PDU 插座/支路/相位数据
→ GPU/CPU Power Limit 与 Throttle Reason
→ 故障时间的业务负载和环境温度
```

若满载才重启，应比较功率、温度和 PSU/PDU 事件，并做受控的 CPU-only、GPU-only、combined load 隔离。不要在冗余不足时直接施加满载。

## 10. 练习与答案

**问题：服务器平均功耗 1800 W，配置 2000 W PSU 是否足够？**

答案：不能据此判断。还需峰值、瞬态、风扇、输入条件、PSU 效率/降额和冗余失效后的单 PSU 能力。

**问题：为什么 PSU A/B 都是 Online，仍可能没有真正的双路冗余？**

答案：两者可能接到同一 PDU、同一支路、同一 UPS 或共享上游故障点。冗余要沿完整电力链验证。
