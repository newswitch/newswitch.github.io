# 从应用到硬件的完整调用链学习路线

硬件不会直接理解 `read()`、`send()` 或 PyTorch 算子。上层调用会逐层转化为系统调用、内核对象、驱动队列、MMIO、Descriptor、DMA Transaction 和设备命令，完成后再通过 Completion、中断或轮询向上返回。

1. [一次 CPU 指令从程序、虚拟地址到内存完成读取](./01-CPU指令从程序虚拟地址到内存读取.md)
2. [一次文件读取从 read、VFS、Page Cache 到 NVMe](./02-文件读取从read-VFS-Page-Cache到NVMe.md)
3. [一次网络发送从 send、TCP/IP、驱动到 NIC 和物理链路](./03-网络发送从send-TCPIP-驱动到NIC物理链路.md)

5. [一次模型加载从文件系统、主机内存到 GPU HBM](./05-模型加载从文件系统主机内存到GPU-HBM.md)

## 2. 通用调用模板

```text
上层语义
→ Runtime / Library
→ System Call 或 Driver API
→ Kernel Subsystem
→ Device Driver
→ Queue / Descriptor / Command Buffer
→ MMIO Doorbell
→ Device DMA / Bus Transaction
→ Controller / Firmware
→ Physical Execution
→ Completion Queue / Status
→ Interrupt、Polling 或 Event
→ 唤醒线程 / 上层继续执行
```

不是所有路径都经过系统调用。CPU 普通访存由指令直接触发；GPU Kernel Launch 经过用户态 Runtime 和内核驱动；已经建立的 RDMA 数据传输可以主要由 NIC 执行。

## 3. 四个必须分开的概念

### 3.1 控制与数据

CPU 可以写 Doorbell 告诉设备“有新任务”，实际数据再由设备 DMA。此时 CPU 参与控制，但不逐字节搬运数据。

### 3.2 提交与完成

API 返回可能只代表请求已经进入 Queue，不代表设备完成，更不代表远端应用已经收到。必须确认同步语义。

### 3.3 逻辑与物理地址

进程虚拟地址、Kernel Virtual Address、CPU Physical Address、IOMMU IOVA、PCIe BAR 和设备内部地址属于不同地址空间。

### 3.4 同步与异步

异步路径把等待隐藏到后续 Event、Completion 或同步点。延迟没有消失，只是发生位置变化。

## 4. 阅读每条路径的六个问题

1. 请求最初由哪条指令或 API 产生？
2. 每一层把上层对象转换成了什么对象？
3. CPU 在什么时候写控制信息，什么时候真正复制数据？
4. DMA 使用的地址由谁映射，权限由谁限制？
5. 硬件怎样报告完成或错误？
6. 上层 API 返回时，究竟保证到了哪一步？

## 5. 观测方法

| 层次 | 常用证据 |
| --- | --- |
| 应用/Runtime | Trace、Profile、API 延迟 |
| 系统调用 | `strace`、eBPF Tracepoint |
| Kernel Subsystem | `perf`、ftrace、Block/Network Tracepoint |
| Driver | Driver Log、Health Reporter、Queue Counter |
| Bus | PCIe Topology、AER、Link Speed/Width |
| Device | Queue、Firmware、Health、Telemetry |
| 物理层 | FEC、CRC、温度、功率、介质错误 |

一次性能分析不需要把所有工具都打开，应先画路径，再在相邻层之间寻找第一处分叉。

## 6. 学习验收

- 能区分 Function Call、System Call、MMIO 和 DMA；
- 能解释 Page Fault 和设备 I/O Completion 的返回路径；
- 能解释 `read()` 为什么既可能不访问硬盘，也可能等待 NVMe；
- 能解释 `send()` 返回为何不等于对端收到；
- 能解释收包为什么通常是 NIC DMA 而不是 CPU 从网卡复制；
- 能解释模型权重从文件到 HBM 的多级驻留；
- 能解释 GPU Kernel Launch 的异步语义和真实同步点。

## 7. 练习与答案

**问题：CPU 发起设备 I/O 后是否一直等待设备完成？**

答案：不一定。同步 API 可能让当前线程睡眠，CPU 转去运行其他任务；异步 API 则立即返回提交结果，随后通过 Completion/Event 获知完成。

**问题：DMA 是否表示 CPU 完全不参与？**

答案：不是。CPU/Driver 仍要分配和映射内存、填写 Descriptor、写 Doorbell、处理完成和错误；DMA 主要避免 CPU 逐字节搬运设备数据。
