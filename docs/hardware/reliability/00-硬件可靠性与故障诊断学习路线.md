# 硬件可靠性与故障诊断从零到精通学习路线

硬件诊断不是看到一个错误计数就换件，也不是重启后恢复就关闭问题。需要判断错误发生在哪一层、能否纠正、是否持续、故障跟随设备还是槽位，以及修复后是否经受相同压力。

## 1. 学习顺序

1. [RAS、MCE、EDAC、AER、SMART 与 SEL 证据链](./01-RAS-MCE-EDAC-AER-SMART与SEL证据链.md)
2. [硬件基线、Burn-in、压力测试与故障复现](./02-硬件基线-Burn-in-压力测试与故障复现.md)

## 2. RAS 的目标

- Reliability：一段时间内持续正确工作的概率；
- Availability：需要服务时可用的比例；
- Serviceability：发现、隔离、维修和恢复的难易程度。

ECC 提高可靠性，冗余提高可用性，FRU/遥测/热插拔提高可维护性，但任何单一能力都不能替代其他两项。

## 3. 错误生命周期

```text
物理异常
→ 硬件检测
→ 纠正/重试/隔离
→ 固件或驱动记录
→ OS/应用感知
→ 运维关联证据
→ 降级、迁移、维修
→ 修复后回归
```

错误若在硬件层被纠正，业务可能毫无感知；如果只看应用日志，就会错过失效前预警。

## 4. 诊断四问

1. **范围**：单设备、单槽位、单节点、同一批次还是整个故障域？
2. **趋势**：静态历史计数还是当前持续增长？
3. **相关**：是否与负载、温度、功耗、固件或变更同时发生？
4. **跟随性**：错误跟随部件、槽位、线缆、主板还是软件版本？

## 5. 学习验收

- 能区分 Corrected、Uncorrected、Recoverable 与 Fatal；
- 能关联 CPU MCA、EDAC、PCIe AER、NVMe/SMART 和 BMC SEL；
- 能建立部件、BDF、NUMA、槽位和序列号映射；
- 能设计安全且有停止条件的 Burn-in；
- 能用交换部件避免 No Fault Found；
- 能定义隔离、RMA、重新准入和故障复盘标准。

## 6. 练习与答案

**问题：一次 Corrected Error 是否必须立刻更换部件？**

答案：不一定。需要结合错误类型、位置、厂商阈值、增长率、同批次基线和业务关键性。持续增长或固定位置重复通常比单次瞬态更值得隔离。

**问题：重启后错误不再出现，是否说明问题修复？**

答案：不能。重启可能清空计数、重新训练链路或暂时改变温度。必须复现原负载并观察错误计数、性能和稳定窗口。
