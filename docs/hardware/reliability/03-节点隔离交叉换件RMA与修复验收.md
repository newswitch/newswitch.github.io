# 节点隔离、交叉换件、RMA 与修复验收

换件不是诊断的起点，而是验证假设的一种手段。无计划地交换多个部件会破坏现场、引入新接触问题，并最终得到“换了就好了”却无法确认根因的结论。

## 1. 先保护业务和现场

```text
发现异常
→ 停止向节点分配新任务
→ 迁移/排空可恢复工作负载
→ 保留电源和现场（若安全允许）
→ 采集易失证据
→ 决定软恢复、重启或断电
```

如果存在冒烟、漏液、过热、短路等安全风险，应优先按安全流程断电隔离，不能为了日志维持运行。

## 2. 易失证据优先级

重启前尽量保存：

- Kernel Ring Buffer、Driver Health、设备错误日志；
- 当前 PCIe 拓扑、Link、NUMA 和设备状态；
- Sensor、功率、温度、频率与错误 Counter；
- BMC SEL、系统事件和 Reset Reason；
- 业务错误时间、负载和最近变更；
- 物理槽位、序列号、线缆和端口照片/映射。

重启可能清除临时寄存器、重新训练链路并改变 BDF。

## 3. 判断故障范围

- 单部件：错误跟随序列号；
- 单槽位/链路：不同设备插入同槽都失败；
- 单板卡/Riser/背板：同组设备同时异常；
- 单 Socket：同 NUMA 的 DIMM/PCIe 设备异常；
- 单节点：电源、主板或环境；
- 同批次/Fleet：固件、物料或设计问题。

范围判断决定应该换盘、换 Riser、换主板还是暂停整批节点。

## 4. 交叉换件矩阵

以设备 A 和槽位 1 为例：

```text
设备 A + 槽位 1：失败
设备 A + 已知良好槽位 2：？
已知良好设备 B + 槽位 1：？
```

- 错误跟 A：支持设备本体；
- 错误跟槽位 1：支持槽位、Riser、主板或链路；
- 两边都异常：可能有多个问题或换件引入变量；
- 都正常：关注接触、温度、固件状态和复现条件。

每轮只更改一个变量，并标记所有部件。

## 5. FRU 与非 FRU

FRU 是现场可更换单元，例如 PSU、风扇、DIMM、SSD、NIC、Riser 或整块主板。芯片级故障通常通过更换其所在 FRU 处理。

更换前确认：

- 部件号和硬件 Revision；
- 固件和配置兼容；
- Hot-plug 能力与操作步骤；
- ESD、防误拔和扭矩要求；
- RAID/集群冗余和数据备份；
- 序列号、资产与保修变更。

## 6. RMA 证据包

高质量 RMA 应包含：

1. 机型、序列号、部件号、Revision；
2. BIOS/BMC/CPLD/设备固件和 Driver；
3. 物理槽位、拓扑、BDF 与 NUMA；
4. 原始错误日志和统一时间线；
5. 错误增长率、温度、功率和负载；
6. 最小复现步骤、频率与停止条件；
7. 交叉换件结果；
8. 已执行操作及其结果；
9. 数据清除与介质保留要求。

只写“服务器死机，请换主板”容易得到 No Fault Found。

## 7. No Fault Found 为什么发生

- 厂商未运行相同负载和持续时间；
- 故障依赖机箱、Riser、温度或固件组合；
- 重启/运输后接触暂时恢复；
- 日志没有统一时间和序列号；
- 错误实际跟槽位而不是部件；
- 厂商测试环境未达到边缘条件。

解决方法是提供可重复条件和交叉矩阵，而不是重复描述现象。

## 8. 数据安全与介质 RMA

磁盘、SSD、NVRAM 和某些加速器可能保留业务数据或密钥。送修前执行组织规定的：

- 加密密钥销毁；
- Secure Erase/Crypto Erase；
- 介质保留（不返盘）条款；
- 数据销毁证明；
- 资产和链路追踪。

损坏设备可能无法完成软件擦除，此时必须使用加密或物理销毁/保留流程，而不是假设数据不可读。

## 9. 修复后的重新准入

```text
确认部件与固件
→ 恢复 BIOS/BMC/设备配置
→ Inventory 与拓扑对比
→ 子系统测试
→ 原故障条件复现
→ 全机 Burn-in
→ 冷启动与错误差值检查
→ Canary 业务
→ 正式准入
```

验收标准必须比“能开机”严格，并覆盖原问题。更换主板后尤其要检查 TPM、Secure Boot、MAC、资产 ID、NUMA 和许可证绑定。

## 10. 复盘与 Fleet 行动

单机修好后继续判断：

- 是否属于某批次部件或固件；
- 其他节点是否有相同前兆；
- 是否需要增加遥测和预警；
- 备件库存和更换阈值是否合理；
- 机柜、供电、散热或操作流程是否共同影响；
- 是否需要厂商 Field Advisory 或全批升级。

## 11. 练习与答案

**问题：换新网卡后故障消失，是否足以认定旧网卡损坏？**

答案：证据仍不完整。拔插同时改变了接触、复位和固件状态；最好将旧卡放入已知良好槽位复现，并检查错误是否跟随序列号。

**问题：节点换件后为什么还要 Canary 业务？**

答案：合成压力不能覆盖所有真实协议、数据和调度行为。Canary 在受控影响范围内验证真实工作负载，是重新全量准入前的最后一层保护。
