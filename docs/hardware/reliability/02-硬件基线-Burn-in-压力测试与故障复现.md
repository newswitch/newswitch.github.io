# 硬件基线、Burn-in、压力测试与故障复现

Burn-in 不是把所有压力工具同时运行到机器宕机，而是在可控边界内覆盖不同数据路径，暴露早期失效、装配问题、热问题和边缘链路，并留下可比较的基线。

## 1. 先定义目标

- 新机验收：发现运输、装配和早期失效；
- 维修后验证：确认更换部件和受影响路径恢复；
- 固件升级回归：发现兼容、功耗和拓扑变化；
- 故障复现：验证触发条件和根因假设；
- 性能基线：建立同型号节点的合理分布。

不同目标需要不同负载和停止条件，不能复用一个“万能烤机脚本”。

## 2. 测试矩阵

| 子系统 | 单项测试目标 | 组合测试目标 |
| --- | --- | --- |
| CPU | Core、向量、频率、Cache | CPU + Memory 功耗与热 |
| Memory | 容量、带宽、地址/模式 | NUMA、满带宽、ECC 趋势 |
| PCIe | Link、AER、P2P、Reset | 多设备共享 Root/Switch |
| GPU/NPU | 计算、HBM、通信 | GPU + CPU + NIC/NVMe 功率 |
| NIC | PPS、带宽、FEC、Queue | 多端口、RDMA、交换机拥塞 |
| Storage | 读写、Queue、介质 | 多盘、背板、HBA、热 |
| Power/Thermal | PSU、VRM、Fan、Cooling | 全机瞬态和稳态上限 |

单项用于归因，组合用于验证真实上限。直接从全机满载开始，失败时很难定位。

## 3. 基线数据

测试前保存：

- 机型、主板 Revision、部件序列号；
- BIOS/BMC/CPLD/设备固件和配置；
- OS、Kernel、Driver、Runtime；
- CPU/NUMA/内存容量与频率；
- PCIe 拓扑与 Link 状态；
- Sensor、SEL、MCE/EDAC/AER、SMART/NVMe Health；
- 空闲温度、功率、风扇和频率。

没有测试前基线，就无法证明错误是新增还是历史遗留。

## 4. 阶段化执行

```text
Inventory / Idle Baseline
→ CPU
→ Memory
→ Storage
→ Network
→ Accelerator
→ Pairwise Combination
→ Full-System Steady State
→ Cool-down / Postcheck
```

每阶段都检查错误增量，失败立即停在最小可复现范围，避免后续负载覆盖现场。

## 5. 数据安全

- 存储写测试只能使用专用测试盘或明确可破坏区域；
- 网络测试避免打满生产链路和控制面；
- 内存/CPU 故障注入不得在业务节点执行；
- GPU/NPU 压测要确认功率、温度和驱动恢复边界；
- 风扇、PSU、泵等冗余实验遵循厂商安全规范；
- 节点先从集群排空并禁止重新调度。

## 6. 停止条件

示例：

- 新增 UCE、Fatal MCE/AER；
- 温度、功率、电流或流量超过平台限制；
- Link Down、设备消失、Controller Reset；
- 数据校验错误；
- PSU/Fan/Pump 冗余丢失；
- 性能偏离同型号基线且持续；
- BMC 或 OS 失去可观测性。

停止条件应自动化，但自动化还要避免因传感器读数异常误触发破坏性动作。

## 7. 复现变量控制

一次只改变一个变量：

- 设备 ↔ 槽位；
- 线缆/模块 ↔ 端口；
- 固件 A ↔ B；
- 冷启动 ↔ 热重启；
- 空闲温度 ↔ 热稳态；
- 单项负载 ↔ 组合负载；
- Local NUMA ↔ Remote NUMA。

记录随机种子、命令参数、持续时间、数据集和环境，保证下一次能真正重复。

## 8. 性能基线的统计方法

不要只保存一个平均值：

- 吞吐、平均、P95/P99/P999；
- 温度、功耗、频率随时间；
- 错误 Counter 增量；
- 同批节点中位数和分位数；
- Warm-up、Steady State、Cool-down 分段；
- 置信区间和重复次数。

一台节点比平均慢 5% 不一定故障，但持续偏离同硬件分布并伴随降频/AER 就值得隔离。

## 9. 测试后检查

```text
错误计数差值
→ 设备仍完整枚举
→ 性能与温度回到基线
→ 文件系统/数据校验
→ BMC SEL 与 Sensor
→ 冷启动一次
→ 观察稳定窗口
```

压力结束后正常不等于通过；某些错误只在日志中留下痕迹，某些链路会降速后继续工作。

## 10. 练习与答案

**问题：全机压力通过，为什么仍需要单项测试？**

答案：全机通过证明某个组合下稳定，但不能给出各子系统性能边界；全机失败时，单项测试也是定位和复现的基础。

**问题：维修后跑十分钟压力无报错，能否重新上线？**

答案：取决于原故障触发时间和负载。若原问题需要热稳态或长时间写入才出现，十分钟不足；验收应覆盖原触发条件并留稳定观察窗口。
