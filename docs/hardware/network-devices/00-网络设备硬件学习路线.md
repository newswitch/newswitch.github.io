# 网卡、PHY 与光互联硬件学习路线

网络协议栈解决报文语义，网络硬件负责在主机内存、PCIe、网卡队列和物理介质之间搬运比特。链路显示 `UP` 只说明部分训练完成，不证明 FEC、光功率、PCIe、DMA 和队列没有问题。

## 2. 完整主机链路

```text
Application
→ Socket / Kernel / Userspace Driver
→ TX/RX Queue 与 Descriptor
→ PCIe DMA
→ NIC ASIC
→ MAC
→ PCS / FEC
→ PMA / SerDes
→ Module / Cable / Fiber
→ Switch Port
```

任何一层都可能产生丢包和长尾。应用重传只是结果，不能直接定位故障层。

## 3. 三种平面

- 数据面：Descriptor、Packet Buffer、DMA、MAC Frame；
- 控制面：驱动配置 Queue、RSS、Offload、Flow Rule；
- 管理面：固件、温度、模块 EEPROM/DOM、健康报告。

网卡固件可正常回应管理命令，但数据面仍可能堵塞；端口 Link Up，也可能因 PCIe 降宽无法达到线速。

## 4. 常见性能约束

- PCIe 代际、宽度和 NUMA 归属；
- Queue 数、RSS Hash、IRQ/CPU 亲和性；
- Ring 深度和内存分配；
- Small Packet PPS 与大包带宽的差异；
- Checksum/TSO/GSO/GRO、RDMA 等 Offload；
- SerDes Lane、FEC、模块和光功率；
- Switch 端口 Buffer、拥塞和 Pause。

## 5. 学习验收

- 能画出收包和发包从 Host Memory 到线缆的路径；
- 能区分 Ethernet NIC、HCA、CNA、SmartNIC、DPU 与 IPU；
- 能解释 OCP NIC 是外形规范而不是网络协议；
- 能解释 Descriptor、Doorbell、DMA、MSI-X 和 RSS；
- 能区分 MAC、PCS、PMA、PHY 和 SerDes；
- 能解释 FEC 为什么降低误码影响却不能修复所有链路问题；
- 能根据距离、速率和端口选择铜缆、DAC、AOC 或光模块；
- 能把 CRC、FEC、光功率、PCIe AER 和驱动 Reset 放在同一时间线。

## 6. 练习与答案

**问题：端口已经 Link Up，为什么吞吐仍只有标称带宽的一半？**

答案：还需检查 PCIe 是否降速/降宽、流量是否单 Queue、CPU/NUMA、报文大小、FEC 错误、对端拥塞和上游共享。Link Up 不是性能验收。

**问题：换光模块后 CRC 不再增长，是否能证明旧模块本体损坏？**

答案：只能显著缩小范围。拔插动作也重新清洁和连接了端面，还可能改变线缆弯曲与接触；应结合光功率、模块告警、换端口和交叉替换确认。
