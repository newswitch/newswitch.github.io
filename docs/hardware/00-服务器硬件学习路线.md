# 服务器硬件从零到精通学习路线

服务器硬件不是一张配件清单。一次业务请求最终会变成 CPU 指令、内存访问、PCIe Transaction、DMA、网卡报文或存储 I/O；任何硬件层的带宽、延迟、拓扑和错误都会反映到操作系统与应用指标中。

本模块只讲通用服务器硬件本体和硬件边界。GPU/NPU、Linux 内核、网络协议和存储系统继续保留在各自目录，通过链接串联，不复制正文。

## 1. 整体知识地图

```text
机柜供电 / PDU / PSU
          ↓
主板：Socket、DIMM Slot、PCIe Slot、PCH、BMC、CPLD、VRM、Clock
          ├── CPU Core / Cache / IMC / PCIe Root Complex
          ├── DDR Channel → DIMM → Rank → Bank
          ├── PCIe → GPU / NIC / NVMe / HBA / DPU
          ├── PCH → SATA / USB / SPI / Super I/O
          └── BMC → Sensor / FRU / SEL / Power Control

机箱风道 / 风扇 / 散热器 / 冷板
          ↓
温度、功耗、频率、错误率和使用寿命
```

硬件学习要同时回答四类问题：

1. **结构**：组件在哪里，和谁相连；
2. **路径**：数据、控制、管理和电力分别怎么走；
3. **性能**：容量、带宽、延迟、并发和局部性由什么决定；
4. **可靠性**：错误怎样被检测、隔离、恢复并最终判定 RMA。

## 4. 四条硬件路径

### 4.1 数据路径 {/* #数据路径 */}

```text
NIC/NVMe/GPU
→ PCIe Transaction
→ Root Complex / IOMMU
→ DMA 到内存或 Peer Device
→ CPU/GPU 消费
```

### 4.2 控制路径 {/* #控制路径 */}

```text
进程系统调用
→ 内核驱动
→ MMIO / Doorbell / Queue Descriptor
→ 设备固件与控制器
```

### 4.3 管理路径 {/* #管理路径 */}

```text
运维终端
→ 管理网络
→ BMC
→ IPMI/Redfish、Sensor、FRU、SEL
→ 电源控制与硬件状态
```

### 4.4 电力与散热路径 {/* #电力与散热路径 */}

```text
机房供电 → PDU → PSU → 主板电源平面 → VRM → CPU/GPU/DIMM
芯片发热 → 封装/散热器/冷板 → 风或冷却液 → 机房散热系统
```

排障时必须先明确观察的是哪条路径。BMC 能 Ping 通不代表 CPU 数据路径正常；操作系统能读磁盘也不代表冗余 PSU 正常。

## 5. 学习方法

每个硬件主题按同一模板学习：

```text
物理组件
→ 电气/协议接口
→ 固件与控制器
→ Linux 驱动和设备对象
→ 应用可见指标
→ 性能瓶颈
→ 故障证据
→ 隔离、恢复与 RMA
```

不要只背规格。看到“PCIe 5.0 x16”“8 Channel DDR5”“双路 CPU”时，必须能将其转换为理论带宽、实际拓扑、NUMA 归属和故障影响范围。

## 6. 完成后的能力

- 能从主板 Block Diagram 读出 CPU、DIMM、GPU、NIC、NVMe 和 BMC 的连接；
- 能解释 IPC、频率、Cache Miss、内存带宽和 NUMA 的关系；
- 能判断 DIMM 插法为何影响 Channel 数量、频率和容量；
- 能区分 PCIe Link Width、Link Speed、Switch、Retimer 和 Root Complex；
- 能沿 DMA/IOMMU/PCIe 解释 NIC、NVMe 与 GPU 的数据搬运；
- 能把温度、功耗、错误计数和性能抖动放进同一证据链；
- 能区分软件配置、驱动/固件兼容、链路故障和物理部件损坏。

## 7. 练习与答案

**问题：服务器标称 PCIe 插槽是 x16，为什么设备只运行在 x8？**

答案：插槽机械长度不等于实际电气 Lane。还要检查 CPU SKU、主板布线、插槽共享、Riser、设备能力、Link Training 降级和 BIOS 配置。

**问题：为什么业务延迟问题也需要了解硬件？**

答案：CPU Cache Miss、远端 NUMA、内存纠错、PCIe 重传、SSD 垃圾回收、NIC/FEC 错误和温度降频都可能表现为应用长尾，而平均 CPU 利用率仍然正常。
