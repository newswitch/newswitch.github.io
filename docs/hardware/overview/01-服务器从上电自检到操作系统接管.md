# 服务器从上电、自检到操作系统接管

按下电源键并不是所有部件同时开始运行。服务器启动是一条受电源时序、固件、训练和设备枚举约束的状态机；卡在不同阶段，能获得的证据也不同。

## 1. 完整启动链

```text
机房供电 / PDU
→ PSU 获得 AC，输出待机电源
→ BMC、CPLD、部分管理逻辑启动
→ 接收开机命令，检查电源与温度条件
→ PSU 主电源 Rail 稳定，Power Good
→ CPLD/平台逻辑按顺序释放 Reset
→ CPU 从 Reset Vector 执行固件
→ UEFI SEC → PEI → DXE → BDS
→ CPU/内存训练、PCIe 枚举、设备 Option ROM
→ 选择启动项并加载 Bootloader
→ Bootloader 加载 Kernel、initramfs、参数
→ Kernel 初始化 CPU、内存、驱动和根文件系统
→ PID 1 / systemd 接管用户空间
```

不同 CPU 平台的固件阶段和命名可能不同，但“电力稳定 → Reset 释放 → 固件初始化 → 设备枚举 → 启动介质 → OS”这条主线一致。

## 2. 待机电源阶段

服务器关机但电源线接通时，BMC 往往已经运行。此时可以：

- 访问管理网口；
- 查看 FRU、Sensor 和 SEL；
- 更新部分固件；
- 远程开关机；
- 读取 PSU 和机箱状态。

如果 BMC 也完全不可达，优先检查 PDU、PSU 待机输出、管理网口、BMC 固件和主板待机电源，而不是操作系统。

## 3. 电源时序与 Reset

CPU、DIMM、PCH、PCIe Slot、GPU 和 NVMe 需要不同电压 Rail，并要求按规定顺序稳定。CPLD/电源控制器通常负责：

```text
Enable Rail
→ 等待 Power Good
→ 提供参考时钟
→ 解除 Reset
→ 检查设备 Presence/Fault
```

VRM 过流、PSU 不一致、Slot 短路或传感器越界可能使启动在 CPU 执行任何代码之前终止。此时串口和 OS 日志都不存在，只能依赖 BMC SEL、主板 LED 和电气测量。

## 4. CPU 与内存训练

固件需要发现 CPU 拓扑并训练内存控制器与 DIMM：

- 读取 SPD 中的类型、容量、时序和电压；
- 建立 Channel、DIMM、Rank 映射；
- 训练读写时序和信号；
- 选择共同可用频率；
- 启用 ECC、Memory Interleaving 和 RAS。

DIMM 插法错误、混用不兼容型号、接触不良或训练失败，可能表现为启动很慢、容量减少、频率下降或卡 POST。

## 5. UEFI 阶段

简化理解：

| 阶段 | 主要任务 |
| --- | --- |
| SEC | 建立最小可信执行环境、进入固件 |
| PEI | 初始化临时内存、主内存和早期平台 |
| DXE | 加载驱动、枚举设备、建立 Boot Services |
| BDS | 选择启动设备并启动 OS Loader |

厂商可能增加管理、RAS、安全启动和设备固件阶段。POST Code、串口和 BMC KVM 常用于定位固件卡点。

## 6. PCIe 枚举

固件为 Root Port、Bridge、Switch 和 Endpoint 分配 Bus Number、BAR 地址、中断和部分资源：

```text
Detect Presence
→ Link Training
→ 读取 Configuration Space
→ 枚举 Bridge 下级 Bus
→ 分配 MMIO/BAR Window
→ 加载 Option ROM 或设备固件
```

GPU 多、BAR 大或拓扑复杂时，需要 Above 4G Decoding、足够 MMIO Window 和正确 BIOS 配置。设备未出现在 `lspci`，问题往往早于驱动加载。

## 7. Secure Boot 与信任链

Secure Boot 验证下一阶段固件/Bootloader 的签名。结合 TPM Measured Boot，可以把启动组件的度量记录进 PCR：

```text
Platform Firmware
→ UEFI Driver/Option ROM
→ Bootloader
→ Kernel / initramfs
```

“签名验证”和“度量记录”不是同一件事。前者决定是否允许执行，后者为远程证明或审计提供证据。

## 8. Bootloader 与内核

Bootloader 读取启动项，加载 Kernel、initramfs 和命令行。内核随后：

1. 建立页表、内存管理和调度；
2. 发现 ACPI/Device Tree 描述；
3. 初始化 PCIe、块设备、网卡等驱动；
4. 使用 initramfs 找到真实根文件系统；
5. `switch_root` 后执行 PID 1。

能看到 GRUB 但找不到根文件系统，说明电源、CPU、内存和大部分固件已工作，排障应转向存储驱动、initramfs、UUID 和文件系统。

## 9. 分阶段证据

| 现象 | 所处阶段 | 证据 |
| --- | --- | --- |
| BMC 不可达、无 LED | 待机电源/BMC | PDU、PSU LED、管理交换机 |
| BMC 可达但无法上电 | 主电源/时序 | SEL、Sensor、CPLD Code |
| 风扇转但无画面 | CPU/内存/固件 | POST Code、串口、KVM |
| 部分 DIMM/GPU 缺失 | 训练/枚举 | BIOS Event、FRU、Slot 互换 |
| 找不到启动盘 | BDS/存储控制器 | UEFI Boot、HBA/NVMe 状态 |
| Kernel Panic | Kernel/initramfs | 串口、pstore、Crash 信息 |
| 进入 Emergency Mode | 根文件系统/systemd | Journal、Mount Unit、fsck |

## 10. 变更顺序

固件升级、DIMM 扩容、Riser/GPU 调整和 BIOS 参数修改都可能改变资源分配。安全步骤：

```text
记录现状与版本
→ 校验兼容矩阵和恢复方法
→ 单节点变更
→ 完整断电/冷启动（若要求）
→ 对比 CPU、DIMM、PCIe、NUMA、Firmware Inventory
→ Burn-in 与业务验收
→ 再扩大范围
```

不要同时升级 BIOS、BMC、CPLD 和所有设备固件后再排查，变量过多会失去归因。

## 11. 练习与答案

**问题：设备在 BMC Inventory 中可见，但 `lspci` 不可见，说明什么？**

答案：BMC 可能通过 FRU/Presence Bus 知道卡存在，但主 CPU 的 PCIe Link Training 或枚举失败。应检查 Slot 电源、Reset、参考时钟、Riser、Retimer、BIOS 资源和 Link 状态。
