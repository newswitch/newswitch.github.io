# 服务器整体架构导读

一台服务器同时存在计算、数据、控制、管理、电力和散热系统。仅从操作系统的设备列表看不到全部关系；理解服务器需要结合主板 Block Diagram、PCIe Topology、NUMA、BMC Sensor 和实际布线。

## 1. 典型双路服务器

```text
                         ┌──────────── 管理网络 ────────────┐
                         │                                  │
                    ┌────▼────┐                             │
                    │   BMC   │── Sensor / FRU / SEL / Power│
                    └────┬────┘                             │
                         │ eSPI / I2C / SMBus / GPIO         │
┌────────────────────────┴───────────────────────────────────┴────┐
│                             主板                                │
│                                                                 │
│ DIMM ─ IMC ─ CPU Socket 0 ═══ UPI/xGMI ═══ CPU Socket 1 ─ IMC ─ DIMM
│              │ Core/Cache                   Core/Cache │         │
│              │ PCIe Root                    PCIe Root  │         │
│              ├── GPU / NIC / NVMe           ├── GPU / NIC / NVMe│
│              └── PCIe Switch/Retimer         └── HBA / DPU       │
│                                                                 │
│                         PCH                                     │
│                   SATA / USB / SPI / Super I/O                  │
└─────────────────────────────────────────────────────────────────┘

AC/PDU → 双 PSU → 12V/48V 电源平面 → VRM → CPU/GPU/DIMM
风扇/散热器/冷板 → 带走 CPU、GPU、DIMM、NIC、SSD、VRM 热量
```

具体平台可能没有独立 PCH，也可能使用 PCIe/CXL Switch、NVSwitch、OCP NIC、E1.S/E3.S NVMe 背板或 GPU Baseboard。图表示逻辑职责，不代表所有主板的物理走线。

## 2. CPU 不只是计算核心

现代服务器 CPU 通常集成：

- Core、SMT Thread 与各级 Cache；
- Integrated Memory Controller（IMC）；
- PCIe/CXL Root Complex；
- Socket 间一致性互联；
- 中断控制、性能监控和安全单元。

因此 DIMM 和 PCIe 设备都有 CPU/Socket 归属。某个进程运行在哪个 Core，会影响它访问哪组内存、网卡、GPU 和 NVMe 的成本。

## 3. DIMM 为什么分布在 CPU 两侧

DIMM 插槽连接到对应 CPU 的 Memory Channel。双路服务器不是“一池无差别内存”：

```text
CPU0 Core → CPU0 Local DIMM：本地访问
CPU0 Core → CPU1 DIMM：通过 Socket Interconnect 的远端访问
```

远端访问仍由 CPU 的 Load/Store 单元发起，不是“CPU 搬运每个字节”，但请求和数据需要经过 Socket 间互联，延迟更高并占用互联带宽。

## 4. PCIe 设备的归属

GPU、NIC、NVMe、HBA 和 DPU 通常连接到某个 CPU Root Complex：

```text
CPU0 Root Port → PCIe Switch → GPU0、GPU1
CPU1 Root Port → NIC1
CPU1 Root Port → NVMe Backplane
```

跨 Socket 访问设备的常见路径：

```text
CPU0 Thread
→ CPU0 Socket Interconnect Controller
→ UPI/xGMI
→ CPU1 Root Complex
→ PCIe Device
```

这就是 GPU、NIC、NVMe 亲和性和 NUMA 绑定的重要性。

## 5. PCH 的职责

Platform Controller Hub 常承载相对低速或平台级 I/O，例如 SATA、USB、SPI、部分网口和 Super I/O。高性能 GPU/NIC/NVMe 通常直接连接 CPU PCIe Root，而不是绕 PCH。

PCH 到 CPU 的上行链路有带宽上限。多个 PCH 设备同时工作时可能共享上行，因此不能只看每个接口的标称速度。

## 6. BMC 是独立管理计算机

BMC 有独立处理器、内存、固件和管理网口，可在主 CPU 未启动时工作。它通过 I2C/SMBus、PMBus、GPIO、eSPI 等接口读取传感器和控制电源。

```text
带内管理：OS → 驱动/工具 → 硬件
带外管理：运维端 → BMC → 传感器/电源/固件
```

BMC 能看到温度、风扇、PSU 和 SEL，但不一定理解应用、Linux Queue 或 GPU Kernel。两套证据必须关联。

## 7. CPLD、Super I/O 与时钟

- CPLD：上电时序、Reset、Mux、板级状态机和 GPIO Glue Logic；
- Super I/O：串口、低速 GPIO、硬件监控等传统接口；
- Clock Generator/Buffer：为 CPU、PCIe、设备提供参考时钟；
- VRM Controller：按芯片请求调节电压和电流。

这些部件通常不出现在 `lspci`，但故障可造成设备不枚举、随机复位或无法上电。

## 8. 四种拓扑不要混淆

| 拓扑 | 回答的问题 | 常用证据 |
| --- | --- | --- |
| 物理拓扑 | 卡插在哪个 Slot/Riser/背板 | 机型手册、标签、FRU |
| PCIe 拓扑 | 经过哪个 Root/Switch/Bridge | `lspci -tv`、拓扑图 |
| NUMA 拓扑 | 设备和内存属于哪个 Socket | `lscpu`、`numactl -H`、sysfs |
| 管理拓扑 | BMC、传感器、PSU 怎样连接 | BMC Web、Redfish、SEL |

同一个“Slot 3 GPU”必须能在四种拓扑中对应到同一设备，才能可靠换件。

## 9. 性能规格的共同表达

硬件指标可归纳为：

- 容量：Core 数、内存容量、SSD 容量；
- 带宽：GB/s、GT/s、Gb/s；
- 延迟：ns、µs、ms；
- 并发：Queue、Outstanding Request、Memory Bank；
- 局部性：Cache、NUMA、PCIe Root、Rail；
- 可靠性：ECC、CRC、Retry、Spare、Redundancy。

峰值带宽不能代表持续业务性能。协议开销、访问模式、并发、热限制和错误重试都会降低有效吞吐。

## 10. 阅读厂商 Block Diagram

按以下顺序读：

1. 找 CPU Socket 和 Socket Interconnect；
2. 找每个 CPU 的 Memory Channel 与 DIMM Slot；
3. 找 PCIe Root Port、Switch、Retimer 和 Slot；
4. 标记 GPU、NIC、NVMe、HBA 的归属；
5. 找 PCH 及共享上行；
6. 找 BMC、CPLD、管理 NIC 和 Sensor Bus；
7. 对照实际 `lspci -tv`、NUMA 和 FRU。

不要把图上的连线直接当作物理铜线数量；厂商图可能省略 Retimer、Mux 或共享关系。

## 11. 练习与答案

**问题：两块 NIC 型号相同，为什么一块访问 GPU 更快？**

答案：它们可能属于不同 CPU Root Complex。与 GPU 同 Root/同 NUMA 的 NIC 路径更短；跨 Socket 流量需要经过 UPI/xGMI，受额外延迟和共享带宽影响。

**问题：BMC 显示所有部件健康，是否能证明服务器没有硬件问题？**

答案：不能。BMC 主要观察板级传感器和事件，PCIe 重传、CPU Cache 错误、SSD 尾延迟等问题还需 OS、驱动和设备日志。
