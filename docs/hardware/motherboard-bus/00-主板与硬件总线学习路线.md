# 主板与硬件总线从零到精通学习路线

服务器主板不是把部件焊在一起的“底板”，而是同时承载数据、控制、管理、时钟、复位与供电关系的系统。操作系统只能看到成功完成上电和枚举的设备；当设备完全消失时，往往需要回到主板、固件和链路层寻找证据。

## 2. 主板上的五类链路

| 链路 | 典型协议或器件 | 主要作用 |
| --- | --- | --- |
| 高速数据链路 | PCIe、CXL、Socket Interconnect | 传输业务数据、内存事务和设备请求 |
| 低速管理链路 | I2C、SMBus、PMBus、eSPI、GPIO | 传感器、FRU、电源、板级控制 |
| 启动与固件链路 | SPI、eSPI/LPC | 读取固件、连接平台控制器 |
| 时钟与复位 | Refclk、PERST#、Reset Tree | 保证器件按顺序进入可工作状态 |
| 供电链路 | PSU、Power Plane、VRM | 把输入电源转换为各芯片所需电压 |

同一个设备可能同时连接多类链路。例如 GPU 的业务数据走 PCIe/NVLink，状态监控可能走 SMBus，复位由 PERST# 控制，供电则来自 PCIe 插槽和辅助电源。

## 3. 从软件看不到什么

`lspci` 展示的是完成 PCIe Link Training、被固件发现并由系统枚举的功能。以下问题可能让设备根本不出现：

- Slot 未供电或 VRM 未达到 Power Good；
- Reference Clock 缺失；
- Reset 未释放；
- Lane 分叉配置与 Riser/背板不匹配；
- Retimer 固件、均衡或信号完整性异常；
- BIOS 禁用了 Root Port；
- PCIe 训练在低速或窄链路仍然失败。

因此“系统里没有日志”不能证明硬件正常，可能是故障发生在日志产生之前。

## 4. 分层排障方法

```text
物理与供电
→ 时钟与复位
→ Link Training
→ 固件枚举
→ OS 枚举
→ 驱动绑定
→ 业务 I/O
```

每次只回答一层：设备有没有电、链路有没有起来、系统有没有枚举、驱动有没有绑定、业务是否真的发出 I/O。不要在设备未枚举时反复重装驱动。

## 5. 常用证据

```bash
lspci -tv
lspci -nnk
lspci -s 65:00.0 -vv
dmesg -T | grep -Ei 'pcie|aer|dpc|link|firmware'
ls -l /sys/bus/pci/devices/
dmidecode -t baseboard -t slot
ipmitool fru
ipmitool sel elist
```

命令输出必须结合机型手册、主板 Block Diagram、插槽丝印和资产记录。Bus ID 在固件升级或设备变更后可能变化，不能作为永久物理位置标识。

## 6. 学习验收

- 能区分 PCIe 数据面与 I2C/SMBus 管理面；
- 能解释机械 x16 插槽为何可能只提供 x8 电气通道；
- 能从 `LnkCap` 和 `LnkSta` 判断降速、降宽；
- 能区分 Root Port、PCIe Switch、Retimer 与 Endpoint；
- 能解释 CXL.io、CXL.cache、CXL.mem 的职责；
- 能按“供电—时钟—复位—训练—枚举—驱动”定位设备消失。

## 7. 练习与答案

**问题：一块网卡能被 BMC 读取温度，但操作系统看不到它，矛盾吗？**

答案：不矛盾。管理总线和 PCIe 数据链路是两条独立路径。SMBus 仍可读取传感器，而 PCIe 可能因复位、时钟、训练或 Root Port 配置失败而无法枚举。

**问题：PCIe 设备已显示 `LnkSta: Speed 8GT/s, Width x4`，而设备能力是 16GT/s、x8，说明什么？**

答案：当前链路发生了降速和降宽。需要继续核对上游端口能力、插槽电气规格、Bifurcation、Retimer、接触和 AER 记录，而不能只看设备端标称能力。
