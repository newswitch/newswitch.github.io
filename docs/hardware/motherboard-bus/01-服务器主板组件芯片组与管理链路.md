# 服务器主板组件、芯片组与管理链路

主板问题经常表现为“设备消失”“偶发重启”“温度正常但性能下降”或“系统日志什么也没有”。原因是主板上存在多条相互独立的链路，Linux 只直接管理其中一部分。

## 1. 一张逻辑主板图

```text
                                  管理网口
                                      │
                              ┌─────── BMC ───────┐
                              │ Redfish/IPMI/KVM  │
                              └──┬────┬────┬──────┘
                         I2C/SMBus│  GPIO  │PMBus
                                 │        CPLD ── PSU/VRM/Fan/Sensor

 DIMM ─ IMC ─ CPU0 ═══ UPI/xGMI ═══ CPU1 ─ IMC ─ DIMM
                │ PCIe/CXL Root       │ PCIe/CXL Root
                ├─ GPU/NIC/NVMe       ├─ GPU/NIC/NVMe
                └──────────┬───────────┘
                           PCH
                  SATA / USB / SPI / eSPI
                           │
                    BIOS/UEFI Flash、TPM
```

不同平台会把部分功能集成进 CPU，也可能没有传统独立 PCH。判断实际连接关系应以机型 Block Diagram 和平台手册为准。

## 2. CPU Socket 与 Root Complex

CPU 封装内除 Core 和 Cache 外，通常还有 IMC、PCIe/CXL Root Complex 与 Socket Interconnect。它决定：

- 哪些 DIMM 是本地内存；
- 哪些 Slot、NIC、GPU 和 NVMe 属于本 Socket；
- 跨 Socket 访问要经过哪条一致性互联；
- 可提供多少 Memory Channel 与 PCIe Lane。

主板不能凭空增加 CPU 的高速 I/O。PCIe Switch 可以扩展下游端口数量，但多个下游设备仍共享有限的上行带宽。

## 3. PCH 与低速平台 I/O

PCH（Platform Controller Hub）常承载：

- SATA、USB 与部分板载网口；
- SPI Flash、eSPI/LPC；
- 音频或其他平台外设；
- 与 CPU 的平台上行链路。

GPU、高速 NIC 和高性能 NVMe 通常连接 CPU Root Complex。连接 PCH 的多个设备可能竞争同一上行，因此“每个端口都支持某速度”不等于同时工作时都能达到峰值。

## 4. BMC 与带外管理

BMC 是一台独立的小型计算机，主 CPU 未启动时也能工作。它负责：

- 上电、关机与硬复位；
- 温度、电压、电流、风扇和 PSU 监控；
- SEL 事件记录、FRU 读取；
- 远程 KVM、虚拟介质；
- IPMI、Redfish 和厂商管理接口；
- 部分 BIOS、CPLD、BMC 固件升级流程。

BMC 的“健康”通常只表示它能观测到的传感器和事件未越界，不代表 PCIe 没有重传、SSD 没有尾延迟、CPU 没有 Cache 错误。

## 5. CPLD、FPGA 与板级状态机

CPLD 常负责主板 Glue Logic：

- Power Sequence 与 Power Good 汇总；
- Reset 分发与时序；
- GPIO、Mux、Presence、Hot-plug；
- Riser、背板、风扇板等板卡状态；
- BMC 与多个器件间的控制协调。

它不是业务加速器。板级 CPLD 固件错误可能导致某组槽位无法上电或复位，因此固件矩阵不能只记录 BIOS 和 BMC。

## 6. VRM、时钟与复位树

### 6.1 VRM

VRM 把 PSU/主板电源平面的电压转换为 CPU、GPU、DIMM 等所需的低电压大电流。常见异常包括：

- 过流、过压、欠压与过温保护；
- 某 Rail 启动失败；
- 瞬态负载导致电压跌落；
- 散热不足引发限频或关机。

### 6.2 时钟

PCIe 等高速接口需要参考时钟。Clock Generator、Buffer 或布线异常可能造成链路训练失败、随机降速或反复 Recovery。

### 6.3 Reset

设备只有在供电和时钟稳定后才能释放 Reset。过早释放、一直未释放或热复位流程错误，都可能让设备完全不枚举。

## 7. 常见低速总线

| 总线/信号 | 典型用途 | 特点 |
| --- | --- | --- |
| I2C | 传感器、EEPROM、Mux | 两线、地址式、板级低速控制 |
| SMBus | DIMM SPD、设备管理 | 基于 I2C 的管理规范，增加超时等约束 |
| PMBus | PSU、VRM、电源遥测 | 基于 SMBus 的电源管理命令体系 |
| SPI | BIOS/UEFI Flash、控制器固件 | 主从式同步串行，常用于固件存储 |
| eSPI/LPC | CPU/PCH 与 BMC、Super I/O | 平台控制和传统低速 I/O |
| GPIO | Presence、Power Good、Reset | 单比特状态或控制信号 |
| JTAG | 调试、边界扫描、烧录 | 生产测试与底层调试，不是业务数据通道 |

管理总线带宽很低，不承载网卡或 GPU 的业务数据。传感器轮询过密、地址冲突或 Bus Hang 也可能影响板级管理。

## 8. FRU、SPD 与资产身份

- FRU：记录产品名、序列号、部件号、制造商等可更换单元信息；
- SPD：记录 DIMM 组织、时序、容量和厂商参数；
- VPD：PCIe 设备可能提供的产品与资产数据；
- DMI/SMBIOS：固件向 OS 暴露的系统、主板、Slot 和内存信息。

这些数据来自不同来源，可能因维修、固件或厂商实现而不一致。资产系统应同时记录物理槽位、序列号、PCI BDF 和 OS 设备名，并允许 BDF/接口名变化。

## 9. 现场映射方法

```bash
# 系统、主板与槽位
dmidecode -t system -t baseboard -t slot

# PCIe 树和设备身份
lspci -tv
lspci -nnk

# BMC 侧 FRU、传感器和事件
ipmitool fru
ipmitool sensor list
ipmitool sel elist
```

推荐建立映射表：

| 物理位置 | FRU/序列号 | PCI BDF | NUMA | OS 名称 | 上游端口 |
| --- | --- | --- | --- | --- | --- |
| Riser1-Slot2 | NIC-xxxx | 65:00.0 | 0 | enp101s0f0 | 64:00.0 |

换件前后用序列号和物理位置确认，不要只按 `eth0` 或 BDF 操作。

## 10. 故障边界

| 现象 | 优先检查 |
| --- | --- |
| 整机完全无法上电 | PSU、供电输入、CPLD、VRM、SEL |
| 单组槽位设备全部消失 | Riser/背板、Lane 分叉、时钟、复位、Root Port |
| BMC 可读温度但 OS 无设备 | PCIe 训练、固件枚举、Reset，不是管理总线 |
| 满载才重启或降频 | PSU 余量、VRM、温度、风道、功耗限制 |
| BMC 也无法访问 | 待机电源、BMC 固件、管理网络、主板控制路径 |

## 11. 练习与答案

**问题：PCIe Switch 能否把 CPU 的 x16 上行变成四个互不共享带宽的 x16？**

答案：不能。它可以提供多个下游端口和交换并发，但四个设备到 CPU 的聚合流量仍受 x16 上行限制。

**问题：为什么服务器关机后 BMC 仍能远程开机？**

答案：PSU 仍提供待机电源给 BMC 和部分板级逻辑。BMC 通过 CPLD/GPIO 控制上电时序，主 CPU 不需要先运行。
