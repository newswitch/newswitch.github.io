# 服务器磁盘类型、接口、外形与选型总览

“硬盘有多少种”没有一个固定数字，因为 HDD、TLC、NVMe、SAS 和 U.2 不在同一个分类维度。描述一块设备时，至少要分别说明介质、记录方式、协议、外形和产品等级。

## 1. 一块盘的完整身份

例如：

```text
3.5 英寸 + 氦气封装 + CMR/HAMR + SAS 双端口 + 企业级 Nearline HDD

E3.S + PCIe/NVMe + TLC NAND + 1 DWPD + PLP + 企业级 SSD
```

前者每个词分别描述机械外形、内部环境、磁记录方式、主机接口和产品定位；后者则描述外形、协议、介质、耐久度和可靠性能力。

## 2. 按物理介质分类

### 2.1 磁性 HDD

依靠旋转盘片和磁头保存数据，优势是单位容量成本低、单盘容量大，适合容量池、归档和顺序吞吐；随机 I/O 受寻道和旋转延迟限制。

### 2.2 NAND Flash SSD

没有机械寻道，由 Controller、FTL 和 NAND 组成，随机访问和并行能力强。性能、耐久和尾延迟取决于 NAND 类型、Channel、Over-Provisioning、Firmware、温度与稳态负载。

### 2.3 Storage Class Memory / Persistent Memory

它位于 DRAM 与 NAND SSD 之间的概念区域，可按块设备、字节寻址内存或厂商特定方式提供。具体产品生态会变化，不能把“持久内存”自动等同于 NVMe SSD 或 CXL Memory。

### 2.4 磁带和光介质

磁带、光盘也是持久化介质，但不属于通常所说的服务器本地硬盘。磁带适合低成本长期归档和离线副本，不适合随机在线 I/O。

## 3. HDD 按磁记录技术分类

| 技术 | 主要含义 | 对主机的重要影响 |
| --- | --- | --- |
| CMR | 常规、相对独立磁道写入 | 随机覆盖行为较可预测 |
| SMR | 磁道部分重叠，提高面密度 | Zone 重写和后台整理可能产生长尾 |
| HAMR | 通过局部加热辅助写入更小磁粒 | 提高面密度，主机接口可仍是 SATA/SAS |
| MAMR | 通过微波相关技术辅助磁记录 | 同样属于介质记录技术，不是接口协议 |

CMR 与 PMR 经常一起出现：PMR 描述垂直磁记录，CMR 强调非叠瓦的常规磁道布局。选型时以厂商明确标注的记录方式和工作负载限制为准。

### 3.1 SMR 的管理方式

- Drive-managed：设备内部隐藏 Zone 约束，对主机表现为普通块设备；
- Host-aware：主机可利用 Zone 信息，但设备仍可接受部分普通写入；
- Host-managed：主机必须遵守 Zone 顺序写和 Reset 语义。

不能因为接口是 SATA/SAS 就判断它是 CMR 还是 SMR。

## 4. SSD 按 Cell Bit 数分类

| NAND | 每个 Cell 保存 Bit | 一般趋势 |
| --- | ---: | --- |
| SLC | 1 | 耐久和裕量高，容量密度低 |
| MLC | 2 | 性能、耐久与密度折中 |
| TLC | 3 | 企业和客户端 SSD 的常见平衡 |
| QLC | 4 | 容量密度高，更依赖控制器、缓存和工作负载管理 |

NAND 类型不能单独决定 SSD 等级。一块优秀的企业级 QLC SSD 可能比消费级 TLC SSD 更适合大容量读取负载，因为前者还具有 PLP、稳定 QoS、遥测和更严格的 Firmware 验证。

## 5. 按主机接口与命令协议分类

| 接口/协议 | 常见设备 | 关键特点 |
| --- | --- | --- |
| SATA/AHCI | HDD、SATA SSD | 点对点、生态成熟、队列和带宽较有限 |
| SAS/SCSI | 企业 HDD、SAS SSD、磁带 | 双端口、Expander、丰富错误管理与企业拓扑 |
| PCIe/NVMe | NVMe SSD | 多队列、低开销、直接使用 PCIe |
| NVMe-oF | 远端 NVMe Namespace | 通过 RDMA/TCP/FC 等 Fabric，不代表盘在本机 |
| USB 等桥接 | 移动/维护设备 | 中间桥接会改变性能与错误语义 |

`/dev/sda` 不能证明是 SATA，`/dev/nvme0n1` 也不能证明是本机物理 SSD。

## 6. 按外形规格分类

### 6.1 HDD 常见外形

- 3.5 英寸：容量型 HDD 常见；
- 2.5 英寸：企业 SAS HDD、SSD 和部分高转速盘常见。

### 6.2 SSD 常见外形

- 2.5 英寸 SATA/SAS；
- M.2 SATA 或 NVMe；
- U.2/U.3 2.5 英寸企业 NVMe/SAS/SATA 体系；
- PCIe Add-in Card；
- EDSFF E1.S、E1.L、E3.S、E3.L 等。

外形相同不代表电气和协议兼容。M.2 既可能使用 SATA，也可能使用 PCIe/NVMe；2.5 英寸设备也可能是 SATA、SAS 或 NVMe。

## 7. 按产品定位分类

### 7.1 HDD

- Client/Desktop：面向轻负载和有限并发；
- NAS：针对多盘、持续运行和振动环境优化；
- Nearline Enterprise：大容量、持续运行、企业错误处理；
- Mission-critical：历史上常见高转速 SAS，容量和市场占比取决于平台；
- Archive/Zoned：针对顺序写与归档工作负载。

### 7.2 SSD

- Client：成本和突发性能优先；
- Read-intensive：读取为主、较低写入耐久预算；
- Mixed-use：持续混合读写；
- Write-intensive：更高 DWPD 与持续写 QoS；
- Low-latency：强调稳定尾延迟；
- Capacity-optimized：高密度、读取和顺序写为主。

这些名称不是跨厂商完全统一的等级，最终以 Data Sheet 的工作负载、耐久、QoS 和保修条件为准。

## 8. 接口、协议和外形不能互相推导

```text
错误：NVMe = M.2 = TLC

正确：
NVMe 是命令/接口体系
M.2 是机械和连接外形家族
TLC 是 NAND Cell 存储方式
```

同理，SAS 是接口与协议体系，不代表介质一定是 HDD；SAS SSD 同样存在。

## 9. 容量、性能和可靠性维度

选型至少比较：

- Raw/Usable Capacity；
- 顺序吞吐、随机 IOPS 和 P99/P999；
- Queue Depth 与 Block Size；
- TBW/DWPD、工作负载定义和保修期；
- PLP、Flush/FUA 和写缓存持久性；
- 双端口、热插拔和故障隔离；
- 介质错误、遥测和 Firmware 管理；
- 功耗、散热、风阻和环境限制；
- 盘、背板、HBA/PCIe Switch 的共享故障域。

## 10. 场景化选择

| 场景 | 常见方向 | 仍需验证 |
| --- | --- | --- |
| 大容量冷数据 | Nearline HDD、Archive/Zoned | 重建窗口、吞吐、数据副本 |
| 数据库日志 | 企业 SSD、低尾延迟、PLP | 同步写、耐久、故障恢复 |
| AI 模型本地缓存 | NVMe SSD | 可重建性、读吞吐、NUMA、散热 |
| Checkpoint 暂存 | NVMe/企业 SSD | 写入峰值、容量水位、最终持久化 |
| 共享磁盘柜 | 双端口 SAS/NVMe、冗余路径 | Expander/Switch、MPIO、控制器故障域 |
| 长期离线归档 | Tape/Object Storage | 恢复时间、介质校验和演练 |

## 11. 选型流程

1. 先定义数据是否可重建、RPO/RTO 和容量增长；
2. 定义随机/顺序、读写比例、Block Size 和 Queue Depth；
3. 计算持续写入量与耐久，不只看峰值 IOPS；
4. 选择协议和冗余拓扑；
5. 再选择外形、槽位密度、功耗和散热；
6. 用稳态业务模型测试，不用空盘短测代替；
7. 验证 Firmware、遥测、换盘和 RMA 流程。

## 12. 练习与答案

**问题：一块 2.5 英寸硬盘能否仅凭外观判断是 SATA、SAS 还是 NVMe？**

答案：不能。2.5 英寸只是外形，仍需看连接器、标签、型号、背板和控制器支持。

**问题：QLC SSD 是否一定不能用于生产？**

答案：不是。它适合容量和读取密集型场景，但要核对持续写、DWPD、QoS、PLP、GC 和软件数据放置；不能把客户端 QLC 与企业级 QLC 混为一谈。
