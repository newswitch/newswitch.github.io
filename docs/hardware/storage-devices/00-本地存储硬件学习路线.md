# 本地存储硬件从零到精通学习路线

操作系统看到的是块设备，物理介质内部却可能是旋转盘片，也可能是必须先擦后写、依靠映射和垃圾回收工作的 NAND。理解两者的内部约束，才能解释为什么平均吞吐正常时仍会出现秒级长尾，也能避免把文件系统、控制器和介质故障混为一谈。

## 2. 三类边界

```text
应用 / 文件系统
→ Linux Block Layer / I/O Scheduler
→ 驱动与 Host Controller
→ SATA/SAS/PCIe/NVMe 链路
→ 设备 Controller / Firmware / DRAM
→ 磁性介质或 NAND Media
```

- 上层错误：文件系统、队列策略、容量或挂载语义；
- 传输错误：线缆、背板、HBA、PCIe/SAS/SATA 链路；
- 介质错误：坏扇区、NAND 磨损、不可纠正错误、内部映射异常。

同一个 I/O Timeout 可能来自任意一层，不能只凭错误字符串换盘。

## 3. HDD 与 SSD 的根本差异

| 维度 | HDD | NAND SSD |
| --- | --- | --- |
| 物理动作 | 磁头定位、盘片旋转 | 电子读写、先擦后写 |
| 最小操作 | Sector，内部按磁道/扇区组织 | Page 读写、Block 擦除 |
| 随机访问 | 受寻道和旋转延迟限制 | 无机械寻道，但受 FTL/GC 影响 |
| 老化 | 机械、磁介质与磁头 | P/E Cycle、Retention、Read Disturb |
| 长尾 | 重试、重映射、振动 | GC、折叠、磨损均衡、固件后台任务 |

SSD 的延迟更低，不表示延迟恒定；HDD 的顺序带宽尚可，不表示适合大量随机小 I/O。

## 4. 规格必须转换成工作负载

至少同时看：

- 顺序/随机、读/写比例；
- I/O Size 与 Queue Depth；
- 平均延迟和 P99/P999；
- 稳态而非刚清空设备时的峰值；
- 容量占用、Over-Provisioning 和温度；
- 同一 HBA、PCIe Switch 或背板的共享关系；
- PLP、耐久度、保修写入量和故障恢复语义。

## 5. 故障证据链

```text
应用错误时间
→ 文件系统/Block 层超时
→ 驱动 Reset 与链路日志
→ SMART/NVMe Health 与错误日志
→ BMC/背板/电源事件
→ 槽位交换与压力复现
```

一次健康检查的 `PASSED` 不是完整结论。重点是关键计数是否增长、是否与故障同一时间、设备是否发生 Reset，以及错误是否随槽位还是随盘迁移。

## 6. 学习验收

- 能解释 HDD 随机 I/O 为什么慢、SMR 为什么会出现写入抖动；
- 能画出 NAND 的 Page、Block、Plane、Die 与 Channel；
- 能解释 FTL、GC、TRIM、Over-Provisioning 和写放大；
- 能追踪 NVMe 从 Submission Queue 到 DMA Completion 的路径；
- 能从介质、协议、总线和外形四个维度准确描述一块盘；
- 能画出 SATA/SAS 的 HBA、Expander、双端口和 Multipath 拓扑；
- 能解释 M.2、U.2、U.3、EDSFF 和 NVMe 背板的兼容边界；
- 能根据 PLP、TBW/DWPD、稳态尾延迟和工作负载选择企业 SSD；
- 能区分 SMART/Health、Error Log、Persistent Event Log、Telemetry 与 NVMe-MI 的用途；
- 能区分链路错误、控制器错误与介质错误；
- 能设计不破坏生产数据的换槽、换盘和压力验证。

## 7. 练习与答案

**问题：SSD 空盘压测很快，上线一段时间后写延迟增大，是否一定是损坏？**

答案：不一定。设备进入稳态后需要垃圾回收、擦除和磨损均衡，容量接近满、随机写入或 TRIM 不充分都会增加写放大和尾延迟。还需结合健康日志和错误计数判断。

**问题：出现 I/O Timeout 就应该立即更换硬盘吗？**

答案：不能直接判断。Timeout 也可能来自 HBA、背板、线缆、PCIe/SAS 链路、电源或驱动 Reset。应先建立时间线并通过交换部件判断故障跟盘还是跟槽位。
