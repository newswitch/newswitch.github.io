# 交换机硬件从零到精通学习路线

网络配置最终要落入有限的硬件表项、队列和 Buffer。命令行能配置一百万条规则，不代表 ASIC 有足够资源同时按线速执行；端口带宽也不能代表交换 Fabric、队列和缓存没有瓶颈。

## 2. 一次报文经过交换机

```text
Ingress Port / PHY
→ MAC / PCS / FEC
→ Parser
→ Ingress Match-Action
→ Lookup / ACL / QoS
→ Buffer / Traffic Manager
→ Switch Fabric
→ Egress Queue / Scheduler
→ Egress Rewrite
→ Egress Port
```

实际 ASIC 可能采用共享流水线、切片或多 Die，逻辑路径仍可用来分析表项、拥塞和故障位置。

## 3. 三类资源

- 处理资源：Pipeline Stage、ALU、Parser、Recirculation；
- 表项资源：SRAM、CAM、TCAM、Counter；
- 流量资源：Buffer Cell、Queue、Scheduler、Fabric Bandwidth。

配置失败可能是某一种资源耗尽，而不是整台交换机“内存满”。不同 Feature 还可能竞争同一 TCAM Bank 或 Pipeline Stage。

## 4. 性能不能只看端口速率

还需确认：

- ASIC 总交换容量和 Oversubscription；
- Front Panel Port 与 SerDes Lane 组合；
- Packet Per Second，尤其最小包；
- Pipeline 是否需要 Recirculation；
- Buffer 架构、拥塞点和队列映射；
- Chassis Fabric、Line Card 和 Fabric Card 冗余；
- FEC、端口错误和温度降频。

## 5. 学习验收

- 能解释 Parser、Lookup、Action、Rewrite 各自职责；
- 能区分 SRAM、CAM、TCAM 和 Counter；
- 能解释路由、ACL、QoS 为什么竞争硬件资源；
- 能区分 Shared Buffer、Ingress/Egress Queue 和 VOQ；
- 能解释 Head-of-Line Blocking、Microburst 和 Scheduler；
- 能画出机框交换机 Line Card 到 Fabric Card 的故障域；
- 能区分固定盒式、模块化机框、白盒和专用 Fabric 交换机；
- 能在 Fabric 模块降级后重新判断容量和冗余。

## 6. 练习与答案

**问题：交换机总内存还有很多，为什么新增 ACL 规则仍失败？**

答案：ACL 依赖特定 TCAM Bank、Key 宽度和 Pipeline Stage。通用 DRAM 或其他表项空闲不能替代该硬件资源。

**问题：端口平均利用率只有 30%，为什么仍会丢包？**

答案：平均值掩盖微突发。短时间到达速率可能超过出口服务速率并填满 Queue/Buffer，形成瞬时 Tail Drop。
