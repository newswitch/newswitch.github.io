# 附录C：服务器、GPU/NPU、网络和软件资产盘点模板

:::info 系列与定位
**所属系列**：《NVIDIA＋昇腾双资源池 AI 推理集群：从 0 到部署、运维与故障排查》
**用途**：新集群建设、扩容、巡检、故障定位、容量规划和资产审计

:::

:::

## 12. 常用盘点命令 {/* #十二常用盘点命令 */}

```bash
# Linux
hostnamectl; uname -a; lscpu; free -h
lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS
ip -br address; ip -br link; timedatectl

# Kubernetes
kubectl get nodes -o wide
kubectl get nodes --show-labels
kubectl get nodes -o custom-columns=NAME:.metadata.name,CAPACITY:.status.capacity,ALLOCATABLE:.status.allocatable
kubectl get pods -A -o wide
kubectl get storageclass,pv,pvc -A

# NVIDIA
nvidia-smi -L
nvidia-smi --query-gpu=index,uuid,pci.bus_id,name,serial,driver_version --format=csv
nvidia-smi topo -m

# 昇腾
npu-smi info -l
npu-smi info
cat /usr/local/Ascend/driver/version.info
cat /usr/local/Ascend/firmware/version.info
```

具体命令支持随产品和版本变化；盘点脚本应记录执行失败，而不是静默跳过。

## 15. 巡检频率 {/* #十五巡检频率 */}

| 频率 | 内容 |
|------|------|
| 每日 | Node Ready、设备健康、Allocatable、关键组件 |
| 每周 | 版本漂移、故障趋势、网络 Link、存储容量 |
| 每月 | 资产与物理位置核对、容量预测、证书与固件 |
| 每季度 | 兼容矩阵、退役计划、RMA、SOP 和演练 |
| 变更前后 | 完整基线快照和差异报告 |

## 16. 资产数据安全 {/* #十六资产数据安全 */}

资产系统可能包含管理 IP、BMC、序列号和网络拓扑，应做到：最小权限、变更审计、敏感字段分级、定期备份；禁止公开仓库存放凭证；离职和角色变更及时收权。

密码、API Key、BMC 凭证、SNMP 认证和证书私钥不应直接写入资产表，只记录密钥系统中的引用。

## 17. 盘点验收 {/* #十七盘点验收 */}

- [ ] 任何模型请求可以追溯到 Service、Pod、Node 和设备
- [ ] 任何设备可以追溯到物理机架和交换机端口
- [ ] 任何节点可以追溯到完整软件 Matrix ID
- [ ] 任何镜像可以追溯到 Digest 和构建流水线
- [ ] 任何模型可以追溯到 Revision 和 Checksum
- [ ] Capacity、Allocatable 和物理数量可以解释
- [ ] 故障设备有状态、工单和处置记录
- [ ] 资产最后验证时间未过期
