# 附录J：部署验收、性能基准、容灾演练与毕业清单

:::info 系列与定位
**所属系列**：《NVIDIA＋昇腾双资源池 AI 推理集群：从 0 到部署、运维与故障排查》  
**用途**：证明集群不仅「安装完成」，而且可服务、可观测、可运维、可恢复  
**适用范围**：一个 Kubernetes 集群中的 NVIDIA 资源池与昇腾资源池，以及共享网关、存储和监控
:::

:::tip 系列约定
资源池 A = **NVIDIA GPU**（vLLM）· 资源池 B = **华为昇腾 NPU**（vLLM-Ascend）· 同一 Kubernetes · 共享存储/网关/监控 · **禁止**跨池组成同一分布式模型实例。
:::

## 一、验收结论分级

| 结论 | 定义 | 是否可上线 |
|------|------|------------|
| 通过 | 所有阻断项通过，评分达到门槛，无未接受高风险 | 可以 |
| 有条件通过 | 阻断项通过，存在有负责人和期限的中低风险项 | 经审批后可以 |
| 不通过 | 任一阻断项失败、数据不可信或无回滚/容灾能力 | 不可以 |

以下项目默认为**阻断项**：节点或设备健康不稳定；驱动/固件/CUDA/CANN/镜像兼容性未验证；模型输出正确性未通过；生产接口、鉴权或 TLS 不符合要求；容量无法覆盖发布 Surge 或承诺故障场景；监控告警无法发现关键故障；回滚或故障切换从未验证；权重来源、镜像 Digest 或配置不可追溯；存在未接受的高危安全问题。

## 三、基础设施验收

### 1. 公共基础

- [ ] 控制面高可用，备份与恢复流程已验证  
- [ ] 所有节点时间同步、DNS 和证书正常  
- [ ] OS、内核、容器运行时、CNI 版本已登记  
- [ ] 控制面不承载加速器推理工作负载  
- [ ] 节点命名、机架、机房、带外管理和责任人已登记  
- [ ] CPU、内存、系统盘、数据盘和 inode 留有余量  
- [ ] Registry 可用，生产镜像使用 Digest  
- [ ] Kubernetes 审计、日志保留和访问控制符合要求  
- [ ] 备份内容、周期、保留期和恢复负责人明确  

### 2. NVIDIA 资源池

- [ ] 标签 `accelerator.vendor=nvidia`、`resource-pool=nvidia-pool`；Taint `accelerator=nvidia:NoSchedule`  
- [ ] GPU 型号、数量、UUID、显存和拓扑与资产一致  
- [ ] 驱动、Container Toolkit、Device Plugin 版本匹配  
- [ ] Capacity/Allocatable 与物理设备一致；容器内设备与申请一致  
- [ ] 单卡、多卡和必要时多机通信测试通过  
- [ ] DCGM Exporter 可采集；不允许昇腾工作负载误入本池  

### 3. 昇腾资源池

- [ ] 标签 `accelerator.vendor=ascend`、`resource-pool=ascend-pool`；Taint `accelerator=ascend:NoSchedule`  
- [ ] NPU 型号、数量、设备标识、HBM 和拓扑与资产一致  
- [ ] 驱动、固件、CANN、Runtime、Device Plugin 版本匹配  
- [ ] Capacity/Allocatable 与物理一致；容器内设备与申请一致  
- [ ] 单 NPU、多 NPU 和必要时 HCCL 多机测试通过  
- [ ] NPU Exporter 可采集；不允许 NVIDIA 工作负载误入本池  

### 4. 网络与存储

- [ ] 管理/业务/存储/加速器通信网络按设计隔离  
- [ ] MTU、路由、防火墙、NetworkPolicy 一致且有记录  
- [ ] RoCE/PFC/ECN 只按已验证方案配置；带宽/延迟/丢包达标  
- [ ] NFS/Ceph/对象存储容量、吞吐、延迟和健康正常  
- [ ] 模型权重可校验，读权限最小化；CSI 挂载与节点故障恢复已验  
- [ ] 并发冷启动不会压垮存储；本地缓存容量/回收/预热明确

## 六、性能基准设计

### 1. 术语

端到端时延、TTFT、TPOT/ITL、吞吐（请求/s 与 Token/s）、并发、成功率（预期状态码与响应完整性）。

### 2. 请求矩阵

| 编号 | 输入 Token | 输出 Token | 流式 | 并发 | 说明 |
|------|------------|------------|------|------|------|
| S1 | 约 128 | 约 128 | 否 | 1 | 单请求基线 |
| S2 | 约 128 | 约 128 | 是 | | 短对话 |
| M1 | 约 2K | 约 512 | 是 | | 常规业务 |
| M2 | 约 4K | 约 1K | 否 | | 中长请求 |
| L1 | 约 8K 或业务 P95 | 约 1K | 是 | | 长上下文 |
| L2 | 最大允许附近 | 约 128 | 否 | | 边界测试 |
| MIX | 按生产分布 | 按生产分布 | 混合 | 逐级 | 容量测试 |

不要只用「你好」测吞吐——短输入会掩盖 Prefill、KV Cache 和长上下文问题。

### 3. 并发阶梯

`1 → 2 → 4 → 8 → 16 → 32 → ...`，每级稳定后记录：

| 指标 | NVIDIA | 昇腾 | 验收阈值 |
|------|--------|------|----------|
| 成功率 / QPS / 输入·输出 Token/s | | | |
| TTFT / TPOT·ITL / 端到端 P50·P95·P99 | | | |
| 等待请求峰值 / KV Cache 峰值 | | | |
| 显存·HBM 峰值 / GPU·NPU 利用率 / CPU·内存 | | | |
| 429·5xx / 功耗 | | | |

容量点 = 同时满足成功率、TTFT、端到端时延和错误预算的最高稳定负载，不是「未崩溃」。

### 4. 冷态、热态和耐久

| 测试 | 方法 | 记录 |
|------|------|------|
| 冷启动 | 清晰定义无页缓存/无本地权重/容器首次启动 | 镜像拉取、权重读取、初始化、Ready |
| 热启动 | 镜像和权重缓存存在 | 各阶段时长 |
| 预热 | 批准的代表性请求 | 预热次数与达稳定时间 |
| 稳态 | 真实混合负载持续运行 | SLO、资源、温度、错误 |
| 耐久 | 批准的长时间窗口 | 内存增长、错误累积、性能漂移 |

### 5. 报告可复现字段

硬件型号/数量/拓扑；OS/内核/驱动/固件；CUDA 或 CANN、NCCL 或 HCCL；镜像 Digest；模型/Tokenizer/量化/权重哈希；TP/PP、最大上下文、并发、显存/HBM 参数；网关与负载生成器网络位置；Token 真实分布；测试时间窗、原始结果和监控快照。

## 十、容灾演练设计

### 1. 演练原则

先测试环境，再生产受控窗口；每次只注入一个故障；优先服务级模拟，不破坏硬件或数据；提前定义停止条件；设观察员和安全官；结束恢复全部临时配置。

### 2. 场景清单

| 场景 | 安全注入方式 | 期望行为 | 重点指标 |
|------|--------------|----------|----------|
| 单 Pod 失败 | 终止一个可替代副本 | Service 摘除、剩余承接、自动恢复 | 失败请求、SSE、恢复时间 |
| 节点维护 | 按[附录 I](./附录I-发布变更维护容灾与复盘SOP模板.md) 排空 | PDB 生效、业务迁移 | 排队、Ready、迁移时间 |
| 单池服务不可用 | 网关标记不可用或指向隔离端点 | 核心流量按预案进另一池 | fallback、备用队列、429 |
| Exporter 停止 | 仅停测试 Exporter | TargetDown，不误判业务必挂 | MTTD、通知、恢复 |
| 存储变慢 | 隔离环境限速/测试存储 | 冷启动变慢被发现，禁扩大发布 | 加载时间、存储延迟 |
| 网关 5xx | 测试路由注入可控错误 | 比例告警，停止扩大流量 | 5xx、触发时间 |
| 通信异常 | 隔离环境阻断测试链路 | NCCL/HCCL 失败并按 Runbook 定位 | 日志、链路、升级过程 |
| Secret 轮换 | 测试凭据双版本轮换 | 无中断或符合窗口预期 | 401/403、连接错误 |

禁止通过生产拔卡、重置设备、破坏 Ceph、全网改 PFC/ECN、删除 PVC 或同时停两池做首次演练。

### 3. 演练记录与量化


### 4. 双池切换专项

- [ ] 两池均部署经验证的同接口模型；权重/Tokenizer/模板/模型名一致  
- [ ] 备用池有明确可承接容量；不因单次慢请求频繁切换  
- [ ] fallback 单向、有限次、可观测；已输出 Token 的 SSE 不透明重放  
- [ ] 核心/非核心降级顺序明确；切换、观察、回切、停止条件已验  
- [ ] 没有跨 NVIDIA 与昇腾组成一个分布式实例
