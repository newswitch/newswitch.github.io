# 地址绑定、DHCP Snooping、DAI 与 IPv6 接入保护

终端说“这个 IP 是我的”，交换机依据什么判断？仅学习源 MAC 不能证明 IP 归属。地址绑定机制把地址、MAC、VLAN、端口和有效期等上下文联系起来，为后续检查提供依据。

## 1. 三个功能不能混成一个

| 功能 | 主要观察或限制的对象 | 常见依据 |
| --- | --- | --- |
| DHCP Snooping | DHCP 交互及服务器方向合法性 | 端口角色与 DHCP 租约信息 |
| DAI：Dynamic ARP Inspection | ARP 中的地址声明 | 绑定表或显式允许的 ARP 信息 |
| IP Source Guard | 普通 IP 数据的源地址使用 | 地址与接入位置绑定，部分模式还检查 MAC |

仅开启 Snooping，不表示所有普通 IP 包都已被逐包检查；仅检查 ARP，也不能覆盖完全不发送 ARP 的地址冒用场景。具体数据面能力需按产品确认，参见 [Cisco DAI/IPSG 说明](https://www.cisco.com/c/en/us/support/docs/switches/lan-switch-software/222274-troubleshoot-dynamic-arp-inspection-dai.html)。

## 2. 绑定状态是怎样形成的

一个简化过程是：

```text
终端从接入口申请地址
  → 交换机观察合法 DHCP 交互
  → 记录地址、MAC、VLAN、端口与租约期限
  → DAI／源地址保护使用相应绑定检查后续报文
```

它不是从任意一份客户端声明就无条件学习。哪些报文可信、什么时候更新或删除记录，取决于协议交互与实现规则。

同一 IP 在另一个端口出现，不应自动覆盖原绑定。终端真实移动、链路聚合或下级交换结构又可能需要合法更新，因此必须结合接入位置理解，而不只比对地址字符串。

### 2.1 绑定不是 MAC 表，也不是 ARP 表

设终端 M 在 VLAN 10 的端口 P 获得 `10.10.10.23`，租约有效 8 小时。三个表可能同时存在：

| 表 | 记录的主要关系 | 回答的问题 |
| --- | --- | --- |
| MAC 转发表 | VLAN 内的 MAC → 出口 | 把以太网帧往哪里送 |
| ARP 邻居表 | 本地三层邻居 IP → MAC | 构造下一跳二层头时使用哪个 MAC |
| DHCP Snooping 绑定表 | IP、MAC、VLAN、端口与租约等 | 当前接入位置是否获准使用该地址 |

交换机学到了 M 的位置，并不能证明它有权使用 `10.10.10.23`。网关已经有 ARP 项，也不能自动为接入交换机补齐租约来源。

动态绑定一般随合法 DHCP 分配确认而建立，续租更新有效期，租约到期、释放或接入变化触发相应维护；具体删除、持久化与重学习行为取决于实现。Discover 中的身份或 Offer 中的候选地址，不应被等同于已确认的长期使用权。

### 2.2 DAI 究竟在比较哪个地址

一个 ARP 报文同时包含以太网头的源／目的 MAC，以及 ARP 内容中的发送者 MAC/IP、目标 MAC/IP。DAI 的基础地址归属检查，关注 ARP 声明与可信绑定或显式许可是否一致。

部分产品还能额外比较以太网源 MAC 与 ARP 发送者 MAC，或检查响应的目的 MAC、非法地址等；这些是可选检查，不是所有实现的默认全集。具体区别见 [Cisco DAI/IPSG](https://www.cisco.com/c/en/us/support/docs/switches/lan-switch-software/222274-troubleshoot-dynamic-arp-inspection-dai.html)。

还要保留正常协议的语义：IPv4 地址冲突探测可能使用发送者 IP `0.0.0.0`，不能脱离报文阶段把所有零地址都解释成冒用。适用的地址校验与例外行为应匹配 [IPv4 ACD](https://www.rfc-editor.org/rfc/rfc5227.html)，而不是仅因为“更严格”就叠加所有过滤。

## 3. Trusted Port 是功能角色，不是免检的好设备

Snooping 的可信方向通常允许相应服务器消息进入。把连接终端的端口设为可信，并不是证明终端可靠，而是在改变交换机检查消息的边界。

DAI 也可能使用自己的可信端口语义，不能假定不同功能的 trust 设置完全共用。

上联口是否应被信任，取决于它后面是否只有受控服务器或已完成约束的网络；“上联”不是自动可信的密码。链路方向和拓扑改变后，旧的信任判断可能不再成立。

## 4. 静态地址为什么容易被误阻断

打印机或服务器若使用手工静态地址，没有通过 DHCP 形成动态绑定，就可能无法满足依赖该绑定的检查。

合理处理是明确静态归属及设备支持的静态绑定、ARP 许可等机制，而不是无条件关闭整个 VLAN 的保护。静态条目也需要维护 VLAN、端口和终端迁移关系，否则同样可能过期。

特别要注意：DHCP 保留地址仍可能通过正常 DHCP 交互形成租约；手工写死地址则是另一种配置来源。两者都“长期不变”，但绑定学习方式不同。

## 5. 交换机重启后，为什么老终端反而不能用了

终端可能仍持有有效 DHCP 租约，交换机的动态绑定却因重启而缺失。此时终端继续发送业务，新的检查状态无法确认其归属，就可能拒绝合法流量。

这不是简单证明“安全功能不稳定”，而是说明依赖状态需要可恢复、可重新学习并与租期一致。持久化数据若太旧，又可能把已移动或已换人的地址错误恢复。

地址租约、接入授权会话与二层绑定是三种相关但不同的状态。只备份其中一项，不能保证整条接入链自动恢复。

### 5.1 三种状态恢复的先后次序会影响结果

沿一台终端的接入过程理解：

```text
802.1X：身份获准，进入 VLAN 10
DHCP：取得 VLAN 10 中的有效租约
接入交换机：据合法交互建立对应绑定
DAI/IPSG：使用绑定检查后续地址声明和源地址
业务 ACL：再判断允许访问哪些目的
```

如果重认证把终端放入 VLAN 20，而它仍持有 VLAN 10 的地址，旧绑定不能直接跨 VLAN 当作授权依据。类似地，交换机重启后恢复了 802.1X 会话，却没有恢复地址绑定，仍可能无法满足源地址保护。

绑定表中已经出现记录，也要区分软件状态与实际过滤规则是否完成安装。资源不足或设备实现问题可能影响执行；不能因为控制平面有一行表项，就跳过数据面验证。

## 6. IPv6 不能照搬 ARP 检查

IPv6 使用 NDP/RA，并可能通过 SLAAC 生成地址。因此需要按具体消息和地址来源划分保护：

| 机制 | 主要约束 |
| --- | --- |
| RA Guard | 哪些接入位置允许发送路由器通告 |
| DHCPv6 Shield／Guard | 哪些位置允许发送相应 DHCPv6 服务器消息 |
| SAVI 等源地址验证机制 | 地址与接入锚点之间的绑定和源地址使用 |
| NDP 相关检查 | 适用产品对邻居声明等消息的约束 |

RA Guard 不认证业务用户，也不保证所有邻居声明都正确；DHCPv6 检查不天然覆盖 SLAAC 地址。基础机制分别见 [RFC 6105](https://www.rfc-editor.org/rfc/rfc6105.html)、[RFC 7610](https://www.rfc-editor.org/rfc/rfc7610.html) 和 [RFC 7039](https://www.rfc-editor.org/rfc/rfc7039.html)。

扩展首部等情况还影响设备能否正确识别消息，不能只看功能菜单里出现“RA Guard”就认定实现覆盖所有报文形态，相关实现考虑见 [RFC 7113](https://www.rfc-editor.org/rfc/rfc7113.html)。这里讨论的是防护能力边界，不是建议全面屏蔽 ICMPv6。

### 6.1 IPv6 地址来源更多，不能硬套一端口一个地址

同一网卡可以同时拥有链路本地地址、稳定全局地址和临时隐私地址，还可能处在新旧前缀并存期。合法地址数量大于一，不等于冒用；只从 DHCPv6 租约学习，也会漏掉按 SLAAC 形成的地址。

源地址验证必须结合适用的地址生成与生命周期机制，区分普通终端、合法路由器和代理等角色。SAVI 的接入锚点与绑定模型见 [RFC 7039](https://www.rfc-editor.org/rfc/rfc7039.html)。

RA Guard 约束的是路由通告来源；它不替代全部 NS/NA 处理，也不意味着应拦截所有 ICMPv6。安全策略需要约束未经授权的行为，同时允许正常地址配置、邻居可达性确认和必要的网络错误反馈。

## 7. 地址绑定不能替代身份认证

绑定机制证明的通常是“在当前接入上下文中，这个地址按规则被允许使用”，不是“这就是某个经过强认证的自然人或设备”。

802.1X 可以提供身份与授权基础，绑定机制约束地址使用，ACL 再控制可访问的业务。三者层层配合，而不是互相替代。

## 8. 思考与解答

**MAC 表已经学到终端端口，为什么 IPSG 仍可能拒绝它的流量？**

MAC 表回答转发位置，IPSG 需要地址使用权与接入位置的合法绑定。两个状态来源与用途不同，学到 MAC 不会自动证明 IP 归属。

**认证从 VLAN 10 改为 VLAN 20，能直接保留原来的地址绑定吗？**

不能无条件跨 VLAN 复用。地址、端口和 VLAN 共同构成上下文；终端地址配置与新授权网络需要重新匹配。

**ARP 的发送者 IP 为 0.0.0.0，一定是非法终端吗？**

不是。正常 IPv4 冲突探测可能使用该形式，应结合协议阶段及所用设备的检查规则判断，而不是脱离语义作结论。

**IPv6 终端有多个全局地址，是否必须压成一个才安全？**

不是。隐私地址和前缀过渡都可能产生合法多地址；验证应覆盖地址来源与有效期，而不是把正常多地址模型误当成异常。

**开启 DAI 后，所有 IP 数据都会自动按源地址过滤吗？**

不是。DAI 主要检查 ARP，普通 IP 源地址约束属于其他相应功能。

**静态终端无法通信，就应该把全部端口设为可信吗？**

不应该。应先理解它缺少哪种合法绑定，以及设备如何表达静态例外。放宽整个信任边界会影响无关终端。

**RA Guard 能阻止所有 IPv6 地址冒用吗？**

不能。它主要约束路由器通告，地址归属与邻居声明还有不同的控制机制。
