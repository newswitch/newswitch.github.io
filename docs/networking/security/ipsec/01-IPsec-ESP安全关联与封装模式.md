# IPsec、ESP、安全关联与封装模式

两个分支通过不可信网络通信时，公网路由器仍需要知道包应该去哪个 VPN 网关，但不应因此看见被保护的内部业务内容。隧道模式通过“外层负责交付，内层承载原始通信”分开这两个职责。

## 1. IPsec、ESP 与 IKE 分别是什么

| 名称 | 主要职责 |
| --- | --- |
| IPsec | 网络层安全架构，组织策略、关联与报文处理 |
| ESP | 依据协商的参数保护实际数据报文 |
| IKE | 认证对端并建立、维护安全关联与密钥材料 |
| AH | 提供特定完整性与认证保护的另一种 IPsec 协议，不提供数据加密 |

ESP 不是 TCP/UDP 应用协议。未做 UDP 封装时，它使用 IP 协议号 50。ESP 的实际机密性与完整性能力取决于协商的变换，不能仅凭抓到 ESP 就推断采用了某个具体加密算法。[RFC 4301](https://www.rfc-editor.org/rfc/rfc4301.html) 给出总体架构。

## 2. 传输模式保护什么

传输模式大体保持原始 IP 端点关系，保护传输层数据等载荷：

```text
外部可见：原 IP 首部 | ESP 标识等
受保护：                TCP/UDP 等上层内容及相应尾部
```

它常用于端到端保护，或者与其他封装配合。不能把“没有额外隧道 IP 首部”理解为没有 ESP 开销。

ESP 通常不保护外层可变路由首部的全部字段；路由器仍需读取交付信息。AH 与 NAT 的兼容问题也与它覆盖的首部字段有关，不应认为所有 IPsec 协议都能无差别穿过地址改写。

## 3. 隧道模式把原 IP 包放在哪里

```text
原始包：内网 A 的 IP → 内网 B 的 IP → 业务数据

隧道包：网关 A 的外层 IP → 网关 B 的外层 IP
        └─ ESP：保护原始内层 IP 包
```

在典型站点到站点场景中，外部网络根据网关地址转发；接收网关完成验证和解密，再对内层包进行策略检查与路由。

IPsec 只保护选定边界之间的部分。如果业务在两侧内网仍是明文，网关到应用之间不会因隧道存在而自动获得端到端保护。TLS 与网络层 VPN 可以叠加，负责不同边界。

## 4. SA 为什么有方向

SA 是 Security Association，安全关联，保存处理某一方向受保护流量的算法、密钥、序列号和期限等参数。

一个常见双向通道需要对应的单向 IPsec SA：

```text
A → B：使用 B 能识别的入站 SPI 与相应密钥状态
B → A：使用 A 能识别的另一组 SPI 与密钥状态
```

SPI（Security Parameters Index）帮助接收方定位安全关联，不能单独当成全网唯一的“隧道编号”。查找还涉及协议、目的或本地处理上下文。

两边显示不同入站 SPI 可能完全正常；但某一方向找不到匹配 SA，就可能出现单向计数增长和业务失败。ESP 格式与处理规则见 [RFC 4303](https://www.rfc-editor.org/rfc/rfc4303.html)。

## 5. SPD 和 SAD 分别决定什么

| 对象 | 主要信息 | 回答的问题 |
| --- | --- | --- |
| SPD：安全策略库 | 选择条件与保护／绕过／丢弃动作 | 这个包应该怎样处理 |
| SAD：安全关联库 | 已建立的 SA、密钥与状态 | 用哪套具体参数处理 |

因此，“SA 已建立”不等于“当前业务包匹配这个 SA”。源地址、目的网段、协议、端口及实现中的其他标记，都会影响策略选择。

入站也不应只做“能解密就接受”。还需判断解出的内层流量是否符合该对端被允许承载的范围，避免把对端身份认证误当成对任何源地址的授权。

## 6. 防重放窗口如何允许正常乱序

接收方维护序列号与防重放窗口，拒绝已处理过或过旧的报文，同时允许窗口内尚未见过的乱序包。它不是简单要求所有包严格递增到达。

网络多路径、突发排队与并行加解密都可能造成乱序。超过当前窗口允许范围的延迟包，可能被丢弃；重复包也不能因为重新经过一条路径就被当成新的合法业务。

防重放与可靠交付不同：ESP 不负责替业务重传丢失包。窗口状态和序列号空间也参与密钥生命周期管理，不能把旧 SA 的序列号无约束重置后继续复用同一安全上下文。

## 7. 加密成功后仍有哪些信息可见

外层端点、包长、方向、发送节奏等通常仍可被承载网络观察。IPsec 不保证流量形态匿名，也不替应用隐藏所有侧信道。

解密端需要继续执行内部访问控制。一个合法 VPN 用户不应因为能建立隧道，就天然获得全部管理网和数据库权限。

实现层可把控制面与内核数据处理分开，参见 [strongSwan 的 IPsec 概述](https://docs.strongswan.org/docs/latest/howtos/ipsecProtocol.html)。协议协商进程存活与内核 SA 正常转发，不是同一个状态。

## 8. 思考与解答

**SPI 相同就证明是同一条 VPN 吗？**

不能。SPI 要在对应目的、协议和处理上下文中解释，不是全局业务名称。

**IPsec 隧道能替代数据库账户权限吗？**

不能。它保护特定网络边界，数据库仍需验证用户身份和操作权限。

**报文乱序就一定被防重放机制丢掉吗？**

不是。窗口内尚未接收过的乱序包可以被接受；过旧或重复报文的处理才涉及丢弃。
