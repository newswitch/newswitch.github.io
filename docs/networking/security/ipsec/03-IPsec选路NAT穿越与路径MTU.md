# IPsec 选路、NAT 穿越与路径 MTU

“VPN 已连接，内网仍不通”通常意味着某个控制状态成功，却没有完成端到端的数据路径。分析时应明确此刻看到的是明文内层包，还是加密后的外层包。

## 1. 一个包经过哪些决定

```text
内网业务包
  → 选路与保护策略判定
  → 匹配数据 SA，封装并加密
  → 外层包按承载网络路由发送
  → 远端定位 SA、验证与解密
  → 检查内层策略
  → 路由和访问控制送到内部服务
```

回复也需要走通相应逆向关系，不是请求到达就自动有返回路由。

## 2. 策略型和路由型 VPN 有什么差别

策略型主要通过地址、协议等选择条件，把匹配流量关联到 IPsec 保护。路由型则把虚拟接口、路由选择等对象引入数据路径，便于用常见路由机制组织隧道流量。

但路由型不表示没有安全策略，也不表示“只要包进入接口就一定有可用 SA”。例如 Linux XFRM 接口仍依赖对应接口标识、策略与关联状态，见 [strongSwan Route-based VPN](https://docs.strongswan.org/docs/latest/features/routeBasedVpn.html)。

还应分清内层和外层路由：如果把对端 VPN 公网地址错误指向它自身承载的隧道，就可能形成递归路径问题。

## 3. NAT-T 为什么把 ESP 放进 UDP

传统 ESP 没有 TCP/UDP 端口，路径上的 NAT 与安全设备可能无法按预期维护和区分映射。NAT-T 通过 UDP 封装改善这种穿越能力。

常见交互中 IKE 从 UDP 500 开始，检测 NAT 等条件后使用 UDP 4500；采用相应封装时，业务 ESP 也可在 UDP 4500 上传送。规范见 [RFC 3948](https://www.rfc-editor.org/rfc/rfc3948.html)。

```text
外层 IP | UDP | ESP | 受保护内层包
```

UDP 4500 上的 IKE 与 ESP 有不同的区分机制，不能看到端口相同就把它们当成相同消息。没有 UDP 封装的 ESP 则仍是 IP 协议号 50，而不是“50 端口”。

NAT-T 解决的是封装与映射适配，不保证防火墙已放行，也不保证内部地址重叠得到解决。

## 4. 为什么一般上网 NAT 可能影响 VPN 选流

假设策略原本保护 `10.10.0.0/16` 到 `10.20.0.0/16`，但某个处理阶段先把源地址改成公网地址，之后它可能不再匹配预期保护范围。

这需要结合实际设备的 Hook、路由和策略顺序判断，不能把某个系统的 NAT 豁免写法当成所有设备都相同的规则。重点是逐段说明：哪个阶段看见什么地址，哪个策略用什么字段匹配。

当两侧内网使用同一前缀时，还会遇到目的归属和路由歧义。即使为重叠场景引入地址转换，也要同时明确对外呈现地址、选择范围和返回关系。

## 5. VPN 开销怎样吃掉有效 MTU

外层 IP、可选 UDP、ESP 首部、算法相关字段、填充和校验标签都会占用空间，不能使用一个适用于所有隧道的固定开销。

假设某条路径 PMTU 为 1500，某类报文的实际总封装开销为 80 字节，那么这个算例中内层包预算是 1420 字节。换算法、地址族或填充方式后，预算可能变化。这只是算术说明，不是配置推荐。

因此，小控制包能建立 IKE，不能证明大业务包能通过。还要区分：

| 机制 | 处理对象 |
| --- | --- |
| IKE 分片 | 某些较大的 IKE 控制消息，例如证书相关交换 |
| IP 分片／重组 | 对应 IP 层的报文尺寸处理 |
| TCP MSS | TCP 数据载荷协商范围 |
| PMTU 发现 | 路径实际能够承载的 IP 包尺寸 |

IKE 分片并非所有初始消息都可任意使用，也不负责自动修复 ESP 数据大包问题，见 [RFC 7383](https://www.rfc-editor.org/rfc/rfc7383.html)。

## 6. 单向计数增长能说明什么

| 观察 | 可提出的假设 | 仍不能证明 |
| --- | --- | --- |
| 仅本端出站加密增长 | 本端选流与发送正在发生 | 对端已收到并解密 |
| 对端入站解密增长 | 外层传输与相应 SA 处理成立 | 内部服务已收到 |
| 对端服务收到请求但无响应返回 | 内层返回路径或权限可能异常 | 一定是加密算法不匹配 |

应把封装前后地址、双向 SA、内层访问控制和返回路径连起来解释，而不是只看一个总流量数字。

## 7. 多出口切换为什么还涉及身份与状态

外层出口变化可能影响 NAT 映射、对端地址认知、路由、SA 关联和防重放状态。地址相同也不意味着另一个设备已经具有原来的密钥和序列信息。

一些协议扩展和产品支持移动、多出口或状态同步，但必须在双方能力与策略范围内使用。网关 VRRP 接管也不能单独复制 IPsec 关联，相关边界可参照 [VRRP 会话连续性](../../routing-switching/vrrp/02-VRRP收敛双主与会话连续性.md)。

## 8. 思考与解答

**IKE 正常，能否证明 ESP 或 UDP 封装数据都被放行？**

不能。控制与业务数据的协议、尺寸和处理路径可能不同。

**修改 TCP MSS，可以解决全部 VPN 大包问题吗？**

不能。它主要影响相应 TCP 数据，不覆盖所有 UDP、IKE 控制消息及不同封装路径。

**路由型 VPN 就没有 Traffic Selector 约束吗？**

不是。路由组织与安全策略仍需配合，具体实现可能用较宽选择器再结合接口标识和策略限定。
