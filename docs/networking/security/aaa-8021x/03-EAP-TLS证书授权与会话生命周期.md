# EAP-TLS、证书授权与会话生命周期

证书认证的核心不是“客户端拿出一个证书文件”。公开证书可以被复制，真正的身份证明还涉及对应私钥的持有、信任链校验，以及证书身份能获得什么权限。

## 1. 谁验证谁

常见 EAP-TLS 场景中：

```text
终端验证认证服务器：信任链、预期服务身份、有效期等
认证服务器验证终端：客户端证书、私钥证明、用途与策略
验证成功后：把证书身份映射到授权主体和角色
```

在后端终止 EAP 的常见架构中，TLS 对端是终端与 EAP 服务器，AP／交换机主要搬运消息，并不意味着终端拿认证服务器证书来验证每一台 AP。

EAP-TLS 使用 TLS 1.3 的方法规范见 [RFC 9190](https://www.rfc-editor.org/rfc/rfc9190.html)。不能把某个旧系统只支持的 TLS 或证书参数当成协议永远不变的限制。

## 2. 有可信 CA，为什么仍需校验预期身份

CA 签发证书，表达的是证书中的主体和公钥绑定满足其签发规则。客户端还要确认这个主体是不是自己打算信任的认证服务。

如果只接受某个巨大信任集合中的任何证书，却不检查预期服务器身份，安全边界就比“只信任企业指定认证服务”更宽。类似地，证书用于服务器认证还是客户端认证、是否已经过期或撤销，也需要按用途验证。

私钥保护同样重要。证书有效期很长不能弥补私钥泄露；证书文件存在也不能证明终端可以完成私钥签名。

## 3. 证书身份不等于用户最终权限

假设证书表示一台受管电脑，而登录使用它的人可能属于不同部门。服务器可以把证书映射到设备记录，再结合用户、设备状态或策略决定角色。

需要区分：

| 信息 | 用途 |
| --- | --- |
| 外层 EAP Identity | 可能用于路由或选择认证域，不应直接当成最终强身份 |
| 已验证证书身份 | 提供经方法认证的主体依据 |
| 目录或设备记录 | 补充主体归属、启停与管理属性 |
| 授权策略 | 决定角色、VLAN、过滤和会话限制 |

证明“是谁”与决定“允许什么”必须连接起来，但不能合并成一个不可检查的黑盒。

## 4. EAP 导出的密钥和证书私钥不是同一个东西

成功方法可导出供后续接入保护使用的密钥材料。它不是把客户端证书私钥发给 AP，也不是让所有会话直接共用证书里的公开密钥做链路加密。

无线网络还需完成相应链路握手、派生和安装会话密钥。密钥缓存或会话恢复可以减少重复认证成本，但也需要限制生命周期和适用范围。

这解释了为何认证成功、无线握手完成和业务放行是相邻但不同的状态。

## 5. 授权属性必须落到设备能力上

服务器发回一个 VLAN 或角色，接入设备还需要能应用它。如果 VLAN 不存在、上联未承载，或下发过滤规则无法安装，就可能出现身份验证成功但业务不可用。

动态改变 VLAN 还会影响地址上下文：终端之前持有的 IP、默认网关和 DHCP 租约未必适合新网络。不能以为改了授权属性，原有连接一定能不间断继续。

完整关系是：

```text
方法验证 → 生成策略 → 设备接受策略 → 数据面执行 → 网络配置适配 → 业务通信
```

## 6. 已经在线，为什么还会重新认证

会话可以因超时、链路变化、漫游、策略更新或管理员动作重新评估。服务器和设备需要用会话标识关联当前主体，而不能只凭可能已变化的 IP。

RADIUS CoA（Change of Authorization，授权变更）允许后端请求修改已有会话，Disconnect 用于请求终止会话，见 [RFC 5176](https://www.rfc-editor.org/rfc/rfc5176.html)。

请求发出不等于设备已经执行。设备可能确认、拒绝或不支持某属性，也可能找不到匹配会话。CoA 交互本身同样需要可信来源与消息保护，不能让设备无条件接受任意来源的授权变更。

## 7. 证书、时间和离线依赖

证书有效期依赖可信时间，撤销检查依赖证书策略与相应状态来源。证书链不完整、时钟偏差、私钥不可用与用户被禁用，都是不同的失败原因。

初次接入时，还要考虑终端是否能在未授权网络中获得认证所需的最小依赖。不能无条件假设“先联网下载所有依赖，再通过唯一的联网认证”不会产生启动依赖循环。

认证服务器不可达时，是保留已授权会话、给受限角色，还是拒绝新接入，需要事先定义。不可达不等于证书验证失败；服务器恢复后如何退出降级状态，也是会话机制的一部分。

## 8. 思考与解答

**复制一份公开客户端证书就能完成 EAP-TLS 吗？**

不能。正常认证还需要证明持有对应私钥，并满足服务端的信任与授权规则。

**CoA 已经发出，就能证明用户权限改好了么？**

不能。还要区分设备确认、策略安装、会话匹配和实际数据面执行。

**证书合法，但设备被资产系统停用，是否仍应自动允许接入？**

不应只凭证书签名决定。证书证明身份，是否继续授权还取决于有效的主体状态和访问策略。
