# TLS 解决什么问题与安全边界

学习 TLS 的第一步不是背握手报文，而是明确攻击者在哪里、可以做什么，以及 TLS 将保护边界画在哪里。

## 1. 没有 TLS 时会发生什么

客户端通过明文 HTTP 发送：

```http
POST /login HTTP/1.1
Host: shop.example.com

username=alice&password=secret
```

能观察链路的中间节点可能：

- 读取账号、Cookie、Token 和响应内容；
- 把下载文件、JavaScript 或 API 返回值替换掉；
- 冒充服务器响应请求；
- 记录业务元数据并关联用户行为。

仅给报文做哈希不能防篡改，因为攻击者可以修改报文后重新计算哈希；仅加密而不认证对端，也可能与攻击者建立一条“加密得很好”的连接。

## 2. TLS 的三个核心目标

### 2.1 机密性

握手完成后，应用数据由双方派生出的对称密钥加密。旁路观察者通常仍能看到 IP、端口、包长、方向和时间，但不能直接恢复明文。

### 2.2 完整性

现代 TLS 使用 AEAD 同时完成加密与认证。报文被修改、截断或用错误密钥解密时，认证标签验证失败，接收端丢弃记录并终止连接。

### 2.3 身份认证

普通 HTTPS 主要认证服务端：

```text
域名
  → 出现在证书 SAN 中
  → 证书由受信任 CA 链签发
  → 服务端使用私钥生成 CertificateVerify 签名
  → 客户端验证签名，确认对端持有私钥
```

mTLS 还要求客户端提供证书并证明持有客户端私钥。

## 3. TLS、HTTPS、mTLS 与 PKI

| 名称 | 含义 | 关系 |
| --- | --- | --- |
| TLS | 通用安全传输协议 | 可保护 HTTP、SMTP、数据库等上层协议 |
| HTTPS | HTTP over TLS | HTTP 语义不变，外面增加 TLS 保护 |
| mTLS | 双向身份认证的 TLS | 服务端也验证客户端证书 |
| PKI | 公钥身份与信任管理体系 | 为 TLS 提供证书、CA、信任链和生命周期 |
| SSL | TLS 的历史前身 | 不应把旧 SSL 协议作为生产选项 |

“SSL 证书”是行业习惯说法，现代系统实际使用的是 X.509 证书与 TLS 协议。

## 4. TLS 保护到哪里

考虑 TLS 在 Nginx 终止：

```text
浏览器 ==TLS==> Nginx ----HTTP----> 应用
          已保护             未被 TLS 保护
```

TLS 只保护两个 TLS 端点之间的路径。Nginx 解密后，明文可能进入日志、内存、APM、代理缓存和后端链路。因此必须先画出所有终止点，不能笼统声称“系统已经端到端加密”。

## 5. TLS 不能解决什么

### 5.1 端点失陷

浏览器、网关或应用进程已经被控制时，攻击者可以在加密前或解密后读取明文。

### 5.2 应用授权

客户端证书可信不等于允许读取所有数据。TLS 给出传输身份，RBAC、ABAC 或业务逻辑仍需决定它能做什么。

### 5.3 可用性

攻击者仍可丢包、限速、耗尽握手 CPU、填满连接表或攻击 DNS。TLS 不是 DDoS 防护协议。

### 5.4 全部元数据隐私

传统 ClientHello 中的 SNI 可能可见；目标 IP、流量大小和时间仍可见。ECH 可以保护 ClientHello 中的更多信息，但依赖客户端、DNS 和服务端共同支持，不能假定所有环境都已启用。

### 5.5 错误信任配置

若客户端跳过证书验证、信任错误 CA 或不校验主机名，加密连接仍可能被中间人接管。`curl -k` 只能用于受控诊断，不能作为生产修复。

## 6. 前向保密

TLS 1.3 正常握手使用临时 (EC)DHE 密钥协商。会话流量密钥来自临时共享秘密，而不是直接来自证书私钥。因此未来服务器证书私钥泄露时，攻击者通常不能仅凭先前抓到的密文解密历史会话。

前向保密并不保护：

- 会话建立时端点已被控制；
- 应用主动记录明文或会话密钥；
- PSK、Ticket Key 或随机数生成器被破坏；
- 使用不具备该性质的旧式密钥交换。

## 7. 建立威胁模型

每次设计 TLS 时回答：

1. 谁是客户端和服务端？
2. 哪些链路不可信？
3. 谁签发证书，谁持有信任锚？
4. 认证域名、工作负载还是人员？
5. TLS 在哪一层终止，之后是否重新加密？
6. 私钥如何生成、分发、轮换、撤销和销毁？
7. 失败时选择拒绝连接还是降级明文？

安全系统通常应失败关闭，不能在证书错误时自动回落到明文。

## 8. 练习与答案

**问题 1：** HTTPS 能否阻止服务端把密码写进日志？

不能。TLS 只保护传输端点之间的链路，服务端解密后的处理不在其保护范围内。

**问题 2：** 能 ping 通且 TCP 443 建连成功，为什么 HTTPS 仍可能失败？

TCP 成功只证明网络和监听基本可达。TLS 还可能因版本、算法、SNI、证书链、主机名、时间或 mTLS 身份失败。

**问题 3：** 客户端信任自签名证书后是否安全？

只有在信任锚通过可信渠道分发、私钥受保护、名称和用途正确校验时才建立了相应信任。随意导入来源不明的自签名根证书会扩大攻击面。
