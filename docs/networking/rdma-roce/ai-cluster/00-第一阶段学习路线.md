# 第一阶段：通信与 RDMA 基础

本阶段先回答“谁在通信、传什么、为什么同步”，再学习 RDMA 对象与两种 Fabric。
如果一开始只记网卡命令，就无法判断性能问题究竟来自模型并行、GPU 拓扑还是网络。

## 2. 分层基线 {/* #分层基线 */}

```text
L0 服务器硬件：PCIe Link、NUMA、GPU/NIC 拓扑
L1 RDMA 设备：驱动、固件、Port、GID/LID、MR/QP
L2 Fabric：链路、路由、MTU、错误、拥塞
L3 GPU Memory RDMA：GDRDMA 能力和数据路径
L4 NCCL：Collective、Channel、Transport、algbw/busbw
L5 训练：通信占比、Step Time、GPU 等待
```

上层失败时先证明下层。CPU Memory RDMA 不稳定时，不应该直接调 NCCL 环境变量。

## 3. 阶段验收 {/* #阶段验收 */}

- 能根据并行策略画出主要 Collective。
- 能解释 Send/Receive、Read、Write 的控制权差异。
- 能区分 IB 的 LID/SM 与 RoCEv2 的 IP/GID/UDP。
- 能从拓扑证明 GPU 和 NIC 是否就近。
- 能设计一份可重复的 perftest 与 nccl-tests 测试矩阵。
- 能让一次 Socket、普通 RDMA、GDR 三路径对比具有完整证据。
- 能区分 NCCL Collective、NVSHMEM One-Sided、UCX Transport、UCC Collective 与 SHARP 卸载。
- 能指出一次 Put 的源复用、目标交付和消费完成分别依赖什么；能画出跨 PE 与 Stream 的等待关系。
- 能分别证明程序的构建、启动、动态装载与实际传输身份；能解释标签匹配顺序、unexpected 状态及硬件卸载的适用范围。
