# Envoy 服务发现、健康检查、负载均衡、异常检测、断路器与重试

这些功能都影响上游选择，却解决不同问题：发现“有哪些 Host”，健康检查判断“现在能否使用”，负载均衡决定“选谁”，断路器限制“最多占用多少资源”，重试决定“失败后是否再试”。

## 1. Endpoint 来源

| 模式 | 特点 | 风险 |
| --- | --- | --- |
| STATIC | 地址随配置固定 | 变更需发布 |
| STRICT_DNS | 周期解析并使用全部结果 | TTL、DNS 抖动和大规模查询 |
| LOGICAL_DNS | 逻辑目的地/连接时解析语义 | 不适合所有多地址均衡场景 |
| EDS | 控制面下发 Host、权重、Locality、健康元数据 | xDS 陈旧、推送风暴、授权错误 |

服务发现只提供候选 Endpoint。端口、协议、TLS SNI 和应用健康仍需独立验证。

## 2. 主动与被动健康

主动健康检查周期发探针，适合发现已失效实例，但探针端点可能与真实请求不等价。Outlier Detection 根据实际请求连续错误、成功率等被动逐出异常 Host；它是本地数据面判断，不等于全局服务注册中心摘除。

健康阈值、逐出比例和恢复要防止抖动。大量上游共同失败时，过于激进的逐出会把剩余 Host 压垮。

## 3. 负载均衡

Round Robin、Least Request、Random、Ring Hash/Maglev 等适用于不同连接与一致性需求。HTTP/2/gRPC 一条连接可承载多个 Stream，“最少连接”不等于最少在途请求。哈希粘性提高缓存命中，但不能代替会话状态复制，并要评估扩缩容时重映射。

Locality/优先级路由能优先同区流量和跨区故障切换。必须验证单区容量是否承受故障转移，以及健康百分比触发条件。

## 4. 断路器与过载

Envoy Circuit Breaker 主要限制某 Cluster 的连接、待处理请求、请求和重试等上游资源；它不是业务状态机。Envoy Overload Manager 主要保护代理自身的内存、CPU、文件描述符等。两者不要混用。

## 5. 重试预算

安全重试同时满足：错误可恢复、请求幂等、请求体可重放、总超时允许、还有不同健康 Host。配置总超时、per-try timeout、尝试次数/重试优先级和预算，并对 5xx、reset、connect failure 分别选择。

```text
effective upstream attempts = original requests + retries + hedges
```

上游过载时无限重试会形成正反馈。对写请求使用幂等键/业务去重，默认不把所有 5xx 都重试。

## 6. 故障矩阵

| 现象 | 优先检查 |
| --- | --- |
| UH/无健康上游 | EDS/DNS、健康状态、优先级和逐出 |
| 端点正常但流量不均 | 协议连接复用、权重、Locality、哈希键 |
| 少量故障演变为雪崩 | 重试预算、逐出比例、故障转移容量 |
| pending overflow | 连接池/断路器阈值或上游建连变慢 |
| DNS 更新后仍访问旧地址 | 解析模式、刷新、现有长连接和 TTL |

## 7. 验收实验

对三个 Endpoint 注入慢、reset、5xx 和网络不可达，分别观察主动健康、Outlier、LB、重试和 Circuit Breaker。记录首次错误、额外尝试、尾延迟、上游请求总量与恢复时间，证明保护没有把故障放大。
