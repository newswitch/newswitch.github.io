# 第三阶段：网络自动化与智能管控学习路线

## 1. 阶段目标 {/* #阶段目标 */}

自动化不是“把手工 CLI 放进循环”。生产级网络自动化应形成闭环：

```mermaid
flowchart LR
    A["Source of Truth"] --> B["生成候选配置"]
    B --> C["静态与拓扑验证"]
    C --> D["审批和分批发布"]
    D --> E["实时状态验证"]
    E --> F["Telemetry / SLO"]
    F --> G{"符合意图？"}
    G -- "是" --> H["记录证据并结束"]
    G -- "否" --> I["停止、回滚、复盘"]
```

## 3. 阶段验收 {/* #阶段验收 */}

理论阅读可依次跟踪：执行器如何区分“失败”和“结果未知”；Nornir 如何组织主机、子任务与异常；Ansible 如何限定资源覆盖范围；NETCONF/gNMI 的事务和订阅边界；NetBox 如何表达地址与拓扑；静态模型如何验证可达与隔离；遥测如何报告计数连续性和采集缺口。

这些机制分别回答状态归谁管理、何时可以修改、修改后能证明什么。示例命令和项目用于帮助识别对象，不能替代对实际平台版本、模型支持和失败语义的判断。

- 自动化任务具有超时、重试边界、并发限制、审计和凭据隔离。
- 能区分意图状态、候选状态、运行配置和实时运行状态。
- 能在变更前验证语法、策略、邻居、可达性和故障域。
- 能分批发布，并用停止条件而不是“全部执行完成”判断成功。
- 失败时能根据快照和变更记录完成自动或人工回滚。
