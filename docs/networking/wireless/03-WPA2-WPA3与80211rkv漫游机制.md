# WPA2/WPA3 与 802.11r/k/v 漫游机制

从一个会议室走到另一个会议室，无线图标一直亮着，语音却停顿了。原因可能在寻找 AP、密钥切换、数据路径迁移或 IP 连续性，不能只用“是否支持无缝漫游”概括。

## 1. 关联、身份认证、密钥和授权是四件事

Association（关联）让终端与具体 BSS 建立接入关系；身份认证验证凭据；密钥过程准备链路保护；授权决定可访问的网络资源。

802.11 中名为 Authentication 的管理交互，也不总等于企业用户身份验证。传统 Open System Authentication 不会完成后端 EAP-TLS 证书认证，不能仅凭其名称判断用户已被安全验证。

不同安全模式的交互顺序不同。例如常见 WPA2-Enterprise 初次接入会在关联后进行 EAP；WPA3-Personal 的 SAE 认证属于另一条路径，不应机械套用同一时序。

## 2. Personal 与 Enterprise 的区别

| 模式 | 建立信任与密钥基础的方式 | 主要管理边界 |
| --- | --- | --- |
| WPA2-Personal | 基于预共享密钥；口令可按规定派生密钥 | 共享口令本身不提供逐用户身份管理 |
| WPA3-Personal | 使用 SAE 进行基于口令的认证与密钥建立 | 不需要因此额外部署企业 RADIUS |
| WPA2／WPA3-Enterprise | 通过 802.1X 和具体 EAP 方法认证 | 可以结合用户／设备证书与独立授权 |

SAE（Simultaneous Authentication of Equals）不是把 WPA2 的共享密钥报文换个名字，也不是通过空口传输明文密码。实现中的 WPA3-SAE 能力及 PMF 关系可参考 [Microsoft WPA3 支持说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/netcx/wificx-wpa3-softap)。

WPA3-Enterprise 也不等于所有连接都使用 192-bit 安全模式；需要区分认证方案、具体安全套件与设备能力。不同安全模式的支持边界见 [Apple 无线网络安全说明](https://support.apple.com/en-ie/guide/security/sec8a67fa93d/web)。

“支持 WPA3”是能力描述，不是某个会话实际协商成功的证据。兼容过渡模式可能接纳采用不同安全方式的终端，不能把整个 SSID 下的会话都标为相同保护级别。

## 3. PMK、PTK 与 GTK 各自负责什么

PMK（Pairwise Master Key，成对主密钥）是后续链路密钥派生的基础之一；它可以来自不同认证模式的密钥建立过程。

在典型初次接入的四次握手中，双方利用共同的密钥基础、随机数及相关地址信息派生 PTK（Pairwise Transient Key，成对临时密钥），确认密钥持有关系，并协调密钥安装。GTK（Group Temporal Key，组临时密钥）用于相应广播／组播数据保护，按协议受保护地分发。

```text
具体认证／密钥建立方法
    ↓ 提供 PMK 等基础
四次握手：派生、确认并安装会话密钥
    ↓
单播数据使用相应 PTK 保护，组数据使用相应 GTK 保护
```

这个模型解释了两个重要边界：

- 四次握手不是把共享口令直接传给 AP，也不是每次都重新完成完整的后端 EAP 认证。
- 后端认证成功不保证后续密钥交换、安装和业务放行都已成功。

四次握手中的随机数、密钥派生与组密钥分发关系见 [Cisco 802.11 安全基础](https://www.cisco.com/en/US/docs/wireless/wlan_adapter/secure_client/5.1.0/administration/guide/C1_Network_Security.html)。这里引用其密钥机制，不沿用旧文档中的算法选型建议。

在典型初次 RSN 接入中，四次握手可进一步按职责理解：

| 消息 | 核心作用 |
| --- | --- |
| 1：AP → 终端 | 提供 AP 侧随机数 ANonce，终端结合自己的 SNonce 等信息派生 PTK |
| 2：终端 → AP | 提供 SNonce 及完整性校验信息，使 AP 能派生 PTK 并验证对方持有相应密钥基础 |
| 3：AP → 终端 | 提供受完整性保护的确认与密钥安装相关信息，通常包含受保护的 GTK 等密钥数据 |
| 4：终端 → AP | 确认前述交互，配合完成接入状态转换 |

这张表解释消息职责，不表示每次空口抓包恰好只有四个包：重传和其他接入交互会增加数量，FT 等机制也有不同消息安排。

Fast Transition 等路径会使用相应的密钥层次与专门交互，不能要求所有漫游都重放完整的初次接入流程。企业侧证书与授权关系见 [EAP-TLS 与会话生命周期](../security/aaa-8021x/03-EAP-TLS证书授权与会话生命周期.md)。

## 4. PMF 保护什么，不保护什么

PMF（Protected Management Frames，受保护管理帧）为相应的 Robust Management Frames 提供保护，例如在已建立保护关系后处理的解除认证、解除关联及部分 Action 帧。

它不是给所有无线管理消息无差别加密，也不能阻止物理射频干扰。保护范围和建立条件可参考 [Cisco 802.11w 说明](https://www.cisco.com/c/en/us/td/docs/wireless/controller/technotes/5700/software/release/ios_xe_33/11rkw_DeploymentGuide/b_802point11rkw_deployment_guide_cisco_ios_xe_release33/b_802point11rkw_deployment_guide_cisco_ios_xe_release33_chapter_0100.html)。

管理帧保护、业务链路加密和应用 TLS 的保护对象不同。即使无线安全协商完整，应用端点身份和数据授权仍需由对应层处理。

## 5. 802.11k、802.11v 与 802.11r 的分工

| 技术 | 在漫游中主要提供什么 | 不负责保证什么 |
| --- | --- | --- |
| 802.11k | 无线测量与邻居信息，帮助缩小候选搜索范围 | 不自动替终端完成切换，也不建立业务路由 |
| 802.11v | 包括 BSS Transition Management 在内的网络辅助能力，可提供候选建议 | 建议不等于所有终端必然立即照做 |
| 802.11r | Fast BSS Transition，利用密钥层次与快速交互减少切换时认证开销 | 不修复覆盖、拥塞或跨网段 IP 连续性 |

三个后缀对应不同能力，不能理解为同一功能的三个版本。协议分工及具体平台行为见 [Cisco 802.11r/k/v 说明](https://www.cisco.com/c/en/us/support/docs/wireless/catalyst-9800-series-wireless-controllers/221671-understand-802-11r-11k-11v-fast-roams-on.html)。

网络可以引导候选选择，也可以按策略拒绝接入或结束旧关联；但目标 AP 的选择和实际切换还取决于终端实现。不能声称控制器总能无条件把终端平滑地“搬过去”。

## 6. 802.11r 如何减少重复工作

首次认证建立密钥基础后，FT 使用 PMK-R0、PMK-R1 等层次，使受信任移动域内的目标接入点能够建立相应的链路密钥，而不是每次都重新向后端执行完整身份认证。

这仍是受认证与授权边界约束的密钥派生和确认，不是“关闭安全检查”。域的信任关系、密钥持有者、终端支持及有效状态必须匹配。

FT 可以通过目标 AP 的空口进行相关交互，也可以在支持的情况下经当前 AP 和分布式系统与目标侧交互，即常说的 Over-the-Air 与 Over-the-DS。不能一概说所有 FT 握手都在离开旧 AP 前完成。

密钥层次与两种交互路径见 [Cisco Fast Transition 机制说明](https://www.cisco.com/c/en/us/td/docs/wireless/controller/technotes/80211r-ft/b-80211r-dg.html)。

终端实现还可能支持 PMK 缓存等其他加速方式，因此“关闭 802.11r”也不等于每次漫游必然完全重新认证。兼容能力与候选选择的具体例子见 [Apple Wi-Fi 漫游说明](https://support.apple.com/guide/deployment/wi-fi-roaming-support-dep98f116c0f/web)。

## 7. 一次移动过程中，业务在等哪些状态

```text
寻找候选 AP
 → 完成目标侧所需的认证／密钥与重关联交互
 → 新接入点的数据路径、策略及必要会话状态就绪
 → 保持或重新获得可用 IP 连通性
 → 应用恢复连续传输
```

这些步骤可能有重叠或预先准备，不能将日志中的每段时间机械相加。但可以用它们解释为何关联已经成功，业务仍然短暂中断：

- 交换网络或集中数据面还没更新终端交付位置。
- 目标侧策略、密钥或用户 VLAN 尚未就绪。
- 新接入点属于不同地址域，原 IP 不再能正常使用。
- 底层已经恢复，但传输层仍等待重传计时器或应用重建会话。

802.11r 主要缩短其中的认证／密钥相关环节，而不是一次解决整条路径。

## 8. 相同 SSID 为什么不保证 TCP 连接不断

如果终端移动后仍处于相同可达子网，地址和网关保持有效，且转发位置及时更新，已有连接有机会继续工作。

若从一个子网进入另一个子网，则需要明确的三层移动性机制，例如由基础设施保留原有地址和锚定路径；否则可能需要重新获得地址。地址变化通常会破坏原 TCP 五元组的连续性，应用或其他传输协议是否能迁移连接则另有机制。

因此，“同名 SSID + 开启 802.11r”不等于跨园区、跨子网后所有业务无中断。

## 9. 为什么终端不总选择信号最强的 AP

终端会结合自己的漫游阈值、滞回、扫描成本、频段、负载和功耗策略做决定。过于积极的切换可能造成来回振荡，过于保守则可能形成 Sticky Client（黏滞终端）。

AP 看到的上行信号与终端看到的下行信号也不同。若提高 AP 功率，却没有改善终端上行，可能让终端继续留在一个实际双向质量不佳的接入点。

不应把某厂商或某终端的单一 RSSI 阈值当作所有设备共同遵循的协议要求。

## 10. 思考与解答

**开启 802.11r 后，终端是否无需认证即可进入任意 AP？**

不是。FT 在匹配的移动域、密钥基础与安全关系下减少重复认证开销，仍需相应的密钥派生和验证；它不是开放接入。

**开启 802.11k/v 后，为什么终端没有立刻连接信号最强的 AP？**

这些能力提供测量、候选与引导，终端还会结合自身策略和当前状态决策，且信号最强不一定意味着端到端质量最好。

**日志显示重关联只花了很短时间，为什么语音仍停顿？**

重关联只是链路切换的一部分。数据交付位置、密钥、策略、IP 可达性以及应用恢复还可能占用时间，需按完整状态链解释。
