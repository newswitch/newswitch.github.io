# IPv6 与双栈网络学习路线

IPv6 不只是把 IPv4 地址写长。地址如何获得、下一跳如何找到、路由器怎样报告大包无法转发，以及客户端怎样选择 IPv4 或 IPv6，都有需要单独理解的机制。

本系列以以太网中的普通主机与路由器为主要背景，先解释协议和状态之间的关系。示例地址使用文档专用前缀，不代表可直接用于公网的配置。

## 2. 把一台主机接入网络的过程串起来

```text
接口启用
  → 建立链路本地地址并进行重复地址检测
  → 接收 RA，学习默认路由和前缀等信息
  → 根据网络策略和客户端能力使用 SLAAC、DHCPv6 或静态配置
  → 获得 DNS 等名称解析配置
  → 应用取得目标地址并选择地址族与源地址
  → 查路由，解析下一跳链路层地址
  → 发送数据，根据 ICMPv6 等反馈调整传输
```

这不是所有操作系统都严格串行执行的启动脚本。地址配置、邻居发现、DNS 查询可能交错进行；理解重点是每一步依赖哪种状态。

## 3. 与其他模块的联系

- 还不熟悉前缀匹配和网关，先读 [IPv4 与路由表](../03-IPv4子网划分与路由表.md)。IPv6 继续使用这些基本转发思想。
- IPv4 的租约、中继和地址池问题见 [DHCP](../../services/dhcp/00-DHCP学习路线.md)，不要把 DHCPv4 的默认网关选项套到 DHCPv6。
- A、AAAA、缓存与名称解析的关系见 [DNS](../../services/dns/00-DNS学习路线.md)。
- Kubernetes、云网络中的双栈还受平台地址分配、Service、CNI 与安全策略约束，不能仅凭节点有 IPv6 地址就认定整条业务链路已具备双栈能力。
