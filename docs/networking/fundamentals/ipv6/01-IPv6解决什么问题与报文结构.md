# IPv6 解决什么问题与报文结构

假设一台笔记本访问另一座城市的服务器。无论使用 IPv4 还是 IPv6，应用都需要目标地址，主机都要选路，路由器都要把包送到下一跳。IPv6 改变的是部分寻址和协议机制，不是把整个互联网重新发明一次。

## 1. 地址空间变大，意味着什么

IPv4 地址有 32 位，IPv6 地址有 128 位。更大的空间使地址分配可以更多地围绕站点、子网和汇总边界组织，而不是到处依赖端口转换复用少数公网地址。

但要区分三个判断：

- **地址足够**：可以给大量接口分配不同地址。
- **路由可达**：网络中有把这些前缀送到正确位置的路由。
- **访问被允许**：安全策略允许特定主体访问特定服务。

第一项不能推出后两项。一个服务器有全球单播地址，也可能没有上游路由，或者被防火墙拒绝访问。减少地址转换并不等于取消防火墙。

## 2. 一个 IPv6 包包含什么

以 TCP 为例：

```text
以太网帧
└─ IPv6 基本首部：40 字节
   ├─ 可选的扩展首部
   └─ TCP 首部
      └─ 应用数据
```

IPv6 的 40 字节是**基本首部**大小，不是“所有 IPv6 包只有 40 字节网络层开销”。扩展首部、隧道外层、链路层封装都可能继续占用空间。基本首部与扩展首部的定义见 [RFC 8200](https://www.rfc-editor.org/rfc/rfc8200.html)。

| 字段 | 大小 | 作用 |
| --- | --- | --- |
| Version（版本） | 4 位 | 表明这是 IPv6 |
| Traffic Class（流量类别） | 8 位 | 承载 DSCP/ECN 等服务分类和拥塞信息 |
| Flow Label（流标签） | 20 位 | 为同一流提供可用于识别、分流的标签，不是带宽保证 |
| Payload Length（载荷长度） | 16 位 | 普通报文中，统计基本首部之后的字节，包括扩展首部 |
| Next Header（下一首部） | 8 位 | 指出紧接着的首部类型 |
| Hop Limit（跳数限制） | 8 位 | 限制可经过的路由跳数，防止无限循环 |
| Source / Destination Address（源／目的地址） | 各 128 位 | 标识网络层通信端点 |

普通报文的载荷长度字段与特殊的超大载荷机制要分开理解；不能根据这个字段就推断网卡或路径支持多大的帧。

## 3. Next Header 为什么像一条链

IPv4 首部的 Protocol 通常直接说明上层是 TCP 还是 UDP。IPv6 还需要表达中间有没有扩展首部，因此 Next Header 可能先指向另一个网络层首部。

例如：

```text
IPv6：Next Header = Destination Options
  → Destination Options：Next Header = TCP
  → TCP
  → HTTP 数据
```

每一级说明“下一个是什么”，解析器才能继续定位真正的传输层首部。没有扩展首部时，基本首部可直接指向 TCP 或 UDP。

这也解释了为什么防火墙不能永远假设“从 IPv6 首部起偏移 40 字节就是 TCP 端口”：中间可能存在扩展首部。设备的解析能力、硬件快速路径和策略支持会影响实际行为。

扩展首部也不是要求所有路由器逐个深入处理全部内容。不同首部的处理对象不同；Hop-by-Hop Options 有特殊规则，而其处理要求也已被 [RFC 9673](https://www.rfc-editor.org/rfc/rfc9673.html) 更新。是否支持某种路径，仍需看具体设备和策略。

## 4. 包过一个路由器时，什么变，什么不变

设客户端发出的包要经过 R1 到达远端服务器。在没有 NAT、隧道和特殊扩展首部处理的普通转发中：

| 对象 | R1 转发时的行为 |
| --- | --- |
| IPv6 源地址 | 仍是客户端地址 |
| IPv6 目的地址 | 仍是服务器地址，不会改成下一跳地址 |
| Hop Limit | 减 1；耗尽时不能继续转发 |
| 二层源地址 | 换成 R1 出接口的链路层地址 |
| 二层目的地址 | 换成下一跳的链路层地址 |
| TCP 数据 | 不会因为普通路由转发而重建 TCP 连接 |

因此，“把包发给网关”通常表示二层先交给网关，并不表示把网络层目的地址改成网关。这个区别与 IPv4 相同。

## 5. 三个容易套错的 IPv4 经验

### 5.1 没有 IPv6 广播，不等于没有发现报文

IPv6 使用组播等机制完成邻居和路由器发现。以太网本身仍然是一套有广播能力的链路技术；只是 IPv6 地址体系不定义广播地址。两者不矛盾。

### 5.2 没有基本首部校验和，不等于完全不校验

IPv6 不再维护 IPv4 那种 IP 首部校验和，但以太网帧校验和 TCP/UDP 等上层校验仍有各自的职责。普通 IPv6 UDP 报文需要有效校验和；特定隧道存在严格限定的例外，不能推广为一般应用规则。

### 5.3 中间路由器不替发送方分片

IPv6 路由器发现包大于下一段链路可承载的大小时，通常丢弃该包并反馈 Packet Too Big。发送方根据路径信息调整报文；若需要 IPv6 分片，由源端完成。

所以“IPv6 头更规整”不能推出“IPv6 一定更快”。路径、对等互联、封装、安全设备、服务器容量，往往比地址族本身更影响体验。

## 6. 用一个长度计算检查理解

假设没有扩展首部，TCP 首部为 20 字节，应用放入 1000 字节数据：

```text
IPv6 Payload Length = 20 + 1000 = 1020 字节
IPv6 包总长         = 40 + 1020 = 1060 字节
```

以太网还要加自己的封装。若讨论的是三层 MTU，就比较 1060 与三层 MTU；若计算线上利用率，还要计入链路层和物理层开销。不同统计口径不能直接混用。

## 7. 思考与解答

**IPv6 地址多，所以主机可以绕过网关访问任何地址吗？**

不能。地址空间解决标识容量，路由解决跨链路交付。目的不在本链路时，仍需要可用下一跳和端到端返回路径。

**开启 IPv6 后，业务会自动加密吗？**

不会。IPv6 不是加密开关，仍需 TLS、IPsec 等具体安全机制和正确的密钥、身份校验。

**Hop Limit 减少后，路由器要重新计算 IPv6 首部校验和吗？**

不用，因为基本首部没有该字段。但转发时仍会重新形成出链路所需的帧，并按相应链路机制完成校验。
