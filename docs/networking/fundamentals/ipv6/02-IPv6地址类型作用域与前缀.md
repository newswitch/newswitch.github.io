# IPv6 地址类型、作用域与前缀

在一张网卡上看到一个 `fe80::` 地址、一个全局地址和几个临时地址，并不表示配置混乱。IPv6 的接口天然可以同时拥有多个地址，而这些地址可能承担不同职责。

## 1. 先学会读一个地址

IPv6 地址由 8 组、每组 16 位组成，通常用十六进制表示：

```text
完整写法：2001:0db8:0042:0010:0000:0000:0000:0021
压缩写法：2001:db8:42:10::21
带前缀：  2001:db8:42:10::21/64
```

每组可以省略前导零；连续的全零组可以用一次 `::` 代替。只能出现一次，否则无法判断两处各省略多少组。

`/64` 表示前 64 位是前缀，并不是地址还剩 64 位未写完。标准化文本时通常压缩最长的零段、使用小写等规则，详见 [RFC 5952](https://www.rfc-editor.org/rfc/rfc5952.html)。地址比较应基于二进制值，不能直接比较字符串。

## 2. 类型回答“送给谁”，作用域回答“在哪里有效”

| 类型 | 交付语义 | 典型用途 |
| --- | --- | --- |
| Unicast（单播） | 交给一个接口 | 普通客户端与服务器通信 |
| Multicast（组播） | 交给组内接收者 | 邻居发现、路由协议、特定分发业务 |
| Anycast（任播） | 交给具有该地址的某一个实例 | 多地点入口、公共解析等服务 |

任播从单播地址空间中分配，不能仅凭地址字符串判断。路由意义上的“近”也不一定是物理距离最短、负载最低或应用响应最快。地址类型的基本定义见 [RFC 4291](https://www.rfc-editor.org/rfc/rfc4291.html)。

常见地址范围再按用途区分：

| 地址 | 含义 | 能否直接当作公网业务地址 |
| --- | --- | --- |
| `::/128` | 未指定地址，如尚未配置完成时的特定源地址 | 不能 |
| `::1/128` | 本机回环 | 不能用于远程访问 |
| `fe80::/10` | 链路本地地址范围 | 不由路由器转发到其他链路 |
| `fc00::/7` | ULA，唯一本地地址范围；常见本地生成地址使用 `fd00::/8` | 可在组织内路由，不应当作互联网全局可达地址 |
| `2001:db8::/32` | 文档示例专用 | 不能用于实际公网分配 |
| `ff00::/8` | 组播地址范围 | 要按组播语义和作用域处理 |

互联网常见全球单播分配位于 `2000::/3`，但并非这个大范围中的每个地址都可随意使用。要区分地址类型、特殊用途登记和实际获得的前缀。

## 3. 为什么默认网关可以是 fe80 地址

网关只需要在当前链路上被主机找到。主机把目的为远端服务器的 IPv6 包封装进一帧，二层交给网关；网关随后根据**远端服务器地址**继续选路。

因此，网关自身的链路本地地址不需要在公网可达。

但链路本地地址离不开接口上下文。同一台主机的两个网段都可能存在 `fe80::1`，仅写地址不能唯一确定在哪条链路上找它。系统常用 `fe80::1%eth0` 这样的 zone 标识辅助指定范围；`%eth0` 不是 IPv6 地址的 128 位内容。

## 4. /48、/56、/64 应怎样理解

假设获得文档示例前缀 `2001:db8:42::/48`，按 `/64` 划分子网：

```text
前 48 位：站点前缀
后 16 位：可用于选择 /64 子网
后 64 位：接口标识部分

子网 A：2001:db8:42:10::/64
子网 B：2001:db8:42:20::/64
```

可以得到 `2^(64-48) = 65536` 个 `/64` 子网。若拿到的是 `/56`，则得到 `2^(64-56) = 256` 个 `/64` 子网。

这里的 65536 是**子网数**，不是主机数。地址规划通常为楼宇、业务区、租户预留整齐的汇总边界，而不是因为当前只有 20 台主机就把普通 SLAAC 网段缩小到 `/120`。

普通以太网 SLAAC 依赖 64 位接口标识，因此通常使用 `/64`。这不表示路由表只能接受 `/64`：点到点路由器互联有 `/127` 的适用场景，回环和精确主机路由常用 `/128`。[RFC 6164](https://www.rfc-editor.org/rfc/rfc6164.html) 讨论了 `/127` 的用途。

也不能把 IPv4 的“总数减 2”原样套到 IPv6。IPv6 没有子网广播地址，但仍有保留和特殊语义，不能据此认为所有组合都适合任意分配。

## 5. ULA 不是 IPv6 版的自动 NAT

ULA 可以在多个内部子网之间路由，用于组织内部通信。它的本地生成部分需要足够随机，以降低不同组织合并或 VPN 互联时冲突的概率。[RFC 4193](https://www.rfc-editor.org/rfc/rfc4193.html) 定义了这一设计。

ULA 不会自动转换为公网地址，也不自带访问控制。两个组织恰好重复使用相同前缀时，仍会遇到地址重叠；“不是公网地址”也不代表内部任何访问都安全。

## 6. 多个地址中，发送方会选哪一个

客户端可能同时有稳定地址、临时地址、ULA 和链路本地地址。发送数据时，系统需要考虑目标作用域、出口接口、地址是否仍受推荐，以及地址选择策略。应用也可能显式绑定源地址。

例如：

- 访问链路本地邻居，需要与该链路匹配的源地址和接口上下文。
- 访问互联网，不应假定系统会用组织内部 ULA 获得全球返回路径。
- 稳定地址便于被访问；临时地址更适合减少作为客户端时的长期跟踪，但不意味着匿名。

源地址选择和目的地址排序的规则由 [RFC 6724](https://www.rfc-editor.org/rfc/rfc6724.html) 描述；实际系统策略和应用行为还可能影响结果。不要把“列表中排第一的地址”当成必然使用的源地址。

## 7. 思考与解答

**两个地址前 64 位相同，就一定会直接进行邻居解析吗？**

不能只看字符串。IPv6 地址配置与 on-link 判断是不同信息；主机还要依据前缀列表、路由等状态决定是直交邻居还是发往路由器。下一篇会解释 RA 的 A/L 标志为什么分开。

**一个 /56 分成 /64，会得到 256 个地址吗？**

不是，是 256 个子网。每个子网包含一个 64 位接口标识空间。

**任播地址是不是每个请求都会平均分配到不同服务器？**

不是。路由选择决定入口，可能长期稳定在同一个实例；应用负载均衡是另一层机制。路由变化还可能影响已有有状态连接。
