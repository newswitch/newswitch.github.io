# IPv4、子网划分、最长前缀匹配与路由表

## 1. 地址由前缀和主机位组成

`10.20.30.40/24` 不是“一个 IP 加一个固定格式的掩码”。`/24` 表示前 24 位
用于标识网络，剩余 8 位标识该前缀内的地址。

```text
地址：00001010.00010100.00011110.00101000
掩码：11111111.11111111.11111111.00000000
网络：00001010.00010100.00011110.00000000
结果：10.20.30.0/24
```

常用容量：

| 前缀 | 总地址数 | 传统可用主机数 |
| --- | ---: | ---: |
| /24 | 256 | 254 |
| /25 | 128 | 126 |
| /26 | 64 | 62 |
| /27 | 32 | 30 |
| /30 | 4 | 2 |
| /31 | 2 | 点到点链路可使用两个地址 |

“减 2”不是永远成立。点到点 `/31` 有专门用途；云厂商还可能保留每个子网中的
额外地址。容量规划必须查目标平台规则。

## 2. 子网划分方法

假设要从 `10.10.0.0/24` 划分：

- 服务器区至少 100 个地址：`10.10.0.0/25`
- 管理区至少 50 个地址：`10.10.0.128/26`
- 存储区至少 30 个地址：`10.10.0.192/27`
- 预留：`10.10.0.224/27`

步骤：

1. 将需求加上网关、扩容和平台保留量。
2. 向上取整到 2 的幂。
3. 大网段优先分配，减少碎片。
4. 为站点、机架、租户或故障域保留可汇总边界。
5. 在 IPAM 中登记意图，而不是依赖表格和人工记忆。

地址规划的目标不只是“够用”，还要支持路由汇总、故障域识别和自动化分配。

## 3. 最长前缀匹配

路由器可能同时有：

```text
0.0.0.0/0       via 192.0.2.1
10.0.0.0/8      via 192.0.2.2
10.20.0.0/16    via 192.0.2.3
10.20.30.0/24   via 192.0.2.4
```

访问 `10.20.30.40` 时选择 `/24`，因为它是匹配目的地址的最长前缀。路由优先级的
第一步不是比较 metric，而是先比较前缀长度。

只有当前缀长度相同时，才继续比较协议优先级、管理距离、metric 或 ECMP 条件。

## 4. RIB 与 FIB

| 表 | 含义 | 内容来源 | 用途 |
| --- | --- | --- | --- |
| RIB | Routing Information Base | 直连、静态、OSPF、BGP 等 | 控制面选择最佳路由 |
| FIB | Forwarding Information Base | RIB 下发或硬件编程 | 数据面高速查找下一跳 |

一条 BGP 路由存在于 BGP RIB，不代表它一定进入主路由表；进入 RIB 也不代表硬件
FIB 编程成功。生产排障必须验证完整链路：

```text
协议是否学到
→ 是否被策略接受
→ 是否成为最佳路径
→ 下一跳是否递归可达
→ 是否进入 RIB/FIB
→ 数据面计数是否增长
```

## 5. Linux 路由对象

查看所有路由：

```bash
ip -details route show table main
```

典型字段：

```text
10.20.0.0/16 via 192.0.2.1 dev eth0 proto static metric 100
```

- `via`：下一跳。
- `dev`：出口接口。
- `proto`：路由来源，不是 IP 上层协议。
- `metric`：同类候选路由的代价之一。
- `scope`：路由适用范围，例如 link、host、global。
- `src`：偏好的源地址。

验证实际查找结果：

```bash
ip route get 10.20.30.40
ip route get 10.20.30.40 from 192.0.2.10
```

## 6. 策略路由

普通路由主要按目的地址决策。Linux RPDB 还能按源地址、入接口、FwMark 等选择
不同路由表：

```bash
ip rule show
ip route show table all
```

例：源自 `10.10.10.0/24` 的流量使用表 100：

```bash
sudo ip route add default via 192.0.2.1 table 100
sudo ip rule add from 10.10.10.0/24 lookup 100 priority 1000
```

排障时只看 `main` 表会漏掉策略路由。应使用带源地址的 `ip route get` 验证。

## 7. 三节点路由实验

拓扑：

```text
h1 10.0.1.2/24 ── 10.0.1.1 r1 10.0.2.1 ── 10.0.2.2/24 h2
```

创建 namespace 与链路：

```bash
sudo ip netns add h1
sudo ip netns add r1
sudo ip netns add h2

sudo ip link add h1e type veth peer name r1e1
sudo ip link add h2e type veth peer name r1e2
sudo ip link set h1e netns h1
sudo ip link set r1e1 netns r1
sudo ip link set h2e netns h2
sudo ip link set r1e2 netns r1

sudo ip -n h1 addr add 10.0.1.2/24 dev h1e
sudo ip -n r1 addr add 10.0.1.1/24 dev r1e1
sudo ip -n r1 addr add 10.0.2.1/24 dev r1e2
sudo ip -n h2 addr add 10.0.2.2/24 dev h2e

for ns in h1 r1 h2; do sudo ip -n "$ns" link set lo up; done
sudo ip -n h1 link set h1e up
sudo ip -n r1 link set r1e1 up
sudo ip -n r1 link set r1e2 up
sudo ip -n h2 link set h2e up

sudo ip -n h1 route add default via 10.0.1.1
sudo ip -n h2 route add default via 10.0.2.1
sudo ip netns exec r1 sysctl -w net.ipv4.ip_forward=1
```

逐层验证：

```bash
sudo ip -n h1 route get 10.0.2.2
sudo ip -n r1 route get 10.0.2.2
sudo ip netns exec h1 traceroute -n 10.0.2.2
sudo ip netns exec h1 ping -c 3 10.0.2.2
```

制造故障：

```bash
sudo ip -n h2 route del default
```

此时请求可能到达 h2，但回复没有返回路径。抓包时会看到 h2 收到 Echo Request，
却不会发出正确的 Echo Reply。它证明“去程通”不能替代“端到端双向可达”。

清理：

```bash
sudo ip netns del h1
sudo ip netns del r1
sudo ip netns del h2
```

## 8. IPv6 必须建立的概念

双栈环境不能把 IPv6 当成“更长的 IPv4”：

- IPv6 使用 128 位地址与前缀。
- 邻居发现使用 ICMPv6 NDP，不使用 ARP。
- 链路本地地址 `fe80::/10` 在邻居发现和路由协议中非常重要。
- 默认网关通常通过 Router Advertisement 获得。
- IPv6 没有 IPv4 头部校验和，分片行为也不同。
- `0.0.0.0/0` 与 `::/0` 是两套独立路由。

基本检查：

```bash
ip -6 addr
ip -6 route
ip -6 neigh
ping -6 <address>
```

## 9. 常见故障

| 现象 | 优先检查 |
| --- | --- |
| 同网段地址被当作远端 | 掩码是否一致 |
| 请求能到、响应回不来 | 返回路由、策略路由、状态防火墙 |
| 默认路由存在但特定网段不通 | 更长前缀黑洞或错误下一跳 |
| 路由协议有前缀但系统无路由 | 最佳路径、递归下一跳、策略、RIB/FIB |
| 多出口偶发不通 | 非对称路由、反向路径过滤、连接跟踪 |
