# 传统网络从零到精通学习路线

这套课程的目标不是记住协议名或厂商命令，而是建立一套可迁移的网络工程能力：

```text
解释数据包为什么这样走
→ 在隔离实验中复现
→ 从控制面、转发表和报文中验证
→ 主动制造故障
→ 用证据定位根因
→ 设计可回退、可观测、可自动化的生产方案
```

## 1. 基础协议与网络服务 {/* #为什么要重新组织 */}

转发表决定数据包往哪里走，基础网络服务则帮助终端获得通信所需的地址、名称和时间信息。
理解 IPv4 后，可以结合下面的原理系列补齐这部分关系：

| 模块 | 重点 |
| --- | --- |
| [IPv6 与双栈网络](./ipv6/00-IPv6学习路线.md) | 地址、NDP、RA、SLAAC、DHCPv6、路径 MTU 与地址族选择 |
| [DHCP](../services/dhcp/00-DHCP学习路线.md) | DORA、租约状态、中继、地址池与高可用分配权 |
| [DNS](../services/dns/00-DNS学习路线.md) | 递归与权威、委派、缓存、DNSSEC 与加密 DNS |
| [NTP 与 PTP](../services/time-sync/00-时间同步学习路线.md) | 时钟偏差、路径误差、硬件时间戳与同步链 |

这些模块可以与路由交换交叉阅读。它们不替代底层转发，却直接影响终端接入和应用通信。

## 3. 实验环境 {/* #实验环境 */}

主线实验尽量使用开源、可重复的环境：

- Linux network namespace、`veth`、Linux bridge：理解主机和二层数据面。
- `iproute2`、`nftables`、`tcpdump`、Wireshark：查看状态表和报文。
- FRRouting：练习 OSPF、BGP、BFD、VRF、EVPN。
- containerlab 或 EVE-NG：构建多节点拓扑。
- Python、Ansible、Nornir、NetBox、Batfish：完成自动化和变更验证。

生产设备命令因厂商和版本而异。课程重点是协议状态与证据链；示例配置必须在
隔离实验环境验证后，才能根据目标设备文档迁移。

## 4. 每篇文章的统一学习方法 {/* #每篇文章的统一学习方法 */}

1. **先画路径**：明确源、目的、每一跳和封装变化。
2. **再看表项**：接口、邻居、MAC、ARP、RIB、FIB、会话、隧道、策略。
3. **最后抓包**：报文用于验证推理，不用于替代状态检查。
4. **制造一个故障**：关闭接口、改错掩码、过滤协议报文或制造 MTU 不一致。
5. **写排障记录**：现象、影响、假设、证据、根因、恢复、长期改进。

## 5. “精通”的验收标准 {/* #精通的验收标准 */}

完成全部课程后，至少能够：

- 从应用五元组画出同网段、跨网段、NAT、隧道和负载均衡的数据路径。
- 解释 RIB、FIB、邻居表、MAC 表、连接跟踪表之间的关系。
- 独立配置并排查 OSPF、BGP、ECMP、BFD、VRF 和基础 MPLS L3VPN。
- 设计 2 Spine + 4 Leaf 的 Underlay 与 EVPN/VXLAN Overlay。
- 解释 EVPN Type 2/3/5 路由、VNI、VTEP、Anycast Gateway 和对称 IRB。
- 将 VPC 路由、安全策略、NAT、负载均衡和混合云路径映射到传统网络模型。
- 使用 Source of Truth、模板、自动验证和分批发布完成受控网络变更。
- 把网络指标、流日志、Syslog、路由状态和业务 SLO 关联起来。
