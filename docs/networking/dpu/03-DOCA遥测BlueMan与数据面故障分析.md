# DOCA 遥测 BlueMan 与数据面故障分析

BlueMan 聚合 DPU 基本信息、健康与遥测，数据依赖 DOCA Telemetry Service 等服务。Web 页面可打开，只证明展示端可访问，不能直接证明采集链路和业务数据路径正常。

## 1. 从显示值回溯来源

```text
硬件和系统采集源 → DTS → 相关服务及转换 → BlueMan 页面
业务包路径      → Host/DPU 功能 → 卸载规则 → 物理端口
```

两条链路需要关联，但不能相互代替。遥测服务停止时，数据可能缺失或变旧；业务路径故障时，管理页面仍可能正常。

## 2. 先验证依赖

不同 BSP/DOCA 版本有不同服务组织方式。旧版 BlueMan 示例涉及 DPE、DTS 与前端/转换容器；DPF 部署则需检查其对应控制对象。先确定采用哪种路径，再查本机服务状态与容器日志，不跨版本照抄启停命令。

“容器 Running”之后，还应检查采集时间、数据源错误、权限、设备识别和计数器是否推进。多个组件同时无数据，应先排查共同采集源，不必立即重启所有展示端。

### 2.1 Provider Exporter 与展示阈值

在 DOCA 3.5.0 的 DTS 模型中，Provider 决定采集哪些来源，Exporter 决定通过何种通道输出。Prometheus 端点可访问不表示所有 Provider 已启用或读取成功；聚合器还能引入另一个缓存与采集时点。见[DTS 服务指南](https://networking-docs.nvidia.com/doca/archive/3-5-0/doca-telemetry-service-guide)。

BlueMan 的健康颜色还受配置阈值影响。修改阈值可改变展示分类，却没有改变物理温度或转发状态。它的部分信息来自 DTS 与 DPE，所以页面和 DTS 同时报错也不应自动算作两份独立故障证据。[BlueMan 3.5.0 指南](https://networking-docs.nvidia.com/doca/archive/3-5-0/doca-blueman-service-guide)描述了这些关系。

## 3. 计数器差分

教学例子：10 秒内端口字节计数从 100 GiB 增到 120 GiB，平均速率为 2 GiB/s。只有单位确为字节且期间没有重置/回绕，这个计算才成立。若服务重启后计数回到 1 GiB，不能直接相减得到负带宽。

Offload 前后比较还要观察规则命中、硬件卸载状态、CPU 及应用延迟。计数增长只是流量证据，不单独证明所有流量按目标路径处理。

### 3.1 零值 失败值与没有数据

先确认字段和 Provider 的失败语义。DOCA 3.5.0 的 PHY Provider 在电缆断开或温度不可读取时会报告 0；这个特定约定不能被解释成模块温度一定为零摄氏度。其他 Provider 又可能使用缺失或错误状态，不能将所有失败统一处理为数值零。

为每条关键指标保留设备身份、来源、采样时间和有效性。设备更换或来源重置后重新建立差分基线；同名标签未变，不证明还是同一个硬件计数器。

### 3.2 遥测规模与采样预算

教学条件：100 台 DPU，每台稳定产生 600 条时间序列，每 15 秒采样一次，约为 60000 条序列和每秒 4000 个样本。若给每个短命连接增加不同标签，序列数量可能远大于这个静态估算。

提高频率不能补齐未启用的 Provider，也不能自动提高源计数器刷新频率。应从故障检测时效、源更新粒度、CPU/网络成本和后端基数共同选择；不要把全量高频采集作为排障默认动作。

## 4. 三种故障推演

| 现象 | 可能的边界 | 下一份证据 |
| --- | --- | --- |
| 页面正常但数值不变 | DTS、转换链、设备采集、缓存 | 数据时间戳和采集日志 |
| 管理正常但业务丢包 | Representor、规则、物理端口或远端 | 端到端计数差和规则命中 |
| 重启 Arm 后 Host 存储异常 | DPU 服务承载了关键数据面 | 依赖拓扑、服务事件与 Host 错误 |

这些是假设，必须用观测逐一排除，不能把表格当作错误码与根因的一一映射。

## 5. 管理安全与恢复

遥测入口应使用合适的认证、TLS 与管理网络边界。不要为了让页面可访问而关闭整个防火墙或暴露 Arm Root。故障转储可能包含地址、配置与凭据信息，应按最小范围采集和共享。

恢复后需要分别验证管理连接、采集新鲜度、服务功能和业务性能。改正前端依赖不会自动修复错误转发规则；修复数据面也不保证历史告警归属已经正确。

## 6. 掌握检查

为什么计数器归零不能直接解释成没有流量？它可能意味着源重置。为什么 Ping 通不能证明卸载生效？软件路径也可以连通，需要实际规则与硬件证据。
