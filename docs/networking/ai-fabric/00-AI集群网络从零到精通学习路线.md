# AI 集群网络从零到精通学习路线

AI 集群网络不是“更快的以太网”。它连接 GPU 显存、PCIe/NVLink、NIC、交换 Fabric、
集合通信库和训练框架。网络正常但 GPU 拓扑错误、NCCL 退回 Socket、PFC 扩散或
Pod 拿到错误 NUMA 节点，都可能让 GPU 长时间等待通信。

本路线建立一条可以验证的因果链：

```text
训练并行策略
→ 集合通信与消息大小
→ NCCL 算法、协议和 Channel
→ GPU/NVLink/PCIe/NIC 数据路径
→ RDMA Transport
→ InfiniBand 或 RoCE Fabric
→ Kubernetes 资源与拓扑调度
→ 训练 Step Time 和业务 SLO
```

## 前置课程

AI 组网不重复通用网络基础。开始前应完成：

- [传统网络从零到精通](../fundamentals/00-传统网络从零到精通学习路线.md)：IP、路由、ECMP、Clos、QoS 和自动化。
- [Linux 高性能网络](../high-performance/linux高性能网络详解读书笔记（一）.md)：队列、中断、Socket 与零拷贝。
- [GPU 服务器硬件拓扑与 NUMA](../../gpu/pcie-numa/04-GPU服务器硬件拓扑与NUMA.md)：GPU、CPU、PCIe 和 NIC 亲和。

没有真实 RDMA 硬件时，第一阶段仍可学习概念、命令输出和 NCCL 单机实验；
PFC、ECN、DCQCN、真实链路故障和多 Rail 验收必须在隔离的物理实验环境完成。

## 学习方法

每篇文章按照同一流程学习：

1. **画流量**：Rank、GPU、NIC、Rail、交换路径和目标 Rank。
2. **分层验证**：PCIe → RDMA → Fabric → NCCL → 训练框架。
3. **固定口径**：消息大小、Rank 数、算法、协议、单/双向、测试持续时间。
4. **保存基线**：不仅记最好值，还记录 P50/P95/P99、抖动、错误和拓扑。
5. **注入故障**：链路降速、PFC 映射错误、ECN 阈值错误、单 Rail 失效、Socket 回退。
6. **关联业务**：最终观察训练 Step Time、通信占比和 GPU 利用率。

## 性能数字必须带口径

本路线不使用“RDMA 达到 95%”“NCCL 达到 90%”作为脱离环境的通用目标。
任何结果必须同时记录：

```text
硬件与固件版本
物理链路速率和编码开销
消息大小与迭代次数
单向/双向、QP 数、Rail 数
Host Memory 或 GPU Memory
NCCL Rank 数、Collective、algbw、busbw
CPU/GPU/NIC NUMA 位置
交换路径、拥塞和错误计数器
```

目标值来自同型号健康节点和经过评审的容量模型，而不是从别人的博客复制一个百分比。

## “精通”的验收标准

完成全部实验后，至少能够：

- 根据 TP、DP、PP、EP 判断主要 Collective 和流量形态。
- 从 WQE、QP、CQ、MR、GID/LID 解释一次 RDMA 操作。
- 区分 InfiniBand Fabric 管理与 RoCEv2 IP/以太网数据面。
- 解释 DSCP/PCP/TC/Queue、PFC、ECN、CNP 和 DCQCN 的闭环。
- 计算 Clos 端口、收敛比、二分带宽和 Rail 带宽预算。
- 从 `nvidia-smi topo -m`、RDMA 设备和 NCCL 日志证明 GPU→NIC 路径。
- 在 Kubernetes 中选择共享 RDMA 或 SR-IOV，并验证 Pod 内资源和拓扑。
- 把交换机队列、PFC/CNP、NIC 计数、NCCL 和训练 Step Time 对齐到同一时间线。
- 在故障时判断是 GPU、PCIe、RDMA、Fabric、NCCL、容器还是训练框架。
- 用 Canary、前后快照、停止条件和回滚安全变更 AI Fabric。
