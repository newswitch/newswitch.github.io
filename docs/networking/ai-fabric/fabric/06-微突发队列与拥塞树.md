# 微突发、队列与拥塞树

一分钟平均利用率只有 30%，端口仍可能在几十微秒内被多个发送端同时打满。AI Collective
同步启动，天然容易形成突发和 Incast。

## 1. 为什么平均利用率会骗人

假设 8 个 400G 输入同时向一个 400G 输出发送 100 微秒：

```text
瞬时输入：3.2T
输出能力：400G
瞬时超额：2.8T
积压数据：2.8T × 100μs / 8 ≈ 35MB
```

若只按 60 秒采样，平均值几乎看不到，但交换芯片缓冲早已承压。

## 2. Incast 与 Outcast

- Incast：多个发送端同时汇聚到一个接收端/出口；
- Outcast：多个流从同一输入竞争不同出口，调度和缓冲分配造成不公平；
- Elephant Flow：大持续流；
- Mice Flow：短小、对启动时延敏感的流。

All-to-All 既可能充分分散，也可能因 Token/Rank 不均形成局部 Incast。

## 3. 队列时延

近似：

```text
Queue Delay ≈ Queue Bytes × 8 / Egress Rate
```

400G 出口积压 5MB：

```text
5MB × 8 / 400Gbps ≈ 100μs
```

对同步 Collective，额外 100μs 可能在多层、多次调用中累积，并放大慢 Rank。

## 4. Shared Buffer

交换 ASIC 常让端口/队列共享 Buffer，并设置 Guaranteed、Shared、Headroom 等区域。

风险：

- 一个热点 Queue 消耗共享池，影响其他端口；
- 静态预留过多导致 Buffer 利用率低；
- 动态阈值过宽导致拥塞传播；
- Headroom 计算不足触发 No-Buffer Discard；
- 只看总 Buffer，不看每 Queue/每 Priority。

## 5. Head-of-Line Blocking

队列头部报文因下游暂停或拥塞无法发送，后面的报文即使目标路径空闲也被阻塞。

隔离方法：

- 不同流量类映射不同 Queue；
- 限制 PFC Priority；
- 合理 Virtual Lane/Traffic Class；
- 避免所有租户和存储共享同一 Lossless Queue；
- 使用 ECN 从源端减速。

队列数有限，不可能为每个作业单独建硬件 Queue，需要按业务 SLO 聚合。

## 6. 拥塞树

拥塞从根部向上游传播：

```text
慢接收节点/拥塞出口（Root）
← Leaf 发 PFC
← Spine 对多个输入产生反压
← 多个 Leaf/NIC 被 Pause
← 无关作业也变慢
```

告警最多的 Spine 可能不是根因，只是汇聚了下游 Pause。

### 6.1 找根的方法 {/* #找根的方法 */}

1. 找最早出现 Queue 高水位/丢弃的端口。
2. 沿 PFC Tx 方向向下游走。
3. 沿 PFC Rx 方向向上游确认受影响范围。
4. 找到出口、接收节点或降速链路。
5. 对齐 ECN/CNP 和作业 Rank。
6. 验证移除根部瓶颈后整棵树消退。

## 7. 常见根因

- NIC/交换端口从 400G 降到 200G/100G；
- 接收 GPU/NIC/PCIe 无法消费；
- 多个 Rank 同时向一个专家/参数服务器；
- ECMP 极化；
- 单 Rail 故障后流量迁移；
- Storage Checkpoint 与训练共队列；
- 错误 PFC/DSCP 映射；
- ECN 阈值过高或 CNP 返回受阻；
- 交换 ASIC/固件异常。

## 8. 需要的采样

一分钟 SNMP 不够。优先使用：

- 秒级/更高频 Streaming Telemetry；
- Queue Max Watermark；
- ECN/PFC/Discard Counter 增量；
- Hardware Histogram（平台支持时）；
- NIC/RDMA Counter；
- NCCL 每次迭代和训练 Step Time；
- 作业 Rank/节点/Rail 映射。

高频采集也要控制设备和存储成本。

## 9. 故障时间线

```text
10:00:00.000 All-to-All 开始
10:00:00.050 Leaf7 Queue 水位上升
10:00:00.070 Leaf7 ECN Mark 增加
10:00:00.090 Receiver NIC 发 CNP
10:00:00.110 Leaf7 触发 PFC
10:00:00.140 Spine3 收到 PFC
10:00:00.200 多个发送节点吞吐下降
10:00:01.500 训练 Step P99 升高
```

统一时间戳后才能判断因果。

## 10. 容量与控制的分工

```text
容量：减少持续过载
ECMP/路由：分散路径
ECN/DCQCN：源端主动降速
PFC：防止瞬时 Buffer 溢出
Queue/QoS：隔离不同类别
调度：避免不合适作业同时竞争
```

任何单一机制都不能独立解决拥塞。

## 11. 实验

1. 使用多发送端向一接收端运行 perftest。
2. 比较 1、2、4、8 个发送端。
3. 将采样从 60 秒缩短到 1 秒/硬件 Watermark。
4. 对齐 Queue、ECN、CNP、PFC、吞吐和 P99。
5. 将接收端链路临时降速，观察拥塞树。
6. 把背景 TCP 放入独立 Queue，验证隔离。
7. 恢复链路，测拥塞消退时间。

## 12. 掌握标准

能够用端口速率和持续时间估算突发积压；能从一组 PFC 告警找到下游根部，而不是在每台上游
交换机分别调大 Buffer。
