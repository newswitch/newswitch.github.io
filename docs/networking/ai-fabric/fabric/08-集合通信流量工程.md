# 集合通信流量工程

网络流量工程不能脱离 Collective。AllReduce、All-to-All 和 Pipeline Send/Recv 使用的路径、
同步方式和热点完全不同。

## 1. 四层映射

```text
模型并行组
→ NCCL Communicator / Rank
→ GPU / NIC / Rail
→ Leaf / Spine / Fabric Path
```

优化任何一层前，都要确认其他层是否会把流量重新映射。

## 2. AllReduce

Ring AllReduce 的每个 Rank 主要与环邻居交换 Chunk。目标：

- 相邻 Rank 尽量使用高带宽本地拓扑；
- 跨节点边界均匀分布到 NIC/Rail；
- 多 Channel 不集中到同一上行；
- 故障后剩余路径不严重收敛。

Tree 类算法则更关心父子映射和树上层节点/链路。

## 3. All-to-All

每个 Rank 向多个 Rank 发送不同数据：

- 理论上可使用更多路径；
- Token/专家不均会产生局部热点；
- 每个流较小可能受启动和 QP 数影响；
- 多作业叠加后交换芯片状态与队列压力更大。

MoE 优化要同时观察 Expert Load 与 Fabric Port，不能只调网络。

## 4. 分层 Collective

一种常见思想：

```text
节点内先用 NVLink/NVSwitch 归约
→ 每节点代表通过 NIC 跨节点通信
→ 节点内再分发
```

是否使用、如何分层由 NCCL 版本、拓扑和 Collective 决定。手工强制算法前先读取日志和 Profile。

## 5. Rank 放置

调度输入：

```text
TP Group：优先同 NVLink/NVSwitch 域
PP Stage：相邻 Stage 路径
DP Group：跨节点 AllReduce
EP Group：All-to-All 故障域和带宽
```

不合理放置示例：

- TP 跨越慢 Rail，而 DP 留在单机；
- 同一 Ring 的多个边界都经过一张 NIC；
- 所有专家热点集中在同一 Leaf；
- 作业跨越故障中的 Rail；
- 两个重型 All-to-All 作业放在同一 Pod。

## 6. 作业间干扰

多个作业共享 Fabric：

- Collective 时间可能同步；
- 大消息 AllReduce 与 Checkpoint 重叠；
- 推理低时延流被训练突发影响；
- 某作业 PFC Storm 传播到其他租户；
- 公平队列无法感知“一个作业有 1000 个流”。

控制手段：

- 拓扑感知放置；
- Admission/配额；
- 作业级带宽估算；
- 独立 TC/Queue（数量有限）；
- 时间错峰；
- Rail/Pod 隔离；
- 在作业启动前检查剩余容量。

## 7. ECMP 与 QP

RoCEv2 多 QP/Channel 提供哈希熵，但需要验证：

- 五元组是否变化；
- QP 是否被固定路径；
- 是否存在 Polarization；
- 同一流是否乱序；
- 多 Rail 流量是否均衡。

IB 则依赖 SM 路由、LID/LMC 和 Adaptive Routing 等机制。

## 8. 从 Step Time 反推

训练 Step：

```text
Compute
→ Collective A
→ Compute
→ Collective B
→ Synchronization
```

通信慢可能表现为 GPU Kernel 空洞或 Rank 等待。分析：

1. 找到变慢的 Collective；
2. 确定消息大小和 Rank Group；
3. 映射到 GPU/NIC/Rail；
4. 对齐链路、Queue、ECN/PFC；
5. 找最慢 Rank；
6. 区分网络热点与 GPU/CPU 慢节点。

## 9. 设计不变量

- 同一 TP Group 不跨不允许的拓扑域；
- 每个 Rank 至少有一条健康首选 Rail；
- 重型作业不跨故障状态 Pod；
- 单链路故障后的收敛比不超过审批值；
- Storage 不进入 RoCE Lossless Queue；
- 多租户禁止跨 Partition/VRF；
- NCCL Socket 回退必须告警。

## 10. 实验

1. 采集 NCCL Rank/Channel/Ring。
2. 把每条跨节点边映射到 NIC 和交换路径。
3. 对比默认与故意错误 Rank Mapping。
4. 运行 AllReduce 与 All-to-All，比较端口分布。
5. 同时启动第二个作业，观察干扰。
6. 将 Checkpoint 流量与 Collective 重叠。
7. 用调度/隔离调整后复测 Step P99。

## 11. 掌握标准

能够从一段变慢的 Collective 定位到具体 Rank、GPU、NIC、Rail 和队列；能通过作业放置、
通信组映射和容量控制减少热点，而不是把所有问题交给 PFC。
