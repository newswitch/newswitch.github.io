# IGMP、PIM 与组播学习路线

组播把“发送一份数据”和“网络在分支处复制数据”结合起来。要理解它，需要把接收意愿、跨网段分发和二层出口裁剪分开。

## 1. 阅读顺序

1. [组播地址、IGMP/MLD 与成员关系](./01-组播地址IGMP-MLD与成员关系.md)：从 MAC 映射、Group Record 和 INCLUDE/EXCLUDE 汇总理解接收状态。
2. [PIM-SM、共享树、源树与 RPF](./02-PIM-SM共享树源树与RPF.md)：沿 Register、原生数据、源树切换理解建树，再区分 RPF、DR、Assert 与 RP。
3. [Snooping、Querier 与二层组播转发](./03-Snooping-Querier与二层组播转发.md)：理解组表粒度、路由器端口、计时版本差异及逐级离组。

## 2. 各层维护什么

| 位置 | 主要状态 |
| --- | --- |
| 应用与主机 | 哪个接口订阅哪些组与源 |
| 末跳路由器 | 本链路有哪些接收需求 |
| 中间路由器 | 分发树的入接口与出接口集合 |
| 二层交换机 | VLAN 内的成员端口、路由器端口与计时 |

“主机加入组”不等于整条路径的其他三种状态已经形成。单播路由、二层链路与地址作用域仍是理解组播的基础。

理解正常路径后，再分别考虑“一台应用退出”“整个端口失去接收者”“RP 不可达”“源方向路由变化”。它们改变的状态范围不同，不能都通过删除同一张组表解释。
