# 网络命令参考库学习路线

这套参考库解决两个问题：一是看到命令时知道它在修改哪一层状态，二是发生故障时能沿着数据路径收集证据。它不是零散的“命令大全”，而是传统网络、Linux 协议栈、容器网络和 AI 集群网络之间的操作接口。

## 1. 先建立对象地图

```text
网卡/虚拟设备 ── ip link ───────────────┐
  ├─ 三层地址 ─ ip address              │
  ├─ 邻居缓存 ─ ip neighbour            ├─ 主机网络状态
  ├─ 路由/FIB ─ ip route + ip rule      │
  └─ 网络隔离 ─ ip netns ───────────────┘

套接字 ───────── ss ───────── 应用是否监听、连接处于什么状态
Linux Bridge ─── bridge ───── 二层端口、FDB、VLAN、MDB、VNI
队列与限速 ───── tc ───────── qdisc、class、filter、action
线上数据包 ───── tcpdump ──── 抓取并验证协议事实
网卡/驱动 ────── ethtool ──── 链路、队列、Ring、中断合并、Offload、统计

可达性 ───────── ping ──────── 往返连通、RTT、丢包和 PMTU 线索
路径 ─────────── tracepath ──── 无特权路径与 PMTU 发现
路径 ─────────── traceroute ─── UDP/ICMP/TCP 逐跳验证
持续路径质量 ─── mtr ───────── hop 的丢包、时延、抖动与趋势
DNS 报文 ─────── dig ───────── 递归、权威、记录、DNSSEC、DoT/DoH
系统解析链 ───── resolvectl ─── per-link DNS、缓存与 Split DNS
传输层端口 ───── nc ────────── TCP/UDP/Unix Socket 最小验证
网络性能 ─────── iperf3 ────── 吞吐、重传、UDP 丢包和抖动

原生规则集 ───── nft ────────── hook、规则、集合、映射、NAT 与事务
兼容规则集 ───── iptables ───── 表、链、匹配、target 与 nft/legacy 后端
连接状态 ─────── conntrack ──── tuple、NAT 映射、事件、容量与丢弃
防火墙管理 ───── firewall-cmd ─ zone、policy、service 与持久配置

NetworkManager ─ nmcli ─────── profile、device、路由、DNS 与回滚
systemd-networkd  networkctl ── 配置匹配、DHCP、reload 与运行状态
ARP 主动探测 ─── arping ────── 二层可达性、地址冲突与 GARP
LLDP 邻居 ────── lldpcli ───── 交换机、端口、VLAN、能力与统计

HTTP 应用链路 ── curl ─────── DNS、TCP、TLS、HTTP 状态与阶段耗时
TLS/PKI ───────── openssl s_client ─ SNI、证书链、ALPN 与 mTLS
RDMA 对象 ─────── rdma ─────── device、port、QP/MR/CM 与计数器
Verbs/GID ─────── ibv_devinfo/show_gids ─ 能力、Link Layer 与 GID 映射
RDMA 数据面 ───── perftest ──── Read/Write/Send、延迟、带宽与 GPU Direct
```

## 7. 统一安全标记

| 标记 | 含义 | 执行原则 |
|---|---|---|
| `[R]` | 只读查询 | 可在生产环境先执行，但仍要关注全量扫描、解析和抓包开销 |
| `[W]` | 修改运行时状态 | 先保存现状、限定对象、准备回滚，并确认配置管理不会覆盖 |
| `[D]` | 可能中断连接或删除状态 | 必须经过变更审批并在带外通道可用时执行 |

`show/list/get` 通常是 `[R]`；`add/set/change/replace` 通常是 `[W]`；`del/flush`、`ss -K`、清空 nftables/iptables/conntrack、删除根 qdisc、`nmcli/networkctl` 关闭或重配远程管理网卡、修改 Ring/Offload 可能是 `[D]`。LLDP 发送配置和 GARP 也会改变其他设备观察到的状态。命令本身成功不代表业务正常，任何变更都要用反向路径和业务指标验证。

## 8. 每次排障的固定顺序

```bash
# 1. 先确认配置所有者，避免 NetworkManager、networkd 与脚本互相覆盖
systemctl is-active NetworkManager
systemctl is-active systemd-networkd
nmcli device status
networkctl list

# 2. 接口与地址
ip -br link
ip -br address

# 3. 内核路由决策
ip rule show
ip route get 10.20.30.40

# 4. 被动缓存、主动二层探测与直连交换机邻居
ip neighbour show nud failed
ip netns list
arping -I eth0 -c 3 -w 5 10.20.30.1
lldpcli -f keyvalue show neighbors ports eth0 details

# 5. 应用套接字
ss -lntup
ss -tin state established

# 6. 二层转发、队列和网卡
bridge -s link show
tc -s qdisc show dev eth0
ethtool eth0
ethtool -S eth0

# 7. 可达性、路径与 PMTU
ping -4 -n -c 5 10.20.30.40
tracepath -4 -n 10.20.30.40
mtr -4 -n -r -T -P 443 -c 50 10.20.30.40

# 8. DNS 与系统解析路径
resolvectl query api.example.com
dig -r @10.20.0.53 api.example.com A +time=2 +tries=1

# 9. 业务端口；成功只代表 TCP 建连，不代表应用健康
nc -4 -n -v -z -w 3 10.20.30.40 443
curl -sS --fail-with-body --connect-timeout 2 --max-time 10 https://api.example.com/health
openssl s_client -connect api.example.com:443 -servername api.example.com -verify_hostname api.example.com -verify_return_error </dev/null

# 10. 确认防火墙所有者、规则与连接状态
systemctl is-active firewalld
firewall-cmd --get-active-zones
nft -n -a list ruleset
conntrack -S
conntrack -L -p tcp -d 10.20.30.40 --dport 443 -o extended

# 11. 仅在批准的测试窗口做受控吞吐验证
iperf3 -c 10.20.30.40 -t 5 -P 1

# 12. 最后用受控抓包验证假设
tcpdump -i eth0 -nn -c 100 'host 10.20.30.40'

# 13. RDMA 场景再沿 verbs 对象与数据面下钻
rdma -d link show
rdma resource show qp
ibv_devinfo -d mlx5_0 -i 1
show_gids
```

这是一份工具顺序，不是要求每次机械执行全部命令。防火墙命令还需要 root 权限，并应先确认主机使用 firewalld、原生 nftables、iptables-nft 还是 legacy。先根据故障层级选择只读检查，再建立假设，最后用最小范围抓包或受控性能测试验证。不要一开始就 `flush` 邻居表/规则集/conntrack、清 DNS 缓存、重启网络、关闭 Offload 或跑满带宽，否则会改变现场并掩盖真正原因。

## 9. 实验环境

大部分写操作需要 `CAP_NET_ADMIN`，抓包通常需要 `CAP_NET_RAW`。建议在测试虚拟机中使用两个 network namespace 和一对 veth，不要直接改宿主机默认路由：

```bash
sudo ip netns add blue
sudo ip netns add red
sudo ip link add veth-blue type veth peer name veth-red
sudo ip link set veth-blue netns blue
sudo ip link set veth-red netns red
```

实验结束前先确认对象名称，再逐项删除。本参考库的文章会给出完整清理命令。

## 10. 文档基线

- iproute2：以 2026-08-11 获取的[上游手册](https://man7.org/linux/man-pages/man8/ip.8.html)为基线；发行版可能回移补丁或裁剪功能，以本机 `ip -Version` 和子命令 `help` 为准。
- tcpdump/libpcap：以 [tcpdump 官方仓库](https://github.com/the-tcpdump-group/tcpdump)与 [libpcap 官方仓库](https://github.com/the-tcpdump-group/libpcap)为基线。
- ethtool：以 7.1 和[上游发布页](https://www.kernel.org/pub/software/network/ethtool/)为基线；具体能力还取决于内核和驱动。
- iputils：`ping` 与 `tracepath` 以 iputils 20250605 上游手册为基线；具体权限由发行版 capability 和内核决定。
- traceroute：以 Traceroute for Linux 2.1.6 为基线；MTR 以 0.96 上游手册为基线。
- DNS：`dig` 以 BIND 9.20.26 文档为基线；`resolvectl` 必须与本机 systemd 版本和网络管理组件一起核对。
- 端口与性能：`nc` 以 Linux 常见 OpenBSD 兼容实现为主，但必须先识别实现；`iperf3` 以 3.21 为基线。
- 防火墙与状态：`nft` 以 nftables 1.1.6 为基线，`iptables` 以 1.8.13 为基线，`conntrack` 以 conntrack-tools 1.4.9 为基线；`firewall-cmd` 按当前 firewalld 官方手册编写，并要求以本机版本复核对象和选项。
- 配置管理与二层发现：`nmcli` 以 NetworkManager 1.58 为基线，`networkctl` 按当前 systemd 上游手册编写，`arping` 以 iputils 20250605 为基线，`lldpcli` 以 lldpd 1.0.21 为基线；发行版回移、编译选项、服务所有权和硬件驱动都会影响本机能力。
- HTTP/TLS：`curl` 和 OpenSSL 选项变化频繁，正文按当前上游手册的稳定参数族组织，执行时必须记录本机版本、TLS backend 与 trust store。
- RDMA：`rdma` 按当前 iproute2/rdma-core 接口，perftest 按 linux-rdma 上游项目组织；device/driver/firmware、GID 类型、GPU DMA-BUF 支持和两端工具版本都会改变可用选项与结果。

版本变化频繁的命令，文章重点解释稳定的对象模型、常用参数族和排障方法；新增参数应以本机 `--help`、`man` 与发行版文档复核。
