# `tc` 命令详解：队列规则、分类、过滤、限速和网络仿真

`tc` 配置 Linux Traffic Control。它能做发送整形、调度、分类、policing、丢包和网络故障仿真，也能借助 filter/action 重定向或修改报文。它直接处在生产数据路径上，错误的 root qdisc、速率单位或 filter 可以让整台节点断流。

## 1. 命令档案

| 项目 | 内容 |
|---|---|
| 命令 | `tc` |
| 实现 | iproute2 |
| 主要对象 | `qdisc`、`class`、`filter`、`chain`、`action`、`monitor` |
| 安全级别 | `show/list` 为 `[R]`；`add/change/replace` 为 `[W]`；删除 root/clsact、错误 drop/police/filter 为 `[D]` |
| 能力 | 通常需要 `CAP_NET_ADMIN` |

```bash
tc -V
tc help
tc qdisc help
tc filter help
```

## 2. 数据路径与对象关系

```text
应用/转发报文
   │
   ├─ ingress hook ─ filter ─ action/police/drop/redirect
   │
   ▼
协议栈
   │
   ├─ egress clsact hook ─ filter ─ action
   │
   ▼
root qdisc
   ├─ class 1:10 ─ leaf qdisc
   ├─ class 1:20 ─ leaf qdisc
   └─ filter：把流分类到 class 或执行 action
   │
   ▼
驱动队列 → 网卡
```

核心概念：

| 对象 | 作用 |
|---|---|
| qdisc | Queueing Discipline，排队、调度、整形或故障仿真 |
| class | classful qdisc 内的层级带宽类别 |
| filter | 匹配报文并选择 class 或 action |
| action | drop、pass、redirect、mirror、修改字段等动作 |
| chain | 将过滤器组织成可跳转的链 |

整形通常发生在 egress；ingress 原生更适合 policing。要对 ingress 做真正排队整形，常把流量 redirect 到 IFB 设备后在 IFB egress 上整形。

## 3. 全局选项

| 选项 | 作用 |
|---|---|
| `-s` / `-stats` | 显示统计 |
| `-d` / `-details` | 显示详细参数 |
| `-r` / `-raw` | 原始数值输出 |
| `-p` / `-pretty` | 更易读输出 |
| `-iec` | 使用 IEC 单位 |
| `-g` / `-graph` | 以图形化层级形式显示 class |
| `-c` / `-color` | 彩色输出 |
| `-j` / `-json` | JSON 输出，具体对象支持度随版本变化 |
| `-n NAME` / `-netns NAME` | 在指定命名空间执行 |
| `-nm` / `-name` | 显示类名映射 |
| `-cf FILE` / `-conf FILE` | 指定类名配置文件 |
| `-b FILE` / `-batch FILE` | 批处理命令 |
| `-force` | 批处理遇错继续 |

生产采集常用：

```bash
tc -s -d qdisc show dev eth0
tc -s -d class show dev eth0
tc -s -d filter show dev eth0 ingress
tc -s -d filter show dev eth0 egress
```

## 4. 句柄、父子关系和特殊挂载点

标识通常写成 `major:minor`：

- qdisc 句柄如 `1:`，minor 为 0。
- class ID 如 `1:10`。
- `root` 表示设备发送路径根。
- `parent 1:10` 表示挂到指定 class。
- `ingress` 表示入方向特殊 qdisc。
- `clsact` 同时提供 ingress 与 egress 分类 hook，不负责普通排队。

```bash
tc qdisc show dev eth0
```

现代多队列网卡常见默认根 qdisc 是 `mq`，叶子可能是 `fq_codel`。直接 `replace root` 会替换这套结构，可能影响多队列映射和性能。

## 5. `qdisc` 命令族

```text
tc qdisc { add | change | replace | link | delete } dev DEV
    [ root | parent ID ] [ handle ID ] QDISC [ PARAMETERS ]
tc qdisc { show | list } [ dev DEV ]
```

| 动作 | 语义 |
|---|---|
| `add` | 新增，已存在时失败 |
| `change` | 修改已有对象；并非所有 qdisc 都支持原位修改 |
| `replace` | 存在则替换，不存在则创建 |
| `link` | 将 qdisc 连接到已有节点，较少使用 |
| `delete` | 删除并恢复该位置默认行为，可能立即改变路径 |

### 5.1 常见 qdisc 类型

| 类型 | 类别 | 用途 |
|---|---|---|
| `pfifo` / `bfifo` | classless | 按包数/字节数 FIFO |
| `fq` | classless | Fair Queue，常与 TCP pacing 配合 |
| `fq_codel` | classless | 公平队列 + CoDel，控制 bufferbloat |
| `cake` | classless | 综合整形/AQM，是否可用取决于内核模块 |
| `tbf` | classless | Token Bucket，简单速率整形 |
| `netem` | classless | 延迟、抖动、丢包、重复、乱序、损坏等仿真 |
| `htb` | classful | 分层令牌桶，按 class 保证/借用带宽 |
| `hfsc` | classful | 基于服务曲线的分层调度 |
| `prio` | classful | 严格优先级 band |
| `mq` / `multiq` | classful-ish | 多硬件发送队列分发 |
| `ingress` | 特殊 | 入方向 filter/police hook |
| `clsact` | 特殊 | ingress + egress filter/action hook |

每种 qdisc 有独立手册，例如 `man tc-htb`、`man tc-netem`，参数不能靠名称猜测。

## 6. 简单限速：TBF

```bash
sudo tc qdisc replace dev eth0 root tbf \
  rate 100mbit burst 1mb latency 50ms
tc -s -d qdisc show dev eth0
```

| 参数 | 含义 |
|---|---|
| `rate` | 平均发送速率 |
| `burst` / `buffer` / `maxburst` | 令牌桶容量；过小会限制可实现速率并增加丢包 |
| `latency` | 包可在队列等待的最长时间，与 `limit` 二选一理解 |
| `limit` | 队列最大字节数 |
| `peakrate` / `minburst` | 可选峰值速率与第二桶 |

`mbit` 是 megabits/s，`mbps`、`mb` 等单位在不同工具里语义容易混淆。变更前用低风险实验接口验证实际速率。

删除：

```bash
sudo tc qdisc del dev eth0 root
```

删除 root 不一定恢复发行版/网络管理器原先的 qdisc 结构；应先保存 `tc -s -d qdisc`，并准备明确的恢复配置。

## 7. 分层限速：HTB + class + filter

```bash
sudo tc qdisc replace dev eth0 root handle 1: htb default 30

sudo tc class add dev eth0 parent 1: classid 1:1 \
  htb rate 1gbit ceil 1gbit
sudo tc class add dev eth0 parent 1:1 classid 1:10 \
  htb rate 600mbit ceil 1gbit prio 0
sudo tc class add dev eth0 parent 1:1 classid 1:30 \
  htb rate 100mbit ceil 1gbit prio 2

sudo tc qdisc add dev eth0 parent 1:10 handle 10: fq_codel
sudo tc qdisc add dev eth0 parent 1:30 handle 30: fq_codel

sudo tc filter add dev eth0 parent 1: protocol ip priority 10 \
  flower dst_ip 10.20.0.0/16 classid 1:10
```

HTB 关键参数：

| 参数 | 含义 |
|---|---|
| `rate` | 该 class 保证速率 |
| `ceil` | 允许借用后的上限 |
| `burst` / `cburst` | rate/ceil 令牌桶突发容量 |
| `prio` | 借用和调度优先级，较小通常更高 |
| `quantum` / `r2q` | DRR 调度粒度；不理解时先用默认并观察告警 |

看统计：

```bash
tc -s class show dev eth0
tc -s filter show dev eth0 parent 1:
```

如果 filter packet counter 不增长，先怀疑匹配条件、协议族、方向、priority/chain 和硬件 offload，而不是调大 class 速率。

## 8. `filter`、classifier 与 action

```text
tc filter { add | change | replace | delete | get } dev DEV
    [ ingress | egress | root | parent ID ]
    [ protocol PROTO ] [ priority N ] [ chain N ]
    KIND [ MATCH ] [ classid ID ] [ action ACTION ... ]
tc filter show dev DEV [ ingress | egress | parent ID ]
```

常见 classifier：

| 类型 | 用途 |
|---|---|
| `flower` | 按以太网、VLAN、IP、端口、隧道键等结构化字段匹配 |
| `u32` | 通用位移/掩码匹配，强大但难维护 |
| `bpf` | 使用 tc BPF/eBPF 程序 |
| `matchall` | 匹配全部报文 |
| `fw` | 按 firewall mark 分类 |
| `basic` | 配合 ematch 表达式 |

常见 action：

| action | 作用 |
|---|---|
| `gact drop/pass/continue` | 丢弃、放行或继续 |
| `mirred egress redirect dev IFB` | 重定向到其他接口 |
| `mirred egress mirror dev DEV` | 复制到其他接口 |
| `police rate ...` | 超速 policing，可 drop 或继续 |
| `skbedit` | 修改 mark、priority、queue_mapping 等 skb 元数据 |
| `vlan` / `pedit` / `tunnel_key` | VLAN、字段、隧道元数据操作 |
| `ct` | 连接跟踪/NAT action，依赖内核支持 |

`skip_hw` 强制软件执行，`skip_sw` 要求硬件 offload；`in_hw` 表示硬件状态。驱动接受规则不代表交换 ASIC 一定按预期计数，需同时看 `tc -s` 和硬件统计。

## 9. `clsact` 与 ingress policing

```bash
sudo tc qdisc replace dev eth0 clsact

# 所有入方向超过 100 Mbit/s 的流量丢弃
sudo tc filter replace dev eth0 ingress protocol all priority 10 \
  matchall action police rate 100mbit burst 1mb conform-exceed drop

tc -s filter show dev eth0 ingress
```

policing 是超速即处置，不像 shaping 那样通过排队平滑，因此更容易出现突发丢包。

删除整个 clsact：

```bash
sudo tc qdisc del dev eth0 clsact
```

这会同时删除该 hook 上的 ingress/egress filters，包括 CNI、安全或可观测组件安装的规则。生产上绝不能在不确认 owner 的情况下执行。

## 10. IFB 入方向整形

```bash
sudo ip link add ifb0 type ifb
sudo ip link set ifb0 up
sudo tc qdisc replace dev eth0 clsact
sudo tc filter replace dev eth0 ingress matchall \
  action mirred egress redirect dev ifb0
sudo tc qdisc replace dev ifb0 root tbf \
  rate 100mbit burst 1mb latency 50ms
```

流量被 redirect 后会走 IFB 的 egress qdisc，从而能够排队整形。实验前确认机器上没有其他组件使用同一个 IFB 或 clsact。

清理顺序：

```bash
sudo tc qdisc del dev eth0 clsact
sudo tc qdisc del dev ifb0 root
sudo ip link del ifb0
```

## 11. `netem` 网络故障仿真

只在隔离实验接口/namespace 使用：

```bash
sudo tc qdisc replace dev veth-blue root netem \
  delay 50ms 10ms distribution normal \
  loss 1% \
  rate 100mbit
```

能力包括：

| 参数族 | 用途 |
|---|---|
| `delay TIME [JITTER] [CORRELATION] [distribution DIST]` | 延迟与抖动 |
| `loss random PERCENT [CORRELATION]` | 随机丢包 |
| `loss state ...` / `gemodel ...` | 突发丢包模型 |
| `duplicate PERCENT` | 重复 |
| `corrupt PERCENT` | 位损坏 |
| `reorder PERCENT [CORRELATION]` | 乱序，通常需要延迟提供排队空间 |
| `rate RATE` | 速率限制及包开销建模 |
| `slot ...` | 时隙发送模型 |
| `seed N` | 支持版本中的伪随机种子，便于复现 |

`netem` 在发送端观察到的效果还受 GSO/TSO、qdisc 时钟粒度和应用行为影响。需要精确按包仿真时，核对 Offload 并用抓包验证。

## 12. 读懂统计

```text
Sent ... bytes ... pkt (dropped N, overlimits M requeues R)
backlog ...b ...p requeues R
```

| 字段 | 含义 |
|---|---|
| `Sent` | 经过该对象的累计字节/包 |
| `dropped` | 该 qdisc/filter/action 丢弃累计 |
| `overlimits` | 超出速率或限制的事件，不一定都丢包 |
| `requeues` | 驱动忙等原因导致重新入队 |
| `backlog` | 当前排队字节与包 |
| filter/action counters | 规则匹配、动作执行和硬件执行计数 |

保存两次快照并计算增量。累计 counter 从系统启动或对象创建开始，不能直接对应当前告警窗口。

## 13. 生产排障与恢复

```bash
tc -s -d qdisc show dev eth0
tc -s -d class show dev eth0
tc -s -d filter show dev eth0 root
tc -s -d filter show dev eth0 ingress
tc -s -d filter show dev eth0 egress
```

变更前至少记录：命令版本、设备 ifindex、完整对象树、CNI/NetworkManager/systemd 配置、filter counter 与网卡队列统计。文本输出可以审计，但不等价于可直接恢复的完整配置；复杂环境应由声明式工具重新下发。

## 14. 易错点

- `tc qdisc del dev eth0 root` 不是清理无害缓存，而是删除数据路径配置。
- ingress policing 与 egress shaping 语义不同。
- `clsact` 上可能有 Kubernetes CNI、eBPF 或安全代理规则。
- `overlimits` 不等于 `drops`。
- `netem` 放置位置决定模拟的是哪一方向、哪一段路径。
- 硬件 offload 会让软件路径抓包和统计与实际转发出现差异。
- 单位、burst、MTU、GSO 和 Ring 会共同影响结果，不能只看 `rate`。
