# ss 命令详解：套接字、TCP 状态、队列和进程定位

`ss` 从内核 Socket 诊断接口读取状态，用来回答“谁在监听、连接到谁、队列是否堆积、TCP 卡在哪个状态、由哪个进程或 cgroup 持有”。它比已淘汰的 `netstat` 能展示更多 TCP 内部信息，也更适合大量连接场景。

## 1. 命令档案

| 项目 | 内容 |
|---|---|
| 命令 | `ss` |
| 实现 | iproute2 |
| 默认行为 | 显示已打开的非监听套接字 |
| 安全级别 | 查询为 `[R]`；`-K/--kill` 会强制关闭匹配连接，属于 `[D]` |
| 权限 | 普通用户可查大部分状态；进程、BPF、安全上下文等信息受权限限制 |

```bash
ss --version
ss --help
```

## 2. 先理解输出列

```bash
ss -nt
```

```text
State  Recv-Q Send-Q Local Address:Port Peer Address:Port
```

| 列 | 已连接 Socket | 监听 Socket |
|---|---|---|
| `State` | TCP 状态；UDP 常显示 `UNCONN` | 常见 `LISTEN` |
| `Recv-Q` | 应用尚未读取的字节数 | 当前等待 `accept()` 的已完成连接数 |
| `Send-Q` | 已发送但尚未确认，或等待发送的字节 | listen backlog 上限 |
| `Local` | 本地绑定地址和端口 | `0.0.0.0`/`[::]` 表示相应协议族任意地址 |
| `Peer` | 对端地址和端口 | 通常是通配符 |

队列语义因协议和状态不同，不能看到非零 `Send-Q` 就直接认定网络故障。需要结合 `-i` 的重传、RTT、拥塞窗口以及应用读写状态判断。

## 3. 参数全集按功能分类

### 3.1 输出格式与对象范围

| 短参数 | 长参数 | 作用 |
|---|---|---|
| `-h` | `--help` | 帮助 |
| `-V` | `--version` | 版本 |
| `-H` | `--no-header` | 不显示表头 |
| `-Q` | `--no-queues` | 隐藏 Recv-Q/Send-Q |
| `-O` | `--oneline` | 每个 Socket 一行 |
| `-n` | `--numeric` | 不解析主机名和服务名；排障通常应启用 |
| `-r` | `--resolve` | 尝试解析地址/端口名称，可能慢或受 DNS 故障影响 |
| `-a` | `--all` | 同时显示监听和非监听 Socket |
| `-l` | `--listening` | 只显示监听 Socket |
| `-B` | `--bound-inactive` | 显示已 bind 但未监听、连接等的 TCP Socket |
| `-s` | `--summary` | 输出汇总，不遍历完整 Socket 列表，连接数巨大时更轻量 |
| `-E` | `--events` | 持续显示被销毁的 Socket |

### 3.2 扩展信息

| 短参数 | 长参数 | 作用 |
|---|---|---|
| `-o` | `--options` | 显示重传、keepalive、TIME-WAIT 等定时器 |
| `-e` | `--extended` | 显示 UID、inode、Socket cookie 等 |
| `-m` | `--memory` | 显示 Socket 内存与 backlog 统计 |
| `-p` | `--processes` | 显示占用进程；权限不足时可能缺失 |
| `-T` | `--threads` | 显示线程，隐含 `-p` |
| `-i` | `--info` | 显示 TCP 内部指标 |
| 无 | `--tos` | 显示 TOS、IPv6 traffic class 与优先级/class_id |
| 无 | `--cgroup` | 显示 cgroup v2 路径 |
| 无 | `--inet-sockopt` | 显示 INET Socket 选项 |
| `-b` | `--bpf` | 显示 classic BPF 过滤器，通常需要管理员权限 |
| 无 | `--bpf-maps` | 显示 Socket-local BPF map 数据 |
| 无 | `--bpf-map-id=ID` | 只显示指定 map，可重复 |
| `-Z` | `--context` | 进程及 SELinux 安全上下文 |
| `-z` | `--contexts` | 另显示 Socket inode 上下文 |

### 3.3 协议和地址族

| 选项 | 对象 |
|---|---|
| `-4` / `-6` | IPv4 / IPv6 |
| `-t` / `-u` | TCP / UDP |
| `-x` | Unix domain Socket |
| `-0` | PACKET Socket |
| `-w` | RAW Socket |
| `-d` | DCCP |
| `-S` | SCTP |
| `-M` | MPTCP |
| `--tipc` / `--vsock` / `--xdp` | TIPC / VSOCK / AF_XDP |
| `-f FAMILY` | 指定 `unix`、`inet`、`inet6`、`link`、`netlink`、`vsock`、`tipc`、`xdp` 等族 |
| `-A QUERY` | 指定一个或多个表，如 `tcp,udp`；`!tcp` 表示排除 |

### 3.4 命名空间、文件和破坏性选项

| 选项 | 作用 | 风险 |
|---|---|---|
| `-N NAME` / `--net=NAME` | 查询命名 network namespace | `[R]` |
| `-F FILE` / `--filter=FILE` | 从文件逐行读取过滤条件 | `[R]` |
| `-D FILE` / `--diag=FILE` | 将过滤后的 TCP 诊断原始数据写入文件，不正常显示 | `[R]`，注意数据权限 |
| `-K` / `--kill` | 强制关闭匹配的 IPv4/IPv6 Socket | `[D]`，必须使用严格过滤器 |

## 4. 最常用组合

```bash
# TCP/UDP 监听端口、数字地址、进程
sudo ss -lntup

# 所有 TCP 连接
ss -ant

# TCP 汇总
ss -s

# 已建立 TCP 的内部指标和进程
sudo ss -tinp state established

# UDP 及内存
sudo ss -uanm

# Unix Socket 与进程
sudo ss -xlp

# 指定命名空间
sudo ss -N blue -lntp
```

`-n` 应成为排障默认项：名称解析可能产生额外 DNS 流量，把端口显示成服务名，还可能因 DNS 故障拖慢命令。

## 5. TCP 状态过滤

```text
ss [OPTIONS] state STATE [EXPRESSION]
ss [OPTIONS] exclude STATE [EXPRESSION]
```

标准状态：

| 状态 | 解释 |
|---|---|
| `listening` | 服务监听 |
| `syn-sent` | 主动发 SYN 后等待回应 |
| `syn-recv` | 收到 SYN，等待握手完成 |
| `established` | 已建立 |
| `fin-wait-1/2` | 主动关闭路径 |
| `close-wait` | 对端已关闭，本地应用尚未 close |
| `last-ack` | 被动关闭后等待最后 ACK |
| `time-wait` | 主动关闭后的保护状态 |
| `closing` | 双方同时关闭等场景 |
| `closed` | 关闭 |

聚合状态：`all`、`connected`、`synchronized`、`bucket`、`big`、`bound-inactive`。

```bash
ss -ant state syn-recv
ss -ant state time-wait
ss -ant state close-wait
ss -ant exclude listening
```

诊断提示：

- 大量 `SYN-SENT`：查路由、邻居、防火墙、对端监听和回包。
- 大量 `SYN-RECV`：查 backlog、应用 accept 能力、SYN flood 与 CPU。
- 大量 `CLOSE-WAIT`：通常是本地应用没有及时关闭 Socket。
- 大量 `TIME-WAIT`：先确认谁主动关闭、连接复用和请求模式，不要直接修改内核参数。

## 6. 表达式过滤器

表达式使用 `or`、`and`、`not` 与括号；优先级依次升高。Shell 也解释括号和 `!`，因此复杂表达式应整体单引号包裹。

支持的主要谓词：

| 谓词 | 示例 |
|---|---|
| `src` / `dst` | `dst 10.0.0.0/8` |
| `sport` / `dport` | `dport = :443`、`sport >= :1024` |
| `dev` | `dev = eth0` |
| `fwmark` | `fwmark = 0x1/0xff` |
| `cgroup` | `cgroup = /system.slice/app.service` |
| `autobound` | 匹配自动分配本地端口的 Socket |

比较符支持 `= != > < >= <=` 及 `eq/ne/gt/lt/ge/le` 别名。

```bash
ss -nt state established '( dport = :443 or sport = :443 )'
ss -nt 'dst 10.20.0.0/16 and dport >= :8000 and dport <= :8999'
ss -nt 'dev = eth0 and fwmark = 0x1/0xff'
ss -x 'src /run/app/*'
```

IPv6 地址带端口时用方括号消除歧义。一个表达式中混合不兼容的地址族可能得到意外结果。

## 7. `-i`：读懂 TCP 内部指标

```bash
ss -tin state established '( dport = :443 )'
```

| 字段 | 含义 | 观察重点 |
|---|---|---|
| `rtt:A/B` | 平滑 RTT / RTT 方差，毫秒 | 和基线比是否突增 |
| `rto`、`backoff` | 重传超时与指数退避 | backoff 增长通常表示连续超时 |
| `cwnd` | 拥塞窗口，单位为报文段 | 过小可能受丢包/拥塞控制影响 |
| `ssthresh` | 慢启动阈值 | 与 cwnd 联合解释 |
| `mss` / `pmtu` | 最大报文段 / 路径 MTU | 核对隧道和 PMTU 黑洞 |
| `bytes_acked/received` | 已确认/已接收字节 | 两次采样看是否推进 |
| `segs_out/in` | 发出/收到报文段 | 看方向和增量 |
| `retrans` | 重传统计 | 看增量，不只看历史累计 |
| `send` | 估算发送速率 | 不是业务层吞吐的唯一口径 |
| `pacing_rate` | TCP pacing 速率 | 受拥塞控制与 qdisc 影响 |
| `rcv_space` | 接收缓冲自动调优相关值 | 需与应用读取和内存一起看 |
| `lastsnd/lastrcv/lastack` | 距最近事件的毫秒数 | 判断连接是否停滞 |

对连接做两次带时间的采样，比单次快照更有价值。

## 8. 定时器和内存

```bash
ss -ntom state established
```

`-o` 可能显示：

```text
timer:(on,220ms,2)
```

`on` 可代表 TCP 重传、Early Retrans 或 Tail Loss Probe；另有 `keepalive`、`timewait`、`persist`。第三个字段是重传次数相关值，不应脱离 TCP 状态解释。

`-m` 的 `skmem` 常见字段：

| 字段 | 含义 |
|---|---|
| `r` / `rb` | 已分配接收内存 / 接收缓冲上限 |
| `t` / `tb` | 发送相关已分配内存 / 发送缓冲上限 |
| `w` | 尚未进入三层的排队发送内存 |
| `f` | 预分配缓存 |
| `o` | Socket 选项内存 |
| `bl` | backlog 内存 |
| `d` | Socket 层丢包数 |

应用读不动常表现为 Recv-Q 与接收内存上升；对端或网络不确认常表现为 Send-Q、重传和定时器变化。仍需结合应用线程、CPU、抓包与服务指标。

## 9. 端口监听排障

```bash
sudo ss -lntp 'sport = :8080'
```

依次判断：

1. 没有输出：进程未监听、监听在其他命名空间，或协议选错。
2. 只监听 `127.0.0.1:8080`：远端不能通过节点 IP 访问。
3. 只监听 `[::]:8080`：是否同时接受 IPv4 取决于 `IPV6_V6ONLY` 与系统设置。
4. 有监听但访问失败：继续查路由、邻居、防火墙、Service/NAT、backlog 和应用 accept。
5. `-p` 没进程：可能权限不足，使用管理员权限重试。

## 10. `ss -K` 的严格边界

先只读预览：

```bash
ss -nt state established 'dst 203.0.113.8 and dport = :443'
```

只有在明确需要强制断开、确认选择器不会扩大且业务允许重连时才执行：

```bash
sudo ss -K state established 'dst 203.0.113.8 and dport = :443'
```

`-K` 支持内核可销毁的 IPv4/IPv6 Socket；不支持的对象会被跳过。它不是“清理显示”，会真实终止连接。

## 11. 自动化与快照

`ss` 没有与 `ip -j` 等价的稳定 JSON 输出。脚本应：

- 使用 `-H -n -O` 减少格式变化。
- 使用严格过滤器减少数据量。
- 不依赖进程显示字符串作为唯一身份，必要时关联 inode、PID 和 cgroup。
- 记录命令版本、命名空间和采样时间。

```bash
ss -HntO state established > ss-established.txt
ss -s > ss-summary.txt
```

## 12. 易错点

- `ss -l` 默认不限 TCP，排查 TCP 监听应明确 `-lnt`。
- UDP 无连接语义与 TCP 不同，`UNCONN` 不表示异常。
- `0.0.0.0:*`、`[::]:*` 和具体地址的绑定范围不同。
- 队列非零只是现象；要区分应用未读、对端未确认、拥塞和内核排队。
- 宿主机 `ss` 看不到另一个 network namespace 的普通 Socket。
- 一次累计重传值不能证明当前仍在丢包，要看增量和业务时间窗口。
