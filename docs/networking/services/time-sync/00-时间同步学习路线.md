# NTP 与 PTP 时间同步学习路线

把时间显示为同一个时区，只改变显示方式；让不同机器在规定误差内理解同一时刻，才是时间同步。

## 1. 阅读顺序

1. [NTP、时钟偏差与时间误差预算](./01-NTP时钟偏差与时间误差预算.md)：从四时间戳推导进入样本筛选、选源与控制，计算渐进收敛和保持误差，并区分 Linux 时钟与 NTS 两段交互。
2. [PTP、硬件时间戳与 PHC 时钟体系](./02-PTP硬件时间戳与PHC时钟体系.md)：计算 E2E 延迟与偏差，追踪消息匹配、TC 校正、GM 选择与伺服收敛，再理解 PHC 到应用的误差链。

## 2. 先区分要达到的目标

| 目标 | 关注点 |
| --- | --- |
| 时间戳接近共同参考 | 时间／相位偏差及其不确定性 |
| 两个时钟走得一样快 | 频率误差和长期漂移 |
| 测量本机任务耗时 | 合适的单调时钟，不依赖墙上时间是否跳变 |
| 比较跨机器事件 | 各机器误差范围、时间尺度以及事件关联信息 |

NTP/PTP 可以降低时间误差，但不能把跨机器时间戳变成绝对可靠的事件因果排序，更不能替代共识协议或事务机制。

阅读计算示例时，先确认偏差的正负方向、单位和对称性假设；阅读状态指标时，先确认它测的是 PHC、系统时钟还是应用事件，以及比较的是哪一个参考。
