# 网络服务学习路线

路由器能转发数据，不等于应用已经具备通信所需的全部条件。终端还要获得配置、找到服务地址，并为证书、日志、分布式协作提供可信的时间基础。

## 1. 三类服务分别解决什么问题

| 模块 | 核心职责 | 不负责的事情 |
| --- | --- | --- |
| [DHCP](./dhcp/00-DHCP学习路线.md) | 分配和续订地址等网络参数 | 不代替路由转发，不保证配置对应的服务健康 |
| [DNS](./dns/00-DNS学习路线.md) | 将名称映射到地址和其他资源记录 | 通常不转发之后的业务连接，不自动搬迁长连接 |
| [NTP 与 PTP](./time-sync/00-时间同步学习路线.md) | 建立和维持时钟之间的时间／频率关系 | 不替代分布式事务、因果关系和一致性协议 |

## 2. 推荐阅读关系

先理解 [IPv4 前缀与路由](../fundamentals/03-IPv4子网划分与路由表.md)，再学习 DHCP。学习 IPv6 地址配置时，把 DHCPv6 与 [SLAAC、RA](../fundamentals/ipv6/04-SLAAC与DHCPv6地址分配机制.md) 对照起来。

DNS 可以在掌握 UDP、TCP 后学习；时间同步则进一步使用报文往返、延迟和误差预算的概念。

```text
地址配置 → 能否作为一个网络端点通信
名称解析 → 应该与哪个端点通信
时间同步 → 不同端点如何在可控误差内理解时间
```

这不是每个请求都会顺序执行的三步。DHCP 租约、DNS 缓存、时钟校准都具有持续状态，业务请求通常利用已有状态运行。

## 3. 阅读时注意三个边界

1. **协议和实现**：DHCP 是协议，Kea 是实现；DNS 是协议体系，BIND、CoreDNS 等是实现；NTP/PTP 与 chrony、LinuxPTP 也不能混为一谈。
2. **控制与数据**：地址服务器故障可能影响新终端而暂不影响旧终端；解析器故障可能被缓存暂时掩盖。这与数据路径立即中断不同。
3. **成功与可信**：返回地址不代表地址正确且可达；收到时间不代表时间可信且误差满足需求。
